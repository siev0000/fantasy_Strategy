# 物流・運搬ルートの現行ルール

更新: 2026-10-18

## 画面と設定

- 左の縦タブに「物流」を追加。交流（会話/依頼/交渉/提案）とは分ける。
- 固定ヘッダーの「運搬を設定」から専用モーダルを開く。部隊または単独1体、運搬元（自拠点/接続済みの自軍鉱床）、搬送先自拠点、物資1種、1回の上限数、片道/自動往復を選択する。複数物資の一括指定は未対応。
- 左一覧は部隊名・運搬元→搬送先・状態・積荷。右は選択した任務と中断/再開/帰還/解除。稼働中/中断・完了で絞り込む。戦闘ステータスを並べない。
- 設定変更は帰還・荷下ろし後に任務解除して再設定する。積載中の解除は拒否し、帰還は積荷を持って帰還先へ戻す（拠点間は出発拠点、鉱床便は搬送先拠点）。物資を消したり二重加算しない。
- 基本行動から大きな運搬設定を撤去。拠点の旧輸送設定も物流への入口へ統合する。入口警備の既存軍隊指定は土地タブに分ける。手動の鉱床回収/道具の現地使用は基本行動に残す。

## 部隊と実移動

- 部隊全員を担当にする。単独は1体扱い。設定時に同じ世界の周囲2マス以内へ集合が必要。他任務/教官/散開/その場待機/召喚体/既存荷物との兼任を拒否する。
- 任務は `factionState.logisticsRoutes`、ID発番は `logisticsSerial`。各担当者の `transportAssignment.logisticsRouteId` は任務の参照。旧自動往復エンジンへ二重登録しない（旧形式の搬送先IDを持たない）。保存/読込とスナップショットの深い複製に対応する。
- 自分の操作ターン終了時、既存の追従隊列・AP・地形/高低差/壁条件で歩く。積載上限は担当者の既存容量の合計、荷重速度は共通の部隊移動計算を使う。積込は実在庫と容量の範囲、搬入時に在庫へ加算する。
- 積荷は既存の部隊個別荷物 `cargoByUnitId[leaderId]` に保存する。死亡時の既存荷物移管を使い、任務独自の不可視在庫を増やさない。死亡/離脱/別世界への分散時は停止し、残った荷物を消さない。
- 鉱床便は地上と奥地の実入口を経由する。入口通過APと必要な入口周辺への移動APを各員から消費し、範囲内の通行可能な空きマスへ配置する。配置先が塞がれたり足りなければ停止する。入口の配置は中心+隣接1マスまでで、大人数/狭い出口は任務を小さな部隊に分ける必要がある。
- 物資/AP/味方ユニットの移動待ちは待機。通路/接続/搬送先/部隊の不整合は停止して手動再開を待つ。単発は搬入後に完了し担当参照を解除、自動往復は空荷で運搬元へ戻る。同じターンは `lastProcessedTurn` で二重処理しない。
- 有効任務がなければターン終了フックは大きなワールドスナップショットを作らず即時終了する。

## 経路表示

- 物流タブを開いている間だけ、現在表示している世界の出発拠点→搬送先拠点を固定の直線と矢印で結ぶ。これは物資の流れを示す接続線であり、地形/壁/他ユニットを迂回する実歩行経路ではない。運搬担当者の現在位置・空荷帰還・待機で端点や方向を変えない。表示用接続は `v39-logistics-connections.js`、実移動は既存の自動移動/取引エンジンへ分離する。
- 線・矢印はプレイヤーの所属色で不透明表示。選択任務は太線と白い縁取り、他は暗い縁取りで区別し、選択しても所属色を変えない。進行方向は大きい塗りつぶし三角形。線幅/縁取り/矢印寸法は `config/v39-logistics-display.json`、所属色は共通の `v39-player-colors.js` に集約。任務選択で現在の経路を見渡せる倍率・中心へ地図を移動する。別世界の任務は一覧の現在地で区別し、自動的に別世界へ切り替えない。
- 洞窟鉱床便は地上入口→搬送先拠点を点線で結び、入口を「洞窟入口」と表示する。担当者が地上へ出ても端点/点線を変えない。洞窟表示ではその世界の鉱床側と出口側を使い、同じマスなら点だけを表示する。鉱床が地上にあるようには扱わない。未探索区間/未発見入口の線・ラベルは通常プレイでは描かない。
- 「担当部隊を表示」で所有ユニットの現在ワールドを表示し、洞窟内では「地上経路を表示」で戻れる。既存のワールド切替処理を使い、物流タブと任務選択を維持する。位置/AP/積荷/任務は変更しない。他勢力・存在しないユニットや入力ロック中の表示切替は拒否する。
- 停止位置に「×」、待機/中断に「Ⅱ」。押すと該当任務と理由を表示する。目的地へ至れない場合は現在地に表示し、障害物の位置を推測して置かない。
- 通常プレイの未探索区間は描かない。テストモードだけ全経路を確認できる。タブ移動/フィールド再生成時に描画を破棄し、閉じている間は経路を再計算しない。

## 既存データと取引

- 旧ユニット単位の拠点間輸送・鉱床輸送も物流に表示する。中断/再開/任務解除を提供し、旧荷物や任務は勝手に部隊へ変換しない。旧軍隊専用任務のルールは互換として維持する。
- 郵送・貿易は担当者/部隊の進行状況を一覧で確認し、契約変更は既存取引モーダルを開く。地図は自分の提供元拠点→相手の受取拠点を結ぶ物資の流れ。双方向交換は各国色の線を左右へずらし（`tradeLaneOffset`）、互いの矢印を見分けられるようにする。提供物資が空の側は逆向きの物資線を出さない。待ち合わせ範囲/予約/承諾/同時交換/実際の往復移動は従来どおり維持する。
- 2026-10-18: 操作プレイヤーが当事者の国家間取引は、相手国の運搬側も一覧/地図へ追加する。双方の所属色で描き、相手側は閲覧のみ（任務操作/ワールド切替不可）。相手ユニットの座標/停止位置は通常の索敵判定に従い、経路は現在視界内の区間だけ表示する。テストモードでは関係する取引の索敵制限だけ解除する。
- 操作プレイヤーが当事者でない他国同士の取引、および他国の国内輸送は一覧・経路・停止マークの対象外。テストモードでも第三国間の契約公開条件を迂回しない。他国調査による公開は将来仕様として保留し、発見済み地形や友好度だけで勝手に公開しない。共通の当事者判定は `v39-logistics-visibility.js`。

## 施設の発展方針（採用・未実装）

- 2026-10-18: 遠隔採取/中継用の「集積所 → 倉庫」の発展を採用する。現行の森便は集積村からの搬出であり、独立した集積所施設が実装されたわけではない。
- 保管容量・建築/改築条件・備蓄指定・既存倉庫の効果数値は未確定。今回の経路表示変更では施設データや生産量、保管上限を変更しない。

## 検証

- テスト→専用→「物流ルートテスト」で、既存の道具/支援検証とは別の配置を起動する。自国の村3・町2、洞窟鉱床、森の集積村、2人部隊4組を用意する。洞窟→検証村（鉄10）、森の集積村→中央物流町（木材20）、農村→東の交易町（穀物20）、中央物流町→検証村（木材10）を自動往復に設定する。2026-10-18追記: 同じ入口へ北国/東国と国家間取引も統合し、自国の一覧は国内4便＋自国と北国の取引双方2便の計6件を表示する。
- 森便は独立した未領有森の自動採取ではなく、森を領有する集積村の実在庫を搬出する。町は中心+隣の2マスを居住域として配置する。通常ゲームのルール/データや既存専用テストは変更しない。配置・数量・担当者位置は `config/v39-logistics-test.json` で変更可能。
- 起動時に通常の物流処理で初回積込まで実行するため、実在庫を消費し、最初から積荷と搬送先への経路を表示する。そのターンの自動処理は二重実行せず、次のターンから搬送する。再開始は任務/拠点/ユニットを追加せず作り直す。
- `node scripts/check-v39-logistics-fixture.mjs`: PC/スマホ、専用ボタン、村/町/森、全4便の搬入と世界間往復、積荷込み在庫保存、実ターン/保存復元/再開始を確認する。
- `node scripts/check-v39-cave-logistics-visibility.mjs`: 洞窟便の点線/洞窟内表示、洞窟と地上の閲覧切替（瞬間移動/積荷変更なし）、未探索区間の非表示、実際の通常ターンでの地上退出/鉄の搬入を390/1100pxで確認する。
- 「物流ルートテスト」は自国↔北の交易国、北国↔東の交易国も既存の提案/承諾/備蓄確保/実積込から設定する。物流ヘッダーの検証視点で切替でき、自国からは北↔東を隠す。別の「国家間物流テスト」ボタンは廃止し、旧 `startV39InternationalLogisticsTest` APIだけ同じ初期化処理の互換名として残す。通常画面に検証視点選択は出さない。位置・物資・日程は `config/v39-international-logistics-test.json` と既存取引ルールを使い、相手の契約を自軍へ複製しない。
- `node scripts/check-v39-international-logistics.mjs`: 390/1100pxの3視点/当事者の両側表示/非当事者の非表示（テストモード含む）/国別色/相手任務の操作不可/索敵外非表示/実交換と帰還/物資保存/セーブ/再開始を確認する。
- `node scripts/check-v39-logistics-connections.mjs`: 国内/旧輸送/鉱床/国家間の拠点端点、ユニット位置/世界/帰還/待機に依存しない固定線、相互取引の逆方向2レーン、状態不変性、実際の表示を確認する。

- `node scripts/check-v39-logistics-routes.mjs`: PC/スマホの実設定UI、2体の追従/AP、拠点間の積込/搬入、中断/解除制限、保存/再開、鉱床への世界間往復、実ターン終了フック、経路描画/タブ終了。
- `node scripts/check-v39-logistics-stops.mjs`: 経路不能、手動再開、積荷保持/帰還、停止マークの理由、未探索区間非表示、同ターン重複、状態不変性、設定モーダル終了時の入力ロック解除。
