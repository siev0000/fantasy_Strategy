# スマホ向けレスポンシブUI設計書（暫定）

最終更新: 2026-09-12

> この文書は、現在検討中のスマホUI方針を固定するための**設計資料**。現行実装そのものを示す正本ではない。
> UI実装時は、この文書の確定事項を優先して参照し、未確定項目は勝手に補完せず都度確認する。

---

## 1. 目的

スマートフォンを主対象として、フィールドの視認性を確保しながら、ユニット・部隊・戦闘・土地・管理系操作を扱えるUIにする。

特に次を重視する。

- フィールドの上に大きなパネルを重ねない。
- 縦長画面と横長画面で、情報・操作領域の配置を切り替える。
- ヘッダーと左側の固定項目は常時見えるようにする。
- 同じ情報を左右・上下に重複表示しない。
- スマホでは文字を減らせる箇所はアイコン化するが、意味を識別しやすいタブ名は文字を残す。
- 文字やアイコンを小さくして詰めるのではなく、不要な余白を減らして省スペース化する。

---

## 2. 画面全体の基本構成

### 2.1 常時表示

画面の向きに関係なく、次は常時表示する。

1. **上部ヘッダー**
   - 資源表示
   - 必要な上部情報
2. **左側固定バー**
   - 研究など、常時確認したい固定項目
3. **フィールド**
   - マップ、ユニット、射程、移動範囲などを表示

右側や下側の情報・操作UIは、画面の向きに応じて配置を切り替える。

---

## 3. 縦長画面（Portrait）

### 3.1 レイアウト

縦長画面では、画面を大きく上下に分割する。

- 上部: **フィールド領域 約60%**
- 下部: **フッター兼 情報・操作領域 約40%**

ヘッダーは最上部、研究などの固定バーは左側に残す。

概念図:

```text
┌────────────────┐
│ ヘッダー       │
├─┬──────────────┤
│研│              │
│究│  フィールド  │
│等│   約60%      │
│  │              │
├─┴──────────────┤
│ 情報・操作      │
│ フッター 約40%  │
└────────────────┘
```

### 3.2 右サイドバー

縦長画面では、従来の大きな右サイドバーは使用しない。

理由:

- スマホ横幅を大きく消費する。
- マップが見えなくなる。
- 戦闘スキルなどを表示した際にさらに圧迫する。

ユニット・部隊・戦闘などの内容は下部フッター側へ集約する。

---

## 4. 横長画面（Landscape）

### 4.1 レイアウト

横長画面では、**フッターを表示しない**。

縦長画面でフッターに表示していた情報・操作領域を、**右サイドバーへ移す**。

- 上部: ヘッダー
- 左側: 研究などの固定バー
- 中央: フィールド
- 右側: 情報・操作サイドバー
- 下部: フッターなし

概念図:

```text
┌──────────────────────────┐
│ ヘッダー                 │
├─┬────────────────┬───────┤
│研│                │情報・ │
│究│   フィールド   │操作   │
│等│                │右バー │
│  │                │       │
└─┴────────────────┴───────┘
```

### 4.2 重要ルール

**横長時は「下部フッターを右へ移したもの」と考える。**

フッターを残したまま右パネルを追加する構成にはしない。

つまり、縦長と横長で情報・操作UIが二重表示されないようにする。

---

## 5. 画面向き切替

初期方針:

- `portrait` → 下部フッター型
- `landscape` → 右サイドバー型

実装時の正確なブレークポイント、最小幅、タブレット扱いは未確定。

単純な横幅だけではなく、画面の縦横比も考慮する。

---

## 6. フッター / 右サイドバーの役割

縦長時のフッターと、横長時の右サイドバーは、**同じ情報・操作機能を表示するレスポンシブな同一領域**として扱う。

現時点の候補タブ:

- ユニット
- 部隊
- 戦闘
- 土地
- 土地データ
- 管理

タブ構成自体は今後整理する可能性がある。

### 6.1 タブ表記

フッターの主要タブは**アイコンのみではなく文字表示を優先**する。

理由:

- 頻繁に切り替える主要機能は意味がすぐ分かる方がよい。
- 小さいアイコンだけでは識別しづらい。

---

## 7. 部隊タブ

部隊タブは、選択キャラクターを確認・切り替えるための画面とする。

### 7.1 基本構成

表示領域を左右2分割する。

- 左半分: 部隊メンバー一覧
- 右半分: 選択キャラクターの詳細

縦長画面の下部領域でも、この左右分割を基本とする。

### 7.2 左側: キャラクターカード

各キャラクターをカード形式で表示する。

カードに表示する情報は次のみ。

- キャラ名
- 座標（小さく表示）
- HP
- AP

カード全体をタップ可能にする。

タップすると、そのキャラクターを選択し、右半分の内容を更新する。

### 7.3 右側: 選択キャラクター詳細

右側には、左側と重複しない情報を表示する。

主な表示内容:

- 攻撃
- 防御
- 魔法攻撃系ステータス
- 魔法防御系ステータス
- 速度
- 命中
- SIZなど、その他の各種ステータス
- 技能 / スキル一覧

**左側ですでに表示している以下は、右側では原則繰り返さない。**

- キャラ名
- 座標
- HP
- AP

Lvや役割などの扱いは未確定。必要性を見て決める。

---

## 8. 戦闘UI

### 8.1 基本方針

戦闘そのものはフィールド上で行う。

- 移動範囲
- 攻撃射程
- 攻撃範囲
- 対象選択

などはマップ上に表示する。

ただし、スキル選択やコマンド選択のための大きなパネルをフィールド上へ重ねない。

### 8.2 縦長時

戦闘コマンド・スキル選択は下部フッター内に表示する。

### 8.3 横長時

戦闘コマンド・スキル選択は右サイドバー内に表示する。

フィールドの中央へ大きなスキル選択ウィンドウを重ねる構成は避ける。

---

## 9. 資源表示

### 9.1 上部資源

資源はヘッダー側に常時表示する。

詳細表示と簡易表示を切り替えられる構成を想定する。

### 9.2 詳細資源のグループ

現在のUI案では、詳細表示を次の4グループとして扱う。

- 食料
- 木材
- 鉱石
- 貴金属

食料の詳細例:

- 穀物
- 野菜
- 肉
- 魚
- 死体
- 魂

### 9.3 資源詳細ポップアップ

資源詳細は省スペースを優先する。

1項目ごとに表示するもの:

- 大きめの資源アイコン
- 現在値
- 増減値

**資源名の文字は原則表示しない。**

また、上部資源ですでに表示している以下のようなヘッダー情報は詳細側では繰り返さない。

例:

`食料 1,280 +42 / 種類別`

詳細ポップアップ内では、この重複ヘッダーを表示しない。

アイコンを小さくして省スペース化するのではなく、カード・余白の横幅を内容に合わせて縮める。

---

## 10. アイコンと文字の使い分け

### 10.1 アイコン中心にする箇所

スマホでは、補助的な管理操作などはアイコン中心でよい。

例:

- 装備
- 建設
- 設定
- ログ
- ユニット作成

必要に応じて、タップ時に短い説明を表示する。

### 10.2 文字を残す箇所

主要な画面切替タブは文字を残す。

例:

- ユニット
- 部隊
- 戦闘
- 土地
- 管理

### 10.3 説明ラベル

アイコンの意味が分かりづらい場合は、タップなどで短いラベルを表示してよい。

ただし、ラベルが長時間フィールドを塞がないようにする。

---

## 11. 文字・アイコンサイズ

### 11.1 基本方針

省スペース化のために、文字やアイコンを必要以上に小さくしない。

優先順位:

1. 不要な重複情報を消す
2. 不要な余白を減らす
3. 内容に合わせてカード幅を縮める
4. それでも必要な場合だけレイアウトを再構成する

文字やアイコンを小さくするのは最後の手段とする。

### 11.2 PC / スマホ

PCとスマホで固定pxをそのまま使わず、画面サイズに応じて読みやすさを維持する。

具体的な最小フォントサイズ・アイコンサイズは未確定。

---

## 12. 管理系UI

管理系機能はフィールドを圧迫しない場所へまとめる。

対象例:

- 自キャラ / キャラクター
- 都市・建設
- 装備
- ユニット作成
- ログ
- 設定

縦長時は下部の「管理」領域、横長時は右サイドバー内の「管理」領域へ配置する案を基本とする。

独立した右端常設アイコン列は、戦闘・部隊UIと重なりやすいため現時点では採用しない。

---

## 13. 現時点で採用しない案

以下は検討したが、現時点では採用しない。

- スマホ縦長時に大きな右部隊バーを常時表示する。
- 右端に管理系アイコン列を常時表示する。
- 戦闘スキル一覧をフィールド中央へ大きく重ねる。
- 横長時にも下部フッターを残し、さらに右バーを追加する。
- フッター主要タブをすべてアイコンだけにする。
- 資源詳細で資源名・合計値など上部と同じ情報を繰り返す。
- 省スペース化のために文字や資源アイコンを極端に小さくする。

## 15. 実装時の確認事項

UIを変更する際は、最低でも次の画面条件で確認する。

- スマホ縦長: 360px前後
- スマホ縦長: 390px前後
- スマホ縦長: 412px前後
- スマホ横長

確認内容:

- 横スクロールが意図せず発生していない。
- フィールドがUIで隠れすぎていない。
- ヘッダーと左固定バーが維持されている。
- 縦長時に右バーが重複表示されていない。
- 横長時にフッターが残っていない。
- 横長時に右サイドバーへ情報・操作が移っている。
- 主要操作がタップ可能な大きさを維持している。
- 文字やアイコンが読めないほど小さくなっていない。
- 同じ情報を複数箇所に重複表示していない。

---

## 16. 現在の重要ルール要約

**縦長:**

`ヘッダー + 左固定バー + 上フィールド約60% + 下フッター約40%`

**横長:**

`ヘッダー + 左固定バー + 中央フィールド + 右情報/操作バー`

**横長ではフッターを表示しない。**

**部隊:**

`左 = キャラ名 / 座標 / HP / AP のカード一覧`

`右 = 選択キャラの各種ステータス / 技能`

**資源詳細:**

`アイコン + 数値 + 増減のみ。上部と重複する文字情報は出さない。`
