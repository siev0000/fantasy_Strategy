# JSONデータ駆動ルール

最終整理: 2026-09-14

## 1. 目的

- `data/source/export/json` にある全JSON、全レコードをゲームデータの正本にする。対象外のファイルは設けない。
- ゲーム内の種類、数値、条件、表示文言は、コード側で再定義せず対応するJSONから取得する。
- 同じ仕組みに属する種族、クラス、スキル、装備、地形、敵、施設などは、JSONへデータを追加するだけでゲームへ追加できる構成にする。
- Vue、v39モジュール、Phaser内へ、種類名の固定配列や種類ごとの個別分岐を増やさない。

## 2. 基本原則

1. JSONが種類と数値の正本
   - 名前、説明、画像参照名、条件、確率、範囲、コスト、補正値はJSONから読む。
   - JSONに存在する値をコード内の同名定数や固定配列で上書きしない。
   - コード内の初期値は、JSONで既定値が定義できないシステム値だけに限定する。
2. UIはデータから生成
   - 選択肢、一覧、詳細、表、フィルターはJSONの登録内容から作る。
   - 新しい種類名をUI側の配列へ追記しない。
3. 共通ロジックで処理
   - 同じ項目を敵味方、旧UI、v39 UIで別計算しない。
   - 名称そのものではなく、識別キー、カテゴリ、効果タイプを使って処理する。
4. 参照エラーを隠さない
   - 存在しない参照、重複キー、型不正、必須値不足は、ファイル名、レコード名、項目名を開発ログへ出す。
   - 不明な種類を無関係な既定値へ黙って置換しない。
   - JSONの列がどこからも参照されていない場合も、未接続項目として検出可能にする。
5. 保存データへ定義全体を複製しない
   - セーブには定義IDと現在値だけを保存し、性能や説明はロード時に最新JSONから解決する。
   - 生成時に確定して固定すべき乱数結果、レア度、個体差は保存する。

## 3. JSONだけで追加できる範囲

以下を含むディレクトリ内の全データは、既存項目と既存効果タイプを使う限り、コード変更なしで追加できる状態を必須とする。

| 種類 | 正本JSON | 現在の識別項目 | 追加時に行うこと |
| --- | --- | --- | --- |
| 種族 | `種族.json` | `key` | 種族行を追加。必要なら `勢力.json` に初期勢力値を追加 |
| クラス | `クラス.json` | `名前` | クラス行と取得スキル名を追加 |
| スキル | `スキル一覧.json` | `名前` | スキル行を追加。既存の範囲・効果タイプを指定 |
| 装備 | `装備.json` | `装備名` | 装備行を追加。既存スロットと効果項目を指定 |
| 付与 | `付与.json` | `付与能力 + Lv` | 付与行を追加 |
| 地形 | `地形.json` | `地形` | 地形行を追加。生成対象にする場合もJSON側で生成条件を指定できるようにする |
| 敵出現 | `出現敵.json` | 要ID追加 | 出現地形、Lv範囲、個体数、装備などを追加 |
| 施設 | `施設.json` | `施設名` | 施設行と条件、コスト、効果を追加 |
| 研究 | `研究.json` | 要ID追加 | 系統、Lv、条件、効果を追加 |
| 効果 | `効果.json` | `追加効果` | 既存効果ハンドラーの種類を追加 |
| 範囲 | `範囲.json` | `範囲タイプ` | 既存範囲生成方式の設定を追加 |
| 災害 | `災害.json` | 要ID追加 | 発生条件、対象、効果値を追加できる形式へ拡張 |
| 体制 | `体制.json` | `項目カテゴリ + 項目名` | 既存影響タイプを使う行を追加 |
| 外交姿勢 | `外交姿勢.json` | `項目カテゴリ + 項目名` | 既存影響タイプを使う行を追加 |
| 組織 | `組織.json` | `項目名` | 既存影響タイプを使う行を追加 |
| 都市特性 | `都市.json` | `項目名` | 既存影響タイプを使う行を追加 |

このほか `消費量.json`、`勢力.json`、`説明.json`、`都市基本データ.json`、`テストゲーム状態.json` も同じ登録口から読み込む。個別importによる別管理は行わない。

画像やエフェクトを使う種類は、JSON追加に加えて対応ファイルを所定のassetsフォルダへ置く。画像がない場合は共通アイコンへフォールバックし、コードへ種類名分岐を追加しない。

## 4. コード実装が必要になる境界

- 既存にない攻撃範囲の形
- 既存にない効果タイプや対象選択方式
- 新しいAI判断方式
- 新しい地形生成アルゴリズム
- 通信プロトコルや保存形式の変更
- 新しい画面操作そのもの

これらは最初の1種類だけ共通ハンドラーをコードへ実装し、ハンドラーを選ぶキーと数値はJSONへ置く。以後、同じ方式を使う種類はJSON追加だけで増やせるようにする。

## 5. 共通データ登録口

個別コンポーネントがJSONを直接importして独自に検索する方式は段階的に廃止する。

共通データ登録口は以下を担当する。

- `data/source/export/json/*.json` の自動列挙と全JSONの読み込み
- ファイル名ごとのテーブル登録
- 一意キーによる検索
- 名前、ID、カテゴリによる索引
- 数値、割合、配列、空値の正規化
- 重複と参照切れの検証
- 読み取り専用データの提供
- テスト時の差し替え
- 読み込んだファイル数・レコード数と未接続項目の開発時確認

各画面とゲーム処理は、この登録口からデータを取得する。直接importが必要な場合も、登録口内部だけに限定する。

## 6. 追加時の完了条件

新しい種類は次をすべて満たして追加完了とする。

- JSONへ行を追加すると選択肢または生成候補へ現れる
- 一覧と詳細に表示される
- 条件、コスト、効果、ステータスへ反映される
- 保存とロード後も同じ種類として復元される
- 敵味方で共通処理を使う
- 未設定画像は共通アイコンで表示される
- JSON削除または参照名誤りを検証処理が検出する
- 種類名をコードへ追加していない
- JSONに追加した列が、利用済みまたは意図的な予約項目として追跡されている

## 7. 現在の移行対象

- `App.vue`、各モーダル、v39モジュール、`PhaserMapGeneratorPanel.vue` の個別JSON importを共通登録口へ寄せる。
- 現在存在する21ファイルを最初の登録対象とし、新しいJSONファイルも登録口のファイル一覧へコード追記せず読み込めるようにする。
- 地形、攻撃手段、範囲、勢力、都市能力などの固定配列をJSON参照へ置き換える。
- `出現敵.json`、`研究.json`、`災害.json` に安定したIDを追加する。
- 火山、噴火、溶岩は、確率と効果値をJSONへ移し、コードは共通地形イベント処理だけを持つ。
- JSONを追加・変更しただけで主要画面に反映されることを自動テストする。
