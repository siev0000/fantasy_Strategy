# 研究フローチャートルール

更新: 2026-10-12。現行実装。接続の初期配置は調整用の暫定データ。

## 原本と条件

- 原本は `@game_data` の「研究」。生成する `研究.json` だけを編集しない。
- `ID` は保存済み進捗のキー。表示名や分類変更だけではIDを変更しない。
- `必要研究Lv` は同じカテゴリの現在研究Lvの条件。`前提研究ID` は完了が必要な研究ID。カンマ区切りの複数指定はすべて完了が必要。
- 両方を満たすと選択可能。前Lvの全項目完了は要求しない。未解禁項目も詳細・不足条件を閲覧できる。
- 研究Lvは初期1。そのカテゴリで完了した項目の最大 `Lv` + 1で次段階を解禁する。施設・装備・徴兵向けの現在研究Lvは実装済み最大段階を上限とする。
- 項目の `Lv` は難度・必要EXPに使う。必要EXPは `100 × 2^(Lv-1)`。
- `必要ユニットLv` は速度の推奨値であり、解禁条件ではない。既存の担当制・速度式は維持する。
- 不明な前提ID、循環する前提関係は解禁せず、詳細にデータの問題を表示する。

## カテゴリと初期接続

旧研究モーダルのLv列表示を残し、初期表示は「従来表示」。モーダル上部の表示選択で「フローチャート」へ切り替える。両画面は同じ選択・担当・進捗・必要研究Lv/前提ID判定を使う。表示切替では研究データを変更しない。

表示改善: 前提関係で系列を揃え、上から下への矢印で表示する。PCでは幅に応じて系列を並べ、スマホでは幅に応じて2列（狭い場合は1列）に折り返して横方向の欠けを防ぐ。カードは名前・状態・進捗のみとし、標準高さ92〜105px、幅は最大180pxに縮小。条件説明は詳細欄で確認する。スマホは項目選択で詳細へ切り替え、「研究一覧へ戻る」で戻る。従来表示のLv別分類も維持し、スマホではLvごとに縦に並べる。効果・進捗・解禁条件を優先し、速度内訳は折りたたむ。実行ボタンは詳細欄下端に固定する。表示方法・配置のみの変更であり、前提IDや研究ルールは変えない。

鍛冶・魔法・信仰・軍事・経済・調査の6カテゴリ。地質・生態・地下探索は「調査」の枝へ統合する。原本の「技術対象=調査」を確認し、旧IDは維持した。

既存5カテゴリの初期接続は、シートの項目順を基に前Lvの同じ位置へ接続した仮の3系列。調査は地質Ⅰ→Ⅱ→Ⅲ、生態Ⅰ→Ⅱ→Ⅲ、地下探索Ⅰの独立枝。これらは最終バランスの確定ではなく、原本の `前提研究ID` を編集して変更する。別カテゴリの前提も条件に使えるが、図の線は表示中カテゴリ内のみ描き、別カテゴリの条件は詳細に表示する。

## 保存と互換

- 完了項目・項目別EXPはIDを保持して移行。旧調査3カテゴリの完了項目と繰越EXPを「調査」に合算する。
- 1カテゴリの研究中項目は1件。旧3系統が同時研究中だった保存データでは、保存順の最初の選択と担当を引き継ぐ。他の項目の途中EXPは残し、再選択時に続行できる。
- 新しい前提を満たさない旧選択はEXPを削除せず停止し、前提完了後に再開可能。
- 特産品の発見条件は地質・生態の各枝の完了Lvを別々に判定する。地質完了で生態まで解禁しない。薬草・洞窟の接近発見ルールは維持する。

## 今回の範囲外

研究の生産技能・幸福度等の数値列の効果適用、担当制の廃止、Tier2徴兵施設の対応表は未実装案のまま。施設の `level` / `item` 切替は [施設研究解禁の切替.md](./施設研究解禁の切替.md) に従う。
