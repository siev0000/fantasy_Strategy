# モンスター合体

更新: 2026-10-17。最高Lv基準の自動配分と自領全域の素材選択へ変更。未登録ボーナスクラスは新規追加せず、付与せずに実行する。

## 原本

- ウルフ＋ゴーストのディスプレイサービーストは、出現敵の種族/サブクラスと名前が一致する複合魔獣として6枠目を使う。ゴーストを含むだけで霊体画像へ置き換えない。`undeadOrigin` を持つ実アンデッド化個体や、ゾンビ/スケルトンへの変換は従来の専用画像を優先する。

- 2026-10-17画像: 魔獣_ユニット集2.webpの1〜8枠は出現敵原本の登録を共用（マンティコア/キメラ/グリフォン/アウルベア/スフィンクス/ディスプレイサービースト/バシリスク/ハイドラ）。合成結果名・保存したrecipeName・地上強敵の派生名を元種族の動物画像より優先する。手動のファイル/番号とアンデッド専用画像は従来どおり優先。自軍の画像入口でも合体ユニットをモンスターシートへ渡し、プレビューだけ正しくフィールドは元種族、という食い違いを防ぐ。画像参照だけを再利用し、未登録種族の追加・出現の有効化はしない。下段4枠は対象名未確認につき新規対応を追加しない。

- `@game_data` の「モンスター合成」左側のレシピ表が正本。通常変換器から `モンスター合成.json` を生成する。右側の派生表・予定クラス表を混ぜない。
- 素材は `ホース_1,デヴィル_1` のような対象名と体数。状態は原本の確定/候補/未定を保持する。候補を勝手に確定へ変更しない。
- 現在の確定例はバイコーン。未登録の結果名は表示名として使い、未登録ボーナスクラス（例: 幻獣）はデータを追加せず、付与せずに合体する。省略したクラスを画面へ明示する。素材に必須の種族・クラスがない場合は引き続き拒否する。

## 魂の保管庫・魂回収（2026-10-17）

- 原本「施設」に `魂の保管庫`、「CS」に `魂回収`（`効果:魂回収`）を追加。建築4ターン・魔法Lv2・拠点ごと1棟、基礎AP20/射程10は暫定。通常の習得先クラスは未指定。施設費用は原本の既存式を使う。
- 自軍の地上の保管庫があれば、スキルで射程内の死体1体から魂を回収する。自動回収・死亡者保管一覧/資源の「死体」からの回収はしない。軍隊/召喚体は対象外。洞窟からも地上の保管庫へ送れる。
- 魔法の共通ルール（発動待ち最低1ターン、装備の追加AP、使用済み/CT）を使い、予約時と発動時に死体と保管庫を再検証する。発動時に条件を失っても通常の詠唱同様、支払済みAPを返さない。
- 生前の種族/取得クラス/各Lv/総合Lvと成長配分を保持し、装備・荷物・命令・座標は移さない。元の死体と装備/荷物は残す。死体に `soulCollected` を記録し、蘇生/アンデッド化/再回収/合成を拒否する。死体期限や荷物回収は従来どおり。
- 魂は勢力の `soulStorage` に保管し、`units`/部隊へ入れない。死亡状態の合成専用で出撃・取り出し・戦闘・任務不可。現在は勢力共通・上限なし。保管庫を失っても魂は残るが回収/使用できず、再建後に使える。
- 合成モーダルに「魂」ラベル付き素材と保存一覧を表示。保管庫上/隣接の実行者だけが使用可能。保管庫自体もAPなしの施設合成地点となる。魔術工房だけに隣接していても保存魂は使えない。
- 生体＋魂/魂だけの合成に対応し、通常の最高Lv＋残り20%と自動配分を共用。生体があれば最初の生体位置、魂だけなら実行者に隣接する移動可能な空きマスへ結果を配置。配置先なしでは魂/APを消費せず、成功時だけ素材魂を消す。
- 保存時に省略される派生情報は読込時に共通能力計算で再構築する。回収済み死体の印と保存魂を保持する。
- 合体テストに保管庫、隣接するホース/デヴィルの死体、実行者へ `TEST_魂回収` を追加。テスト技は原本の魂回収を `参照スキル` で読み、AP/射程を二重管理しない。`node scripts/check-v39-soul-storage.mjs` で実行動・詠唱・保存・魂だけの合成を確認する。
- 生体を預ける「魔獣工房」の格納・取り出し機能は未実装で、今回の魂保管とは別の残件。

## 確定したLv計算

- 素材総合Lvの合計を `S`、その中の最高Lvを `M` とし、完成値は `M + (S - M) × 0.2`。最高Lvは1体分だけ除く。Lv10+10なら12、Lv30+5なら31、Lv20+10+5なら23。
- 旧式の `S / 2` と獲得クラスへの別枠20%追加は廃止し、二重加算しない。獲得クラスなし/すべて未登録でも完成値は変えない。
- 完成値の整数部分をクラスLvへ配り、小数部分は基礎成長プールの次Lv必要EXPに対する割合へ変換する。未使用の素材EXPは引き継がない。既存合体ユニットを遡って再配分しない。

## 暫定の配分方法

配分の細部は計算関数へ集約し、素材消費前のプレビューと実行時の再検証で共用する。

- 条件の種族・クラスおよび登録済み獲得クラスへ最低Lv1を確保する。同名は1つとして扱う。必要数を確保できない場合は失敗し、総合Lvを水増ししない。
- 残りの整数Lvは素材の実際の種族/クラスLv比で自動配分。新規の獲得クラスは素材内比率0なので最低Lv1のみ。元から保持する獲得クラスは元Lvに応じた配分も受ける。
- 小数余りの大きい順に残りの整数予算を配る。同値は素材のクラス記載順。合計クラスLvと完成総合Lvを一致させる。
- 保存形式は既存の成長プールを維持する。`baseLevel` は完成整数Lvから獲得クラスの最終Lv合計を引いた値。完成値の小数分はこのプールへ1回だけ入れ、獲得クラス別の初期EXPは0。
- 例: ホースLv5＋デヴィルLv6、獲得クラスが角なら完成Lv7、ホース3/デヴィル3/角1。Lv6＋6なら完成値7.2で、0.2Lv分をEXPにする。
- 素材の未使用EXPは現在引き継がない暫定仕様で、最終確認にも明示する。現在の計算は総合Lvのみを入力し、端数EXPは合体式から算出する。

## 実装状況・残件

- `v39-monster-fusion-growth.js`: 読み取り専用のLv/EXP配分。入力を変更せず、重複素材・不足クラス・上限超過を拒否する。
- `v39-monster-fusion.js`: 実行直前にも所有、生存、距離、ワールド、素材条件、AP、待機、CT、必要クラスを検証し、素材の削除と結果の作成を1回の状態更新で行う。失敗時は入力を変更しない。素材の部隊所属・リーダー参照・戦闘予約を整理し、結果は単独へ配置する。
- 専用モーダル: 上画面に結果画像/名前/総合Lv、下画面の左に共通ユニットカード、右に共通詳細を表示する。素材未確定時は結果のシルエットを表示。素材枠を選び、候補を確認して「素材に選ぶ」で確定する。詳細は素材/合成後を切り替え、能力/スキル/装備/成長のタブを保持する。装備変更とスキル発動は行わない。確認/戻る/実行は固定フッターとし、生成後に短い収束/発光演出を行う。スキップ・閉じる・連打で再生成しない。一覧の背景更新では同じカードとスクロール位置を保持する。
- 行動欄の「合体」から起動。暫定の実行施設は自領の「魔術工房」に隣接（APなし）、スキルは `効果:合体`（行ごとのAP・CT）で、モーダル内でも方法を切替可能。施設名、素材の距離2マス、演出時間、合体後EXPの重みは `config/v39-fusion-defaults.json` に集約。正式な施設・スキル原本行の追加は別途行う。
- 素材は実行者以外の自軍の無名・単体・生存ユニット。同じワールドを必須とする。`territoryWideMaterials=true`（初期ON）かつ地上の実行者が自領内なら、距離によらず自領内のユニットを対象にする（別拠点の領土も含む）。近くても領土外なら不可。設定OFFまたは実行者が領土外/地下なら従来の周囲2マス（専用テスト6マス）へ戻る。設定は `config/v39-fusion-defaults.json` に集約し、モーダルにも現在の範囲を表示する。
- 軍隊・固有キャラ・召喚中/召喚体・教官・自動任務・装備/荷物あり・効果時間中の素材は拒否する。装備や輸送物資を黙って消去/増殖しないための暫定制約。結果は最初の素材の位置へ配置し、そのマスに他者がいる場合は拒否。作成ターンの結果APは0。
- 結果の身体は最初の素材の種族、主クラスは最初の追加クラス、その他の継承種族/クラスは保持。結果名は表示名として扱う。`fusionGrowth.levelsByClass` を能力/習得スキルの正本にし、保存復元時に通常の半々配分へ戻さない。画像は既存の動物＋属性対応を利用する。
- 端数EXPと獲得クラス別EXPを `fusionGrowth` へ保存。合体後の獲得EXPは暫定で「基礎プール1 : 各獲得クラスのプール1」の重みで分ける。基礎プールが閾値に達すれば主クラス、獲得クラスプールが閾値に達すれば該当クラスへLvを加算。必要EXPは各プールLvで更新する。クラスLv合計と総合Lvを一致させ、HP比率を維持する。成長タブに内訳表示。上位職への変更は当面拒否する。通常ユニットのEXP・施設徴兵成長停止は変更しない。
- 通常は原本の確定行のみ。バイコーンは幻獣を付与せず実行可能。省略クラスは `fusionGrowth.skippedClasses` へ保存し、後日データが追加されても既存ユニットへ自動付与しない。「テストプレイ→鉱床・道具・部隊支援→モンスター合体テスト」の素材ホースLv5＋デヴィルLv6を選ぶと、ホース3/デヴィル3/エヴォリューション・ホーン1、総合Lv7になる。別のテスト専用レシピも維持する。
- 残件: 施設/スキル名とAPの正式決定、装備付き素材や軍隊の合体、直接獲得スキル指定、合体後の職業変更。候補/未定レシピは通常利用しない。未登録ボーナスクラスの追加は合体実行の前提にしない。

### 専用テストの配下

- `config/v39-fusion-test.json` で最低配置数、基本Lv、固定素材、配置中心、素材距離を設定する。原本レシピの素材を集計し、クラスJSONに存在する対象だけを自軍の無名・単体・装備なしで生成する。レシピ内の同名素材の必要数は合算し、各種の最大必要数と最低配置数2体を満たす。
- 現行データでは28種類71体。ウルフ3体、スネーク9体、ホーク9体、ホース/デヴィル/エンジェルなどは各2体。最初のホースLv5・デヴィルLv6は維持し、追加素材はLv10。クラス未登録の10種類は生成しない。
- 固定素材と既存ユニットの占有を避け、専用マップ内の空きマスへ近い順に配置する。テスト実行者だけ素材距離を6マスとし、通常ゲームは2マスのまま。テストモードを切ると距離の特例は無効になる。
- テスト開始時に、実行者を中心とする周囲6マス（`territoryRadius`）を検証拠点の自領へ広げる。現行配置では7マスから92マスへ拡大。所有者・領土状態の拠点ID・拠点の領土一覧を同時更新し、素材71体をすべて領土内へ配置する。一般村など他者の領土は除外する。通常ゲームと共通の鉱床テストの初期領土は変更しない。ユニットの重ね配置や部隊移動ルールも変更しない。
- 候補/未定を含む原本レシピ44件＋テスト専用1件を、専用フィクスチャ中だけ表示。通常ゲームの確定行限定は維持。元の状態を変更せず「候補・テスト限定」等を表示する。未登録の必須素材を含むレシピは依然実行不可。
- `check-v39-fusion-test-materials.mjs` で種別数/体数、必要数、占有重複、素材適格性、通常ゲームへの非露出、登録済み素材で組める全レシピのプレビュー、ケルベロスの4体消費と実生成を確認する。
