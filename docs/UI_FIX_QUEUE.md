# UI修正一覧

更新: 2026-10-16。機能の修正と、ゲームとしての画面構成の評価を区別する。以前の「修正済み」はUI全体の完成を意味しない。

## 共通構成への変更

方針は [GAME_UI_LAYOUT_RULES.md](./GAME_UI_LAYOUT_RULES.md)。実際の描画元で変更し、完成DOMへの後付け変換は増やさない。

| 画面 | 今回の変更 | 引き続き確認すること |
| --- | --- | --- |
| 合成 | 上に結果、下に共通カード/共通詳細。素材枠・素材/結果・詳細タブを切替、明示選択、固定確定操作。320/390/1100pxで実操作確認 | 大量レシピの検索、長い名前の読みやすさ。全画面UIの完成を意味しない。専用確認はcheck:fusion-layout |
| 自キャラの他タブ | 部隊も同じHP/APカード・能力/スキル/装備/成長へ統一。選択メンバーに装備・道具・昇格操作を適用。死体・死亡者も共通描画 | 長い名前・大量メンバー時の読みやすさ |
| 部隊操作 | 所属を維持する単独行動/散開/集合/集合先指定/中止を共通詳細へ追加。編成候補は地理条件と所属を併記。集合進捗と停止理由を表示 | 多数の召喚ユニット、満員の集合地点では指定変更または単独行動で対処 |
| 研究 | 小型カードのLv別一覧、フローチャートを併存。スマホは全カテゴリ表示と詳細への切替/戻る、開始ボタン固定 | 長い研究名・大規模な前提線の把握しやすさ |
| 拠点 | 概況/生産/運用へ分離。取引ボタンはtoolbarへ置き、グリッド行を増やさない | 大量施設・複数拠点・輸送ルート設定時 |
| 土地 | 操作を上部固定、説明の縦潰れを解消。情報を小型グリッドへ | 特殊地形や多数の追加情報を持つマス |
| フィールド下部の交流 | 実際の通常起動にタブを追加。既存の村/放浪者/守護者の接触操作を移設。土地から入口も用意 | 洞窟NPCなど別所有者の交流は未統合。キャラ同士の新規交流は未追加 |
| 取引 | スマホも提供/要求を2列で比較。数量入力とメーターを狭幅用に配置。同じ物資・日程・検索・契約のDOMを保持し在庫は更新 | 配送/日程の大量契約時の見やすさ |
| 会話 | 発言と選択肢のスクロールを分離。交渉役/スキル/履歴とテスト操作を折畳み | 旧依頼と番号付き依頼のデータ移行後の統合 |

構成確認: `npm run check:game-ui-layout`。320/390/1100pxの画像と実操作を確認する。自動テスト成功だけで使いやすさを確定しない。

## 機能面の修正履歴と残作業

| 優先 | 画面・問題 | 状態 | 所有者・対応 |
| --- | --- | --- | --- |
| 1 | 会話中に元の資源ヘッダーが隠れる | 修正済み | `v39-trade-layout.js` を会話と取引で共用。元ヘッダー/内訳/特産品を保持し、モーダルをその下へ配置。重複ヘッダーなし |
| 1 | イベントを選んでも通常の操作が混在する、選択肢が伸び続ける | 修正済み | `v39-world-population.js` が既存モーダルを所有。番号付き会話パネルへ切替、依頼一覧/戻るを用意。回答は既存の上下会話へ表示 |
| 1 | 会話の同一内容更新でも交渉役・履歴・スキル欄を再作成する | 修正済み | `v39-negotiation-conversation.js` で同一HTMLを保持。更新時もdetailsの開閉を復元 |
| 1 | 洞窟の休息カードが毎回消え、開閉/フォーカスを失う | 修正済み | `v39-cave-world.js` 内で同じカードを再利用し、実行先だけ最新の地点へ更新。対象消失時は除去 |
| 1 | ターンラベル/停止ボタン表示だけで全ゲーム状態を複製する | 修正済み | `v39-turn-system.js` が既存のtimeline getterを使用 |
| 2 | 取引本体の再描画で入力DOMを置換する | 修正済み | `v39-trade-ui.js` 内で同じ物資/入力/契約を保持更新。入力中も在庫/可否を更新し、日程・検索選択・詳細開閉を保持。プレイヤー切替では旧所有者の画面を閉じる。全体再デザインとは別 |
| 2 | 洞窟の鉱床担当欄が更新で初期選択に戻る | 修正済み | `v39-cave-world.js` 内で軍隊/搬入先のselectとoptionをIDで保持。選択候補が消えた場合は有効候補へ戻す。別階層/別所有者には引き継がない。休息地点カードは前工程で保持済み |
| 3 | 召喚/呼集の一覧・詳細を全体再描画する | 修正済み | `v39-summon-modal.js` が同じ候補/タブ/詳細/実行ボタンを保持。取引と同じ更新関数を使用。状態通知をまとめて最新のAP/候補を反映し、同じターンの通常更新では閉じない。呼集の選択不可対象も解除可能。候補条件・費用は変更しない |
| 3 | 研究フローチャートのカード密度・スマホ可読性 | 現行構成で再確認済み | 320/390/1100pxで一覧/フロー/詳細/戻ると固定実行ボタンを確認。旧モーダルは維持。状態更新は同じDOMを保持し、担当欄・説明の開閉を維持する。全カテゴリ・長い名前の最終デザイン評価は継続 |

自キャラ/部隊カードの保持更新は前工程で対応済み。再発時は `check-v39-ui-render-work.mjs` で確認し、別モジュールから同じ画面を置換し直さない。

## 検証

- `check-v39-village-sheet-dialogue.mjs`: 320/390/1100px、既存ヘッダーの最前面/モーダル位置、同じ会話のDOM/フォーカス/開閉保持、選択肢切替と戻る、納品・討伐・魂報酬、保存後の再開。
- `check-v39-negotiation-ui.mjs`: 交渉役、自己強化、AP20、取引への遷移。会話もヘッダー直下へ配置する現行仕様に合わせた。
- `check-v39-trade-baskets.mjs`: 元ヘッダー/内訳/特産品、複数物資、入力、固定フッター、会話との共用後も確認。
- `check-v39-trade-input-stability.mjs`: 320/390/1100pxで数量/日程/検索/フッターのDOM、編集中の数値と検索選択、在庫の実更新、契約詳細/再開日、提案反映と所有者切替を確認。
- `check-v39-summon-retained-ui.mjs`: 320/390/1100pxで多数候補・同じDOM/フォーカス/スクロール・AP更新・実召喚・呼集の死亡者の解除/候補削除・ターン変更時のロック解除を確認。密度用の追加スキルは試験中の読み取りスナップショットだけへ注入し、生成JSONは変更しない。
- `check-v39-expedition-test-fixture.mjs`: 洞窟休息カードの同一性/開閉/フォーカス、実道具使用、輸送・侵入・保存。

`check-v39-research-discovery-ui.mjs` と `check-v39-research-efficiency-ui.mjs` は現行の統合調査カテゴリへ移行済み。洞窟は研究なしで調査発見・入場でき、研究完了による資源自動発見は調査済み範囲だけに適用する。調査APの持越し、未調査/他プレイヤー/保存階層の分離と保存復元を確認する。`check-v39-research-flow-ui.mjs` は旧一覧とフローの併存・前提解禁・進捗保存に加え、担当欄/カード/説明開閉の保持も確認する。
