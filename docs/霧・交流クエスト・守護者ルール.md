# 霧・交流クエスト・守護者ルール

更新: 2026-10-13。以下の機能は現行v39へ接続済み。明示した確定値以外の数値は、調整可能な試作値。

## 1. 霧

- 通常の霧と死の霧の両方に適用する。
- 観測者・対象・両者を結ぶ六角マスの経路にある霧を数え、外から中、中から外、霧越しの索敵に同じペナルティを適用する。
- 暫定では霧1マスにつき索敵値-50、視界半径-1。隣接1マスの視界は維持するが、隠密との判定は索敵減少後の値を使う。
- プレイヤーの発見・敵AI・勢力AIの索敵は共通ルールを参照する。縄張りの範囲自体は縮めない。
- `効果`に`霧`がある技は攻撃範囲へ一時的な霧を配置する。`氷霧`で発生を確認。名称だけから霧を推測しない。
- 持続は`効果時間`をターンとして読み、未指定時だけ暫定3ターン。再配置時は長い期限を残す。`mapData.fogMap`へ期限を保存する。
- 地形変換で作られた死の霧には、既存の地形変換の持続ルールを使う。
- 表示画像は通常霧が`assets/images/background/pipo-fog018.webp`、死の霧が`pipo-fog019.webp`。霧のあるマスだけへ切り抜き、暫定30%の透明度で重ねる。通常プレイでは現在の視界内、テストモードでは全体を表示する。
- 死の霧はエフェクト属性設定の`死霊`の色を参照する。単色設定ならTint、グラデーション設定なら先頭色を霧全体の着色に使う。属性設定変更時も再描画し、色コードを別途固定しない。
- 画像・透明度・索敵減少・視界減少の調整先は`frontend/src/lib/v39-gameplay-balance.js`の`V39_FOG_BALANCE`。
- 自然の通常霧は全勢力のターン終了後、5の倍数ターンに発生判定し、5ターン持続する（例: T5発生、T10消滅）。同じターンの再評価・ロードで再抽選しない。地下では自然発生しない。
- 発生量の暫定設定は8×8マスごとの地域で5%、同時最大3地域、半径1～2マスの不規則形。森林・湿地・沼地・湖・川のマスを中心候補にする。発生確率・対象地形・広さ・上限は未確定で、共通設定から調整できる。
- `系統`に`風`があり、`炸裂`が0.5以上の攻撃は実際の攻撃範囲内の通常霧・死の霧を吹き飛ばす。炸裂端数による範囲も対象。風属性値だけ・名称だけでは判定しない。敵味方共通。消した霧は次の自然発生判定まで自動補充しない。
- 死の霧の地形変換は特殊レイヤーから霧だけを取り除き、基本地形を保持する。通常霧の自然発生周期はスキル霧の`効果時間`を変更しない。

### 浄化値と死の霧・アンデッド

- マスの浄化0を中立とし、死体の残るマスは毎ターン-1（数が増えても同じ）、死の霧があるマスは追加-1。回収・蘇生・期限切れ後の残存死体だけを扱う。
- 浄化-5以下のマスで毎ターン排他的イベント判定。暫定は死の霧8%、アンデッド8%、何もなし84%。成立した同じマスは5T再判定しない。旧死体数×確率/5T抽選は廃止。
- 地上は発生地点+周囲1の7マス、洞窟は生成時の部屋所属エリアだけ。通路は近い部屋に割当て、階層全体へ広げない。複層Z座標は採用しない。
- 霧発生時は中心の浄化-2、周辺/同エリア-1。暫定持続5T、風で除去可能。死体が消えても既存霧を即座に消さない。発生だけで死体を消費しない。
- 発生したばかりの霧から同じターンにアンデッドを重ねて生成しない。次Tから既存の死体変化を判定する。
- 浄化-5以下の死の霧内で、死体1体ごとに毎ターン、発生源100%・その他50%でゾンビ/スケルトンへ変化。発生源はLv+3。生成成功時だけ元ユニット/死体100を消費し、荷物を残す。空きがない・生成失敗なら保持。通常の霧内死体変化は有限の死体/配置先で抑制し、自然発生最大2体/5Tを別途適用しない。
- 死体のない不浄イベントによる自然発生は既存候補重み（ゾンビ50/スケルトン30/ゴースト20）を使用。同ワールドで最大2体/T、同マス5T。死体のあるイベントは死体変化処理を共有して自然発生上限を適用し、同じ死体から二重生成しない。
- 霧外の死体1%、空の死の霧2%という旧独立抽選は廃止。災害による既存発生は別処理。調整はV39_UNDEAD_SPAWN_BALANCE/V39_FOG_BALANCE。
- アンデッドAIの味方種族除外、死の刃の現在値-5、未実装の召喚所属/上位化はアンデッド・不浄ルールを参照。
- 肉食/雑食の生物の安全時の死体資源消費は維持する。埋葬行動は未実装案。霧・浄化・エリア・抽選済みターン・自然発生履歴は保存対象。

## 2. 一般村の依頼

- 土地タブで一般村のマスを選び、表示された依頼から受注する。同じ村で各プレイヤーが同時に受注できるのは1件。
- 既存の`イベント_一般村.json`の不足物資補給・アンデッド駆除に加え、動物駆除を接続した。出現条件、走査範囲、対象数、報酬友好度、再発生条件は対応する正式イベント行を参照する。
- 動物駆除は村周辺の好戦的な生存動物を受注時に選ぶ。守護者は対象外。動物分類タグがない種族の判定だけ仮設定を使う。
- 食料支援（穀物50）と修繕用木材（木材50）は仮依頼。完了で友好度+8、同じ支援の再受注は5ターン後。
- 納品は選択中拠点の在庫を消費する。不足時は完了しない。今回の支援は一般村の在庫・人口維持を直接更新するものではない。
- 討伐対象IDは受注時に保存し、その対象の全滅後に報告できる。受注前に倒した敵を新しい依頼へ遡って加算しない。
- 受注・報告は地上で行う。完了済み依頼への二重報告・二重報酬は拒否する。
- プレイヤー別の受注状態、友好度、完了ターンはセーブ対象。

## 3. 守護者の依頼・譲渡

- 勝利対象土地を調査して発見し、生存する自軍ユニットが中心から3マス以内にいるとき、土地タブから交渉できる。
- 依頼は木材納品100、3ターンの連続見張り、周辺の好戦的な敵の討伐（8マス以内、最大3体）の3種類。討伐対象がなければ討伐依頼は出さない。
- 1件完了で友好度+35。同じ依頼は1回だけ。友好度70で「守護者を引き継ぐ」を選べる。受注・進捗・完了・友好度はプレイヤー別に保持する。
- 見張りは受注後のターンから加算する。範囲から全員離れたターンは進捗0へ戻す。同じターンの再評価では増えない。
- 受注中・交渉継続中は守護者AIがそのプレイヤーを攻撃対象から外す。ただし守護者を攻撃して交戦状態に入った場合は反撃し、交渉を拒否する。他プレイヤーとの戦闘は妨げない。
- 譲渡時は対象土地の占有マス全体を選択中拠点の領土へ登録し、守護者・配下・巣を撤去する。他プレイヤー所有マスを含む場合は譲渡を拒否する。
- 平和的な交代では撃破経験値・戦利品を付与しない。譲渡済み守護者は再生成しない。
- 戦闘で守護者を倒し、通常の領土取得処理で確保する既存の経路も維持する。

## 4. 勝利判定

- プレイヤー・NPCは共通の支配判定を使う。勝利対象土地の占有マスすべてを所有していることが必要。
- 現在の試作値は1地点・1ターン。1ターンには取得ターンを含むため、譲渡直後の判定でも達成する。
- 地点数と維持ターンは`V39_VICTORY_CONDITION_BALANCE`で変更する。正式な必要数・維持ターン・最終儀式は未確定。
- 支配を失うと、未達成の維持進捗は取り消す。勝利時は結果を保存し、通知して通常のターン進行を停止する。

## 5. データ原本と未対応

- 正式な村イベントはスプレッドシートから生成されたJSONを読む。生成JSONだけの項目追加はしない。
- 未定義の支援・守護者依頼・動物分類は`config/v39-event-defaults.json`、数値は`V39_QUEST_BALANCE`で仮管理する。
- 仮依頼を正式シートへ移す際は読込処理も対応させて仮定義を除去する。現在は新しい守護者シートを自動認識する仕様ではない。
- 全イベント種別の汎用実行、建築支援・契約依頼、分割納品、依頼放棄、最終儀式は今回の実装範囲外。既存の洞窟ドワーフ依頼とは区別する。
