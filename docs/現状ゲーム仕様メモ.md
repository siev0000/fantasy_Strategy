## 1. 今のゲーム全体像

- キャラの「行動」から領土外の森・洞窟で採取できる。JSONの基礎産出1ターン分（既存収入スケールを使用）を運搬品へ積載し、拠点へ帰還して搬入する。暫定AP100、1マス1ターン1回、運搬上限あり。単独・輸送指定者は個別荷物に保持する。死亡・待機・調査中・自動輸送中は採取不可。採取済み記録はセーブ/ロードで保持する。集積所や採取地点への自動往復はまだ未実装。

- 拠点タブの「輸送」から、占有マス内の生存軍隊ユニットを輸送用に指定できる。ヒーロー・ネームドは対象外。同一プレイヤーの搬入先拠点・資源を選び「往復開始」で、ターン終了時に残りAPによる積み込み・運搬・荷下ろし・空荷帰還を繰り返す。指定した個体は通常部隊移動から外れ、本人は単独で手動移動可能。停止時は拠点内なら荷下ろしし、外なら荷物を保持する。積載中は指定解除・搬入先変更不可。個別荷物と往復状態はセーブ/ロード・死亡処理へ接続済み。瞬時の共有在庫ではない。集積所は未実装。詳細は `領土・資源生産ルール.md` 9。

- 勝利対象土地はマップサイズに応じて1〜4件生成される。規模は大都市相当の7マスで、生成時には既存の出現敵定義から守護ボス1体・配下・敵巣・半径3の守護領域を作る。守護者を倒し、中央マスへ生存ユニットが到達すると本体7マスを一括領土化する。2026-10-20更新: 本体の全占有マスを取得した後、確保進捗5が必要。取得時0、敵対者が占有範囲にいるターンは-1、いなければ+1、所有喪失で解除する。達成すると勝利者を共通ゲーム状態へ保存し、以降のターン終了を停止する。必要地点数は現行1。地点数の追加調整、勢力滅亡による勝利は後続仕様とする。

- ヘックスの島マップ上で、勢力の初期設定、村配置、領土運用、ユニット管理、索敵、奇襲、毎ターン経済処理を回すファンタジーストラテジー。
- 初回のプレイ形式選択は `シングルプレイ / マルチプレイ` に分かれ、シングルプレイはさらに `通常プレイ / テストプレイ` を選択する。内部識別は `single-normal / single-test / multiplayer`。`single-test` はテストデータを使って初期からテストモードONで開始する専用経路として残す。一方、`single-normal` と `multiplayer` でもゲーム開始後に表示設定からテストモードを任意にON/OFFできる。
- シングル通常プレイとシングルテストプレイは、どちらも `プレイ形式選択 -> RaceSelectModal.vue -> ClassSelectModal.vue -> CharacterNameModal.vue -> ゲーム開始設定 -> 初期村配置 -> 通常ゲーム` の同じ開始導線・同じゲームロジックを使用する。開始前の選択内容は一時プロフィールとして保持し、ゲーム開始設定で `players[]` を初期化した直後、マップ生成前に `applyV39InitialSovereignProfile()` で `player-1` へ反映する。2勢力目以降はマップ生成後に同じ Vue モーダルを開く。テストプレイは `テストゲーム状態.json` の確認用ユニット・拠点計画などを追加データとして保持して初期からテストモードを有効化する。シングル通常・マルチプレイは通常データで開始するが、ゲーム開始後は表示設定から同じテスト操作・確認用表示を任意に有効化できる。テスト用データの有無を理由に、通常プレイと別のUI・戦闘・移動・ターン・装備等の基本処理を作らない。マルチプレイは `プレイ形式選択 -> ルーム作成 / 参加 -> ロビー -> 担当勢力の開始種族を各自選択 -> ホストのゲーム開始設定 -> 全員準備完了 -> ホストがゲーム開始 -> 空の勢力状態でホスト生成ワールドを初期同期` までを実装している。
- v39の初期表示では、ゲーム開始設定の前にプレイ形式を選択する。`シングル通常` と `シングルテスト` はともに共通の種族・クラス・統治者名設定を通ってから同じゲーム開始設定へ進む。通常プレイはテストモードOFF、テストプレイはテストモードONで開始する。`single-test` は `テストゲーム状態.json` の確認用データを初期プレイヤーテンプレートとして使うが、`single-normal` と `multiplayer` はそのテスト初期データを使わない。テストモード自体は開始形式と独立した表示設定とし、シングル通常・シングルテスト・マルチプレイのいずれでも任意にON/OFFできる。ON時はFog等の確認用表示、管理タブのテスト操作、テスト専用機能を有効化する。マルチプレイは初期状態ではテストモードOFFのまま通信ロビーへ直接進み、ルーム作成者だけがロビーの「ゲーム開始設定」を開いて共有設定を保存できる。各参加者は自分が担当する `playerId` の開始種族を `種族.json` の選択肢から決める。担当する全勢力の開始種族を選んだ参加者だけが準備完了にでき、全参加者の準備完了後にホストだけがゲーム開始できる。
- v39通信ロビーのプレイヤー名入力欄は、ルーム作成側では初期値 `ホストプレイヤー`、参加側では初期値 `プレイヤー1` を最初から表示する。同名で参加した場合はサーバー側で `プレイヤー2`、`プレイヤー3` のように末尾番号を調整して重複を避ける。手入力名も同一ルーム内で重複させない。再接続では本人の既存名を維持し、ホスト移譲では表示名を変更しない。
- 通信ロビーのホスト用 `ゲーム開始` ボタンはロビー上部の主要操作列へ表示する。操作勢力数は参加プレイヤー数以上とし、参加者が増えた場合は勢力枠を自動増加して参加順に担当を割り当てる。参加者退出時は勢力を自動削除せず、必要ならホストが参加者数まで減らす。ゲーム開始設定だけを変更しても準備完了は解除せず、勢力数・担当者・開始種族が変わった場合だけ準備を解除する。通信ロビーと、ロビーから開いたゲーム開始設定は背景タップでは閉じない。ゲーム開始後に `ゲームから切断` した場合は参加者枠と再接続情報を保持し、同じルームIDへ再参加すると同じ参加者IDでサーバー保持中のゲームスナップショットを受け取って復帰する。
- 旧 `v39-initial-sovereign-ui.js` の独自DOM選択画面はbootstrapから外し、通常の開始導線では使用しない。種族・クラスの表示や選択ロジックを二重管理しない。
- シングルとマルチの開始種族選択は同じ `RaceSelectModal.vue` を使用する。マルチの通信ロビーは独自の種族プルダウンや詳細UIを持たず、担当勢力の `選択 / 変更` から共通種族選択画面を開き、決定後にロビーへ戻って `playerFactionSelections[playerId]` を更新する。クラス選択もシングル・マルチ共通の `ClassSelectModal.vue` を使用する。種族・クラスの詳細表示は共通データから `ステータス技能 / スキル` の2タブで表示する。`ステータス技能` 内ではステータスと数値技能を同じスクロール領域へ順に表示し、ステータスは `HP / 攻撃 / 防御 / 魔力 / 精神 / 速度 / 命中 / SIZ`、スキルは `Skill1..5` の取得スキルとして分離する。
- 種族・クラス選択のwideモーダルは背景をほぼ使わない画面占有型とし、外側モーダル全体はスクロールさせない。候補一覧と詳細タブ内容はそれぞれ枠内で独立スクロールする。種族詳細上部にはHP/ATK等の重複した「基礎値」を表示せず、能力値は `ステータス` タブを正本表示とする。\n- 種族・クラス選択の詳細UIは、フィールド下部の `aria-label="操作UI"` と同じ構成を基準にし、`ステータス技能 / スキル` の2タブとする。タブは `footer-tab` と同系統の角丸・枠・選択色、ステータスは `detail-stat` 型グリッド、技能は `proficiency-item` 型グリッド、スキルは `technique-card` 型の要約カード＋展開詳細で表示し、種族・クラスで `V39SelectionDetailPanel.vue` を共通利用する。
- 種族・クラス選択の `ステータス技能` 内では、耐性表示を共通コンポーネントで統一する。通常時はアイコン+補正値を表示し、PCはホバー、タッチ端末はタップ/フォーカスで耐性名をポップアップ表示する。耐性一覧はキャラ詳細でも同じ共通表示を使用する。
- 装備情報は `クラス.json` の `武器1 / 武器2 / 頭 / 体 / 足 / 装飾1 / 装飾2` を正本とする。種族行では各列を「装備箇所」として扱い、`× / x / 不可` は装備不可、空欄は装備可能とする。職業クラス行では同じ列に入った装備名を「装備追加（初期プリセット）」として扱う。ユニット生成時の装備可能箇所は種族行から決定し、クラス側の装備追加はその種族制限を越えて装備させない。
- 種族選択は `種族.json.className` から対応する `クラス.json` 行を解決し、その `種類` を分類として自動生成する。現行開始種族では `人族 / 亜人 / 魔族` の3分類。分類説明は `種族分類.json` を正本とし、人族=`あらゆる技能に優れるが、ステータスが低い。`、亜人=`ステータスに優れるが、技能にペナルティを持つ。`、魔族=`魔法に優れて耐性を持つが、弱点がある。`。スマホは上約30%へ `人族 / 亜人 / 魔族` の分類タブだけを並べ、その直下の独立した説明欄へ選択中分類の説明文を表示する。説明文をタブ内へ埋め込まない。下約70%は左=同分類の種族一覧（アイコン+省略しない名称）、右=`ステータス技能 / スキル` 詳細とする。分類内でまだ種族を選んでいない場合はその分類の先頭種族を自動表示し、分類を切り替えて戻った場合は分類ごとに最後に表示していた種族を復元する。外側画面は固定し、種族一覧と詳細内容だけを枠内スクロールする。
- クラス選択も種族選択と同じ上下構造を使い、上段を `戦士系 / 狩人系 / 魔法系 / 信仰系 / その他` の系統タブ、下段を左=同系統のクラス一覧（アイコン+名称）、右=`ステータス技能 / スキル` 詳細とする。現時点の系統判定は暫定で `クラス.json.画像ID` を使用し、`戦士 -> 戦士系`、`狩人 -> 狩人系`、`魔導士 -> 魔法系`、`神官 -> 信仰系`、それ以外を `その他` とする。後で `クラス.json` に正式な分類列を追加した時点で画像ID判定を廃止する。各系統の初回表示は先頭候補、系統を切り替えて戻った場合は系統ごとに最後に表示していたクラスを復元する。
- マルチプレイの新規ゲーム状態は `テストゲーム状態.json` をプレイヤーテンプレートとして使用しない。開始時は選択済みの `players[].race`、担当 `controllerParticipantId` と空の `factionState` を作る。共有ワールド生成後もルームは `setup` のまま保持し、各担当参加者はロビーで確定済みの種族を維持したまま共通の `ClassSelectModal.vue -> CharacterNameModal.vue` で統治者を設定してから、マップ上で初期拠点を選択する。要求はホストが確定し、全勢力の統治者・初期拠点がそろった時点で `playing` へ進む。ゲーム開始後の移動・戦闘・建設・研究・外交・ターンなどの継続通信は未接続。
- 「ゲーム開始設定」（旧フィールド設定）にはターン進行方式（現行方式 / フェーズ方式）、1ワールドターン中の最大戦闘ターン数、操作勢力数、仮参加者数、勢力ごとの担当参加者を持つ。設定値は共通ゲーム状態とセーブデータへ保持する。操作勢力数は1〜8、仮参加者数は1〜操作勢力数で、現時点では1台で担当勢力を順番に切り替えるローカル順番制として動作する。フェーズ方式による操作制限・フェーズ遷移は未実装。
- 研究ツリー、簡易戦闘、計算シミュレータは補助UIとして存在する。
- UI文字サイズは `v39-typography.css` へ集約。PC15px・幅699px以下12pxを基準とし、各サイズ段階と表示設定倍率を連動させる。後付けの `v39-readable-fonts.js` は廃止し、描画元へ統合した。詳細は `UI_TYPOGRAPHY_RULES.md`。
- オンライン要素は旧 `簡易戦闘ルーム` に加え、v39通信ロビーとゲーム開始時の初期ワールドスナップショット同期まで接続済み。ゲーム開始後の操作コマンド・ターン進行・状態差分同期は未接続。

## 2. ゲーム開始フロー

- ゲーム開始時に `プレイヤー数` と `別勢力数` を設定できる。
- 合計勢力数は最大 `8`。
- 初期配置方式は以下の3種類。
  - `全勢力ランダム`
  - `プレイヤーのみランダム`
  - `プレイヤーは手動選択`
- 各勢力は順番に `種族 -> クラス -> 統治者名 -> 村名` を設定する。
- プレイヤー選択種族は現在以下の8種。
  - 只人
  - エルフ
  - オーガ
  - ゴブリン
  - 竜人
  - 悪魔
  - 天使
  - ヴァンパイア
- 統治者の初期Lvは人族7・亜人10・魔族12。通常ユニットも同じ値、新規軍隊・強化軍隊・一般村守備軍は人族3・亜人6・魔族9とする。プレイヤー・NPC共通で、軍事研究Lvとは分離する。調整値は `V39_UNIT_INITIAL_LEVEL_BALANCE`。既存セーブのLvと明示Lvのテストデータは変更しない。
- 初期村はマップ上に別途配置する。手動配置モードではクリックしたタイルに村と統治者が置かれる。
- 初期拠点が複数指定されている場合は、必要数に達するまで手動配置を繰り返す。複数勢力では1勢力分の配置完了後に次勢力へ切り替え、全勢力の配置完了まで敵・一般村の初期生成を行わない。敵の安全距離と近距離Lv制限は、所有する全初期拠点のうち最も近い拠点までの距離で判定する。
- ゲーム開始時のフィールド設定（マップ生成）画面から、v39セーブJSONを選択して既存のセーブ/ロード処理を使い、そのままゲームを再開できる。新規生成とは別経路で、マップ・全勢力・ターン・研究・経済・戦闘状態・カメラ位置を復元する。
- 初期村は中心と周囲1マスの合計7マスがすべて通行可能な内陸だけに配置できる。海・湖・火山・溶岩、他勢力領土、他勢力ユニット、敵を含む候補は選べない。
- 別勢力も同じデータ構造で作られ、ローカル順番制ではターン終了時に次勢力へ切り替える。
- プレイヤー所有データは `players[]` の各要素にある `factionState` へ保持し、画面は `activePlayerId` に一致するプレイヤーのユニット・部隊を参照する。複数プレイヤーのユニットを単一のトップレベル配列へ混在させない。`players[].controllerParticipantId` と `sessionParticipants[]` で担当参加者を保持する。
- ゲーム状態の取得APIは部隊員ID、村施設、装備、死亡履歴を含む入れ子データも複製して返す。状態変更は取得値の直接変更ではなく、必ず共通更新APIへ渡して確定する。
- 1プレイヤーの共通型は `frontend/src/lib/player-state.js` で生成する。`factionState` は都市、ユニット、部隊、回収済み死亡者、選択状態、配置・移動状態、勢力ログ識別子、接敵移動停止、索敵状態、研究状態を必ず持つ。スキーマ正本は `config/player_state_schema.json`。
- 現在のv39画面に表示するテスト編成は、ローカル確認用の `data/source/export/json/テストゲーム状態.json` から読み込む。このテストデータは通信・セーブデータとは区別する。
- テストJSONではプレイヤー、所属部隊、配置座標、種族、クラス、Lv、装備、現在HP率、現在AP、土地の選択条件を指定する。
- 種族別幸福度の確認用テスト状態では、プレイヤー1の通常キャラクター数を絞って複数種族を混在させ、`initialSettlementPlans` に2拠点分の初期データを定義する。ゲーム開始時は1拠点目、2拠点目の順にマップ上で設置場所を選び、各拠点は別々の `populationByRace`・食料在庫・施設・所属領土を持つ。配置後は拠点タブの切替とターン経過後の幸福度差を比較できる。
- テストゲーム状態のユニットAPは全員 `最大AP=100 / 開始AP=100` に統一する。現時点ではクラス・種族による最大AP差を設けない。HP・基礎ステータス・技能・取得技は `クラス.json`、技詳細は `スキル一覧.json`、装備性能は `装備.json`、土地性能は `地形.json` から生成する。
- データ設計上は `data/source/export/json` 内の全JSON・全レコードを正本とし、同じ仕組みの種類追加はJSONへデータを追加するだけで行える構成にする。コード側へ種類名、数値、選択肢を重複定義しない。現在残っている個別importや固定配列は `docs/DATA_DRIVEN_RULES.md` に従って移行する。

## 3. マップ・地形

- マップは `pointy-top` のヘックス。
- 表示基準は `1280x720`。
- ワールドラップは ON/OFF 切り替え可能。
- 島形状プリセットは以下を実装済み。
  - 標準諸島
  - リアル島
  - 大陸型

  - 双子島
  - 列島型

  - 平地
  - 森
  - 丘陵
  - 山岳
  - 雪原
  - 火山
  - 河川
  - 湖
  - 海
  - 砂漠
- 特殊地形:
  - 沼地
  - 洞窟
  - 峡谷
  - 溶岩
- タイル変換魔法を実装済み。スキルの `効果` が `○○_変換` の場合、`○○` を `地形.json` の地形名として解決し、同JSONの `変換レイヤー=基本 / 特殊` に従って対象マスを書き換える。個別の地形名分岐は増やさない。
- 初回の変換対象は `平地 / 森 / 荒野 / 砂漠 / 雪原 / 沼地 / 湿地 / 薬草の群生地 / 死の霧`。湖・海・河川・火山・溶岩・洞窟・峡谷など、高度・水系・災害状態と連動する地形は初回対象外とする。変換対象の各行はExcelの`地形`シートで`変換レイヤー`を必須とし、`平地 / 森 / 荒野 / 砂漠 / 雪原`は`基本`、`沼地 / 湿地 / 薬草の群生地 / 死の霧`は`特殊`としてJSONへ出力する。`死の霧`は特殊地形として重ねる。
- テスト専用クラス `ジオマンサー（地形術師）` を `クラス.json` に登録し、`テストゲーム状態.json` のプレイヤー1へLv10のテストユニットを追加している。通常の職業選択には出さない。
- 魔法の標準発動待機は `1T`。スキル側に `待機` が明示されている場合はその値を使用し、標準値より長い待機も設定できる。
- 変換魔法は使用時にAPを消費して詠唱予約し、次のターン進行時（待機1T）に発動する。射程値は10=1マスの共通尺度を使い、JSONから調整する。
- `薬草の群生地` の `回復=1` は、所属拠点が確保しているマス数ぶん領土内ターン回復へ加算する。
- 雪原と積雪は別状態として扱う。雪原は基本地形のまま、積雪はマップの `snowCoverMap` に保持し、元の地形色・高度色を変えずヘックス外枠線の内側約20%を白リングで表示する。
- 現在降雪中の表示は `snowfallMap` に保持し、小さな `❄` を重ねる。積雪・降雪とも森・砂漠など元地形と既存アイコンを維持する。
- 積雪・降雪の表示状態はマップスナップショットに含まれるためセーブ/ロードされる。地域天候の抽選は実装済み。降雪マークと天候の自動同期、積雪開始、融雪は未接続。
- 地形ごとの産出量、危険度、開拓難易度、災害相性は `地形.json` ベースのデータ駆動。
- マップ生成で使う地形一覧、生成順、色、抽選重み、略称は `地形.json` の `生成対象 / 生成順 / 生成色 / 生成重み / 生成略称` から組み立てる。生成対象を追加する場合はコード側の地形配列を変更しない。
- 勢力データの優先地形を基本地形・特殊地形のどちらとして検索するかは、`地形.json` の `勢力配置区分` を参照する。現行値は `基本 / 特殊` で、コード側に地形名一覧を重複定義しない。`勢力.json` で使う略称・旧称は地形行の `別名` から正規名へ変換する。
- `地形.json` の山岳行にある `休火山候補率` 20%を休火山候補へ適用する。毎ターン噴火率は `災害.json` の火山噴火にある `基本発生率` 1%へ、山岳行の `噴火` 20%を相対補正として掛け、`1% × (1 + 0.2) = 1.2%`とする。噴火後は休火山状態を解除して火山へ恒久変化するため、同じ中心から再噴火しない。
- 噴火中心は抽選された休火山マス、直接影響は `災害.json` の `影響半径` 1マス、産出低下等の効果時間は `効果継続ターン` 2ターンとする。イベントには影響座標、産出倍率、人口減少、治安減少を保存する。
- 火山からの溶岩は1ターン最大3マス、低い高度を優先し、進行方向38度以内を維持する。各マス35%で停止し、川・海・湖へは進入しない。各溶岩マスは発生時に2〜4ターンの冷却期限を持ち、期限到達後は荒野になる。
- 溶岩が川・湖・海へ接した場合は水域へ入る直前で停止し、水域と周辺地形は変化させない。噴火発生のターン通知は現在視界に関係なく全プレイヤーへ出し、Fog内の地形変化はそのタイルを探索した時点で更新後の状態を表示する。
- 休火山・火山・溶岩流路・発生ターン・停止理由はワールド共通状態へ保存し、ターン処理済み番号で重複実行を防ぐ。セーブ・ロード後も処理済みターンは再実行しない。地形更新時もカメラ位置と選択を維持する。
- 溶岩は通常通行不可。炎耐性100以上または耐熱能力持ちだけ通行できる。ターン終了時の最大HP割合と軽減耐性名は `地形.json` の `ターンダメージ最大HP率 / ターンダメージ耐性` を敵味方共通で参照し、HP0なら通常の死亡処理へ渡す。現行値は最大HP10%と炎耐性軽減。
- 領土マスはHP / 最大HPを持つ。最大HPは正式値未確定のため共通設定100を暫定使用する。噴火・新規溶岩到達時の領土ダメージは `25 + 噴火元高度Lv × 25` とし、同一ターンに同じマスへ複数の火山イベントが重なった場合は最大ダメージ1回を適用する。
- 領土の人口許容は現在HP率を掛けて再計算する。火山の直接人口被害は被災直前の当該マス収容人数へ `min(100%, 領土ダメージ / 領土最大HP)` を掛け、小数が残る場合は切り上げる暫定処理とする。
- 被災マス上の施設は `領土ダメージ × 3` を受ける。施設最大HPは暫定100で共通設定に集約し、HP0でも削除せず `損壊` として残す。施設の生産効果は残HP率に比例し、HP0では停止する。
- 拠点中心が被災した場合は拠点在庫、個別保管先が被災した場合はそのマスの保管在庫だけを対象に、今回ダメージ率と同率を失う。保管先HPが0になった場合は残在庫を全損する。食料・資材・未装備品を同じ保管先単位で処理する。
- 噴火イベントの `周囲産出倍率` は影響座標と終了ターンを `activeTerrainEffects` に保存し、効果中だけ対象マスの地形・探索資源産出へ適用する。損傷施設は溶岩冷却後、領土修復と同じ資材・回復率で修復できる。
- 人口が人口許容を超えた拠点は自然人口増加を停止し、毎ターン `ceil(超過人口 × 10%)` が流出する。幸福度・治安には `-(人口過多率 × 10)` の一時補正値を保持し、人口過多解消時に0へ戻す。
- 土地タブには休火山/活動火山、噴火率、溶岩接触、直近発生ターンを表示する。溶岩被害はキャラクター上のダメージ値とHPバー、ターン通知、対象プレイヤーの活動ログへ対象名と被害値を表示する。
- Fog of War あり。未探索/非可視タイルは隠れる。
- 探索済みタイルと現在視界は勢力ごとに保持する。プレイヤー切替では切替先勢力の履歴へ切り替え、セーブ復元では保持し、新しいマップを生成した場合だけ全勢力の旧マップ視界履歴を初期化する。
- 敵・他勢力ユニット・戦闘エフェクトは現在視界内だけ表示し、視界外へ出た敵の最終位置マーカーは残さない。発見済みの他勢力拠点と特殊地形は地形情報として記憶表示する。
- 現在は山、高低差、森、天候による視界遮蔽と、他勢力との視界共有を行わない。各勢力の村、ユニット、所有する索敵施設だけで現在視界を計算する。
- 領土・巣・一般村・合算索敵の境界は点線で外周だけを表示する。生存ユニットの索敵範囲も薄水色の個別点線で表示し、同じマス・同じ範囲の部隊員は1本にまとめる。個別索敵線は合算索敵外周とは別レイヤーで、通常表示とテストモードの両方で描画する。
- 強敵候補や特殊地形は設定で常時表示を切り替えられる。
- 初期拠点配置後、`出現敵.json` の出現地形・Lv範囲と `クラス.json` の定義が一致する敵だけをフィールドへ生成する。
- 初期拠点配置はフィールドの明るい範囲をタップ→下部で位置・周辺Lv・種族目安を確認→「ここに拠点を設置（OK）」で確定する2段階。4マス以内には初期の通常敵・強敵を生成せず、5〜8マスは暫定Lv1〜3（強敵地形でも通常個体）とする。`V39_START_AREA_BALANCE` で調整可能。
- 初期配置の案内・確認ボタンはフィールド上ではなく下部 `footer-body` の専用画面に表示する。配置可能な場所から選択範囲が地図端で切れにくい場所を優先し、その中で種族に対応するクラス.jsonの適正土地を周囲2マスまで評価して候補を最大20件生成する。異なる適正土地を併せ持つ場所、苦手土地の少なさ、適正土地の広さ、低地の順で優先する。河川はriverSet/riverTouchSetで判定する（番号付き候補一覧は表示しない）。同条件では中央寄りを優先し、候補同士の選択範囲が重ならない距離を確保する。フィールドのマスを直接選択し、配置確認画面へ反映する。下部確認画面は詳細だけをスクロールさせ、決定ボタンを下端に固定する。初期配置中は左の通常タブを押しても配置確認画面を維持し、配置完了後に通常タブ切り替えを再開する。高度の配置制限は未確定で導入しない。初期配置は候補と周囲2マスの有効マスに加えて、種族の適正地形かつ高度の絶対値1以下の土地が連続7マス以上ある地帯も選択可能にする。追加地帯は最大20候補の上限とは独立して拾い、配置不可マスは除外する（周囲半径・低地高度・最低連続数は暫定設定）。マスをタップする前から、初期配置画面の開始時に選択可能範囲をフィールド上に薄水色で表示し、それ以外は初期配置中だけゲーム中の索敵外・未探索Fogと同じ色・透明度で暗くする（V39_FIELD_FOG_STYLEを共通参照）。通常Fogとは別の表示で、探索履歴は変更せず、配置終了時に通常Fogへ戻す。候補は安全保証ではなく、周辺の敵Lv・種族目安も確認して決定する。
- 出現敵JSONのLv1〜3と交差する定義を序盤範囲で使用し、該当定義がない地形では最低Lv帯の種族をLv1〜3の序盤個体として生成する。通常のJSON定義は変更せず、遠方の通常個体は高度と出現敵JSONの出現範囲を参照し、初期Lv上限15に収める。ボス個体はLv20〜25、暫定で高度7以上または-7以下はLv30を優先する。勝利対象の守護者はLv40、配下は既存差分-2によりLv38。調整値はV39_ENEMY_LEVEL_BALANCEとV39_VICTORY_GUARD_BALANCEを参照し、生成済みJSONは変更しない。自然発生・後日の移動侵入・勝利対象守護者まで排除する永久安全地帯ではない。
- 敵数は出現可能タイル120マスにつき1体を基準に、8～30体へ収める。マップ寸法と拠点座標から決めた乱数列を使い、同条件では同じ初期配置になる。

## 4. 領土・村

- 村を設置すると、村中心と隣接6マス（半径 `1`）のうち、海・湖・火山を除く通行可能タイルが自領になる。他勢力が所有済みのタイルは上書きしない。
- マップ上の領土境界は操作中勢力の外周だけを勢力色で表示し、他勢力の境界線は重ねない。プレイヤー切替時に切替先勢力の境界へ差し替える。
- 村中心は施設「拠点」かつ土地状態「拠点」、周囲の取得タイルは土地状態「領土」として保持する。
- 村は以下の要素を持つ。
  - 人口
  - 種族別人口
  - 食料在庫
  - 資材在庫
  - 都市能力
  - 建物
  - 人口許容
- 初期人口は勢力データの `初期人数` を参照する。
  - 例: 人間50、エルフ50、ゴブリン90、竜人15、悪魔5 など
- 初期食料・初期資材は、村中心予定地とその周辺領土の産出をもとに算出し、開始時に `3倍` した値を在庫として持つ。
- v39の人口・在庫・都市能力・施設・建設キューは `players[].factionState.settlements[]` の各拠点へ保存し、プレイヤー切替時や拠点切替時に混在させない。
- 拠点規模は `scaleKey / scaleLevel / type` の明示状態で保持し、人口到達だけでは自動変化しない。次規模の必要人口を満たしたうえで手動の発展工事を完了すると規模が変化する。名称・規模Lv・下限人口・ネームド上限・表示画像・表示サイズ・1マス収容人数・占有マス数は `施設.json` の `分類=拠点規模` 行から取得する。
- ネームド上限は規模連動。
  - 村: 2
  - 町: 4
  - 都市: 7
  - 大都市: 10
- 領土タイルは `資源化` と `居住化` を持ち、`2ターン` で切替できる。
  - 土地タブのボタンは資源化マスで「居住化」、居住化マスで「居住化解除」と表示する。解除も2ターンで資源化へ戻す。拠点本体の占有マスと発展工事で使用中のマスは解除できない。
  - 居住化完了時に対象マスの完成施設・建設待ち・施設HPデータを撤去し、拠点の施設一覧・効果と世界側の施設一覧からも削除する。施設から居住化・居住化解除・居住地から施設への変更は確認ポップアップを表示し、キャンセル時は変更しない。拠点占有・発展工事中・土地用途変更中のマスには施設を建設できない。
  - 完成施設・建設中施設があるマスは施設シートの `土地用途` で人口許容・雇用枠・基礎産出倍率を決める。現在は居住化（+15 / 5 / 1.0倍）。生産施設の対応技能100は既存式で2.0倍となり、対象資源の合計は基礎1.0×施設2.0倍。施設マスには村画像を重ねない。
  - 資源化: 産出 `2.0倍`、人口許容 `+5`
  - 居住化: 産出 `1.0倍`、人口許容 `+15`
- 村中心タイルは常に居住化扱い。

## 5. 経済・ターン処理

- 現在の村経済処理は概ね以下の順。
  1. 領土収入
  2. 建物収入
  3. ユニット維持食料消費
  4. 村人口食料消費
  5. 不足判定
  6. 人口増減
  7. 人口許容超過の切り詰め
- 食料カテゴリ:
  - 穀物
  - 野菜
  - 肉
  - 魚
  - 死体
  - 魂
- 資材カテゴリ:
  - 木材
  - 黒木
  - 特木
  - 石材
  - 鉄
  - 銀鉄
  - 青金鋼
  - 赤黒鋼
  - 金
  - 銀
  - 宝石
- 通常食料不足時は、穀物・野菜・肉・魚の間だけで他食料を `1.2倍換算` して代用消費する。魂と死体は他資源から代用できず、相互にも代用できない。
- 領土収入は現行の `0.1倍スケール` を維持し、人口・ユニットの通常維持消費だけ消費スケールを `0.2` とする。`クラス.json` の各資源値に対して `資源値 ÷ 10 × 0.2` を1人口・1ユニットの1ターン通常必要量にする。建設、装備、ユニット作成などのスケールは変更しない。
- 食料不足は4ターン未満で消費50%、2ターン未満から人口減少、1ターン未満で自然回復停止、0.5ターン未満でHP以外の能力・技能-15%とAP上限80、資源0で最大HP5%ダメージを適用する。回復時は1ターンに1段階ずつ解除する。
- v39ではターンごとに全プレイヤーの領土収入、ユニット維持、人口消費、不足、人口増減を処理する。`lastEconomyDelta.turn` が同一の場合は再処理せず、同じターンの二重収入を防ぐ。
- 人口成長の正式設計は `docs/人口成長・食料不足ルール.md` を参照する。人口・ユニットの維持消費は `クラス.json` の各資源列、人口成長の資源種別は `増加条件`、成長基礎量は `コスト` を正本とする。必要成長ゲージは `同種族人口 × (コスト ÷ 10 × 0.2) × 2`。複数種族が同じ資源を必要とする場合は必要量比で配分し、維持消費後の余剰も `同種族人口 × コスト` の比率で各種族の成長ゲージへ分配して二重加算しない。死体1体と魂1つはそれぞれ資源値100として扱い、発生・回収・運搬方法は未確定とする。
- 人口許容上限中は人口増加を停止して成長ゲージを現在値で保持し、上限中の余剰は追加蓄積しない。人口許容が増えた後の次ターン終了時に通常の人口増加判定を行う。勧誘、移住、軍隊ユニット作成、イベントなど、人口成長以外の人口変動でもゲージの進捗割合を維持する。
- 成長ゲージが残っている間は不足による人口減少だけを遅らせる。自然HP回復停止、能力・技能低下、AP低下、飢餓ダメージは、成長ゲージ残量とは分けて実際の不足段階に従う。維持資源として設定された魂・死体が不足した場合も代用せず、同じ不足ペナルティを適用する。
- 上部資源表示は固定サンプル値を使わず、操作中プレイヤーの食料・資材在庫と直前ターン増減を参照する。
- 食料・木材・石材・金属・貴金属・宝石・特殊資源のキー一覧とHUD分類は `都市基本データ.json` の `分類 / データ分類` から生成する。旧Vue、キャラクター詳細、装備、物流、v39経済で別の資源名配列を持たない。
- 土地に複数の産出資源がある場合の地図アイコンは、`都市基本データ.json` の `地図表示優先度` が小さい資源を優先する。現行順は希少金属、通常金属、貴金属、木材、石材、食料、特殊資源の順を基準にする。
- プレイヤー所有拠点は `factionState.settlements[]` を正本とし、各拠点が人口・種族別人口・食料・資材・施設・建設キュー・規模識別キー・規模Lvを個別保持する。規模情報のない旧セーブだけ、人口と `施設.json` の拠点規模行から読込時に一度補完する。旧セーブの `factionState.village` は読込時に配列へ移行し、正規化後の実行状態には保持しない。
- 各拠点は安定した `settlementId` を持つ。`territoryStateByTile` は領土状態と所属拠点IDを同じレコードに保持し、各拠点の収入と施設効果を所属領土だけから計算する。
- 経済ターンは選択中拠点だけでなく全所有拠点を1回ずつ処理する。ユニットは `settlementId` で維持元の拠点へ所属し、国家総人口は拠点配列から都度集計する。
- 資源化は人口許容5・雇用枠10・産出2倍、居住化は人口許容15・雇用枠5・産出1倍とする。拠点人口を総雇用枠で割った共通稼働率を、所属領土の地形基礎産出・用途倍率・施設補正へ掛ける。フィールド上のユニットは就業人口に含めない。
- 居住化マスは元の地形判定と地形画像を変更せず、暖色の敷地区画レイヤーを重ねて資源化マスと視覚的に区別する。拠点本体の占有マス以外で居住化が完了したマスには、既存の村画像を表示する。完成施設と建設中施設は `建築_アイコン一覧1.webp / 建築_アイコン一覧2.webp` を4列×3行で分割し、施設名に対応する画像を村画像と同程度の60pxで対象マスへ表示する。建設中は半透明画像と残りターンを表示し、画像対応がない施設だけ施設名の先頭1文字へフォールバックする。
- 下段 `拠点` タブは所有拠点名を横スクロールで並べ、枠色で選択状態を示す。人口・食料・資材・施設・領土・修復は `▷ / ▽` の項目ヘッダーで個別に開閉でき、複数項目を同時に開ける。
- 反乱が発生すると対象拠点の種族別人口を減らし、減少人数を `rebelPopulation` に持つ反乱軍1体を敵としてフィールドへ生成する。反乱軍は通常の敵AIへ統合するが、ユニットや物資の追跡より領土攻撃だけを優先し、HPにかかわらず逃走しない。
- 反乱発生条件の正式値は未確定。現行の暫定値は不満度75以上、治安25以下、対象種族人口10%（最低1人）、同一拠点の再発間隔3ターンとし、`v39-gameplay-balance.js` へ集約する。
- 幸福度・不満度・治安は0～100、初期値と平常基準値は50とする。各ターンは現在値をそのターンの目標値へ近づけ、1ターンの変化上限は5とする。不満度が50を超える分に比例して産出を最大30%低下させる。
- 幸福度・不満度・治安の具体式と係数はプレイ調整前提の暫定実装とし、`v39-gameplay-balance.js` の `V39_CIVIC_BALANCE` に集約する。現行の幸福度目標は、平常基準50へ食料備蓄、人口許容に対する住環境余裕、施設、イベント補正を加え、飢餓、人口過多、災害、占領、異種族混在を減算する。数値は処理本体へ直書きせず、係数だけで調整可能にする。
- 幸福度は種族ごとに個別計算し、`civicState.happinessByRace` と `happinessTargetByRace` に保持する。拠点全体の幸福度は各種族幸福度の人口加重平均とする。不満度・治安は現時点では拠点全体値のまま扱う。
- 種族別幸福度係数はまず `クラス.json` の種族クラス行にある `幸福度基礎値 / 幸福度食料倍率 / 幸福度住居倍率 / 幸福度施設倍率 / 幸福度飢餓倍率 / 幸福度人口過多倍率 / 幸福度災害倍率 / 幸福度占領倍率 / 幸福度異種族倍率 / 幸福度イベント倍率` を参照する。各項目が未設定の場合だけ `種族幸福度仮.json` の同名項目をフォールバックとして使用する。0は設定済み実値として扱い、未設定とは区別する。
- 現行暫定値では、十分な食料備蓄と住環境余裕はそれぞれ最大+5、追加種族1種ごとに幸福度・治安-2 / 不満度+2、占領中は幸福度・治安-15 / 不満度+15、警備による治安補正は最大+30とする。人口過多は人口過多率1.0あたり幸福度・治安-10、災害は `災害.json` の `治安減少` を1倍で幸福度・治安低下と不満度上昇へ使う。
- `施設.json` の `影響範囲=全体` の幸福度・治安系効果は100%、`単体マス` の幸福度・治安系効果は暫定50%で拠点全体の住民状態へ反映する。この換算率も `V39_CIVIC_BALANCE.localFacilityCivicScale` で調整する。
- 種族選択では種族に対応する `クラス.json` の `適正土地`・`苦手土地` を表示する。未設定欄は表示しない。初期候補の優先順位にも反映する。適正土地以外を一律禁止せず、移動・産出の補正は追加しない。
- 追加動物の画像指定は `@game_data` の出現敵シートを正本とする。ホースは「狼・馬」、ボアは「ベア・ボア」、ドレイクは「ワイバーン・ドレイク」のユニット集.webpを使う。いずれも4列×3行の7番目（2行目・3列目）の通常個体を固定表示し、Lvによる別種・属性個体への画像切替はしない。
- 動物種族と属性クラスの画像組み合わせは `frontend/src/lib/animal-artwork-config.js` の画像対応表で管理する（画像専用で、能力データとは分離）。敵の `race` と `className` を読み、フレイム=炎、フロスト=氷、ウィンド=風、スパーク=雷、ポイズン=毒、シー=水、ストーン=地の画像を選ぶ。対応画像がない組み合わせは同じ種族の通常画像へ戻す。Lvでは画像を切り替えない。個体に画像ファイルと画像番号を直接指定した場合はその指定を優先する。出現敵の定義IDによる基礎画像より、この種族・属性対応を優先する。上記7属性クラスの能力値はクラスシートから生成した `クラス.json` を正本とし、出現条件は既存の出現敵シートを維持する。
- 苦手土地は拠点中心と所属の居住化マス（拠点占有マス・居住用途の施設マスを含む）で判定し、各マスを1件として数える。種族別の幸福度目標から `苦手土地マス数 / 対象マス数 × 暫定30` を引く。拠点全体には種族人口割合で反映し、実際の幸福度は既存の1ターン最大5の変化速度を維持する。工事中の居住化は完成してから対象となる。暫定30は `V39_CIVIC_BALANCE.unfavorableTerrainHappinessPenalty` で調整する。適正土地の幸福度ボーナスは今回追加しない。
- 拠点UIの「住民状態」には現在値に加えて目標幸福度・目標不満度・目標治安と、食料・住居・施設・飢餓・人口過多・災害・占領・異種族・苦手土地・イベントの幸福度側補正内訳を表示し、プレイ中に調整根拠を確認できる。
- 反乱条件を満たさず、不満度65以上かつ治安40以下の場合、毎ターン人口2%（最低1人）が流出する。種族別人口から人口比で減らし、成長ゲージの進捗割合を維持する。反乱発生ターンは通常流出を重ねず、反乱だけを適用する。

## 6. 都市能力・建設

- 村には以下の5能力がある。
  - 鍛冶場
  - 魔法
  - 信仰
  - 軍事
  - 経済
- 内部定義は `Lv7` まで持てるが、現在の有効上限は `Lv4`。
- 経済Lvは収入倍率に反映される。
  - Lv1: 1.00
  - Lv2: 1.15
  - Lv3: 1.30
  - Lv4: 1.50
- v39の建設候補は `施設.json` のうち `分類=拠点規模` 行を除く25施設を表示する。土地タブの建設ボタンから開き、施設名、説明、地形条件、建築時間、研究条件、資材コストはJSONを正本とする。
- 施設画像は対象マス中央へ村と同程度の60pxで表示する。建設中は半透明画像と残りターンを表示し、未対応施設だけ頭文字表示とする。
- 同じ建物の重複建設は不可。
- 施設は1マスにつき1つまでとし、完成済みまたは建設中の施設があるマスへの追加建設は不可。
- 都市規模に対応する `施設.json` の `建築数` を施設枠上限にする。
- 拠点規模は `scaleKey / scaleLevel / type` の明示状態を正本とし、人口だけでは自動昇格・自動降格しない。これらの規模状態を持たない旧セーブに限り、読込時に人口と `規模下限人口` から現在規模を補完する。
- 拠点発展は施設建設画面の「拠点発展」から拡張位置選択を開始する。現在の占有マスは固定選択とし、次の `規模Lv` の `施設.json(分類=拠点規模)` 行が要求する `占有マス数` まで、地図上で追加マスを手動選択する。追加候補は同じ拠点に属する自領の居住化マス、既存占有マスと連結、施設・建設・土地用途変更がないマスとする。地形の種類だけでは禁止せず、水上でも領有と居住化などの条件を満たせば選択できる。
- 次の規模の `規模下限人口` 以上の人口、必要数の連結した選択マス、同じ行の資源コストをすべて満たした場合だけ発展を開始できる。選択マスに既存の下位拠点規模の居住マスが含まれる場合は、再利用した1マスにつき工期を1ターン短縮する。短縮後も最低1ターンとし、短縮値は `V39_SETTLEMENT_DEVELOPMENT_BALANCE.reusedResidentialTileTurnReduction` で調整する。未使用の新規居住化マスには短縮を適用しない。
- 発展開始時に必要資源を一度だけ消費し、拠点の `developmentProject` に発展先・残りターン・総ターン・短縮前ターン・再利用マス数・短縮ターン・開始ターン・使用する居住マスを保持する。短縮後の工期が経過すると `scaleKey / scaleLevel / type` と中心住居クラスターを更新し、拠点画像、人口許容、施設枠上限、ネームド上限へ新しい規模を反映する。人口許容は「全領土の土地用途分 + 拠点規模の `1マス収容人数 × 実占有マス数`」で計算する。人口が後から減少しても規模は自動降格しない。
- 拠点中心の旧「住居拡張」は新規の規模変更経路として使用せず、施設建設画面の拠点発展へ一本化する。旧住居拡張工事が残っている間は、同じ拠点で発展工事を同時開始できない。
- 建設開始時に資材を一度だけ消費し、`建築時間` のターン数を建設キューで進める。完了時に都市と対象土地の施設一覧へ反映する。
- 研究条件は研究画面・ユニット生成と同じ現在研究Lv（完了項目の最大Lv+1、実装済み段階を上限）を参照する。施設の数値効果列は完成施設から参照し、`影響範囲=全体` は都市全体、`単体マス` は設置マスだけへ適用する。
- 施設による正の資源産出倍率は `1 + (生産力 + 資源カテゴリ技能) / 100`。穀物・野菜・肉は農業、魚は漁業、木材類は林業、鉱石・貴金属類は工業を参照する。負の産出には増産倍率を掛けない。
- 拠点の農業・林業・漁業・工業は生産項目であり、人口構成から得た対応技能値を生産倍率表へ換算して表示する。稼働率は人数補正、生産項目倍率は資源種別ごとの技能補正として、タイル収入の別段階で掛ける。技能35は100%、節点間は直線補間、-25以下は50%、125以上は190%で固定する。フィールド上のユニットは含めない。対応技能は`都市基本データ.json`の資源行を正本とし、通常土地・発見資源・単体土地の収入へ施設補正と乗算して反映する。建設必要ターンへの接続は未実装。
- 施設の `回復` は所有マス上の生存ユニットのターン回復率へ、`索敵` は所有マスからの索敵範囲へ反映する。領土を失った施設は索敵源にならない。

## 7. ユニット・成長

### フィールド画像

- 敵は `assets/images/illust` の画像を使用し、`画像`、画像名、敵名、種族名、クラス名の順で対応画像を検索する。
- プレイヤー側ユニットは `assets/images/units/<種族名>` の画像を使用する。基本ファイル名は `<種族名>_<クラス名>`、只人のみ `<クラス名>` も使用でき、種族・クラス画像がない場合は種族画像を使用する。
- 対応する敵・ユニット画像がない場合は `assets/images/アイコン` の画像で代用する。
- 拠点は旧描画仕様と同じく `村.webp`、`町.webp`、`都市.webp`、`大都市.webp` を使用する。表示サイズは順に `60px`、`57px`、`66px`、`78px`。拠点レベルが未設定なら村として描画する。
- フィールドの描画順は、地形タイル、森林・山岳等の地形画像、拠点・敵巣、ユニットの順とする。地形画像は六角タイル内をほぼ満たす大きさで表示し、対応画像がない地形は同じレイヤーへ拡大した記号で代用する。
- 敵巣は `assets/images/アイコン/<巣種別>.webp` を使用し、通常時は現在視界内だけ表示する。巣画像と外周線をユニットより大きくして、同じマスに敵が重なっても巣の存在を判別できるようにする。テストモードON時は確認用に全巣を表示する。
- 敵巣の縄張りは `territoryRadius` 内のタイル群を使用し、プレイヤー領土と同じく縄張り全体の外周だけを赤橙色の枠線で表示する。通常時は巣の中心が現在視界内にある場合だけ表示し、テストモードON時は全巣を表示する。

### 領土・索敵表示

- 操作中プレイヤーの領土は、同じ領土同士が接する辺を描かず、領土全体の外周だけを勢力色で表示する。
- ユニットの索敵範囲は基本1マスで、技能の索敵値75ごとに1マス増える。拠点は周囲1マスを索敵する。
- 現在の索敵範囲は、範囲全体を塗らずに外周だけを薄水色の線で表示する。
- 一度も索敵していないマスは暗く覆い、発見したマスはプレイヤーごとの `factionState.visibility.exploredTileKeys` に保存する。
- 敵は現在の索敵範囲内にいる場合だけフィールドへ表示する。通常モードではこの表示制限を維持し、視界外の敵を残さない。テストモードON時だけ全敵を確認用に描画し、通常ルールで未発見となる敵は透明度40%で半透明表示する。通常ルールで発見済みの敵は通常の不透明度で表示する。
- 他勢力ユニットおよび一般村守備軍も、通常モードでは現在視界内かつ発見判定を通った場合だけ表示する。テストモードON時は未発見のものも透明度40%で表示する。
- 勝利対象土地は、マップ生成前に種類と必要地形を決める。候補地数はマップ長辺に応じて36×36以下=1件、60×60以下=2件、72×72以下=3件、83×83以上=4件とし、島形状に合う対象を優先して残り枠を他の種類で補う。どれが実際の勝利対象かを地形だけで判別できないよう、選択結果に関係なく全種類の成立地形を毎回生成する。各本体は大都市相当の中心＋周囲6マスを占有し、画像も大都市の表示サイズを使う。本体外側2リングを含む半径3・37マスは対象地形の必要核とし、その外側は全種類で自然またはランダムな不規則形状にする。太陽の山と星の火口は必要核へ約50%の山岳を追加し、黄昏の樹は中心37マスを必ず森林化したうえでマップサイズ別に61〜169マスまで不規則に広げる。宇宙の海は半径3を確保できる自然の深海域を使う。高地型3種は中心から1リングごとに高度Lvを1段下げ、周辺から隣接高度差1以内で進入できる麓を作る。実際の対象マーカー・守護者・勝利判定は選択された対象だけに付ける。正確な対象座標だけは全勢力の初期拠点配置後に決め、各開始拠点から長辺の38%以上（不足時でも28%以上）離れた場所を使い、候補地同士も長辺の24%以上離す。これらの暫定値は `V39_VICTORY_LANDMARK_BALANCE` で調整する。
- 勝利対象土地は発見した勢力にだけ名称・詳細・専用画像を表示する。専用画像は中心マスへ1枚だけ置き、中心＋周囲6マスの本体7マス全体を覆う大きさで表示する。通常プレイでは未発見の対象を描画しない。テストモードON時は未発見画像を不透明度60%で表示し、対象マスを半透明の黄色で塗り、太い黄色の六角外枠を表示する。通常モードではこの強調表示を出さない。
- 索敵範囲内でも、観測側の有効索敵が対象部隊の隠密未満なら敵・他勢力ユニットを発見できず、画像と土地詳細へ表示しない。距離2マス目以降は1マスごとに有効索敵を50減らす（下限0。視界内の隠密0の対象は距離減衰だけでは非表示にならない）。同じマスの部隊は最大索敵値へ他メンバーの索敵20%を加算、隠密合計を人数×0.75で除算して比較する。敵AIの新規標的取得にも同じ判定を使う。
- 戦闘による露見は索敵・隠密判定へ共通反映する。攻撃を実行したユニットは直後の有効隠密を0とし、次ターン1/3、2ターン後2/3、3ターン後に元の値へ回復する。再攻撃すると0からやり直す。回復ターン数は `V39_ATTACK_STEALTH_RECOVERY_TURNS` で調整する。元の技能値は変更しない。範囲・炸裂を持たない単体攻撃の直接対象になったユニットもそのターン中の有効隠密を0とする。範囲攻撃に巻き込まれただけのユニット、地形・溶岩・継続ダメージなど攻撃行動以外の被害では隠密を変更しない。攻撃後の回復は `lastStealthAttackTurn`、単体攻撃対象の当ターン露見は `lastStealthBreakTurn / lastStealthBreakReason` で保持する。被攻撃で攻撃後の回復履歴を上書きしない。旧セーブのattack露見は既存の記録を参照する。プレイヤー側表示と敵AI索敵の両方で同じターン判定を使う。
- 敵・他勢力画像は現在視界内と判定した後にだけ読み込み、通常の戦闘エフェクトもFog内では生成しない。テスト・強制演出だけ `allowInFog` を明示して例外化する。
- 60×60の描画負荷は `npm run benchmark:render` で地形、Fog、陣地、索敵、キャラ、敵、エフェクトを個別計測し、結果を `artifacts/v39-render-layer-benchmark.json` へ出す。
- 敵ターンのAI計算中は、`game-state-changed` 等から発生するFog・索敵・縄張り・ユニット/敵マーカーの再描画要求を保留し、敵AI計算完了時に各レイヤーを1回だけまとめて更新する。描画完了を待ってから敵ターン演出へ移り、演出中はマップのドラッグ・ズーム・マス選択・ユニット選択をロックする。通常の地形レイヤーはこのstate更新バッチの対象ではなく、地形データ自体が変わる場合だけ従来どおり更新する。

- ユニット区分は以下。
  - 統治者
  - ネームド
  - モブ
  - 軍隊ユニット
  - 強化軍隊ユニット
- モブ上限は `人口 / 10`。
- 軍事Lvによって高位生成モードが解放される。
  - Lv1: 個体ユニット
  - Lv2: 軍隊ユニット
  - Lv3: 強化軍隊ユニット
- 軍隊ユニットは人口消費つきで、HP倍率と攻撃回数が増える簡易軍勢表現。
- 通常の個体ユニットは人口消費なし、軍隊ユニットは `1体あたり3人`、強化軍隊ユニットは `1体あたり5人` を消費する。維持資源は通常ユニットを1人分、軍隊ユニットを3人分、強化軍隊ユニットを5人分として `クラス.json` の資源列から計算する。通常軍隊はHP2倍・3回攻撃。生成画面の必要軍事Lvは解放条件で、実際の初期Lvとは別に表示する。
- 新規ユニットLvは種族区分と通常/軍隊の共通設定で決まる。詳細は `CHARACTER_STATUS_RULES.md` の作成時初期値を参照。
- 非人族は総合Lvに応じて `種族Lv` と `クラスLv` が交互成長する。
- 人族は `クラスLv` のみ成長する。
- 人族は `Lv10以上` で第2クラス設定が可能。
- モブはネームドに昇格できる。統治者は最初からネームド扱い。

## 8. 部隊・装備

- 拠点画面で所有拠点名のタブを押すと、配置済みの選択拠点中心へフィールドカメラを移動する。ズーム倍率・選択キャラを維持し、未配置拠点ではカメラを動かさない。通常の状態更新や再描画だけでは移動しない。

- 部隊タブは操作中プレイヤーの実ユニット配列・部隊配列を参照する。明示された部隊のユニットIDを優先し、未登録ユニットは自身の所属IDへ補完、未所属の初期キャラ・新規生成ユニットは「単独」に表示する。部隊IDから数字を抽出して別IDへ変換しない。表示用補完は保存編成そのものを書き換えない。
- 2026-10-13: 自キャラステータスの「部隊」タブから部隊の新規作成・メンバー変更・解散を実行できる。表示中マップの同勢力生存ユニットを最大5体まで選び、同一マス条件は使わない。編制で座標・APを変えず、地上も洞窟と同じ先頭への追従・狭路での縦列化を使う。共有運搬品のある部隊の所属変更は荷下ろし後、自動任務中の追加は任務解除後。詳細は `部隊運用・敵軍編成ルール_2026-09-17.md` の現行v39節。

- 部隊は `1リーダー + 最大4名` の計 `5名` まで。
- 同じ座標にいるユニットだけ部隊化できる。
- 部隊の索敵は高い索敵値を主軸に使い、隠密は全員合算を人数補正して使う。
- モブのみ削除可能。削除時は部隊情報も整理される。
- 装備スロット:
  - 武器1
  - 武器2
  - 頭
  - 体
  - 足
  - 装飾1
  - 装飾2
- 装備変更時は村の資材を消費し、鍛冶場Lv・魔法Lv・信仰Lvが必要条件になる。
- 魔法系装備は魔法Lv、信仰系装備は信仰Lvも満たす必要がある。
- ネームド/ヒーロー系ユニットは個別装備変更UIの対象。
- モブは個別装備編集を行わず、クラス固定の装備プリセット参照を基本とする。
- モブ装備はアイテム一覧モーダルに表示しない。
- モブで許可する装備更新は「レア度一新」のみとし、実行時はユニット作成時と同等の素材消費を行う。
- v39の装備画面は、プレイヤーごとの村装備在庫を正本とし、一覧・キャラ装備・生成を切り替える。装備一覧はネームド/統治者の装備済み数と村の残数を `E数 / 残数` で示す。
- 装備生成費は `消費量.json(種別=装備, Lv)` を基礎に、`装備.json` の `木材 / 鉱石` 倍率を掛ける。品質キー、表示名、略称、品質倍率も同じ装備Lv行から読み、現行はコモン～レジェンダリーを鍛冶Lv1～5へ対応させる。キャラクター詳細、旧Vue装備処理、v39装備画面の候補と表示は同じ品質行から生成し、別の固定品質配列を持たない。
- `装備.json` の基礎能力値は装備生成時に品質倍率を掛ける。現行の杖は `魔力=15` を持ち、生成後は `round(15 × 品質倍率)` を装備由来の魔力補正としてキャラクターへ加算する。
- 防具の物理・魔法耐性は `装備.json` の耐性、品質倍率、`消費量.json` の `防具_物理 / 防具_魔法` を合成し、装備変更直後に再計算する。
- 武器種別は装備名から推測せず `装備.json` の `武器分類` を参照する。現行分類は `近接 / 射撃 / 魔法 / 盾` で、盾だけ副武器枠へ装備できる。自動装備候補と装備変更UIは同じ分類・スロット判定を使う。
- v39の付与画面は `付与.json` から対象装備に適用可能な候補を生成し、鍛冶/魔法/信仰/軍事/経済LvをAND条件で検証して `消費量.json(種別=付与)` の素材を消費する。
- 武器付与は最大3件かつ付与Lv合計を装備品質Lv以下とする。付与の能力値、耐性、威力、ガード、Cr、射程、攻撃属性は装備派生値と共通戦闘処理へ反映する。付与済み装備は付与構成ごとに別在庫として扱う。
- 付与の1ターン当たり上限は魔法または信仰Lvに人口倍率 `1 + floor(人口 / 25)` を掛ける。1回の必要数は `付与Lv + max(0, 品質Lv - 1)` とし、使用数を村のターン別状態へ保存する。

## 9. 探索・索敵・移動

- マップ上のユニットは移動値を持ち、移動と戦闘で同じ共通APを使用する。共通APはターン開始時に回復する。
- 移動値は `基礎速度 → SIZ補正 → 脚数基礎値 → その他移動補正 → 移動値` の考え方で算出する。SIZ補正はオートマン側 `siev0000/game-project` の既存ルールを踏襲し、`SIZ>=180` は `round(SIZ/50+8)%` 相当の速度低下、`SIZ<=150` は `-round((160-SIZ)/3)%` 相当として小型ほど速度を上げ、151～179は補正なし。脚数は `クラス.json` の種族・動物データを参照し、基礎移動値は `10 + 脚数×5`（脚0=10、脚1=15、脚2=20、脚4=30）。速度補正は `SIZ補正後速度/10` を加算し、速度100を上限にせず500以上も同じ式で伸ばす。最終移動値は `round(10 + 脚数×5 + SIZ補正後速度/10 + その他移動補正)`。脚数未設定の旧データは互換用に2脚扱い、その他移動補正は現時点0。固定 movement 値は使用しない。マップ尺度は10=1マス相当、1マスの基礎移動APは `1000 / 移動値`。上りは高度差1ごとに移動コスト率へ+25ポイントし、高度差2以上は飛行なしでは通行不可とする。飛行が正なら高度差制限を解除し、登坂ペナルティはmax(0,上り高度差+通常壁の高さ-飛行/100)×25ポイント。端数も比例軽減し、地形ペナルティは維持、障壁付き壁は通過不可とする。下りと同高度移動には高度由来の追加ペナルティを付けない。
- 下部の移動と攻撃は同時に選択できず、同じボタンの再押下またはEscapeで解除する。待機はAPを保持したまま、そのターンの行動を終了する。待機済みは次ターンまで移動・攻撃・調査を開始できない。
- 同じユニットの同名スキルは1ターン1回まで。CT未設定/0でも発動後は次ターンまで使用不可、CTが2以上ならそのCTを優先する。敵も同様に別スキルを選ぶ。同じスキルを別ユニットが使うことは可能。回復/蘇生/地形変換にも適用し、失敗時は消費しない。待機スキルは発動時から再使用制限を計上する（発動待機中は元々他の技も開始不可）。反撃の基礎攻撃は別扱いで、この制限を消費しない。使用済みは行動欄で薄く表示し、使用済みの理由を示す。保存後のロードでも同ターンの制限を保持する。
- 移動確定後は実際の経路・各マスでの部隊配置に沿ってユニット画像をスライドさせ、演出後に座標とAPを確定する。経路線を演出中も残し、部隊員は同時に動く。演出中は操作・ターン終了をロックする。ワールド端をまたぐ移動は画面全体を横切る演出にしない。調整値は `V39_MOVEMENT_PRESENTATION_BALANCE`（1マス140ms、全経路最大1200ms）。
- 移動の案内・距離/消費AP/残AP・取消/移動確定は、下部の部隊→行動欄上部の固定枠へ表示する。行動欄をスクロールしても確認枠は上端に残る。移動先未選択では確定ボタンを無効化し、取消は可能。移動開始時は行動欄を開く。マップ上は移動可能範囲・経路・移動先のみを表示し、通知領域へ移動確認を重ねない。
- 行動一覧で同じ攻撃を再押下すると対象選択を解除する。移動・待機・調査・非攻撃スキルへ切り替えた時も攻撃の範囲表示と選択強調を解除する。調査不可の場合もクリックで対象選択を解除し、AP不足・調査済み・調査中などの理由を表示する。
- 地形移動ペナルティは `地形.json` の `移動コスト` を使用する。移動コスト1/2/3/4はそれぞれ100%/150%/200%/250%として扱い、連続値も同じ換算を使う。登坂時はこの地形コスト率へ高度差1ごとに+25ポイントを加える。早業は1ポイントごとに0.5ポイントずつ、地形と登坂を合算した追加ペナルティを軽減し、`最終移動コスト率 = max(100%, 地形コスト率 + 登坂ペナルティ - 早業×0.5%)` とする。早業に100の上限はなく、100なら50ポイント、200なら100ポイント軽減する。軽減対象は追加ペナルティのみで、通常移動100%より下にはならない。地形の通行条件は `地形.json` の `移動条件` を敵味方共通で参照し、早業では無視できない。`|` はいずれかを満たせば通行可能、`能力名:数値` は最低能力値を表す。海・湖は遊泳、峡谷は飛行、溶岩は耐熱または炎耐性100以上を必要とする。
- 敵・他ユニットのいるマスへの進入と通り抜けは不可。選んだ目的地へ到達できない場合は、現在APで目的地に最も近い到達可能マスを手前の停止位置として提示する。
- 調査はキャラクターの行動一覧から現在地を中心とした索敵範囲全体へ実行する。残りAPをすべて消費し、その数値を調査進捗へ加算する。必要累計APは100（`v39-gameplay-balance.js` の `V39_SURVEY_BALANCE.requiredAp`）。不足分は次ターン以降に継続し、完了時は未調査マスの危険度低下・探索資源・特産品発見を処理する。通常土地の領土化は行わず、勝利対象土地の専用獲得条件だけ維持する。死亡・移動による中断は従来どおり。土地タブには結果と残留品回収を表示する。
- 通常土地は拠点タブの「開拓」で地図から選んで取得する。自領隣接の探索済み陸地、船着き場周囲1マス・港周囲2マスの海/湖が候補。生存モンスター・他勢力ユニットのいるマス、一般村、他勢力領土、勝利対象土地は対象外。敵侵入時は進捗保持で停止し、担当者を生産に戻す。条件回復後は自動再開する。
- 開拓は暫定10人・2ターン・1拠点同時1件。人数を生産から外すだけで人口・食料消費・備蓄資材は減らさない。稼働率は `min(1, max(0,人口-進行可能な開拓担当人数)/雇用枠)`。計画は各拠点の `landExpansionProjects` に保存し、NPCにも共通適用する。詳細は領土・資源生産ルール.mdを参照。
- プレイヤー移動は命令ごとに即時・逐次解決する。同時移動と接敵ロックは採用せず、敵または他ユニットがいるマスへの進入を禁止する。
- 部隊員は同一マスへ重ねず、部隊の `unitIds` で所属を管理する。部隊移動は隊長の移動先を基準とし、全生存部隊員を隊長と同じ方向へ1マスずつ移動させて隊形を維持する。1人でも通行条件、高度差、他ユニット占有を満たせない方向は移動候補から除外し、空きマスへの自動再配置は行わない。
- 奇襲による即時撃破は現行v39では使用しない。敵への攻撃は下部の行動画面から射程・範囲を選ぶフィールド直接戦闘へ統一する。
- 地図はマウス/タッチのドラッグ、ホイール、ピンチ、ダブルタップに対応する。入力欄以外では矢印キーでカメラ移動、`+/-` で中央基準ズーム、Enterで中央タイル選択を行う。
- ユニット、敵、拠点の画像が見つからない場合は、名称や種類名をマスへ書かず共通記号へフォールバックする。
- 峡谷の特殊地形表示には既存の `アイコン/渓谷.webp` を使用する。
- 通常プレイでは操作プレイヤーの現在索敵範囲と隠密判定を満たした敵・他勢力ユニット・一般村の守備ユニットだけを表示する。索敵判定が未準備の間も表示しない。未発見の勝利対象土地は非表示とし、テストモードをOFFに戻した時も即座に表示を更新する。テスト表示は通常の視界・発見状態へ加算しない。

## 10. ターンイベント

- 敵AIは各個体の残APで可能な移動・攻撃を再判断して繰り返す。待機・発動待ち・訓練・回収、AP不足、AP消費のない行動や失敗でその個体の行動を終了する。通常徘徊を含む視界内の移動をスライド表示し、視界外の経路は演出しない。敵の戦闘ログとAI判断ログにはLvを表示する。
- v39フィールド右上の `ターン終了` から手動でターンを進める。自動ターン進行は現状 OFF。
- ターン番号と停止状態は共通ゲーム状態 `timeline` で保持する。ローカル順番制では、ターン順 `playerTurnOrder`、現在操作勢力 `activeTurnPlayerId`、終了済み勢力 `endedPlayerIds` も保持する。
- 操作勢力が複数の時は、`ターン終了` で次の未終了勢力へ切り替える。全勢力が終了した時だけエネミーターンと全体終了処理を1回実行し、次ラウンドは先頭勢力へ戻す。
- ターン開始時は生存ユニットの共通APを最大値まで回復し、死亡者は回復対象外とする。
- v39のターン解決順は `ターン開始(AP回復) -> 地形イベント -> AI命令 -> 調査 -> ワールド住民 -> 経済・建設 -> 研究 -> 外交 -> 生存者HP回復 -> ターン完了` とする。生存者の基礎HP回復は最大HPの5%、死亡者は回復しない。
- ターン進行では選択タイル、選択ユニット、カメラ位置、ズームを変更しない。
- 例外として、表示設定「ターン終了時に未行動キャラを確認」（初期ON）では、操作勢力に未行動キャラが残っていたらターンを進めず、そのキャラを選択してカメラを合わせる。待機済み・死亡・AP0・行動済みは対象外。OFF時は従来どおり終了する。テスト用の一括ターン進行ではこの確認を省略する。
- 現行実装の `停止 / 再開` は実秒ベースの待機、CT、効果時間、敵AIを止める。正式仕様ではこれらをターン基準へ移し、停止中は自動進行せず、手動でターン終了を確定するまでは残りターン数を進めない。
- ターン経過と停止・再開はフィールド右側の共通ポップアップで通知する。停止状態そのものはターン操作ボタンに保持する。
- v39ターン処理は地形、調査、ワールド住民、経済・建設、研究、外交、回復を一括実行し、完了後の状態変更で索敵表示を更新する。
- ターン解決中は「敵AI計算中 / AI結果の画面反映 / 敵行動の再生 / 各解決段階 / 最終画面反映」をロード表示で区別し、操作をロックする。表示を描画してから処理を始め、ターン後半のマップ更新は描画バッチでまとめる。完了・例外時とも表示とロックを解除する。`getV39LatestTurnPerformance()` で直近の敵AI計算・状態反映・描画待ち・演出と各段階の所要時間（ms）を確認できる。画面反映時間は予約描画を待つ時間を含み、GPU単独の時間ではない。

## 11. 研究・戦闘・補助UI

- `地形.json` のHP・攻防・速度・命中・技能などの数値補正は、基礎値を保存し直さず現在地から戦闘時に加算する。敵味方・反撃・外部ダメージAPIで同じ処理を使い、土地詳細、部隊詳細、ダメージ計算ログへ補正理由を表示する。

- 研究ツリーUIは以下の5系統を表示できる。

- 一般村の守備軍隊ユニットは村中心を空け、周囲の通行可能マスから1マス1ユニットで配置する。周囲6マスで足りない場合は外側へ広げ、プレイヤーユニット・敵・敵巣・他拠点などの使用中マスを避ける。人口変動時は軍隊人口上限を再計算して守備軍を再同期する。一般村の依頼は食料または資材の提供とし、完了時に関係値と別種資源の謝礼を得る。一般村への襲撃は村範囲内の選択ユニットと実守備軍の戦力で判定し、関係値を低下させる。外部襲撃はターン処理で決定的に抽選し、守備軍が防げない場合は人口が減少する。確率・必要量・関係値は共通暫定設定へ集約する。
- TEST ONの選択マス拠点情報では、一般村の住民と生存中守備軍を合算し、`クラス.json`の資源消費と人口維持費倍率から算出した`必要物資(1T)`を表示する。中心と周囲6マスから、通常拠点と同じ地形産出・稼働率・人口構成の対応技能倍率を使った`推定産出(1T)`、食料の`不足候補(1T)`、上位3件の`得意資源`も表示する。一般村自身の在庫・消費・不足ペナルティはまだ保存処理へ接続しないため、これらは確認専用とする。
- 2026-10-14: タイトルのテスト操作に「村依頼・悪魔契約テスト」を追加。一般側/悪魔側の納品・討伐、達成友好度+10、悪魔への魂要求権と在庫移転、部隊休息時の村強襲、通常フィールドでの村との戦闘、死亡/拘束判定、来訪時の人物と装備の受け渡しを専用仮データで確認できる。正式な交渉判定・通常村への自動適用・捕虜利用は未接続。詳細は `一般村イベント共通ルール.md`。
- 火山以外の災害は、`災害.json`のIDを参照してターンごとに発生を評価する。発生率、対象地形、範囲、継続、産出倍率、治安低下、最大HP割合ダメージは、正式列が未追加の間だけ`V39_PROVISIONAL_DISASTER_BALANCE`を使用する。対応済みの災害は`地形.json`の災害相性列を使い、`発生率 = 基礎発生率 × (1 + 地形相性)`で発生判定する。対応は洪水、暴風、地震、落雷嵐、大寒波で、他の災害は相性列が追加されるまで補正なしとする。発生中の災害はワールド環境状態に保存し、対象タイルの産出・治安と、設定された地形ダメージへ反映する。一般村では、領域にかかった災害の`最大HP割合ダメージ`を住民人口にも同じ割合で適用し、守備軍にも通常ユニットと同じダメージ処理を適用する。各被害マスには災害種別の小アイコンを重ねて表示する。`災害.json`の`アイコン`列があればそれを優先し、未設定時は暫定アイコンを使う。TEST ONでは災害種別を選び、選択マスへ強制発生できる。
- アンデッドの自然発生はマスの浄化-5以下で排他的イベントを判定する（暫定: 死の霧8%/アンデッド8%/なし84%、同マス5T）。死体のあるマスは毎T-1、死の霧は追加-1。地上は7マス、洞窟は部屋所属エリアのみ。既存霧内の死体変化は発生源100%/+3Lv・他50%、浄化-5以下/翌T以降、成功時のみ死体消費。自然発生は同ワールド2体/T・同マス5T、通常霧内の有限死体変化は別扱い。旧霧外死体1%/空霧2%抽選は廃止。死の刃は所持者の撃破マスの現在浄化から5減らす。AIアンデッドは他のアンデッドへ能動攻撃せず反撃は維持。詳細はアンデッド・不浄ルール.md。一般村の討伐依頼との脅威ID連携は維持。

- 攻撃対象、HP、AP、CT、発動待機、効果時間、死亡、反撃、戦闘ログは共通ゲーム状態へ即時反映し、そのままセーブ対象とする。
- v39フィールドの攻撃は、選択キャラクターの装備武器と `行動A` の技を同じ処理へ渡す。装備武器も単体の通常攻撃として表示する。
- 取得済みの `行動P` は攻撃時に条件照合する。`攻撃手段` 指定は同じ手段、`条件系統` 指定は同じ属性、`ガード時` は反撃時だけ、能力値・威力補正を敵味方共通計算へ一時適用する。
- 装備武器の通常攻撃は、その装備攻撃行で算出された武器APをそのまま消費する。`攻撃手段=武器` の `行動A` 技は、技自身の `AP消費` に主武器（`武器1` 優先、未装備なら `武器2`）の武器APを加算する。通常攻撃には武器APを二重加算しない。
- `攻撃手段=魔法` の `行動A` は、技自身の `AP消費` に現在装備している全アイテムの `魔法AP` 合計を加算する。武器1/武器2/頭/体/足/装飾を同じ装備一覧から集計し、未設定は0とする。例: 杖(`魔法AP=30`) + 火球(`AP消費=8`) は38AP、さらに鎧(`魔法AP=10`)を装備していれば48AP。行動カード表示、AP不足判定、実消費は同じ共通計算を使う。
- 攻撃APが足りない候補は薄く表示して選択・実行不可にする。射程値は10=1マスとして扱い、10/20/40なら1/2/4マス。射程未記載は1マス、武器攻撃は武器射程、範囲未記載は単体、炸裂未記載は0とする。
- 攻撃位置選択中は射程を黄色、通常の攻撃範囲を赤、炸裂の小数ダメージ範囲をオレンジで表示する。
- スキル対象選択中に味方または死亡者のフィールドマーカーを押した場合、そのマスを対象として扱い、攻撃者の選択は切り替えない。通常時の味方マーカー押下だけ、従来どおり選択ユニットを切り替える。これにより味方への同士討ち、回復、強化、蘇生を同じ射程・対象選択経路で実行する。
- ダメージは敵味方で同じ式を使う。`(計算威力 - Lv/10×耐性値) / (1 + 防御値/100) × 乱数0.4～0.5 × (1 - 耐性割合) × 共通ダメージ倍率` を各攻撃回数ごとに計算する。共通ダメージ倍率は `v39-gameplay-balance.js` の `V39_COMBAT_BALANCE.damageMultiplier` を正本とし、現在の暫定値は `3`。魔力判定は精神、それ以外は防御を参照し、同士討ちはさらに半減する。
- `ガード` は技の使用者または支援対象へ付与する消費型軽減値とする。付与されたガードは被ダメージの各ヒットから先に差し引き、残量があれば同じターン中の次の攻撃も軽減する。プレイヤー側は次のプレイヤーターン開始時、敵側は次のエネミーターン開始時に残量を消去する。
- **盾・障壁・壁の試験実装（2026-10-10）**: `効果`で種類を判定し`ガード`を基礎値に使用。盾は付与側精神で算出して毎ターン復元、障壁は命中Hitごとの威力軽減で消費、壁は辺／マスへ設置しHP0・期限で解除。防壁／城壁の施設完成時にも壁を生成する。通常壁は高度と移動APで乗り越え、障壁付き壁は破壊が必要。テスト技、残量表示、保存復元を追加。仮数値・消費順と接続済みの視界／射線遮断は [戦闘ダメージ・耐性ルール.md](./戦闘ダメージ・耐性ルール.md#77-試験実装の仮運用確認方法) を参照。
- **結界の試験実装（2026-10-10）**: `効果:結界`で一つの共有耐久を持つ外周結界を設置。単体1マス、向き選択の三角形3マス、周囲は炸裂0／10／20／30で1／7／19／37マス。通常攻撃の炸裂とは別処理。仮運用では設置勢力の範囲内ユニットへの外部攻撃の威力を軽減し、復元なし・通行自由・残量0または期限で解除する。未確定部分を正式確定扱いにせず、[戦闘ダメージ・耐性ルール.md](./戦闘ダメージ・耐性ルール.md#77-試験実装の仮運用確認方法) に分離した。
- 戦闘ログは攻撃者、使用技、各ヒット値、合計値、消費APを表示し、計算詳細を内部データとして保持する。基本命中率は、通常攻撃が `命中 / 相手の回避 × 75%`、魔法攻撃が `精神 / 相手の回避 × 75%`。回避が未定義の場合は速度を使用し、未確定の最低・最大命中率は共通設定の暫定値5%・95%とする。攻撃回数ごとに判定し、失敗時はダメージ0で `Miss` を表示する。
- 攻撃エフェクトは `アニメ` を参照し、攻撃技の未記載時は `斬撃`。回復・強化などの支援技は未記載時に斬撃を出さない。フレーム枚数に関係なく1.5秒で再生する。`:` 区切りは10ms間隔で順番に再生し、炸裂0.5なら基準の1.5倍にする。
- 魔法の最低6ターン待機とJSONの `待機`、`CT`、`効果時間` はターン数で管理する。ゲーム進行に影響する実時間処理と秒数からターン数への実行時換算は行わない。`プレイヤーターン → エネミーターン → 全体終了処理` を完了して次のプレイヤーターンへ戻った時点を1ターン経過とし、全体終了処理で1回だけ進める。
- 敵の実時間行動トリガーは使用しない。敵はエネミーターン中に1体1行動とし、AP、索敵、行動A、待機、CT、同じダメージ式、エフェクト、ログを使って行動する。
- 敵ターンの索敵、標的選択、逃走、移動候補、攻撃候補、待機判断は共通の純粋AIプランナーを使用し、通常はWeb Workerで敵ID順に処理する。Worker内部では先行する敵の移動・AP・待機状態を反映してから次の敵を判断し、一斉判定にはしない。
- WorkerへはAI判断に必要な敵・対象・巣・残留品・地形だけを軽量化して送る。戦闘結果、HP/AP/CT、物流、ゲーム状態保存、DOM、Phaser、カメラ、エフェクトはメイン側で順番に確定する。戦闘・回収後は確定状態をWorkerへ再同期する。
- Workerの生成失敗・例外・タイムアウト時は、同じ純粋AIプランナーをメインスレッドで8行動ごとに描画へ制御を返しながら実行する。Worker化によるセーブ形式の変更は行わない。
- 敵ターン中の行動は移動・攻撃イベントとして保持する。自勢力の索敵範囲内の攻撃は、状態確定後に対象地点へカメラを移動して既存エフェクトを再生する。標的を追跡する移動も索敵内なら移動演出を行い、通常徘徊や索敵外イベントではカメラ演出を行わない。演出時間は待機・CT・ターン数へ加算しない。
- TEST計測では敵AIのWorker計算時間、メイン側反映時間、Worker経路全体時間、フォールバック有無、演出イベント数を個別表示し、処理中は右通知欄へ進捗件数と割合を表示する。
- 生成敵は `出現敵.json` の明示的な `ID` を `sourceDefinitionId` に保持し、定義全体は状態へ複製しない。巣が設定された敵は安定 `nestId` を持ち、巣状態はワールド共通の `enemyNests[]` に種族別人口、成長ゲージ、所属ユニットID、縄張り半径、食料・資材・装備在庫を保持する。巣人口とフィールド個体数は別管理とし、敵死亡時は所属IDだけを外して巣人口を直接減らさない。
- 敵巣は縄張り内の地形から食料・資材を得て、所属するフィールド個体の維持費も負担する。プレイヤー拠点と同じ種族別成長・不足・飢餓関数を使用し、生成時は実維持量4ターン分を暫定初期備蓄とする。
- 部隊は `cargo.resourcesByType / cargo.equipmentInventory` に運搬中の資源と個別戦利品を保持する。UI上の単独枠は `cargoByUnitId` で個体別に分離する。通常部隊は生存中の所属員全員が帰還した時、単独ユニットは本人の帰還時に拠点在庫へ自動搬入する。敵部隊も `enemySquads[]` で同じ運搬形式を使い、全員が所属巣へ帰還すると巣在庫へ自動搬入する。
- プレイヤー部隊のフィールド移動は生存中の最遅メンバーを基準にする。移動値10をAP100で平地1マス移動できる基準とし、1マスの基礎消費APを `1000 / 移動値` で求める。10刻み以外の移動値も切り捨てずAP効率へ反映し、実際の1ステップ消費は地形・高低差補正後に切り上げる。移動と戦闘は同じ共通APを使用し、部隊移動時は参加する生存メンバー全員の共通APから同じ移動コストを消費する。移動可能範囲は参加メンバーのうち残APが最も少ない値を上限とし、ターン開始時のAP回復は通常の共通AP回復処理で行う。
- 部隊が全滅すると共有運搬品を最後に死亡した一体の `corpseCargo` へ移す。一部生存時は部隊 `cargo` を維持する。死体回収時は回収キャラクターの所属部隊へ移し、死体期限切れ時は食料だけ消失して、その他の資源・装備を未発見の `groundLootByTile` へ残す。
- 地上残留品は同じマスで1ターン調査すると発見でき、土地タブの「残留品回収」で回収者の部隊 `cargo` へ移る。モンスターは索敵内の残留品へ移動・回収し、所属巣へ帰還すると巣在庫へ搬入する。
- 食料不足の巣は、帰還した探索役から報告された食料領土を略奪候補にする。探索役は対象領土へ移動し、`行動A` の攻撃で領土HPを0にすると、そのマスの通常食料産出3ターン分を部隊 `cargo` へ積載して帰還する。運搬上限は生存個体ごとの `100 × (SIZ / 170)` の合計で、超過分は保持しない。略奪済み領土は再略奪不可かつ通常産出停止になり、敵・溶岩がない場合に所属拠点の資材を使って手動またはターン終了時の自動修復を行える。
- 初期配置の通常敵は巣なしとし、強敵・強敵配下のグループだけ初期巣を持つ。同一強敵グループは1つの巣を共有する。敵巣は初期縄張り半径2、`種族名の巣1` から始まる数値連番名を持つ。所属フィールド個体が1体だけの巣アイコンは通常巣の80%サイズで表示する。共通ユニット生成費で所属種を増員し、満員時は出現待ちにする。次規模最低人口の90%以上かつ食料余裕ありなら、規模拡大または人口・食料25%を移す巣立ちを50%ずつで選ぶ。巣なし個体が後から自力で巣を作る条件・必要ターンは未確定。
- 敵巣は軍事Lvを最低1で保持する。所属敵が巣マスにいて緊急行動・戦闘・食料探索・物資回収がない場合、暫定3ターン間隔の平時候補として通常訓練を行い、個体へ `軍事Lv × 10` EXPを付与する。間隔と係数は敵AI共通設定で変更でき、AI判断ログには軍事Lvと獲得EXPを残す。
- 巣なし敵は縄張りを持たず、AI上の移動基準には現在位置を使う。未設定座標を `(0,0)` の巣として表示・判定しない。
- 巣の縄張りが衝突すると別巣所属個体を通常戦闘の対象にする。同巣への範囲巻き込みだけを同士討ち半減とし、別巣には通常ダメージを適用する。同種の敗者巣は勝者へ統合し、異種の敗者巣は備蓄を巣マスの戦利品へ変換して生存遠征個体を巣なしにする。
- ユニットは敵味方とも `lastMovedTurn / lastCombatTurn` を保持する。ターン終了時は、そのターンに移動も戦闘もしていない生存者だけ、共通回復式の基本5%と現在地補正で自然回復する。
- 敵はエネミーターン中に縄張り内を決定的に徘徊し、追跡・帰還も同じ敵ターン内で判定する。好戦的な敵は索敵対象を縄張り外へ移動力分まで追跡し、非好戦的な敵は縄張り内の対象または攻撃してきた対象を外側1マスまで追跡する。限界を超えると縄張り中心へ戻る。通常の敵対は個体単位だが、巣の周囲1マスへ侵入された場合だけ同じ巣の全個体が防衛対象として扱う。
- 敵の逃走開始HP率は好戦的10%、非好戦的30%とし、巣の有無にかかわらず性格別の同じ閾値を使用する。巣あり敵は巣周囲へ、巣なし敵は現在の敵対対象と反対方向へ逃走し、対象が索敵外へ出た後にさらに1回移動して終了する。確率抽選は行わない。非好戦的な敵は、巣の防衛時または攻撃者を記憶している間だけ反撃・追跡する。
- `players[]` の `isPlayer:false` は基本勢力AIとして扱う。毎ターン、既存の人間用検証関数を通して調査1件、建設1件、ユニット生成1件、未選択の各研究系統を決定的な順序で選び、`aiState.lastProcessedTurn` で二重実行を防ぐ。
- TEST ONの「勢力追加」では `プレイヤー勢力` と `NPC勢力` を選べる。どちらも既存の `players[] / factionState` を複製してIDを再採番し、NPCだけは `isPlayer=false` とする。追加勢力は既存の統治者を含む勢力編成を元にし、同じ初期拠点・領土・人口・研究・ユニット配置規則を通して自動配置する。
- NPCは通信参加者へ割り当てず、手動のプレイヤーターン順にも含めない。勢力状態、拠点、領土、人口、研究、ユニット、探索履歴はプレイヤー勢力と同じセーブJSONへ保存し、AIの操作対象であることだけが異なる。
- 単体近接攻撃を受けて生存した対象は、1回の被攻撃につき1回だけ反撃する。直前に使った近接武器を優先し、なければ装備中の近接武器または `素手 / 角 / 牙 / 爪 / 翼 / 尾 / 針` を使う。弓・銃・魔法・射程2マス以上・範囲・炸裂は反撃対象外で、反撃への再反撃はしない。反撃APは暫定で、その反撃に使う通常攻撃APの50%を小数切り上げで消費する。残りAPが反撃AP未満なら反撃せず、APが残っている限り別の攻撃を受けた際にも再度反撃できる。
- `攻撃手段:武器` の近接スキルも、通常武器攻撃と同じ条件で被攻撃側の反撃を発生させる。スキル自身の射程・範囲・炸裂に加え、使用するメイン武器が近接であることを確認する。反撃発生の対象を増やすだけで、反撃に選ぶ攻撃へ武器スキルを追加するものではない。
- 攻撃解決時は攻撃者のフィールド画像を対象方向へ8pxだけ往復させる。
- HPが0になると状態を `死亡` にし、灰色表示のままフィールドへ残す。2026-10-20変更: 消滅期限は通常死体10ターン・アンデッドの残骸5ターン、地面の死体資源も追加分ごとに10ターンで消滅する。期限切れでも装備・他物資は地面へ残す。2026-10-17変更: 同マスへの到達では遺体を自動回収しない（荷物回収は維持）。霊廟の「回収する」から明示的に保管する。保管中は死体由来の浄化低下・自然アンデッド化・消滅を止める。死亡・回収・消滅・蘇生履歴は死亡地点、ターン、原因、当時の装備と所属を含めてプレイヤー状態へ保存する。
- キャラクターモーダルは `キャラクター / 部隊 / 死体回収 / 死亡者一覧` を持つ。回収済み死亡者の再配置とフィールド上の死体に対する蘇生は、`reviveV39Unit` の共通復活処理を使用する。
- 部隊長が死亡した場合は同部隊の生存者からLv、指揮、ID順で後任を選ぶ。統治者と拠点担当者も生存候補へ引き継ぎ、候補がいなければ空席にする。
- 蘇生スキルは `スキル一覧.json` の構造化列だけを参照する。`効果` に `蘇生_Lv-N` がある場合、同じマスの自軍死亡者を対象とし、対象LvをN低下させる。低下後Lvが0以下なら蘇生せず、HPも回復しない。成功時だけ状態を生存へ戻し、現在HPを `回復` 列の値にする。射程、AP、魔法の発動待機、CTは通常のスキル処理と同じ規則を使う。
- 管理タブの `国家・外交` は `体制.json / 外交姿勢.json / 組織.json` から選択肢を生成し、安定IDをプレイヤー別 `nationPolicy` に保存する。JSON上に数値がある項目だけ補正として集計する。
- 他プレイヤー勢力への攻撃には宣戦が必要。宣戦時は外交評価を20ターン `-20` とし、関係ペアへ宣戦者・開始ターン・停戦ターンを保存する。双方の種族クラス分類が `魔族` の場合は宣戦要求と評価低下を免除する。
- 勢力ペアは友好度 `-100～100` と友好・中立・敵対区分を持つ。親善は1ターン1回、宣戦・停戦でも友好度が変化する。不可侵条約、交易協定、同盟は必要友好度と期限を持ち、解除履歴も同じ勢力ペアへ保存する。
- 交易協定中は双方の選択拠点へ毎ターン暫定交易収入を加え、友好度も上昇する。`isPlayer:false` の国家AIは友好度、戦争状態、有効条約から宣戦または条約締結をターンごとに判断する。閾値、条約期間、収入は共通暫定設定を使用する。
- 都市規模以上の所有拠点は `都市.json` の通常候補から条件を満たす専門化を1つ選ぶ。農業・産業・交易は産出、軍事・城塞は防衛、魔法・信仰・学術は住民状態へ暫定補正を加える。レア都市特性は専門化と別枠で決定的に付与し、名称・条件は `都市.json`、未定義の補正値だけを共通暫定設定とする。
- 視界内の他プレイヤーユニットはフィールドへ表示する。未宣戦勢力を選択しても攻撃を開始せず、未宣戦勢力が範囲に含まれた場合も現在はダメージ対象外とする。
- 部隊タブのユニット作成は、`クラス.json` の `種類=職業 / 条件Lv=初期` を候補にし、軍事Lv、`勢力.json` の種族別ヒーロー・軍隊上限、種族人口、資源を検証する。軍事Lvは初期Lv1とし、拠点の軍事Lvと軍事研究の現在Lv（完了項目最大Lv+1）の高い方を使う。生成名は `種族名 + クラス表示名 + 軍隊時のみ「軍」+ 連番` とし、クラス表示名は `ルビ`、未設定時は `名前` を使う。軍隊ユニットはフィールド上のキャラ画像右上に `combatProfile.memberCount` の編成人数を数字で表示し、旧データは `populationCost` を代用する。作成種別の表示名、必要軍事Lv、人口消費、HP倍率、攻撃回数、簡易行動限定、表示順は `都市基本データ.json(分類=ユニット作成)`、通常軍隊の軍事Lv別補正は `v39-gameplay-balance.js` の `V39_MILITARY_UNIT_LEVEL_BALANCE` を正本とする。現行はLv1・Lv2ともarmy行の基本値を維持する。クラスJSONの固定装備を持たせる。拠点規模とヒーロー上限補正は `施設.json(分類=拠点規模)` の `規模Lv / 規模下限人口 / ネームド上限` を共通参照し、JSONにない規模段階をコード側で補わない。
- ユニット作成資源は `消費量.json(種別=ユニット作成, Lv=1)` を正本とし、現行は1体につき穀物・野菜・肉・木材・石材・鉄を各2消費する。複数作成時は個数倍する。
- 作成は初期Lvに応じた訓練予約として受け付け、人口・資源を受付時に消費する。全勢力ターン一巡ごとに訓練EXPを加算し、完了後に作成拠点へ配置する。教官は自領内の現在クラスが訓練対象と同じ生存キャラから明示的に設定する（前提職の一致だけでは不可）。領土外などは候補を暗く表示し選択不可。通常の経路・AP消費で施設へ移動し、到着後に現教官と交代する。移動中も訓練は継続する。指導した教官も暫定25EXP/Tを1ターン1回受け取る。予約もユニット上限に含める。計算値は `V39_RECRUIT_TRAINING_BALANCE`、詳細は `施設上位クラス徴兵ルール.md` を参照。
- 同時訓練は1施設につき1ユニット。同じ施設の増設で並行数が増える。施設なしの基礎職は拠点共通3枠。予約順で割り当て、超過は順番待ち、完了した枠は次ターンから次の予約を進める。使う施設の教官のみ効果を適用し、待機中はEXPを増やさない。訓練後の総合Lvを選択可能。基礎職は人族3〜10、亜人・魔族3〜20、上位職は前提職込みの最低Lv〜既存成長上限。訓練時間と生成時の能力へ反映する。
- シミュレータモーダルでは、開拓進行、不満度、災害率の簡易試算ができる。

## 12. セーブ・ロード・マルチ

- v39のゲーム設定からJSONをダウンロード・読込できる。形式名は `fantasy-strategy-v39`、現在のバージョンは `4`。旧v39セーブは段階移行関数を通し、参加者・担当勢力・ローカルターン順がない旧状態を `local-1` が既存全勢力を担当するv4形式へ変換する。
- 開発サーバーまたは `teston` ビルドでは画面右上に緑文字だけの使用メモリ表示を出し、通常の本番ビルドでは生成しない。
- 表示設定のテストモードをONにすると、下部操作UIの通常タブ列へ独立した `テスト` タブを表示する。管理タブ内の旧 `テスト操作` 入口は使用しない。テスト画面の `選択マスの拠点情報 / フィールド / 拠点・資源 / キャラクター / テストスキル / 敵AI診断 / 拠点技能・研究 / 選択領土` は各項目ごとに独立して `▷ / ▽` で折りたたみ・再展開でき、開閉状態は画面更新後も保持する。選択マスについて、所有拠点は所属領土から拠点を解決し、一般村は7マス範囲、敵巣は縄張り内から関連拠点を解決して、所有者・種族・人口・規模・軍事Lv・備蓄・守備・縄張り等の確認情報を表示する。あわせて、選択マスの強制噴火、溶岩進行、1ターン進行、拠点資源・人口、選択キャラクターのLv・HP・AP、拠点技能Lv、選択研究EXP、選択領土HPを手動変更できる。敵AI診断では敵を切り替え、現在の判断と理由、好戦性、索敵、認識標的、攻撃候補、巣、縄張り、追跡限界、逃走、前回行動、発動待機、CTを確認できる。敵がいるマスを選択した場合は該当敵へ自動で切り替える。テストモードOFFでは `テスト` タブを表示せず、操作関数も実行しない。

- 初期のテストスキルは `TEST_即死` と `TEST_蘇生`。即死はテスト専用効果として命中・防御・ガードを無視し、対象の現在HPを0にして通常の死亡・死体処理を通す。蘇生は既存の `蘇生_Lv-* ` 処理を再利用し、`蘇生_Lv-0`・十分大きい回復値によりLv低下なし・最大HPまで復帰させる。
- 強制噴火は選択した陸地マスを山岳・休火山状態へ揃えてから噴火させる検証専用処理とし、同時に無関係なランダム噴火を発生させない。
- 描画負荷の基準は、60×60マップ、味方40体、敵40体、溶岩120マス、同時エフェクト6個をWebGLで表示した状態で30FPS以上とする。`npm run benchmark:render` で各レイヤーと全体を測定する。
- v39セーブは全プレイヤー状態、共通ワールド状態、マップ、フィールド設定、選択タイル、カメラ位置・倍率を保存する。

- マップ内の `Set / Map` は型情報付きで保存し、川・火山・溶岩データを欠落させず復元する。

- v39通信ルームは `lobby -> setup -> playing` の開始遷移を持つ。ホストの `ゲーム開始` は、ホスト権限・全員接続済み/準備完了・共有ゲーム設定・担当勢力をサーバーで確認した後、ホストへ既存v39ワールド生成を要求する。生成後は既存v39セーブ形式を利用した初期フルスナップショットをサーバーへ送り、参加者へ同じマップ・ゲーム状態を配信する。ゲーム開始後の新規途中参加は現時点で拒否し、既存参加者の再接続ではサーバーが保持する最新スナップショットを再送する。移動・攻撃・建設・研究・ターンなどゲーム開始後の操作同期はまだ未実装。Render等のサーバー再起動後はメモリ上のルームとスナップショットを保持しない。

## 14. 経験値システム（2026-09-24更新）

- キャラクターは `exp / totalExp` を保持し、`totalExp` を基準に総合Lvを自動再計算する。現行実装上限はLv120。
- 次Lvまでの必要EXP:
  - 人族: Lv15未満 `175 + Lv×50` / Lv15以上 `150 + Lv×80`
  - 亜人: Lv15未満 `150 + Lv×50` / Lv15以上 `150 + Lv×80`
  - 魔族: Lv15未満 `100 + Lv×50` / Lv15以上 `200 + Lv×100`
  - 上記以外は互換用として亜人テーブルの110%を使用する。
- 戦闘EXPは撃破時だけに付与せず、敵対対象の実HPを削った割合で発生する。
- 対象1体のHPを100%削った時の総EXPは `基準EXP × 対象Lv × 対象種族倍率`。現行のプレイ調整用暫定値は基準EXP15、人族1.0、亜人1.25、魔族1.5、その他1.0で、`V39_UNIT_EXP_BALANCE` を変更して調整する。
- 1回の攻撃で得るEXPは `対象1体分EXP × 実HP減少量 / 最大HP`。ガードで吸収された値、Miss、現在HPを超えるオーバーキル分は含めない。
- 同じ対象を回復させて繰り返し削るEXP稼ぎを防ぐため、1体から支払う累計EXPは最大HP100%ぶんまでとする。
- 通常部隊では発生したEXPプールをその部隊の生存メンバーへ均等分配する。単独枠では攻撃者1人が全量を受け取る。
- Lvアップ時は既存のキャラクター派生計算を再実行し、能力値・技能・取得スキルを新Lvへ合わせる。HPはLvアップ直前の最大HP比率を維持する。
- 蘇生でLvが低下した場合は、低下後Lvの開始EXPへ揃えて、次のEXP獲得で即座に旧Lvへ戻らないようにする。
- 部隊タブではユニットアイコン外周を円形EXPゲージとして表示する。現在Lvに必要なEXPへ到達して一周するとLvアップし、次Lvのゲージへ切り替わる。
- EXP獲得量とLvアップは戦闘ログへ記録し、Lvアップ時は `v39:unit-level-up` イベントを発行する。

- 戦闘以外のユニットEXPは、調査・研究の実進捗から担当者本人への付与を接続済み。建設・領土化・外交・訓練の付与接続は未実装。調整値は `V39_UNIT_EXP_BALANCE`、計算は `v39-unit-experience.js` を正本とする。
- 調査は開始地点の地形JSONの開拓難易度・高度から総EXPを固定し、投入APの進捗差分でターン終了時に付与する。索敵範囲内のマス数でEXPを倍増しない。脅威度の正式な入力元は未接続のため、現行は既存計算関数の既定値0を使用する。死亡・移動・別ワールドへ移った場合は未処理分を付与せず中断する。開始時の対象範囲は地下追加視界も含め固定する。
- 研究は対象研究の実進捗差分だけを付与し、完了を超える分はユニットEXPに含めない。研究の持越し値は従来どおり保持する。担当者本人へ付与し、部隊分配しない。行動別の小数EXP、調査の付与済みAP、研究の処理済みターンはセーブに保存し、再処理で二重付与しない。Lvアップは共通能力再計算とHP比率維持を使用し、Lv不変時はHPを変えない。
- 基本EXPは戦闘15、調査10、建設10、研究10、領土化15、外交15、訓練3。
- 共通式は `基本EXP × 難易度倍率群 × 成果率`。標準ターン倍率=`1+(元ターン-1)×0.5`、開拓難易度倍率=`1+(開拓難易度-1)×0.2`、脅威度倍率=`1+脅威度×0.5`、高度倍率=`1+max(0,高度Lv)×0.05`、汎用難易度倍率=`1+(難易度Lv-1)×0.25`。
- 建設EXPは `10 × 標準ターン倍率 × 汎用難易度倍率 × 進捗率`。元ターンは `施設.json` の短縮前 `建築時間` を使い、研究・技能等で実時間が短縮されても総EXPは減らさない。
- 調査EXPは `10 × 標準ターン倍率 × 開拓難易度倍率 × 脅威度倍率 × 高度倍率 × 進捗率`。現行の標準調査時間は1Tで、将来短縮処理を追加してもEXPは短縮前ターンを参照する。
- 領土化EXPは `15 × 開拓難易度倍率 × 脅威度倍率 × 高度倍率 × 進捗率`。
- 研究EXPとユニットEXPは別管理。研究担当者のユニットEXPは `10 × max(1,必要研究EXP/100) × (1+(研究Lv-1)×0.5) × 進捗率`。現行必要研究EXPでは100%完了時にLv1=10、Lv2=30、Lv3=80、Lv4=200。
- 外交EXPは `15 × 汎用難易度倍率 × 成果率`、訓練EXPは `3 × 汎用難易度倍率 × 成果率`。
- 複数ターン作業は短縮前の標準難易度から総EXPを決め、各ターンの実進捗割合で分割する。短縮で1ターンの進捗が増えればそのターンのEXPは増えるが、完了までの総EXPは変わらない。

### 身体武器
- 角・牙・爪・尾・翼などは、種族・取得クラスの対応値の最大値÷10を身体武器Lvとして扱う。正の値を持つ身体武器は行動へ表示し、同名スキルとの重複を除く。
- 身体装備の基礎威力・ガードへLv1=1倍、Lv35=2倍、Lv50=3.5倍の連続補間倍率を掛ける。小数Lvも有効。Lv50超は暫定で3.5倍。APと攻撃回数は装備JSONの基礎値を維持する。
- 詳細と調整値は `CHARACTER_STATUS_RULES.md` の「身体武器」を参照。通常装備の品質倍率は変更しない。

### 強敵動物のクラス追加
