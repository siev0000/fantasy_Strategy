# 現状ゲーム仕様メモ

最終整理: 2026-09-14

## このメモの位置づけ

- このメモは、現行リポジトリ内の実装・データ・既存ドキュメントを突き合わせて整理した「今ある仕様」のまとめ。
- 将来案や未接続要素も一部含むが、なるべく「画面やコードで確認できるもの」を優先している。
- 迷う箇所は `実装済み` / `暫定` / `未実装` の温度感で読む前提。

## 1. 今のゲーム全体像

- ヘックスの島マップ上で、勢力の初期設定、村配置、領土運用、ユニット管理、索敵、奇襲、毎ターン経済処理を回すファンタジーストラテジー。
- 現在の主なプレイ導線は `ゲーム開始設定 -> 統治者作成 -> 初期村配置 -> マップ探索/内政/ユニット運用 -> ターン進行`。
- 研究ツリー、簡易戦闘、計算シミュレータは補助UIとして存在する。
- オンライン要素は現状 `簡易戦闘ルーム` が中心で、ワールドマップ全体のネットワーク同期は未接続。

## 2. ゲーム開始フロー

- ゲーム開始時に `プレイヤー数` と `別勢力数` を設定できる。
- 合計勢力数は最大 `8`。
- 初期配置方式は以下の3種類。
  - `全勢力ランダム`
  - `プレイヤーのみランダム`
  - `プレイヤーは手動選択`
- 各勢力は順番に `種族 -> クラス -> 統治者名 -> 村名` を設定する。
- プレイヤー選択種族は現在以下の8種。
  - 只人
  - エルフ
  - オーガ
  - ゴブリン
  - 竜人
  - 悪魔
  - 天使
  - ヴァンパイア
- 統治者は自動生成され、初期レベルは `Lv5〜10`。
- 初期村はマップ上に別途配置する。手動配置モードではクリックしたタイルに村と統治者が置かれる。
- 初期村は中心と周囲1マスの合計7マスがすべて通行可能な内陸だけに配置できる。海・湖・火山・溶岩、他勢力領土、他勢力ユニット、敵を含む候補は選べない。
- 別勢力も同じデータ構造で作られ、ローカルのテスト用に勢力を切り替えて確認できる。
- プレイヤー所有データは `players[]` の各要素にある `factionState` へ保持し、画面は `activePlayerId` に一致するプレイヤーのユニット・部隊を参照する。複数プレイヤーのユニットを単一のトップレベル配列へ混在させない。
- ゲーム状態の取得APIは部隊員ID、村施設、装備、死亡履歴を含む入れ子データも複製して返す。状態変更は取得値の直接変更ではなく、必ず共通更新APIへ渡して確定する。
- 1プレイヤーの共通型は `frontend/src/lib/player-state.js` で生成する。`factionState` は都市、ユニット、部隊、回収済み死亡者、選択状態、配置・移動状態、勢力ログ識別子、接敵移動停止、索敵状態、研究状態を必ず持つ。スキーマ正本は `config/player_state_schema.json`。
- 現在のv39画面に表示するテスト編成は、ローカル確認用の `data/source/export/json/テストゲーム状態.json` から読み込む。このテストデータは通信・セーブデータとは区別する。
- テストJSONではプレイヤー、所属部隊、配置座標、種族、クラス、Lv、装備、現在HP率、現在AP、土地の選択条件を指定する。HP・基礎ステータス・技能・取得技は `クラス.json`、技詳細は `スキル一覧.json`、装備性能は `装備.json`、土地性能は `地形.json` から生成する。
- データ設計上は `data/source/export/json` 内の全JSON・全レコードを正本とし、同じ仕組みの種類追加はJSONへデータを追加するだけで行える構成にする。コード側へ種類名、数値、選択肢を重複定義しない。現在残っている個別importや固定配列は `docs/DATA_DRIVEN_RULES.md` に従って移行する。

## 3. マップ・地形

- マップは `pointy-top` のヘックス。
- 表示基準は `1280x720`。
- ワールドラップは ON/OFF 切り替え可能。
- 島形状プリセットは以下を実装済み。
  - 標準諸島
  - リアル島
  - 大陸型
  - 多島海
  - 双子島
  - 列島型
- 地形生成は概ね `海 -> 陸地 -> 高度 -> 山/丘/平地 -> 森/砂漠 -> 湖 -> 川` の順で構成される。
- 基本地形:
  - 平地
  - 森
  - 丘陵
  - 山岳
  - 雪原
  - 火山
  - 河川
  - 湖
  - 海
  - 砂漠
- 特殊地形:
  - 沼地
  - 洞窟
  - 峡谷
  - 溶岩
- 地形ごとの産出量、危険度、開拓難易度、災害相性は `地形.json` ベースのデータ駆動。
- 山岳の20%を休火山候補とし、各ターン1%で噴火して恒久的に火山へ変化する。噴火率は現在 `map-generator.js` の地形生成設定を正本とし、`地形.json` の災害値との合成は未接続。
- 火山からの溶岩は1ターン最大3マス、低い高度を優先し、進行方向38度以内を維持する。各マス35%で停止し、川・海・湖へは進入しない。冷却処理は未実装。
- 休火山・火山・溶岩流路・発生ターン・停止理由はワールド共通状態へ保存し、ターン処理済み番号で重複実行を防ぐ。セーブ・ロード後も処理済みターンは再実行しない。地形更新時もカメラ位置と選択を維持する。
- 溶岩は通常通行不可。炎耐性100以上または耐熱能力持ちだけ通行できる。ターン終了時、溶岩上の敵味方へ `ceil(最大HP × 10% × (1 - 炎耐性/100))` のダメージを与え、HP0なら通常の死亡処理へ渡す。
- 土地タブには休火山/活動火山、噴火率、溶岩接触、直近発生ターンを表示する。溶岩被害はキャラクター上のダメージ値とHPバー、ターン通知、対象プレイヤーの活動ログへ対象名と被害値を表示する。
- Fog of War あり。未探索/非可視タイルは隠れる。
- 強敵候補や特殊地形は設定で常時表示を切り替えられる。
- 初期拠点配置後、`出現敵.json` の出現地形・Lv範囲と `クラス.json` の定義が一致する敵だけをフィールドへ生成する。
- 初期拠点から4マス以内には敵を生成しない。拠点から10マス以内の敵はLv10以下に制限する。
- 敵数は出現可能タイル120マスにつき1体を基準に、8～30体へ収める。マップ寸法と拠点座標から決めた乱数列を使い、同条件では同じ初期配置になる。

## 4. 領土・村

- 村を設置すると、村中心と隣接6マス（半径 `1`）のうち、海・湖・火山を除く通行可能タイルが自領になる。他勢力が所有済みのタイルは上書きしない。
- 村中心は施設「拠点」かつ土地状態「拠点」、周囲の取得タイルは土地状態「領土」として保持する。
- 村は以下の要素を持つ。
  - 人口
  - 種族別人口
  - 食料在庫
  - 資材在庫
  - 都市能力
  - 建物
  - 人口許容
- 初期人口は勢力データの `初期人数` を参照する。
  - 例: 人間50、エルフ50、ゴブリン90、竜人15、悪魔5 など
- 初期食料・初期資材は、村中心予定地とその周辺領土の産出をもとに算出し、開始時に `3倍` した値を在庫として持つ。
- v39でも人口・在庫・都市能力・施設・建設キューを `players[].factionState.village` に保存し、プレイヤー切替時に混在させない。
- 村規模は人口で自動変化する。
  - 村: 〜159
  - 町: 160〜259
  - 都市: 260〜419
  - 大都市: 420〜
- ネームド上限は規模連動。
  - 村: 2
  - 町: 4
  - 都市: 7
  - 大都市: 10
- 領土タイルは `資源化` と `居住化` を持ち、`2ターン` で切替できる。
  - 資源化: 産出 `2.0倍`、人口許容 `+5`
  - 居住化: 産出 `1.0倍`、人口許容 `+15`
- 村中心タイルは常に居住化扱い。

## 5. 経済・ターン処理

- 現在の村経済処理は概ね以下の順。
  1. 領土収入
  2. 建物収入
  3. ユニット維持食料消費
  4. 村人口食料消費
  5. 不足判定
  6. 人口増減
  7. 人口許容超過の切り詰め
- 食料カテゴリ:
  - 穀物
  - 野菜
  - 肉
  - 魚
  - 死体
  - 魂
- 資材カテゴリ:
  - 木材
  - 黒木
  - 特木
  - 石材
  - 鉄
  - 銀鉄
  - 青金鋼
  - 赤黒鋼
  - 金
  - 銀
  - 宝石
- 食料不足時は、他食料を `1.2倍換算` で代用消費する。
- 経済は現状 `0.1倍スケール` の簡易計算で回しており、コストと収入は暫定値。
- 不足ペナルティはログ表示まで実装されているが、大きなイベント化はまだ未接続。
- v39ではターンごとに全プレイヤーの領土収入、ユニット維持、人口消費、不足、人口増減を処理する。`lastEconomyDelta.turn` が同一の場合は再処理せず、同じターンの二重収入を防ぐ。
- 上部資源表示は固定サンプル値を使わず、操作中プレイヤーの食料・資材在庫と直前ターン増減を参照する。

## 6. 都市能力・建設

- 村には以下の5能力がある。
  - 鍛冶場
  - 魔法
  - 信仰
  - 軍事
  - 経済
- 内部定義は `Lv7` まで持てるが、現在の有効上限は `Lv4`。
- 経済Lvは収入倍率に反映される。
  - Lv1: 1.00
  - Lv2: 1.15
  - Lv3: 1.30
  - Lv4: 1.50
- v39の建設候補は `施設.json` のうち都市規模行を除く25施設を表示する。施設名、説明、地形条件、建築時間、研究条件、資材コストはJSONを正本とする。
- 同じ建物の重複建設は不可。
- 都市規模に対応する `施設.json` の `建築数` を施設枠上限にする。
- 建設開始時に資材を一度だけ消費し、`建築時間` のターン数を建設キューで進める。完了時に都市と対象土地の施設一覧へ反映する。
- 研究条件は各系統で、そのLvの全研究項目が完了したLvを参照する。施設の数値効果列は完成施設から参照し、`影響範囲=全体` は都市全体、`単体マス` は設置マスだけへ適用する。
- 施設による正の資源産出倍率は `1 + (生産力 + 資源カテゴリ技能) / 100`。穀物・野菜・肉は農業、魚は漁業、木材類は林業、鉱石・貴金属類は工業を参照する。負の産出には増産倍率を掛けない。
- 施設の `回復` は所有マス上の生存ユニットのターン回復率へ、`索敵` は所有マスからの索敵範囲へ反映する。領土を失った施設は索敵源にならない。

## 7. ユニット・成長

### フィールド画像

- 敵は `assets/images/illust` の画像を使用し、`画像`、画像名、敵名、種族名、クラス名の順で対応画像を検索する。
- プレイヤー側ユニットは `assets/images/units/<種族名>` の画像を使用する。基本ファイル名は `<種族名>_<クラス名>`、只人のみ `<クラス名>` も使用でき、種族・クラス画像がない場合は種族画像を使用する。
- 対応する敵・ユニット画像がない場合は `assets/images/アイコン` の画像で代用する。
- 拠点は旧描画仕様と同じく `村.webp`、`町.webp`、`都市.webp`、`大都市.webp` を使用する。表示サイズは順に `60px`、`57px`、`66px`、`78px`。拠点レベルが未設定なら村として描画する。

### 領土・索敵表示

- 操作中プレイヤーの領土は、同じ領土同士が接する辺を描かず、領土全体の外周だけを勢力色で表示する。
- ユニットの索敵範囲は基本1マスで、技能の索敵値75ごとに1マス増える。拠点は周囲1マスを索敵する。
- 現在の索敵範囲は、範囲全体を塗らずに外周だけを薄水色の線で表示する。
- 一度も索敵していないマスは暗く覆い、発見したマスはプレイヤーごとの `factionState.visibility.exploredTileKeys` に保存する。
- 敵は現在の索敵範囲内にいる場合だけフィールドへ表示する。
- 敵・他勢力画像は現在視界内と判定した後にだけ読み込み、通常の戦闘エフェクトもFog内では生成しない。テスト・強制演出だけ `allowInFog` を明示して例外化する。
- 60×60の描画負荷は `npm run benchmark:render` で地形、Fog、陣地、索敵、キャラ、敵、エフェクトを個別計測し、結果を `artifacts/v39-render-layer-benchmark.json` へ出す。

- ユニット区分は以下。
  - 統治者
  - ネームド
  - モブ
  - 軍隊ユニット
  - 強化軍隊ユニット
- モブ上限は `人口 / 10`。
- 軍事Lvによって高位生成モードが解放される。
  - Lv1: 個体ユニット
  - Lv2: 軍隊ユニット
  - Lv3: 強化軍隊ユニット
- 軍隊ユニットは人口消費つきで、HP倍率と攻撃回数が増える簡易軍勢表現。
- 通常の個体ユニットは人口消費なし、軍隊ユニットは `1体あたり4人`、強化軍隊ユニットは `1体あたり5人` を消費する。
- 通常モブは `Lv5` 固定で生成される。
- 非人族は総合Lvに応じて `種族Lv` と `クラスLv` が交互成長する。
- 人族は `クラスLv` のみ成長する。
- 人族は `Lv10以上` で第2クラス設定が可能。
- モブはネームドに昇格できる。統治者は最初からネームド扱い。

## 8. 部隊・装備

- 部隊は `1リーダー + 最大4名` の計 `5名` まで。
- 同じ座標にいるユニットだけ部隊化できる。
- 部隊の索敵は高い索敵値を主軸に使い、隠密は全員合算を人数補正して使う。
- モブのみ削除可能。削除時は部隊情報も整理される。
- 装備スロット:
  - 武器1
  - 武器2
  - 頭
  - 体
  - 足
  - 装飾1
  - 装飾2
- 装備変更時は村の資材を消費し、鍛冶場Lv・魔法Lv・信仰Lvが必要条件になる。
- 魔法系装備は魔法Lv、信仰系装備は信仰Lvも満たす必要がある。
- ネームド/ヒーロー系ユニットは個別装備変更UIの対象。
- モブは個別装備編集を行わず、クラス固定の装備プリセット参照を基本とする。
- モブ装備はアイテム一覧モーダルに表示しない。
- モブで許可する装備更新は「レア度一新」のみとし、実行時はユニット作成時と同等の素材消費を行う。
- v39の装備画面は、プレイヤーごとの村装備在庫を正本とし、一覧・キャラ装備・生成を切り替える。装備一覧はネームド/統治者の装備済み数と村の残数を `E数 / 残数` で示す。
- 装備生成費は `消費量.json(種別=装備, Lv)` を基礎に、`装備.json` の `木材 / 鉱石` 倍率を掛ける。品質はコモン～レジェンダリーを鍛冶Lv1～5へ対応させる。
- 防具の物理・魔法耐性は `装備.json` の耐性、品質倍率、`消費量.json` の `防具_物理 / 防具_魔法` を合成し、装備変更直後に再計算する。
- v39の付与画面は `付与.json` から対象装備に適用可能な候補を生成し、鍛冶/魔法/信仰/軍事/経済LvをAND条件で検証して `消費量.json(種別=付与)` の素材を消費する。
- 武器付与は最大3件かつ付与Lv合計を装備品質Lv以下とする。付与の能力値、耐性、威力、ガード、Cr、射程、攻撃属性は装備派生値と共通戦闘処理へ反映する。付与済み装備は付与構成ごとに別在庫として扱う。
- 付与の1ターン当たり実行回数は未確定で、現在は素材と必要Lvだけを制限に使う。

## 9. 探索・索敵・移動

- マップ上のユニットは移動力を持ち、ターン開始時に回復する。
- 下部の移動と攻撃は同時に選択できず、同じボタンの再押下またはEscapeで解除する。待機は選択ユニットの残APを0にして、そのターンの行動を終了する。
- 海/湖には通常移動できない。
- 敵・他ユニットのいるマスへの進入と通り抜けは不可。選んだ目的地へ到達できない場合は、現在APで目的地に最も近い到達可能マスを手前の停止位置として提示する。
- 選択タイルに対して `調査` と `奇襲` を実行でき、どちらも移動力 `3` を消費する。
- 調査は敵発見処理を強める行動。
- 奇襲は対象マスのモンスター敵を撃破し、危険度低下や領地化を起こす。
- 接敵時は移動停止や接敵ロックが発生する。
- 地図はマウス/タッチのドラッグ、ホイール、ピンチ、ダブルタップに対応する。入力欄以外では矢印キーでカメラ移動、`+/-` で中央基準ズーム、Enterで中央タイル選択を行う。
- ユニット、敵、拠点の画像が見つからない場合は、名称や種類名をマスへ書かず共通記号へフォールバックする。

## 10. ターンイベント

- v39フィールド右上の `ターン終了` から手動でターンを進める。自動ターン進行は現状 OFF。
- ターン番号と停止状態は共通ゲーム状態 `timeline` で保持する。
- ターン開始時は生存ユニットの共通APを最大値まで回復し、死亡者は回復対象外とする。
- v39のターン解決順は `ターン開始(AP回復) -> 地形イベント -> AI命令 -> 調査 -> ワールド住民 -> 経済・建設 -> 研究 -> 外交 -> 生存者HP回復 -> ターン完了` とする。生存者の基礎HP回復は最大HPの5%、死亡者は回復しない。
- ターン進行では選択タイル、選択ユニット、カメラ位置、ズームを変更しない。
- `停止 / 再開` は実秒ベースの待機、CT、効果時間、敵AIを止めるための状態とし、手動ターン終了は禁止しない。
- ターン経過と停止・再開はフィールド上部のテロップで通知する。
- v39ターン処理は地形、調査、ワールド住民、経済・建設、研究、外交、回復を一括実行し、完了後の状態変更で索敵表示を更新する。

## 10.5 フィールドHUD（資源サイドバー）

## 11. 研究・戦闘・補助UI

- `地形.json` のHP・攻防・速度・命中・技能などの数値補正は、基礎値を保存し直さず現在地から戦闘時に加算する。敵味方・反撃・外部ダメージAPIで同じ処理を使い、土地詳細、部隊詳細、ダメージ計算ログへ補正理由を表示する。

- 研究ツリーUIは以下の5系統を表示できる。
  - 鍛冶Lv
  - 魔法Lv
  - 信仰Lv
  - 軍事Lv
  - 経済Lv
- v39研究は `研究.json` の5系統・全項目を表示し、プレイヤーごとに選択項目、担当ユニット、項目別EXP、Lv別完了、カテゴリ別繰越EXPを保存する。
- 各カテゴリで研究中にできる項目は1件。担当ユニットのLvが必要Lv以上で、前Lvの全項目が完了している場合だけ選択できる。100%到達時は完了表示へ変わり、超過EXPを同カテゴリへ繰り越す。
- 必要EXPは `100 × 2^(研究Lv-1)`。ターン終了時の獲得EXPは `floor(10 × (1 + 対応技能/100))` とし、死亡・不在の担当ユニットは進行させない。魔法系統の対応技能は `魔法技術`、現行キャラクターデータでは `魔術` を代替参照する。
- 研究項目IDは `カテゴリ:Lv:項目名` とし、JSONの行追加や並べ替えで保存参照が変わらないようにする。
- 研究完了による施設・装備・ユニットの解放は、`研究.json` に解放対象IDが未定義のため未接続。
- マップ生成時、`地形.json` の資源・回復値からレア資源候補を抽出し、通行可能地形の約2%へ未発見地点として決定的に配置する。未発見地点はワールド共通、調査結果はプレイヤー別に保存する。
- 選択キャラクターが同じマスにいる場合、土地タブから1ターンの調査を開始できる。完了時は危険度を低下させ、金山・銀鉱脈・宝石脈・薬草の群生地・水脈などを発見するか異常なしになる。
- 発見済み地点が自領なら `地形.json` の産出を通常土地収入へ加算する。回復値がある発見地点上では、通常5%に地形回復率を加えたHPをターン終了時に回復する。調査のAP/移動力消費は未確定のため現在はターン占有だけを適用する。
- 中立一般村と放浪者はプレイヤー所有データへ混在させず、ワールド共通の `neutralVillages / wandererGroups` に保存する。一般村の種族・初期人口は `勢力.json`、初期クラスは `クラス.json` から決める。
- 放浪者は通常の都市・部隊と分けた裏データとして通行可能な隣接マスへ毎ターン移動し、生存中のプレイヤーユニットと同じマスに入った場合だけそのプレイヤーへ表示する。
- 発見済み放浪者は同じマスから勧誘できる。成功率は基本50%、同種族+20%、異種族-20%、幸福度条件達成時+10%。成功時は30～70%が種族別人口へ加入し、失敗時は10%が離散する。属国条件、依頼、襲撃は未確定。
- 活動ログはプレイヤー別に最大300件を保存し、管理のログ画面へ新しい順で表示する。戦闘、地形被害、建設、研究、調査、ターン経過を同じ保存口へ集約する。
- 戦闘モーダルは別系統の簡易バトル。
  - 通常攻撃
  - 種族スキル
  - ターン終了
  - リセット
- この戦闘はマップ戦闘の本実装ではなく、単体の戦闘テスト/デモ寄り。
- v39フィールドの攻撃は、選択キャラクターの装備武器と `行動A` の技を同じ処理へ渡す。装備武器も単体の通常攻撃として表示する。
- 取得済みの `行動P` は攻撃時に条件照合する。`攻撃手段` 指定は同じ手段、`条件系統` 指定は同じ属性、`ガード時` は反撃時だけ、能力値・威力補正を敵味方共通計算へ一時適用する。
- 攻撃APが足りない候補は薄く表示して選択・実行不可にする。射程未記載は1、武器攻撃は武器射程、範囲未記載は単体、炸裂未記載は0とする。
- 攻撃位置選択中は射程を黄色、通常の攻撃範囲を赤、炸裂の小数ダメージ範囲をオレンジで表示する。
- ダメージは敵味方で同じ式を使う。`(計算威力 - Lv/10×耐性値) / (1 + 防御値/100) × 乱数0.4～0.5 × (1 - 耐性割合)` を各攻撃回数ごとに計算する。魔力判定は精神、それ以外は防御を参照し、同士討ちはさらに半減する。
- 戦闘ログは攻撃者、使用技、各ヒット値、合計値、消費APを表示し、計算詳細を内部データとして保持する。命中・回避式が未確定のためMiss判定は未実装。
- 攻撃エフェクトは `アニメ` を参照し、攻撃技の未記載時は `斬撃`。回復・強化などの支援技は未記載時に斬撃を出さない。1画像の再生時間はフレーム枚数に関係なく4秒、`:` 区切りは10ms間隔で順番に再生し、炸裂0.5なら基準の1.5倍にする。
- 魔法は対象決定とAP消費後、停止可能なゲーム内時間で最低6秒待ってから発動する。JSONの `待機`、`CT`、`効果時間` も同じ実秒時計で管理し、発動中の技名と期限をユニット別戦闘状態へ保持する。
- 好戦的な敵は自分の索敵範囲で生存中のプレイヤーユニットを発見し、12秒ごとに射程内で使用可能な行動Aから、敵IDと行動回数を種にした決定的疑似乱数で1つ選んで攻撃する。射程内に技がなければ対象へ近づき、移動不能なら待機する。敵もAP、待機、CT、同じダメージ式、エフェクト、ログを使う。
- `players[]` の `isPlayer:false` は基本勢力AIとして扱う。毎ターン、既存の人間用検証関数を通して調査1件、建設1件、ユニット生成1件、未選択の各研究系統を決定的な順序で選び、`aiState.lastProcessedTurn` で二重実行を防ぐ。
- 単体近接攻撃を受けて生存した対象は1回だけ反撃する。直前に使った近接武器を優先し、なければ装備中の近接武器または `素手 / 角 / 牙 / 爪 / 翼 / 尾 / 針` を使う。弓・銃・魔法・射程2以上・範囲・炸裂は反撃対象外で、反撃への再反撃はしない。
- 攻撃解決時は攻撃者のフィールド画像を対象方向へ8pxだけ往復させる。
- HPが0になると状態を `死亡` にし、灰色表示のままフィールドへ30秒残す。生存中の自軍ユニットが同じマスへ到達すると回収済み死亡枠へ移り、未回収のまま期限を過ぎると消滅する。死亡・回収・消滅・蘇生履歴は死亡地点、ターン、原因、当時の装備と所属を含めてプレイヤー状態へ保存する。
- キャラクターモーダルは `キャラクター / 部隊 / 死体回収 / 死亡者一覧` を持つ。回収済み死亡者は `reviveV39Unit` の共通復活処理で再配置できるが、蘇生スキル・資源消費との接続は未完了。
- 管理タブの `国家・外交` は `体制.json / 外交姿勢.json / 組織.json` から選択肢を生成し、安定IDをプレイヤー別 `nationPolicy` に保存する。JSON上に数値がある項目だけ補正として集計する。
- 他プレイヤー勢力への攻撃には宣戦が必要。宣戦時は外交評価を20ターン `-20` とし、関係ペアへ宣戦者・開始ターン・停戦ターンを保存する。双方の種族クラス分類が `魔族` の場合は宣戦要求と評価低下を免除する。
- 視界内の他プレイヤーユニットはフィールドへ表示する。未宣戦勢力を選択しても攻撃を開始せず、未宣戦勢力が範囲に含まれた場合も現在はダメージ対象外とする。
- 管理タブのユニット作成は、`クラス.json` の `種類=職業 / 条件Lv=初期` を候補にし、軍事Lv、`勢力.json` の種族別ヒーロー・軍隊上限、種族人口、資源を検証する。軍隊は人口4人・HP2.5倍、強化軍隊は人口5人・HP3倍とし、クラスJSONの固定装備を持たせる。
- ユニット作成資源は旧現行値を0.1スケールした暫定値で、1体につき穀物・野菜・肉・木材・石材・鉄を各2消費する。正式な作成コスト列はJSONへ未追加。
- シミュレータモーダルでは、開拓進行、不満度、災害率の簡易試算ができる。

## 14. 経験値システム（2026-03-27 追加）

- キャラクターは `status.exp` と `status.totalExp` を保持する。
- `totalExp` を基準に自動でLv再計算する（上限は内部で120）。
- 必要経験値（次Lvまで）:
  - 人族: `Lv < 15 => 175 + Lv * 50` / `Lv >= 15 => 150 + Lv * 80`
  - 亜人: `Lv < 15 => 150 + Lv * 50` / `Lv >= 15 => 150 + Lv * 80`
  - 魔族: `Lv < 15 => 100 + Lv * 50` / `Lv >= 15 => 200 + Lv * 100`
  - 上記以外: 亜人テーブルの `+10%`
- `totalExp` が減るとLvが下がる。スキルは下げず、能力値のみペナルティ適用。
- ペナルティ率は `penaltyLv / (currentLv + 5)`（`penaltyLv = peakLv - currentLv`）。

### 戦闘後EXP

- 勝利時のみ、戦闘参加ユニットにEXP配布。
- 基本値: `敵Lv * 50 * 敵数` を参加人数で等分。
- レベル差補正:
  - 差が5未満: 高レベル敵 `+25%` / 低レベル敵 `-25%`
  - 差が5以上: 高レベル敵 `+50%` / 低レベル敵 `-50%`
- 撃破種族補正:
  - 人族 `+15%`
  - 亜人 `+25%`
  - 魔族 `+35%`

### 表示方針

- EXP表記は `panel modal-card modal-card-wide`（キャラクター状態モーダル）内のみ表示。
- `docs/都市研究と施設ルールまとめ.md`
