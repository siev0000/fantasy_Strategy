## 研究の見直し

### 研究シートの数値列による効果定義（2026-10-12追記・未実装案）

ユーザー案: 研究シートの既存数値列へ値を記入し、研究によって生産力などが上がるようにする。研究ごとの効果・数値は原本スプレッドシートで管理し、コードは共通の適用処理を持つ方向。今回の追記では原本シート・生成JSON・ソースは変更しない。

| 列 | 適用案 |
| --- | --- |
| 農業・林業・漁業・工業 | 拠点の対応する生産技能へ加算し、既存の生産倍率式を通して資源収入へ反映 |
| 統治・交渉・魔術・信仰 | 対応技能へ補正。ただし具体的な適用先は未確定 |
| 治安・幸福度・環境安定度 | 対応する指標への補正。適用式・上限・継続の扱いは未確定 |
| 道路発展数 | 対象・単位・効果の意味を確認してから対応。未確定 |

- 提案中の解釈: `農業=10` は「農業技能+10」であり、直接の「生産量+10%」ではない。この単位はまだ確定扱いにしない。
- 空欄・0は効果なしとする案。
- 完了済み研究の定義から補正を集計し、ロード・再描画・再集計で同じ効果を重複加算しない。人口由来の基礎技能と研究補正を分けて保持する案。
- 未確定: 勢力全体の全拠点に適用するか、研究した拠点だけに適用するか。人口技能の平均に補正するかなど、既存生産式への加算位置も実装前に確定する。
- 施設解禁とは別の効果として扱う。必要研究Lvは保持し、個別研究による施設解禁方式との切替も維持する。

2026-10-12実装: 原本の「技術対象=調査」を確認し、必要研究Lv・前提研究IDを原本へ追加。6カテゴリに統合し、フローチャートと旧進捗移行を実装した。初期接続は暫定。詳細は [研究フローチャートルール.md](../rules/economy/研究フローチャートルール.md)。下記の旧5系統統合案は採用しない。

### 2026-10-12 確定・実装反映

- 担当ユニットLvによる研究の解禁制限は廃止する。
- 必要研究Lvと前提研究IDによる項目別解禁へ変更し、担当Lv不足は研究EXP効率にのみ反映する。
- 推奨Lvは既存原本列 `必要ユニットLv` から読む。数値引下げ案は採用していない。
- 暫定式・調整箇所は [都市研究と施設ルールまとめ.md](都市研究と施設ルールまとめ.md) を参照。
- 担当制廃止・人口技能への切替・行動からの研究EXPは未実装。項目別フローチャートと調査統合は実装済み。

### 旧統合案と行動EXP案（未反映・統合案は不採用）

- 研究の大分類は鍛冶・魔法・信仰・軍事・経済の5系統を維持する。
- 地質調査Ⅰ〜Ⅲは鍛冶、生態調査Ⅰ〜Ⅲと地下探索Ⅰは経済の研究項目へまとめる。
- 現行コード/JSONには地質調査・生態調査・地下探索を独立系統として追加した計8系統がある。5系統への統合はまだ行っていない。既存の研究進捗・取得済み項目の移行も必要。
- 調査・採取・洞窟探索などの行動から、対応する研究項目へ研究EXPが入るようにする。研究未選択でも蓄積し、調査は消費APに比例させ、分割調査による重複加算を防ぐ。
- 完了済み項目ではなく次段階へ加算する方向。ただし、前提条件を満たすまでは蓄積のみとし、自動取得しない。加算先・量・持越し上限・取得処理の具体化は未確定。
- 対応例: 調査→地下探索/生態調査、鉱石採取/洞窟探索→地質調査、植物/食料採取→生態調査。正式な対応表と配分は未確定。研究EXPと行動キャラのユニットEXPは別管理。
- 研究詳細の「新たに発見できる対象」の自動表示は実装済み。特産品/地形の発見条件を正本とし、研究側へ対象名を重複定義しない。

### 旧フローチャート案（接続例は不採用・人口技能方式は検討中）

- 5系統は分類として残し、取得順は項目ごとの前提研究で決める。
- 必要ユニットLvと担当ユニット選択を廃止し、拠点人口の対応技能から研究速度を算出する候補。
- 研究対象を切り替えても途中EXPを保持する。担当ユニットの頻繁な入替えが最適になる運用を避ける。
- 前提研究・研究速度式・人口の集計範囲・拠点間の研究共有/進行は未確定。
- 下記は接続例であり、正式な前提関係ではない。

```text
基礎調査
 ├─ 生態調査Ⅰ → Ⅱ → Ⅲ
 └─ 地下探索Ⅰ → 地質調査Ⅰ → Ⅱ → Ⅲ
```

## 上位クラス徴兵

### ユーザー提示の基本方針（設計上の合意・実装反映は別途）

| 項目 | 方針 |
| --- | --- |
| 施設から直接徴兵する上限 | Tier2まで |
| Tier3以上 | 直接徴兵せず、ユニットの育成・クラスアップで取得 |
| 複合クラス | 施設徴兵対象から除外 |
| 施設の単位 | 1クラス1施設ではなく、近い役割を組織・育成系統としてまとめる |

- 通常育成の提示例: Tier1 Lv10 → Tier2 → 育成 → Tier3以降。Lv10条件の適用範囲・現行クラス条件との照合は別途必要。
- 国家・都市による徴兵: 研究と施設を整えてTier2を直接徴兵し、Tier3以降は実際に育成する。
- 「暗部 → アサシン」はユーザー提示上、会話で確定済み。施設/徴兵処理への反映は未確認・未実施。

### 施設枠の候補（検討中）

| 施設系統 | Tier2候補 |
| --- | --- |
| 軍事 | ウォーリアー、ガーディアン、スカーミッシャー等 |
| 武術 | キ・マスター、ストライカー、マーシャルアーツ |
| 射撃・狩猟 | ハンター、マークスマン |
| 魔法 | アークウィザード、キャストマスター等 |
| 信仰 | ハイクレリック、エクソシスト、インクイジター |

候補の名称・Tier・複合判定は、採用前に原本「クラス」シートと照合する。列挙だけで徴兵対象にはしない。

### 解禁段階の第一候補（未確定）

- 研究Lv1=基礎解放、Lv2=分岐開始、Lv3=分岐強化、Lv4=上位特化という整理。
- 軍事/魔法/信仰などの研究Lv4で上位育成施設を解禁し、単一系統Tier2の直接徴兵を可能にする案。
- フローチャート方式を採用する場合、「研究Lv4」を段階の目安として残すか、特定項目の取得条件に置き換えるかを決める必要がある。自動的に同じ条件とは扱わない。

### 担当ユニットLvの旧比較案（現在は解禁条件にしない）

| 研究Lv | 既存資料の値 | 引下げ候補 |
| --- | --- | --- |
| 1 | 5 | 5 |
| 2 | 15 | 10 |
| 3 | 25 | 15 |
| 4 | 35 | 25 |
| 5 | 45 | 35 |
| 6 | 55 | 45 |
| 7 | 65 | 55 |

- 現行JSONでは既存5系統の項目にLv1〜4の必要ユニットLv=5/15/25/35がある。Lv5〜7は既存資料の計画値であり、本メモで実装済みとしない。
- Tier2徴兵のために担当Lv35を要求すると厳しい、という問題提起。引下げ候補は未確定。
- 前節の「担当ユニット/必要Lvを廃止」案と、この「担当制を残して必要Lvを引下げ」案は代替案。両方を確定扱いにしない。

### ディストラクターのデータ差

- 2026-10-12のローカル生成JSON確認: `クラス.json` はディストラクターの `Tire=2`、ディザスターの `Tire=3`。
- ユーザー想定はディストラクター=Tier3。今回のTier2徴兵候補にはディストラクターを入れない方向。
- 「どのTier2 → ディストラクターTier3 → ディザスターTier4」にするかは未確定。現行JSON/シートを本メモだけで変更しない。

## 次に決めること

1. 項目ごとの前提研究と、担当変更の扱い。Lvによる解禁制限の廃止は決定済み。
2. Tier2徴兵を解禁する具体的な研究項目・前提条件・施設枠。「Lv4」は現時点では候補。
3. 行動による研究EXPの対応先・配分・加算量・未解禁時の蓄積と取得処理。
4. 施設ごとのTier2対象、複合クラス除外の判定、ディストラクター系統の正式なTier構成。

担当制を廃止する場合は必要ユニットLv1〜4の数値決定は不要になるため、まず研究方式を決める。
