# NPC勢力の開始と行動

更新: 2026-10-21 / UI60。

## 開始設定

- ゲーム開始設定の「ゲーム進行」にNPC勢力数（0〜8）を設ける。新規設定の初期値は2。一般村数、操作勢力数、参加者数とは別。
- `gameSettings.npcFactionCount` として設定・セーブに保持する。古い設定や、数を渡さない内部テストの開始は0とする。
- 通常の開始種族とクラス候補からNPC統治者を生成する。初期編成はヒーロー枠の統治者1体と一般兵1〜2体。一般兵は同じ種族・基礎職の単独個体で、軍隊1駒に人数をまとめる意味ではない。既存のユニット生成・クラス初期装備・種族別初期Lvを使い、初期配置で別々のマスへ置く。
- 一般兵の数はconfig/v39-npc-faction-ai.jsonのinitialSoldiersMin/Maxで変更できる。開始時の支給で、通常の訓練キューには追加しない。既存セーブへ初期兵を再支給しない。テストの「勢力追加」は既存編成の複製用途を維持する。
- 人の初期配置後、NPCの拠点を自動配置する。配置不能なら拡大/勢力数削減の案内を出す。人の担当勢力や操作順へNPCを加えない。
- ローカルと通信ホストの開始状態生成は同じNPC生成を使う。通信ではホストの生成済み状態を配布する。

## 行動方針

- 人の操作終了後の既存AIフェーズで行動する。一般村とは別の国・拠点・部隊を持つ。
- 未発見の覇権地は目標に使わない。発見した未確保の覇権地を優先し、既存の奥地入場・攻略・退出・取得処理を使う。
- 取得した地点は確保期間中または妨害中に防衛目標とする。同じ勝利判定が人とNPCを評価する。
- 攻撃可能な敵がいるときは探索でAPを使い切らず、戦闘へ回す。対象がなければ調査・探索移動で情報を増やす。地上/奥地の座標や退出待機を混同しない。
- 訓練を建設より先に判定する。生存ユニット+訓練待ちの目標数は当面6で、`config/v39-npc-faction-ai.json` から変更可能。
- 建設候補は施設シートの前提施設・基礎優先度を使用し、防衛・探索に加点する。食料不足時は食料施設とその前提となる墓地の優先度を上げる。通常の研究・地形・費用・枠・工期を満たす必要がある。
- 同施設を際限なく増設せず、拠点の建設キューがある間は次の建設を開始しない。村と共通の前提判定は `v39-facility-development-rules.js`。

## 実行元と確認

テストON時は「テスト操作 → 診断 → NPC勢力診断」に全NPC勢力を表示する。現在プレイヤーの視界では絞らず、勢力名/種族/拠点数/生存数/訓練数/目標/直近コマンド/完成施設と、所属ユニットの種別・Lv・ワールド・座標・HP/APを読む。敵AI診断は野良と村守備軍向けのまま。NPCなしの場合も未登録の案内を表示する。診断は状態を読むだけでAIを実行しない。

開始画面は `v39-field-settings-final.js`、生成は `v39-game-state-bridge.js`、自動配置は `v39-initial-placement.js`、行動は `v39-faction-ai.js`。同じ処理を別の画面やタイマーへ追加しない。

`scripts/check-v39-npc-start.mjs` は390/1100で入力から生成、NPC2勢力の配置、人のみの担当/ターン、保存読込、設定再表示、実ラウンドのAI、発見済み覇権地の目標、NPC0を確認する。既存のlocal-session、faction-ai-objective、faction-ai-explorationも使用する。

外交による自動開戦、戦力の精密評価、拠点昇格の計画は今後の調整対象。今回の確認は複数NPC間の長期勝率や完全攻略のバランスを保証するものではない。
