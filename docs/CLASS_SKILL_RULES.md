# クラススキル構成ルール

最終更新: 2026-10-17

## 1. 目的

この文書は、`@game_data` の `CS` / `クラス` シートでクラスを新規作成したり、既存クラスのスキル構成を意図的に再設計したりするときの、クラススキル配置ルールと系統別設計方針の正本とする。

過去チャット、古いクラス行、旧メモだけから P / A の個数・配置Lv・系統ごとの役割を推測しない。

---

## 2. 基本構成

新規クラス、またはこのルールへ合わせて再設計するクラスは、クラス固有の P / A スキルを原則6個とする。

- A（アクティブ）: 3個
- P（パッシブ）: 3個

基本配置は固定する。

| クラスLv | 基本種別 |
| ---: | :---: |
| Lv1 | A |
| Lv3 | P |
| Lv5 | A |
| Lv7 | P |
| Lv9 | A |
| Lv10 | P |

したがって、基本形は次の通り。

`Lv1 A / Lv3 P / Lv5 A / Lv7 P / Lv9 A / Lv10 P`

Lv2 / Lv4 / Lv6 / Lv8 は、新規のクラス固有 P / A を自由配置する枠として扱わない。
既存共通スキル、身体部位スキル、個別仕様上の取得物などを置く必要がある場合は、対象クラスの個別仕様または現在のユーザー指示で明示する。

---

## 3. 系統別クラス設計方針

新規クラスや既存クラスの再設計では、最初に `クラス` シートの `種類` を確認し、その系統の役割に沿ってステータス傾向とスキル内容を組む。

A3 / P3 の配置だけを満たしていても、系統の役割から大きく外れる場合は設計を見直す。

### 3.1 戦士系

- 戦闘能力を最も重視する系統。
- 攻撃・防御が高め。
- 派生によっては回避を重視する型も存在する。
- 基本的に、特定ステータスを強化するスキルと攻撃系スキルを持つ。
- ガード系または回避系のスキルを最低1つ持つ。
- 特定武器に依存しない戦闘上の特徴を持つ。
- 武器そのものへの専門化は「武器専門 / ○○マスター系」と役割を分ける。

### 3.2 武器専門 / ○○マスター系

- 特定の武器、またはその武器の特定攻撃属性を専門化する。
- 対象武器・対象属性の威力を上げる。
- Cr率とCr威力を上げる。
- ステータス傾向は命中が高い。
- 汎用的な戦闘力よりも、対象武器を使ったときの性能を伸ばす。

### 3.3 狩人系

- 命中と回避が高め。
- 技能として隠密と索敵が高い。
- 探索と戦闘サポートの両方に強い。
- 怯み系のスキルで相手のAPへダメージを与えることができる。
- 相手の戦闘能力を削るステータスダメージ系効果を扱う。
- 代表例として `効果:防御ダメージ`、`効果:回避ダメージ` などを使用する。
- 正面から純火力だけで押すより、妨害・弱体化・位置取りで有利を作る。

#### 暗殺系派生

- 急所攻撃を重視する。
- 相手の背後から攻撃することで大ダメージを狙う。
- 隠密、奇襲、背後取りを活かす設計とする。

### 3.4 魔法系 / 魔導士系

- 魔力と精神が高い。
- それ以外のステータスは低めで、極端な能力配分を持つ。
- 魔法を使い、遠距離から高ダメージを与える。
- 範囲攻撃で複数対象へ高ダメージを与えることを得意とする。
- 攻撃魔法だけでなく、補助魔法・防御魔法も扱え、汎用性が高い。
- 魔法発動にはラグがあり、即応性が低く扱いにくい。
- 高火力・高汎用性の代わりに、位置取りと発動タイミングを要求する。

### 3.5 信仰系

- 回避は低め。
- その他のステータスは比較的バランスがよい。
- 魔力攻撃と物理攻撃の両方を扱える。
- 回復魔法と光魔法を扱う。
- 味方の戦闘継続力を伸ばす役割が大きい。
- 回復・支援・攻撃を兼ね、部隊における重要度が高い。

### 3.6 ドルイド系

- 基本的な役割とステータス傾向は信仰系に準ずる。
- 信仰系の回復・支援・物理/魔法両対応に加え、植物魔法を使用できる。
- 植物・自然を使うことが、信仰系との差別化要素となる。

### 3.7 格闘系

- 攻撃と回避が高め。
- 武器に依存しないため、装備コストの面で有利。
- 武器で攻撃力不足を補うことができないため、基礎攻撃力が足りない場合は火力不足になりやすい。
- 移動ペナルティを受けにくい。
- 探索と戦闘の両方に強い。
- 武器専門系とは異なり、素手・身体能力そのものを伸ばして戦う。

### 3.8 バード系

- 歌・演奏を中心に戦うサポート特化系統。
- 精神系の状態異常を解除できる。
- 演奏中、部隊のステータスを継続的に上げることができる。
- 相手へ状態異常や弱体効果を継続して与えることもできる。
- サポート能力に特化している。
- 本人の直接戦闘力はほぼ持たない。

### 3.9 実装上の注意

この節はクラス設計上の役割を定義する。

`回避`、`発動ラグ`、`APダメージ`、`防御ダメージ`、`回避ダメージ`、演奏中の継続効果などの具体的なランタイム処理については、現在のコードと `docs/スキル効果対応状況.md` を確認する。

設計として確定していても処理が未対応の場合は「仕様確定済み・未実装」と区別する。

## 4. 例外

この配置または系統方針から外す場合は、次のいずれかの根拠を必要とする。

1. 現在の会話でユーザーが例外を明示した。
2. 対象クラス・系統の現行個別仕様書に例外が明記されている。
3. 既存実装上、互換性維持のため変更できないことを確認した。

古い `CS` 行に別配置・別傾向のクラスが存在することだけを理由に、例外ルールを作らない。

既存の旧クラスに本ルールと異なる配置・内容が存在しても、ユーザーの指示なく一括修正しない。
その場合は「既存データは旧設計 / 新規・再設計は本ルール」と区別する。

---

## 5. クラス追加・再設計前の必須確認

`CS` または `クラス` シートへ書き込む前に、必ず次を確認する。

1. 現在の作業ブランチ。
2. `AGENTS.md`。
3. `docs/README.md`。
4. 本文書 `docs/CLASS_SKILL_RULES.md`。
5. `クラス` シートの対象クラスの `種類`。
6. 本文書の該当する系統別設計方針。
7. 対象系統の既存クラスを `CS` で確認する。
8. 対象クラスまたはテンプレート行を `クラス` シートで確認する。
9. A/P の個数と配置Lvが本ルールに一致しているか確認する。
10. 既存スキル名・既存効果・既存のデータ記法を再利用できないか確認する。

**系統とA/P配置を確認する前にSheetへ書き込まない。**

---

## 6. 設計時のチェック

クラス案を組むときは、スキル名や数値より先に次の骨格を固定する。

| Lv | 種別 | 内容 |
| ---: | :---: | --- |
| 1 | A |  |
| 3 | P |  |
| 5 | A |  |
| 7 | P |  |
| 9 | A |  |
| 10 | P |  |

その後で、系統別設計方針に沿って各枠の役割・数値・AP・効果時間・CT等を決める。

「Pを3個」「Aを3個」という個数だけを満たしていても、配置Lvが違う場合は基本ルール違反とする。

同様に、配置だけ正しくても対象系統の役割から大きく外れる場合は、系統別設計方針と照合する。

---

## 7. Sheet反映後の確認

`CS` / `クラス` を編集した場合は、書き込み直後に読み戻して確認する。

最低限確認する項目:

- クラス名
- `種類`
- Lv1〜Lv10のスキル名
- 各スキルの `行動`（A / P）
- AP消費
- H列 `データ`
- J列 `効果説明`
- `クラス` シートの Skill1〜Skill10
- `出力確認` 等、JSON出力に必要な列
- スキル構成が対象系統の役割から大きく外れていないか

読み戻しで配置違反、系統違反、テンプレート由来の残存値を見つけた場合、そのまま完了扱いにしない。

---

## 8. データ管理との関係

ゲームデータの編集原本は Google スプレッドシート `@game_data` とする。
JSON生成・反映手順は `docs/SPREADSHEET_DATA_WORKFLOW.md` に従う。

本書は「クラススキルの構成・配置・系統別設計方針」の正本であり、個々のスキル数値や実装済み効果の対応状況を重複管理しない。

特殊効果の実装可否は `docs/スキル効果対応状況.md` と現在のコードを確認する。

---

## 9. 仕様と実装の区別

本ルールがSheet上で確定していても、コンバータやランタイムに自動検証が未実装の場合は、

- 仕様確定済み
- Sheet反映済み / 未反映
- 自動検証未実装

を分けて扱う。

将来的にはコンバータ等で A/P の個数・配置Lv・系統との明らかな不整合を検証し、違反を警告またはエラーにすることを検討する。
