# クラススキル構成ルール

最終更新: 2026-10-17

## 1. 目的

この文書は、`@game_data` の `CS` / `クラス` シートでクラスを新規作成したり、既存クラスのスキル構成を意図的に再設計したりするときの、クラススキル配置ルールの正本とする。

過去チャット、古いクラス行、旧メモだけから P / A の個数や配置Lvを推測しない。

---

## 2. 基本構成

新規クラス、またはこのルールへ合わせて再設計するクラスは、クラス固有の P / A スキルを原則6個とする。

- A（アクティブ）: 3個
- P（パッシブ）: 3個

基本配置は固定する。

| クラスLv | 基本種別 |
| ---: | :---: |
| Lv1 | A |
| Lv3 | P |
| Lv5 | A |
| Lv7 | P |
| Lv9 | A |
| Lv10 | P |

したがって、基本形は次の通り。

`Lv1 A / Lv3 P / Lv5 A / Lv7 P / Lv9 A / Lv10 P`

Lv2 / Lv4 / Lv6 / Lv8 は、新規のクラス固有 P / A を自由配置する枠として扱わない。
既存共通スキル、身体部位スキル、個別仕様上の取得物などを置く必要がある場合は、対象クラスの個別仕様または現在のユーザー指示で明示する。

---

## 3. 例外

この配置から外す場合は、次のいずれかの根拠を必要とする。

1. 現在の会話でユーザーが例外配置を明示した。
2. 対象クラス・系統の現行個別仕様書に例外が明記されている。
3. 既存実装上、互換性維持のため配置を変えられないことを確認した。

古い `CS` 行に別配置のクラスが存在することだけを理由に、例外ルールを作らない。

既存の旧クラスに本ルールと異なる配置が存在しても、ユーザーの指示なく一括修正しない。
その場合は「既存データは旧配置 / 新規・再設計は本ルール」と区別する。

---

## 4. クラス追加・再設計前の必須確認

`CS` または `クラス` シートへ書き込む前に、必ず次を確認する。

1. 現在の作業ブランチ。
2. `AGENTS.md`。
3. `docs/README.md`。
4. 本文書 `docs/CLASS_SKILL_RULES.md`。
5. 対象系統の既存クラスを `CS` で確認する。
6. 対象クラスまたはテンプレート行を `クラス` シートで確認する。
7. A/P の個数と配置Lvが本ルールに一致しているか確認する。
8. 既存スキル名・既存効果・既存のデータ記法を再利用できないか確認する。

**A/P配置を確認する前にSheetへ書き込まない。**

---

## 5. 設計時のチェック

クラス案を組むときは、スキル名や数値より先に次の骨格を固定する。

| Lv | 種別 | 内容 |
| ---: | :---: | --- |
| 1 | A |  |
| 3 | P |  |
| 5 | A |  |
| 7 | P |  |
| 9 | A |  |
| 10 | P |  |

その後で各枠の役割・数値・AP・効果時間・CT等を決める。

「Pを3個」「Aを3個」という個数だけを満たしていても、配置Lvが違う場合は基本ルール違反とする。

---

## 6. Sheet反映後の確認

`CS` / `クラス` を編集した場合は、書き込み直後に読み戻して確認する。

最低限確認する項目:

- クラス名
- Lv1〜Lv10のスキル名
- 各スキルの `行動`（A / P）
- AP消費
- H列 `データ`
- J列 `効果説明`
- `クラス` シートの Skill1〜Skill10
- `出力確認` 等、JSON出力に必要な列

読み戻しで配置違反やテンプレート由来の残存値を見つけた場合、そのまま完了扱いにしない。

---

## 7. データ管理との関係

ゲームデータの編集原本は Google スプレッドシート `@game_data` とする。
JSON生成・反映手順は `docs/SPREADSHEET_DATA_WORKFLOW.md` に従う。

本書は「クラススキルの構成・配置ルール」の正本であり、個々のスキル数値や実装済み効果の対応状況を重複管理しない。

特殊効果の実装可否は `docs/スキル効果対応状況.md` と現在のコードを確認する。

---

## 8. 仕様と実装の区別

本ルールがSheet上で確定していても、コンバータやランタイムに自動検証が未実装の場合は、

- 仕様確定済み
- Sheet反映済み / 未反映
- 自動検証未実装

を分けて扱う。

将来的にはコンバータ等で A/P の個数・配置Lvを検証し、違反を警告またはエラーにすることを検討する。
