このページは、クラス・種族スキルを新規作成・調整するときの**作成基準と数値目安**をまとめる。数値は絶対値ではなく目安とし、条件・デメリット・射程・範囲・複合効果・クラス固有コンセプトを見て個別調整する。

## 1. スキル構成

- クラス・種族のスキルは**合計10個まで**。
- スキルの基本分類は **P / A / Q** の3種とし、Sは新規作成では使用しない。
- **P（パッシブ）**：常時または条件成立中に働き、単独で行動を起こさない。原則3個前後を目安とする。
- **A（メインアクション）**：戦闘中に選択して実行する通常攻撃、技、回復、防御、支援など。
- **Q（強化）**：Aを強化・変質させる。旧Sは内容に応じてAまたはQへ整理する。
- クラススキル10枠のうち、**P・A・Qそれぞれに原則1つ程度は汎用スキルを含める**。
- 汎用スキルは他クラスでも取得・流用できる内容を基本とする。特殊性が高く、無理に入れるとクラスコンセプトを損なう場合は例外としてよい。
- **同じスキル名を使う場合は、原則として同じ効果・同じデータを使用する。** 同系統でも効果を変える場合は別名称にする。
- P/A/Qとは別に、スキルの性質を表す**系統**を持たせることができる。
- 形態変化・変身・竜化などはスキル分類そのものを増やさず、例として `系統:変形` のように系統側へ記載する。
- `系統:変形` を持つスキルはP/A/Qのいずれかとして取得しつつ、発動タイミング、行動消費、持続、解除、ステータス変動など必要な特殊処理を個別に設定できる。

### 取得順の目安

- **多くのクラスで、Lv1～10の役割配置は下記を基本テンプレートとして使用する。** クラス特性に応じて多少の入れ替えや例外は許容する。
  - Lv1：クラスの基本技。原則として、そのクラスの基本的な戦い方を示すAを置く。
  - Lv2：対応技能を伸ばす汎用Q。
  - Lv3：クラス専用P。クラスの基礎特性・専門性を示す。
  - Lv4：クラス補助技または一時強化。A/Qは内容に合わせて選ぶ。
  - Lv5：ステータスを伸ばす汎用Q。
  - Lv6：汎用P。
  - Lv7：クラス補助技または一時強化。A/Qは内容に合わせて選ぶ。
  - Lv8：攻撃方式を拡張する枠。攻撃回数・射程・範囲・対象・攻撃追加などを扱う。
  - Lv9：上位クラス専用P。Lv3より強く、クラスの完成形へつながる専門Pを置く。
  - Lv10：クラス固有の最大技・完成技・必殺技。A/Qは内容に合わせて選ぶ。
- Lv4とLv7はクラスごとに役割を入れ替えてよい。片方を補助A、もう片方を効果時間を持つバフQにするなど、クラスの戦い方に合わせて配置する。
- Lv4・Lv7の種別はA/Qのどちらでもよく、役割を先に決めてから種別を選ぶ。
- Lv8は単純な数値強化より、攻撃回数・射程・範囲・対象・攻撃追加など、攻撃そのものの使い方を変える効果を優先する。
- Lv1とLv10はそれぞれ「基本技」「最大技・必殺技」として扱い、クラスの入口と完成形が分かる構成を優先する。
- Lv1～10の取得順では、A・Q・Pが一方に偏らないよう、ある程度ばらけさせる。
- Pを3個配置する場合は、基本テンプレートでは **Lv3・6・9** を原則とする。クラスの中核PをLv1へ置くなど、クラス構成上の理由がある場合のみ例外を許容する。
- **Lv1にPを置くのは、そのパッシブがクラスの中核となる場合を優先する。**
- Lv1の中核Pは、単なる無条件ステータス上昇ではなく、武器種・戦闘姿勢・行動条件・属性・状態など、**クラスらしい条件を満たしたときに発動する条件付きP**を基本とする。
- Pを早期に集中取得して基礎ステータスだけを大量に伸ばす構成は避ける。
- Pはクラス固有の戦い方を支える役割を優先し、単純な常時数値上昇だけでスキル枠を埋めない。
- **Lv10は原則として、そのクラスの最大技・完成形となるスキルを配置する。** 単純な下位スキルの数値強化だけでなく、クラス固有の戦い方をまとめた効果を優先する。
- Lv10の最大技は、必要に応じて `クールタイム:`、`待機`、高消費、命中・回避低下などの制約を付けて強い性能を許容する。

## 2. 参照・確認ルール

- クラス・種族スキルを新規作成・調整するときは、**過去会話や記憶だけで作成せず、必ず最新のNotionを参照する。**
- 情報源の優先順位は、原則として次の順とする。
  1. ユーザーが直近で明示した指示
  2. `クラス・種族スキル作成ルール`
  3. `基本スキル`
  4. `効果一覧`
  5. `戦闘ルール`
  6. 編集対象のクラス・種族ページ
  7. 過去会話・旧データ・表計算などの参考資料
- 上位の情報源と下位の情報源が矛盾する場合は、**上位の情報源を優先する。** 過去会話や旧データを理由に最新Notionの内容を上書きしない。
- 作成・調整前は、次の順で確認する。
  1. `クラス・種族スキル作成ルール` を確認する。
  2. `基本スキル` を確認し、同一・近似の汎用スキルがないか探す。
  3. `効果:` を使用する場合は `効果一覧` を確認する。
  4. 判定・攻撃回数・待機・射程・効果時間など戦闘処理へ関わる場合は `戦闘ルール` を確認する。
  5. 編集対象のクラス・種族ページを確認する。
  6. 既存ルールで意味が不明な項目がある場合は推測せず確認する。
- **同一効果・実質的に同じ効果の既存スキルがある場合、新しい名称で近似スキルを作らない。**
- MP/ST消費はLvだけで決めず、必ず性能・効果時間・条件・デメリットと格別基準を照合して決める。
- `待機`、`クールタイム:`、能力低下などの制約は「Lv10だから」「必殺技だから」という理由だけで付けず、**その性能を成立させるために必要な場合だけ設定する。**
- 効果時間を持つQは、単発Qの基準値をそのまま複数ターン維持させない。効果時間・条件・消費を含めて性能を個別調整する。
- Notionへ変更を書き込む場合は、**書き込み直前に対象ページを取得し、書き込み後に再取得して反映を確認してから完了とする。**

## 3. データ記載ルール

- クラス・種族スキルの作成・調整時は、**新規スキルを作る前に必ずNotionの `基本スキル` ページを確認する。**
- `基本スキル` に同一効果、または実質的に同じ役割・同じデータのスキルが登録済みなら、**新しい名称・近似効果を作らず、登録済みスキルをそのまま使用する。**
- 特にLv2の技能系汎用Q、Lv5のステータス系汎用Q、Lv6の汎用Pなど、汎用枠へ配置するスキルは `基本スキル` の既存スキルを優先する。
- 既存スキルへ条件・対象・効果時間などを追加して性能が変わる場合は、同名流用せず別スキルとして扱う。
- `基本スキル` に該当するものがない場合のみ、新規の汎用スキルを作成する。
- スキル表の基本列順は `Lv / スキル名 / ルビ / 系統 / 行動 / 処理種別 / HP消費 / MP消費 / ST消費 / データ / 説明` とし、`説明` は必ず `データ` の右隣に置く。

### 行動枠と処理種別

- `行動`の `P / A / Q` は**使用する行動枠・発動タイミング**を表し、攻撃か強化かの判定には使用しない。
- `処理種別`はA/Qの実処理を明示する独立欄とし、現行の明示値は `攻撃` / `強化` とする。Pは処理種別を使用せず空欄とする。**処理種別が空欄の場合は、Aを攻撃、Qを強化として既定処理する。**
- 処理判定の優先順位は、**明示された `処理種別` → 盾・障壁・壁・回復・生成などの専用処理 → 空欄時の行動既定値**とする。空欄Aは攻撃、空欄Qは強化として扱う。`攻撃手段:`、`威力`・属性・状態数値、旧`特殊:攻撃`そのものを攻撃識別フラグには使用しない。
- `処理種別=強化`はステータス・武器・攻撃性能などへ補正を付与する処理として扱う。**Aで強化を行う場合は `処理種別=強化` を明示する。Qで独立攻撃を行う場合は `処理種別=攻撃` を明示する。**
- 盾・障壁・壁・回復・生成など、既存の`効果:`や専用数値で処理を一意に判定できるものは処理種別を空欄にしてよい。
- 旧`特殊:攻撃`は攻撃識別には使用しない。既存データに文字列が残っていても、`処理種別`を優先する。
- `データ` 欄はゲーム処理用の記述だけを置き、人間向けの補足文章は `説明` 欄へ分離する。
- `データ` 欄では、独立したデータ同士を半角スペース1つで区切る。`。` や `/` は使用しない。
- **数値に `%` が付く場合は割合・倍率補正、`%` が付かない場合は固定値の増減として判定する。** このため `倍率` を項目名へ追加して区別しない。例：`全威力-20%` は全威力を20%低下、`攻撃+10` は攻撃を固定値10上昇。
- **`威力+N` とダメージ種別ごとの補正は意味を分ける。** `威力+N` は使用する攻撃の元のダメージ種別を問わず、その攻撃自体の威力を上げる。例：`攻撃手段:素手 威力+20` なら、使用する素手が打撃・切断・貫通のいずれを持つ場合でもその攻撃の威力補正として扱う。
- **`打撃+N`、`切断+N`、`貫通+N` などは、そのダメージ種別だけを追加・強化する。** 技そのものが「衝撃を加える」「切断力を加える」など特定の攻撃性質を持つ場合はこちらを使う。例：`攻撃手段:素手 打撃+25` は、元の素手が切断・貫通主体でも、技によって打撃成分を追加する意味になる。
- スキル作成時は、**元の攻撃性能を種類を問わず底上げしたいのか、特定のダメージ種別を追加・強化したいのかを先に決め、`威力+N` と各ダメージ種別補正を使い分ける。**
- 同じ項目に複数の値を指定する場合は `|` で区切る。特に `攻撃手段:` と `効果:` は複数指定時に `|` を使用する。
- 例：`攻撃手段:近接武器|肉体 威力+20 追加威力:早業 判定:攻撃`
- 例：`効果:麻痺|転倒`

### 対象指定の記法

- スキルの対象を明示する場合は `対象:` を使用する。
- 対象指定は `対象:自身`、`対象:味方`、`対象:敵`、`対象:味方|自身` の4形式を基本とする。
- `対象:` は「誰を選択できるか」を指定し、対象へ届く距離は `射程:` で別に指定する。`対象:全体`、`対象:味方全体`、`対象:敵全体` のような全体指定は使用しない。
- 同時に選択・適用できる対象の数は `対象数:` で指定する。例：`対象:味方 射程:2 対象数:2 HP回復+30`。
- `対象:味方|自身` のように `|` で複数種類を指定した場合、後続する同一データを指定対象へ適用する。
- 例：`対象:味方|自身 射程:接触 対象数:2 HP回復+50`
- 条件欄へ特定スキル名を指定した場合、そのスキルが有効・使用中の間だけ効果を適用する。例：`条件:プラクシマティモード`。
- スキルデータで `効果:` を使用する場合は `効果一覧` を必ず参照し、登録済みの効果名だけを使用する。
- `効果:` は自由記述にせず、必要な効果が未登録の場合は先に `効果一覧` へ登録する。
- 効果の補足説明が必要な場合は `効果:` へ文章を書かず、別の `説明` 欄へ記載する。

### スキルデータで使用できる基本項目

`威力` `全力` `ダメージ幅` `切断` `貫通` `打撃` `物理ガード` `魔法ガード` `炎` `氷` `雷` `酸` `音` `光` `闇` `善` `悪` `回復` `精神攻撃` `毒` `盲目` `幻覚` `石化` `怯み` `拘束` `呪い` `即死` `時間` `出血` `疲労` `体幹` `Cr率` `Cr威力` `射程` `範囲` `対象` `効果` `攻撃回数` `攻撃追加` `追加威力` `判定` `効果時間` `待機`

### 運用上の注意

- `炎`、`氷`、`雷`などの属性値、`切断`、`貫通`、`打撃`などの物理種別、`毒`、`盲目`、`幻覚`、`石化`、`怯み`、`拘束`、`呪い`、`即死`、`時間`、`出血`、`疲労`、`体幹`などは、スキル自身が持つ数値項目として直接記載できる。
- 例：`幻覚+25 判定:変装 追加威力:騙す`
- `効果:` は上記の数値項目とは別で、`効果一覧` に登録された固定処理名だけを指定する。
- **威力系の数値項目をスキルへ設定する場合は、スキルごとに `判定:` または `追加威力:` のどちらか一方、もしくは両方を必ず設定する。** `威力`、物理種別、属性、状態、`体幹` などが対象となる。
- `判定:` と `追加威力:` は、そのスキル自身が持つ威力系数値の計算に使用する。
- 各項目の具体的な意味・計算・表記方法が不明な場合は推測で補完せず、仕様を確認してから使用する。

### `効果:障壁` の数値記法

- `効果:障壁`では、`威力+N`を障壁HPの基礎値として使用する。`判定:` / `追加威力:` はこの `威力` に適用し、計算結果を最大障壁HPとする。
- 障壁生成時の障壁HPには攻撃ブレを適用しない。
- `HP+N`は従来どおり使用者本体のHP補正であり、障壁HPには使用しない。
- `炎+N`、`切断+N`など `威力` 以外の威力系数値は障壁HPへ合算しない。それらに別の固定処理を持たせる場合は、対応する `効果:` を別途定義する。
- `効果:障壁`では物理ガード／魔法ガードを障壁性能として使用しない。防御性能を追加する場合は物理軽減・魔法軽減・耐性を使用する。

## 3. 攻撃Aの基本

- ダメージや状態蓄積を発生させるAには、A自身の威力値を設定する。
- 武器参照型Aでは、**武器の威力とAの威力を別々に計算し、最後に合算する**。
- 武器側の該当属性・ダメージ種別が0でも、A側の威力はそのまま発生する。
- `判定`、`追加威力`はA側の威力計算に使用する。威力値がない攻撃Aへ、攻撃用の `判定` や `追加威力` だけを付けない。
- **Aは主行動を消費するため、同格・同消費のQより大きな性能を許容する。目安として、単純な補正量ではQの約2倍程度までを許容範囲とする。**
- 特に威力を直接強化しない補助・機動型Aは、威力強化型Aとの釣り合いを見て命中・回避・移動力などの補正を大きくしてよい。

## 4. 格別の基準値

下位・中位・上位に関する基準は、この節を共通の参照先とする。中間性能の場合は、近い格へ数値を寄せて調整する。

| 格 | 武器参照A 通常 | 武器参照A 強技 | 状態・体幹 | Q ステータス | Q 技能 | Q 全力+ | MP・ST消費 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 下位 | 15～20 | ～25 | 10～20 | +25 | +50 | +15 | 5 |
| 中位 | 15～25 | ～35 | 20～35 | +45 | +90 | +27 | 10 |
| 上位 | 30～40 | ～50 | 30～50 | +60 | +125 | +35 | 15 |
| 条件付き最上位 | 40～55 | ～60程度 | 50～70 | 個別調整 | 個別調整 | 個別調整 | 個別調整 |

- 数値は最低値ではなく、標準～上限の目安。
- 状態異常・範囲・追加効果などが強い場合は威力を下げてよい。
- 通常ダメージと状態蓄積は別枠の数値として扱う。
- Qの数値は**1項目・短時間強化**の基準値。
- `全力+` は通常のステータス上昇とは別枠として扱い、複数効果補正を機械的に適用しなくてもよい。
- MP・ST消費は段階固定ではなく、**5～15の範囲で性能が近い格へ寄せる**。例：中位に近い性能ほど10へ近づける。
- 条件・デメリット・待機・クールタイムなどが強い場合は、性能との釣り合いを見て消費を下げてよい。

## 5. Pの基準

- 無条件の常時ステータス上昇は基本 `+5～10` 程度。
- 上位でも単純な常時補正は `+10～15` 程度を目安とし、強い補正には条件を付ける。
- 条件付き・専門技能などはクラスの役割に応じて大きな数値を設定してよい。
- Pは原則として使用時消費を持たない。

## 6. Qの補正

### 複数効果

1つのQで複数のステータス・技能を同時に上げる場合、各項目を下げる。

- 1項目：100%
- 2項目：各75%
- 3項目以上：各50%程度
- ステータスと技能を混ぜる場合も、それぞれの基準値へ倍率を掛ける。
- 実データでは扱いやすい数値へ丸めてよい。

### 持続ターン補正

| 効果時間 | 基準値に対する目安 |
| --- | ---: |
| 1t | 100% |
| 2t | 75% |
| 3t | 50% |
| 4t | 40% |
| 5t | 30% |
| 6t以上 | 25% |

- 複数効果と持続時間が両方ある場合は、両方を目安として加味する。
- あくまで作成時の目安であり、条件・消費・用途を見て個別調整する。

## 7. 消費の記載

- スキル固有のHP・MP・ST消費は、スキル表の `HP消費 / MP消費 / ST消費` 欄へ記載する。
- 消費そのものを人間向け文章として `データ` 欄へ書かない。
- 消費量を増減・倍率変更する効果は、ゲーム処理用データとして `データ` 欄へ記載する。
- 消費軽減・消費増加を強い性能の根拠として使う場合は、効果時間・条件・対象系統なども合わせて調整する。
- HP・MP・ST以外の弾薬・装填・専用資源などを消費する場合は、その資源側の共通ルールを先に定義してからスキルへ記載する。
- A/Qは効果量・用途・条件に応じて消費を設定する。MP・STの数値基準は「4. 格別の基準値」を参照する。

## 8. 強いスキルの調整

基準より高い数値を設定する場合は、明確なデメリット・制約を付ける。

- 待機時間
- 命中低下
- 回避低下
- 移動不可
- HP / MP / STの高消費
- 全力限定
- 特定状態・特定条件中のみ
- その他、実際の戦闘行動へ直接影響する制約

技能低下など、場面依存が強い軽いデメリットは増加量の根拠として弱く扱い、効果を大きく増やしすぎない。

## 9. 攻撃回数の扱い

- **武器が元から複数回攻撃の場合**、外部から加算される固定威力補正は、武器本来の攻撃回数で等分する。武器本体の威力は分割しない。
- **A/Qによって攻撃回数そのものを増やす場合**は別処理とし、スキル側に威力率を設定する。
- 武器＋Aを使う攻撃回数増加の目安：2回攻撃化は各80%前後、3回攻撃化は各70%前後。
- この目安は武器威力＋A威力を合わせたバランス用であり、魔法の多段攻撃計算には適用しない。

## 10. 全力・疲労

- `全力+10` などは、全力行動時の威力上昇を表す。
- 全力行動による使用者自身の疲労増加は、戦闘ルール側の共通処理を使用する。
- 自分が全力行動を行うスキルへ `疲労+` は記載しない。
- `疲労+` は、相手へ疲労蓄積を与える攻撃・妨害効果として扱う。

## 11. 魔法について

- 魔法はクラススキルの武器参照Aとは別の作成基準を持つ。
- 本ページの武器参照A・武器多段の威力目安を、そのまま魔法へ適用しない。
- 魔法ランク、射程、範囲、攻撃回数、待機時間などは魔法側の作成・計算基準を優先する。

## 12. 個別クラス・系統ルール

個別のクラス・種族・系統だけに適用する例外や専用基準は、共通ルールと混在させず、この節以降へまとめる。

### マギテック系

- マギテックは**Lv1で宝珠装備枠1**。レベル上昇で枠を解放し、**最大3枠**。
- 宝珠装備枠の増加と、複数魔法の同時発動は別能力として扱う。
- **マギリアクター**は魔法の制御・運用を強化する専用クラスとして扱う。
- 射程増加、二門同時発動、詠唱増加による威力強化などはマギリアクター側の候補。
- **魔法二重化**のような高度な多重処理は、マギリアクターの上位クラス側へ配置する。

#### マギテック専用クラス候補

- **マギリアクター**：魔法全般の発動・射程・詠唱・並列制御を強化する汎用魔法制御クラス。
- **マギリアクター上位クラス**：魔法二重化、多重処理、より高度な並列制御を扱う上位系統。正式名称・詳細は後で確定する。
- **属性リアクター系**：特定属性の魔法だけを専門強化するクラス群。条件属性を付けることで、通常の常時パッシブ基準を超える補正を許可できる。例：`条件属性:炎 魔力+35`。
  - **フレイムリアクター**：炎属性魔法を強化する。
  - **クライオリアクター**：氷属性魔法を強化する。
  - **ボルトリアクター**：雷属性魔法を強化する。
  - **アシッドリアクター**：酸属性魔法を強化する。
  - **エアリアクター**：風属性魔法を強化する。
  - **テラリアクター**：地属性魔法を強化する。
  - **アクアリアクター**：水属性魔法を強化する。
  - **フォースリアクター**：力場属性の魔法・現象操作を強化する。
- **シールドリアクター**：属性ではなく**防御魔法系統**を専門強化するクラス。物理ガード、魔法ガード、シールド、耐性、持続時間、展開範囲、即時防御などを強化する。力場リアクターとは別系統として扱う。
- 属性リアクターやシールドリアクターは、新しい属性・魔法を自動取得するクラスではなく、**対応する属性・系統の魔法を所持・使用できることを前提に、その性能を強化するクラス**として扱う。

## データ表記の追加ルール

- `効果:` に付ける `_` 以降は、その効果に対する制限・指定を表す。例：`効果:回避ダメージ_1T` の `_1T` は効果時間1ターンを指定する。
- `回避ダメージ`、`命中ダメージ`、`防御ダメージ` のような固定処理は、数値項目として `回避ダメージ:15` のように書かず、`効果:` で記載する。
- `威力`、属性値、物理種別、状態・体幹などの**威力系数値をスキルに設定する場合は、必ず `判定:` または `追加威力:` のどちらか、もしくは両方を設定する。**
- `判定:` / `追加威力:` に使うステータスはスキルごとに個別設定し、同系統だからという理由だけで自動的に共通化しない。

## 特殊処理チェック

- スキルの説明に、`生成する`、`製造する`、`修復する`、`換装する`、`変形する`、`装甲へ直接ダメージを与える` など、数値補正・条件・対象・射程・威力だけでは実行できない処理が含まれる場合、必ず対応する `効果:○○` または既存の正式データ項目が必要か確認する。
- `データ` 欄に対応する処理指定が存在しない場合、そのスキルは**記載されている数値補正・条件・対象・射程・威力などだけを処理し、説明文に書かれた特殊動作は発生しない**ものとして扱う。
- 説明文だけに特殊処理を書いて成立させない。ゲーム上の特殊処理は必ず `データ` 欄で明示する。
- 必要な特殊処理が `効果一覧` に未登録の場合は、スキル側へ先に仮記載せず、**まず `効果一覧` に処理内容を登録・確定してから `効果:○○` として使用する。**
- 既存の正式データ項目で表現できる場合は、新しい `効果:` を作らず既存項目を優先する。
