# 取引・郵送・貿易の現行ルール

更新: 2026-10-15

## 入口と対象

- 会話表示/APの最新仕様は [交渉モーダルルール.md](./交渉モーダルルール.md)。NPC判定は成功/拒否とも交渉役のAP20を消費し、自己強化の持続補正を参照する。同ターン同条件の再判定は不可。取引入力は閉じても同一セッションで保持する。

- 拠点タブまたは一般村の接触画面の「取引・郵送」から共通モーダルを開く。
- 地上の生存する名前付きキャラ・軍隊を担当者にできる。部隊なら生存メンバー全員で移動・運搬する。
- 他プレイヤーは自分の操作ターンに一覧から承諾する。提案者による強制承諾はできない。
- 村は交渉/威圧・友好度・要求量/備蓄負担による暫定確率で判断する。魂は実在庫のみで、人口から勝手に作らない。
- 洞窟内取引、サーバー権威による遠隔プレイヤー承認、正式な馬車クラス/研究は今回の対象外。現在のプレイヤー承認はローカル交代操作で検証している。

## 条件

- 物資一覧は親の取引画面とは独立した選択モーダルで開く。選択中は親画面を操作不可にし、選択完了・×・Escで選択モーダルだけを閉じる。複数種類を続けて追加でき、数量は親画面で編集する。
- 元のゲーム画面の物資ヘッダー本体を、取引・物資選択モーダル表示中も最前面に表示する。既存の資源内訳/特殊資源パネルもその上で開ける。別の在庫ヘッダーは作らない。モーダルは元ヘッダーの実測した下端より下へ配置し、閉じるとヘッダーの通常配置へ戻す。元ヘッダーは従来の操作プレイヤーの資源集計を維持し、相手在庫へ切り替えない。
- 物資はアイコン右上に数量を表示する。名前/在庫の説明はツールチップ・読み上げに残す。物資を選択するとスライダーと数値入力で数量を編集できる。初回確保/積載等の常時説明は出さず、無効な条件は提案ボタン付近に理由を表示する。
- モーダルはヘッダー下から画面下まで高さを固定する。物資の分類/検索で内容が増減してもタイトル・分類・完了ボタンの位置は変えず、一覧部分のみスクロールする。画面サイズ変更時は元ヘッダーの高さに追従する。
- 配下・武器/装備・薬/道具の取引は未対応。特産品の一時的な利用権は対応済み。

- 同時交換または一方向の郵送、単発または定期往復を選ぶ。
- 「渡す物資」と「要求する物資」を独立した一覧で編集する。「物資を追加」からアイコン一覧（食料/基本資材/特殊資源、名前検索）を開き、各側に複数種類を追加できる。資源は既存のフィールド/ヘッダーと同じアイコン＋数量で表示し、名前は補助表示・読み上げ・ツールチップとして残す。
- 追加済みの物資を選んでも重複追加せず数量の編集対象を切り替える。スライダーと数値入力は連動し、×で選択中の物資を削除する。
- 渡す側が空で、相手への要求だけを提案することも可能。両側とも空なら提案不可。相手の承諾やNPCの判定は必要で、要求だけで物資を取得できるわけではない。
- 通常の新規提案は物資を空で開始する。専用取引テストだけ、穀物30と木材30を初期入力する。閉じても同セッションの全資源/数量を維持する。
- 出発拠点・運搬担当者・待ち合わせ・日程・交渉方式は「配送・日程」で変更する。会話/スキルと予約説明も折りたたみ、主画面は物資編集を優先する。折りたたみ状態と本文スクロールを数量変更でリセットしない。経済の詳細概算は配送設定を開いたときに計算する。
- 提案ボタンは固定フッター。編集時に積載・数量・予約条件を検証し、無効ならボタンを無効化して理由を表示する。モーダルの外側/内側padding・外枠・角丸・幅制限は撤去し、元の物資ヘッダーより下の画面全体を使う。
- 郵送は要求を指定しない。要求がある状態で郵送へ切り替える場合、削除を確認する。取消なら全資源と交換方式を維持する。
- 提案後の取引一覧も、契約した全資源をアイコン＋数量で表示する。予約/携帯/未確保の個別進捗は詳細で確認できる。既存の種類別数量オブジェクトを使い、保存形式・初回予約・同時交換処理は一括して適用する。
- 共通範囲に隣接した停止先2マスがない条件は成立しない。双方の先頭が共通範囲内の隣接マスに揃ってから交換する。同一マスへの重複配置や現地への分割搬入は使わない。実際に通行できるかは移動時に判定し、塞がれていれば待機/期限切れとして扱う。
- 指定日から猶予最終日まで交換可能。猶予は3～30ターン、許容半径は0～30マス。周期0は単発、定期周期は猶予より長くする。値は `config/v39-trade.json` で調整する。
- 交換前に双方の全担当者の生存、地上所属、到着、携帯物資を再確認する。

## 特産品の一時的な利用権

- 特産品は保有マス数で管理し、ターン経過で物資在庫を増やさない。5ターンごとに1個の在庫案は撤回。
- 取引数量は対象特産品のマス数。受諾時は数量全体を予約し、同じ保有分の重複貸出を防ぐ。予約だけでは幸福度に使える保有数を減らさない。
- 担当部隊の現地交換時から、渡す側の有効保有数を減らし、受け取る側へ同数の利用権を与える。土地の所有者・位置は変えない。借りた分は再貸出できない。
- 初期貸出期間は10ターン（V39_SPECIALTY_BALANCE.tradeLoanTurns）。画面で1〜100ターンに指定できる。期間は実際の交換ターンから数え、期限時点で有効保有数が自動復帰する。セーブ/読込後も期限を維持する。
- 交換前の取消で特産品の予約を解除する。死亡で荷物が失われても、取消時には利用権の予約を解除する。交換済みの貸出は契約を中止しても期限まで続く。
- ヘッダーの特産品一覧・拠点の幸福度は、有効保有数（自己保有−貸出＋受領）を参照する。地上マスの発見記録と領土の所有数は書き換えない。
- 専用取引テストは両者へ発見済みの特産品マスを追加。先頭特産品は自軍2マス・相手1マスで、一時移転/期限復帰を確認できる。

## 在庫・収入

- 承諾時に次回1回分の1/3（整数切り上げ）を双方の手持ちから予約へ移す。片側だけ支払って失敗することはない。
- 予約は通常在庫から除外され、建設・維持費等に使えない。ヘッダーの使用可能数にも予約分は含まない。
- 残りは実取得量から `未確保量 / 残りターン数` を目標に成立順で確保し、残りだけを通常在庫へ加える。収入不足は翌ターンに持ち越し、同じターンの再処理は重複確保しない。
- 通常在庫からの自動補填はしない。手動の「手持ちから追加確保」は可能。村側の備蓄追加は別途交渉判定を行う。
- 画面には使用可能在庫、初回確保、積載上限、基礎収入/維持費/確保目標の概算と不足警告を表示する。概算は地形の基礎産出で、将来の人口変化・周期採取等を保証しない。
- 収入処理は実取得→取引予約→通常在庫→維持費。積み込みは予約から携帯物への移転、交換は双方の携帯物の同時交換、帰還で拠点へ荷下ろしする。
- 定期契約の次回開始にも1/3を確保する。不足または往復時間不足なら中断し、手動で再協議する。
- 村の取引在庫は、その村が取引対象になった後の地上世界ターンで実際の地形産出と維持費を反映する。全村の完全な人口/需要シミュレーションを実装したという意味ではない。

## 運搬と中断

- 通常のAP・地形・狭路追従を使う。各メンバーがAPを支払う。自動中は手動移動、輸送、教官、洞窟警備、呼集、編成変更等との兼任を禁止する。
- 容量は生存メンバーの `100 × SIZ / 170` と `cargoCapacityBonus` の合計。運搬車両は攻撃平均から除く。
- 速度倍率は `clamp(2 - 積載量 / 容量 + 平均攻撃 / 1000, 0, 1)`。資源の数量と運搬装備の行数を荷重に含め、容量0も別処理する。
- 自動担当者はカードに循環マーク、中断時は警告マークを表示し、未行動確認から除外する。
- 死亡・担当者消失・期限切れは中断する。自軍の携帯物は既存の死体荷物、村の輸送役の携帯物は地面の戦利品へ移し、元拠点へ複製しない。
- 中断は自動移動/新規収入確保を止め、予約と携帯物を維持する。日程の再開は双方の承諾が必要。NPCは再判定する。
- 中止は未積載予約を解除し、携帯物は物理的に帰還・荷下ろしする。返却拠点を失った予約を黙って消さない。
- 受け渡し済み履歴を巻き戻さない。返却を求める場合は新しい取引として再交渉する。数量/担当者変更も旧取引を中止・荷下ろしした後に再提案する。
- 契約と履歴は提案者の `factionState.tradeContracts`、携帯物は既存部隊の `cargoByUnitId` に保存する。セーブ/読込でも途中状態を保持する。

## テスト

タイトル→テスト操作→専用→「取引・郵送テスト」。2プレイヤー、実在庫を持つ村、仮の運搬馬車を用意する。

`scripts/check-v39-trade.mjs` はスマホ390px・PC1100pxでネイティブ画面、承諾、実ターンの予約/移動/同時交換/帰還、セーブ/読込を確認する。村側の世界ターン/AP回復/実収入/交換/帰還も実ターンで確認する。純粋ルールの追加検証では定期2回、NPC魂取引、一方向郵送、中止帰還、死亡停止/戦利品一度性、二者承認による再開、猶予切れ、成立順の収入配分、初回不足・範囲不一致・荷重境界を確認する。

`scripts/check-v39-trade-baskets.mjs` は320/390/1100pxで追加・検索・重複禁止・数量変更・削除・要求のみ・郵送切替取消・入力保持・積載上限・固定ボタンを確認する。2種類ずつの取引を承諾し、各資源の1/3確保、保存復元、実ターンの同時交換/帰還と履歴一回性まで検証する。

生成JSONには今回の仮データを追加していない。正式な馬車クラスや取引用ゲームデータを追加する際はスプレッドシート原本から生成する。
