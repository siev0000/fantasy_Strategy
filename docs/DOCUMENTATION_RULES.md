# 文書・メモ運用ルール

制定: 2026-10-23

## 基本方針

文書を増やす前に [入口](README.md) と [文書一覧](INDEX.md) で既存資料を探す。同じ機能の現行仕様は原則1ファイルにまとめ、会話ごと・修正日ごとに新しいメモを作らない。

画像の依頼と進捗は [画像素材準備リスト](references/画像素材準備リスト.md) に一本化する。UIアイコン/ユニット/施設/地形・背景・エフェクトに分類し、制作待ち/受領済み/ゲーム反映済みを区別する。存在・流用・割当が不明なものは要確認とし、不足確定にしない。残タスクには詳細を複製せず、このリストへのリンクだけ置く。

仕様の優先順位は [README](README.md) に従う。古いメモや Issue の提案だけを根拠にゲーム挙動を変更しない。

## 置き場所

- ルート: 入口・一覧・本ルール・現状概要・統合タスク・必読のデータ/クラス/画像ルールのみ。`MEMO.md` は互換のため残す。
- `rules/units/`, `rules/world/`, `rules/economy/`, `rules/diplomacy/`, `rules/ui/`: 分野ごとの現行仕様。主な責任を持つ分野に置き、他分野からリンクする。
- `development/`: 起動・コード構成・更新作業の手順。
- `tests/`: 検証対象・操作手順・期待結果。
- `tasks/`: 個別分野の詳細チェックリスト。全体の入口は `ALL_TASKS_UNIFIED.md` に一本化する。
- `design/`: 未実装案・比較案・未決事項。現行ルールと混ぜない。
- `references/`: 参考資料・素材対応表・準備リスト。参考画像・HTMLは `references/assets/` に置く。
- `history/`: 廃止・置換済み文書と移動記録。現行仕様の根拠にはしない。

## 書き分け

現行ルールは「目的」「実装先（コード・設定・データ）」「現行動作」「操作・確認方法」「未実装・検討事項」を必要に応じて記載する。数値は原本の設定キーを示し、コードと別に独自の数値表を増やさない。

実装状態は次の言葉で区別する。

- **実装済み**: 実行経路を確認した動作。検証方法・実装先を示す。
- **暫定実装**: 動作するが調整値や制約が残る。制約も記載する。
- **決定済み・未実装**: 方針は決まっているがコードに未接続。
- **検討中**: 未採用案。課題・選択肢・未決事項を記載する。

文書全体に一括で実装済みと書かず、混在する場合は節ごとに状態を書く。`design/` 内に既に採用された記載があっても、未実装部分まで実装済みとみなさない。

## 更新の流れ

1. 対象の既存ルールと実装を確認する。
2. 実装変更時は該当ルールの現行動作を更新する。検討案の採用部分は現行ルールへ反映し、設計側には反映先を示す。
3. 残作業は対応する Issue に記載し、統合タスクからリンクする。同じ全体タスクを複数メモへ転記しない。
4. テスト手順や期待結果が変わった場合は `tests/` の対応資料も更新する。
5. 移動・追加した場合は一覧を再生成し、リンク検査を実行する。

```sh
npm run docs:index
npm run check:docs
```

スプレッドシート管理データは [更新手順](SPREADSHEET_DATA_WORKFLOW.md) に従い `@game_data` を編集する。クラスと画像はそれぞれ [クラスルール](CLASS_SKILL_RULES.md)、[画像ルール](UNIT_PORTRAIT_GENERATION_RULES.md) を先に読む。

## 命名・移動・保存

- 名前は内容を示す短い名称にする。既存ファイル名を整理のためだけに無理に改名しない。
- 新規ファイルに `最終版`・`最新版2`・日付違いの現行コピーを作らない。日付は本文の更新情報または履歴に使う。
- 必読資料のルートパスと `MEMO.md` は維持する。移す必要がある場合は参照元と明示的な移行方針を確認する。
- 移動時はMarkdownリンク、コード・設定内のパス、`AGENTS.md`、ゲーム内文書閲覧を確認する。相対リンクは移動先を基準に直す。
- 外部 Issue やブックマークの旧URLは自動で変わらない。今回の旧パスは [移動記録](history/document-moves-2026-10-23.json) から調べる。
- 旧資料は削除せず `history/` へ移し、冒頭に現行資料への案内を付ける。内容の削除・大幅統合は別途確認する。
- `MEMO.md` と `progress.md` は過去の経緯。新しい仕様・タスクの正本として増築しない。
- 文書はUTF-8で保存する。画像・HTMLの移動ではバイナリ内容を変更しない。

一覧の生成対象は `docs/` のMarkdown・参考ファイル。リンク検査はローカルファイルの存在を確認するもので、外部URLの疎通や見出しアンカー、本文の仕様の正しさまでは保証しない。
