# UI移植 保護ルール（2026-09-12）

この文書は、スマホUIプロトタイプの見た目をメイン実装へ移植する際に、既存ゲーム機能を壊さないための保護ルールを定める。

## 基本方針

プロトタイプから移植するのは **UI構造・配置・見た目** を中心とする。

マップのゲームロジック、探索状態、Fog、領土、地形、移動、攻撃、ワールドラップなどは既存実装を正とし、プロトタイプの簡易ロジックで置き換えない。

## 必ず維持する既存機能

- 未探索 / 非可視タイルのFog表示
- 発見済み / 可視タイルが地形本来の明るさで表示されること
- 索敵判定と視界更新
- 地形種類・高度・川・滝・溶岩・特殊地形
- 領土境界と勢力別境界色
- ユニット / 敵 / 集落 / 資源 / 特殊地形マーカー
- 移動可能範囲、移動経路、攻撃射程、攻撃範囲
- マップドラッグ、ズーム、ワールドラップ
- タイル選択と既存ゲームデータ連携

## UI側で変更してよいもの

- Portrait: 下部の情報・操作領域
- Landscape: 下部フッターを表示せず右サイドバーへ切替
- タブ構成と表示順
- 部隊選択 → メンバー選択 → 詳細の表示構造
- 左右の独立スクロール
- スクロールバーを幅ゼロ / 非表示にする見た目
- 技能と技を別カテゴリとして表示
- 資源チップ / 詳細ポップアップの見た目
- 六角タイルの **枠線・選択時強調など視覚スタイル**

## プロトタイプから移植しないもの

- プロトタイプの仮マップ生成ロジック
- プロトタイプの仮Fog / 明暗判定
- 点線円の仮索敵表示
- 仮キャラ / 仮部隊 / 仮座標 / 仮HP / 仮AP
- 仮の攻撃処理・移動処理
- プロトタイプ側の地形データ

## 六角タイル表示

プロトタイプの六角形は枠線が明瞭で見やすいため、枠線の色・不透明度・選択強調は参考にしてよい。

ただし、タイルの塗り色、Fogの重ね方、発見済み / 未発見判定は現行実装を維持する。

つまり **六角形の外観だけ改善し、探索ロジックは変更しない**。
