# 調査・特産品ルール

最終更新: 2026-10-04

## 調査

- 行動の調査カードを選ぶと詳細だけを開く。詳細の「使用」で開始する。選択だけではAP消費・調査開始を行わない。
- 行動一覧の調査は選択キャラの現在地を中心に、そのキャラの索敵範囲全体を対象とする。
- 範囲はFogと同じ `resolveV39UnitVisionRange` を使用。ワールド端はマップのラップ設定に従う。
- 対象マスは開始時に `surveyTask.tileKeys` へ保存する。途中で索敵値が変わっても変更しない。
- 残りAPを全消費して進捗へ加算。累計100APでターン解決時に完了し、不足時は次ターン以降へ保持する。
- 死亡・開始地点からの移動で中断する。旧セーブの対象一覧がない調査は旧来の1マス対象を維持する。
- 範囲内の探索地点・特産品・残留品を発見する。発見状態は勢力別で、他勢力へ自動共有しない。
- 危険度低下は初回調査時だけ適用。重複した範囲を調査しても同じマスへ繰り返し加算しない。
- 通常土地の取得は拠点の開拓を使用。勝利対象は範囲調査で発見できるが、取得には既存の守護排除・現地到達条件が必要。

## 特産品の配置と表示

- マップ生成時に、地形に対応した食料・鉱石を `specialtiesByTile` へ配置する。
- シートの最低高度・最高高度も出現条件へ適用する（空欄は制限なし、0も有効）。同じ条件を満たす候補から出現重みによって選択する（空欄=1、0=出現なし）。
- 塩は新規配置対象から除外。通常特産品としてタコ（海）、カニ・エビ（海・湖）、カキ・貝（海）、リンゴ（平地・森・丘陵）、オレンジ（平地・森）を原本へ追加済み。高度制限なし、出現重みは他の通常特産品と同じ1。食料在庫や周期採取資源にはせず、保有マス数と幸福度の種類数へ反映する。既存セーブの塩地点は保持する。
- 特殊資源は、素材ごとの適正マスが六角形の隣接関係で連続8マス以上ある地域ごとに最低1地点を確保する（8マスは調整用の暫定値）。さらにマップ全体で各素材の地点数が操作プレイヤー数以上になるよう補充する。通常抽選で既に足りている地域には追加しない。既存地点・通常特産品・予約地を上書きせず、出現重み0の資源は保証対象外。適正地形や空きマスが足りない場合は条件を破って配置せず、全体の不足をコンソールへ記録する。各プレイヤーの到達距離・初期領土内での取得保証や地形の強制生成は行わない。
- 研究を必要条件として採取を解禁する案は未確定。現在は従来どおり発見・領有で採取でき、研究は採取速度を上げる。
- 薬草は暫定で平地・森・湿地へ配置する。通常の調査で発見し、マスに薬草アイコンを表示する。薬草マスを群生地相当として扱うが、そこでターンを過ごした際の自然回復補正は後回し・数値未確定。既存の薬草群生地地形と旧来の処理は今回削除しない。
- 溶岩および勝利対象の占有範囲には配置しない。同一シード・地形では配置が再現される。
- 未発見の特産品は通常時には表示しない。TEST ONでは60%の半透明で配置を確認できるが、発見済み情報・ヘッダー一覧・幸福度へは加算しない。
- 特産品の文字アイコンはマス中央に表示し、見えているユニットがいる場合は右上へ移す。敵・一般村守備軍・他勢力・放浪者も表示中なら対象とし、未発見の敵だけでは表示位置を変更しない。
- 発見済み情報は `players[].factionState.exploration.discoveredSpecialtiesByTile` に保持する。
- ヘッダーは「食料・資材・金・特殊資源」の4分類。「特産品」タブは発見済みかつ健全な自領の特産品を種類ごとにまとめ、保有マス数を表示する。消費する在庫にはしない。
- ヘッダーの特殊資源の数値は在庫合計。発見した特産品の種類数・マス数を在庫に混ぜない。
- 配置・発見結果はセーブ/ロード対象。通常特産品は発見だけで在庫へ加算しない。特殊資源は下記の周期採取で加算する。
- 既存の金山・銀鉱脈・薬草群生地等の地形由来探索産出は、従来のルールを維持する。

## 幸福度

- **暫定**: 発見済みかつ健全な自領マスにある特産品を、所属拠点ごとに重複なしで数える。
- 1種類につき幸福度目標+2、最大+20。実際の幸福度は既存のターンごとの接近処理に従う。
- 領土外の発見、他勢力の発見、襲撃中・HP0の領土は加算しない。所有権を失えば次の経済解決で対象から外れる。
- 拠点の幸福度内訳に特産品補正を表示する。
- 消費する特殊資源6種は特産品の種類数・幸福度補正には含めない。
- 種族ごとの好物・追加幸福度は**将来対応**。好物の値・定義列は未確定なので、現在は種族別の仮加算を行わない。

## 原本・調整箇所

- 編集原本: `@game_data` の「特産品」シート。変換器へ登録済みで `特産品.json` を生成する。正式データがある場合、旧 `data/manual/特産品仮.json` は混ぜない。
- 列: `名前`、`出現地形`（カンマ区切り、旧JSON配列も可）、`分類`、`採取周期`、`採取量`、`研究区分`、`研究速度補正`、`設定状態`、`最低高度`、`最高高度`、`出現重み`。暫定の地形・研究補正はシート上にも明記する。具体的な高度条件は未確定なので現在は高度指定なし、重みは一旦すべて1。
- **暫定の数値**: `frontend/src/lib/v39-gameplay-balance.js` の `V39_SPECIALTY_BALANCE`（配置率12%、幸福度加算・上限、マス表示サイズ、未発見透明度、ユニット時の右上位置）。
- `V39_SPECIALTY_BALANCE.minimumResourceSites` はマップ全体での各特殊素材の最低地点数（初期値1）。実際の下限はこの値と操作プレイヤー数の大きい方。
- `V39_SPECIALTY_BALANCE.minimumResourceRegionTiles` は地域ごとの素材保証に必要な連続適正マス数（暫定8、0で地域保証を停止）。
- アイコン: `frontend/src/lib/resource-icon-glyphs.js`。Notionの候補は `V39_UI_ICON_CANDIDATES` と `V39_SPECIAL_RESOURCE_ICON_CANDIDATES` に保持する。アイコン候補の存在は資源種類の正式採用を意味しない。
- 参照元: [UI文字アイコン候補](https://app.notion.com/p/3dffa1b30dc98126a39aed1e19ef1249)。ルール本文の正本はこのリポジトリとする。

## 特殊資源の周期採取

### 出現地形の編集場所

- 種類ごとの出現地形は `@game_data` の「特産品」シートの `出現地形` 列で管理する。コードの変数や「地形」シートの産出列には重複定義しない。
- 複数地形は `森, 丘_2, 山岳_3~5` のように入力する。高度なしは制限なし、`_2` は高度2のみ、`_3~5` は高度3〜5（両端を含む）。`湖_-2~-1` のような負の高度、`平地_0` も可。地形名は「地形」シートの名前・別名を使う（`丘` は `丘陵` の別名）。地形名自体は増やさない。
- 地形ごとの高度条件は候補ごとに判定し、別列の最低高度・最高高度が設定されている場合は共通条件としてさらに適用する。旧JSON配列も対応する。
- 現在の暫定設定は次のとおり。下表は説明用であり、変更時はシート原本を編集する。

| 資源 | 出現地形 |
| --- | --- |
| 黒木 | 森 |
| 特木 | 森 |
| 銀鉄 | 山岳・洞窟 |
| 青金鋼 | 山岳・洞窟 |
| 赤黒鋼 | 山岳・洞窟 |
| 銀 | 山岳・丘陵・洞窟 |

- 反映順: シート編集 → 最新XLSXをエクスポート → `scripts/game_data_converter.py --input path/to/game_data.xlsx --sheet 特産品 --dry-run` → 検証成功後に同コマンドから `--dry-run` を外して生成 → 新規マップ生成。
- 実行時の参照先は `data/source/export/json/特産品.json`。既存セーブの配置は変えない。
- マスへの配置率の共通値は `V39_SPECIALTY_BALANCE.placementRate`、各資源の高度条件・出現重み・採取周期・量・研究区分・速度補正はシートで管理する。重みは候補間の相対値であり、資源ごとの独立した配置確率ではない。

- 対象は分類「特殊資源」の黒木・特木・銀鉄・青金鋼・赤黒鋼・銀。死体・魂は対象外。
- 調査で発見済みかつ健全な自領マス1つにつき、基本5経済ターンで1個を所属拠点の資材在庫へ加算。2マスなら同じ周期で2個。未発見・領土外・襲撃中・HP0・溶岩マスからは採取しない。
- 発見/領土取得後、対象拠点の次の経済解決から進捗を加算。1経済解決が1ターンであり、プレイヤー人数や操作回数では短縮しない。同一ターンの重複解決では加算しない。
- 進捗は `players[].factionState.settlements[].specialResourceHarvestByTile` に保存。セーブ/ロードと選択拠点切替で保持。襲撃中は停止、領土喪失・拠点変更時は旧拠点の進捗を破棄し新所有者は0から開始する。
- **暫定**: 木材系は既存の経済研究、鉱石系は鍛冶研究へ接続。カテゴリ内の全項目を完了した研究Lvごとに採取速度+20%。未完了の研究は速度へ加算しない。
- 1ターンの進捗は `1 + 完了研究Lv × 研究速度補正`。周期に達すると採取し、端数は次周期へ持ち越す。速度補正はシート列で変更できる。
- 採取量へ人口・稼働率・施設・幸福度の倍率は掛けない。発見難易度を下げる研究は未実装。
- 資源地点は在庫欄へ「×保有マス数 ⌛次の採取までの残りターン」で表示（複数地点は最短、研究と進捗を反映）し、在庫は選択拠点のもの、特産品の保有数は操作勢力全体のものとする。
- 新規マップは正式シートから6種も配置する。既存セーブに新しい地点を自動追加する処理は行わない。
