# 一般村イベント共通ルール

最終更新: 2026-10-14

## 現行接続

`イベント_一般村.json` の既存納品・周辺討伐依頼を、ID個別分岐から `v39-event-rules.js` の種類駆動処理へ移した。IDは保存・重複防止・クールダウンの識別子として使い、処理の種類は `生成設定.方式` / `目標.タイプ` / `完了効果[].タイプ` から判定する。原本と生成JSONの値は変更していない。

| 項目 | 対応 |
| --- | --- |
| 発生条件 | 一般村友好度、プレイヤー種族。未知条件は成立扱いしない |
| 生成方式 | 村不足資源、周辺脅威 |
| 目標 | 単一の納品、単一の討伐 |
| 対象 | JSONの走査範囲・タグ・好戦的条件・最小/最大対象数で確定 |
| 完了効果 | 一般村友好度変更、村産出資源受取 |
| 失敗効果 | 一般村友好度変更 |
| 再発生 | 再発生フラグとクールダウン |
| 期限 | 受注ターン＋期限ターン。期限で失敗し、進行中のまま放置しない |

- 受注時に解決済み必要量/対象IDと元定義のスナップショットを保存する。定義を更新しても既に受けた依頼の条件・報酬を勝手に差し替えない。
- 詳細を見るだけでは受注しない。既存の土地タブで依頼ボタンから受注する。
- `部分納品:true` の納品目標は、現在の選択拠点の在庫から残り必要量まで納品できる。村へ実際に渡した量と進捗を即時保存する。報酬・友好度は必要量すべての納品後だけ付与する。
- 「納品・報告」で進める。部分納品済み分を再び請求しない。完了・期限後の報酬再受領は拒否する。
- 共通効果処理は未知効果を拒否し、適用途中で失敗した場合は元の状態を返す。
- 数量計算「不足度と村規模」や謝礼の正式係数はまだ未確定。以前の共通バランス値を暫定アダプターとして維持し、JSONに勝手な数値を追加しない。

## 既存機能と残作業

### 採用済みの編集書式（2026-10-14）

イベントの正式な編集原本は `@game_data` の「イベント」1シート、1行=1イベントとする。選択肢・回答・条件・消費・報酬・効果は各セル内で改行し、`1.` / `1-1.` / `1-2.` 等の同じ番号で対応付ける。子選択肢の親は番号から求め、効果等のない番号は省略できる。詳細と例の正本は [`イベントシステム設計.md`](./イベントシステム設計.md) 21節。

これは採用済みの入力ルールであり、シート作成・番号付きセル変換・会話分岐の実装完了を意味しない。既存のJSON納品/討伐と契約等の未対応範囲は引き続き下記の区別を維持する。

仮の警備・建設支援依頼は既存の `config` 定義を維持する。今回の共通処理へ移ったJSONの納品・討伐とは区別する。

契約/定期支払/休息地解放、イベント生成敵、一般村領域内の防衛施設建設、複数目標の順次進行は未対応。`inspectV39EventDefinition` が未対応箇所を返し、不明な条件や効果を無条件化して実行しない。共通基盤を作ったことと、JSONにある全試作イベントの完成を混同しない。

2026-10-14検討案: 魂・死体・作物等を一定期間受け取る代わりに村の守護や力を提供する報酬交渉・継続契約を追加候補とする。1行=1イベントと番号付きセルの入力方式を維持する。生贄と人口/魂/死体の関係、履行判定、数量・期間・周期は未確定。詳細の正本は [`イベントシステム設計.md`](./イベントシステム設計.md) 23-3節。現在の実装済み依頼や試作契約JSONの完成扱いにしない。

同契約の拒否時分岐も検討案として追加: 初回拒否→見逃す/戦闘、戦闘勝利→再交渉、再拒否→見逃す/殲滅。拒否だけで自動攻撃せず、勝利だけで契約成立にしない。初回戦闘の勝利条件は村の戦闘ユニットを全て倒すこと。殲滅対象/人口等への影響は未確定。詳細は同設計書23-4節。ゲーム処理は未変更。

2026-10-14採用: 通常交渉は交渉技能、威圧交渉は威圧技能を主に参照し、方式を選べる。威圧は戦力差/対象戦闘の勝利で有利になる一方、友好度を下げる。拒否後の方式変更も可能とする。具体的な判定式は未確定、処理は未実装。詳細は同設計書23-5節。

同日に追加した方針: 契約された村を訪れる他プレイヤーに、休息ユニットの生贄事件や村からの救援要請が起こり得る。村人口に対して緩やかに上がる強襲威力で、残HP以上の最終ダメージなら拘束、耐えれば逃走/反撃可能。村との戦闘に敗北した対象は死亡/拘束を50%ずつ判定する。契約先のユニットが村へ来たときに捕虜/死体と装備を受け渡し、装備は契約先プレイヤーへ移す。儀式や時間経過だけの自動引き渡しは設けない。村の契約状態と各プレイヤーの事件状態を区別し、発生率・救出等の詳細は検討中。詳細は同設計書23-6節。現在の休息処理やユニットの死亡条件は変更していない。

村事件の分岐条件（採用、未実装）: 上記の契約/来訪/休息条件に加え、村と威圧している契約先プレイヤーとの友好度が高ければ生贄供給、低ければ他プレイヤーへ救援要請とする。訪問者との友好度やプレイヤー同士の関係を参照しない。友好度は-100～+100に制限し、暫定で+20以上は生贄供給、-20以下は救援要請、その間は事件なしとする。境界値は変更可能とし、発生確率は未確定で、契約にない生贄供給は友好度だけでは発生させない。詳細は同設計書23-6節。

休息/救援の追加採用事項（未実装）: 休息は部隊単位で、休息参加メンバー全員が強襲対象。休息開始時に1回だけ発生判定し、各メンバーの防御/残HPで結果を判定する。1体だけをランダムに狙う方式は採用しない。友好度の中間帯は事件なし、契約先本人/同盟相手は強襲対象外。救援は威圧契約解除で成功し、解除後は強襲/引き渡しを停止して村の生存捕虜を解放対象にする。強襲威力は村人口を強襲開始時の対象人数で割った人数から算出し、威力計算後の人数割りはしない。基準威力等の具体値は未確定。詳細は同設計書23-6節。

クエスト完了報酬の追加方針（未反映）: 友好度の暫定標準報酬は+10。依頼した村と達成プレイヤーとの関係に、完了報酬確定時に1回だけ適用し、上限+100に制限する。部分納品/受注だけでは付与せず、他プレイヤーである契約先の友好度を同時に変更しない。クエスト定義の個別値は標準値より優先し、二重加算しない。既存依頼データの報酬変更は別途原本で行う。

## 検証

### 村依頼・悪魔契約の専用仮テスト（2026-10-14）

- タイトルの「テスト操作」→「専用」タブから「村依頼・悪魔契約テスト」を開始する。現在のゲームを専用データへ置き換える確認を出す。土地タブで検証村を選ぶと、依頼と事件の操作を表示する。
- 専用テスト開始時は「村で会話・依頼」モーダルを自動表示する。「悪魔側」に切り替え、「受注: 悪魔の要求…」を選ぶ。受注後は「納品・報告」「依頼完了」へ切り替わり、達成後に「魂を要求」できる。仮契約の成立と依頼の受注は別操作である。
- 閉じた後は村領域内のキャラの行動欄「村で会話・依頼」→「実行」で再表示する。土地タブの村詳細からも開ける。既存の村詳細そのものをモーダルへ移すため、受注/進捗/報酬処理を二重実装しない。
- 会話/取引モーダルのポインター・タッチ・ホイール入力は背後のPhaserへ渡さない。村会話から取引を開くときは会話を閉じ、クリック途中のユニット切替・再描画やモーダルの重なりを防ぐ。
- 行動欄に「村で休息」を追加。詳細を選ぶだけでは実行せず、「実行」で部隊全員にAP30を消費する。全員が村領域内でAPを満たす必要があり、同じ部隊の同ターン重複休息は拒否する。通常村の暫定回復率は最大HPの25%で `config/v39-village-rest.json` に保持。専用テストの強襲率100%は通常村へ適用しない。
- `config/v39-village-incident-test.json` は正式イベントシート未接続の仮定義。通常村や他のテストには自動適用しない。管理対象の生成JSONは変更しない。
- 一般側の食料納品/ウルフ討伐、悪魔側の木材納品/ウルフ討伐を既存の種類駆動の依頼処理へ接続する。仮依頼の完了報酬は友好度+10。部分納品や受注では報酬を付けず、受注前の討伐は新しい依頼の対象にしない。既存の正式/試作JSON依頼に明示されている報酬値は維持する。
- 悪魔側の仮依頼完了で魂要求権2を付与する。「魂を要求」は村へ来訪中に選択でき、村の仮在庫10から操作側拠点の `foodStockByType.魂` へ実物を移す。要求権と村在庫を減らし、重複受領・在庫不足を拒否する。村人から魂を生成する処理や人口消費は未接続。
- 「一般側」「悪魔側」で操作プレイヤーを切り替える。「仮契約を成立」は検証用に契約状態を直接作る。威圧/交渉技能の成否計算、拒否後の交渉分岐、契約の定期履行はまだ実装しない。
- 契約先との友好度は+20以上で生贄供給、-20以下で救援要請、中間帯は事件なし。仮強襲発生率は100%とし、契約なし/契約先本人/指定同盟相手は対象外。部隊休息は地上の操作ターンに行い、参加メンバー全員が村領域内・AP30以上であることが必要。1部隊につき同ターンの休息は1回まで。
- 仮の各人への強襲威力は `160 × sqrt((村人口 / 対象人数) / 50)`、防御を差し引いた整数ダメージを使う。村人口200・対象3人を初期配置し、HP全快なら耐えて反撃、HP1なら全員拘束を確認できる。通常戦闘のスキル威力式と、この仮の強襲防御係数を混同しない。
- 強襲に耐えると「反撃して戦闘」「逃走」を表示する。反撃では村の守備兵を通常の敵一覧へ移し、フィールドの通常攻撃/敵AIで戦う。守備兵を二重生成せず、敵AIは事件の対象プレイヤーを狙う。逃走選択後は通常移動で村を離れる（自動移動や戦闘中の撤退条件は未接続）。
- この村事件で実戦中にHP0となった参加者だけ、50%死亡/50%生存拘束として村の保持一覧へ移す。通常の死体回収が装備を処理する前に確定し、同じ人物/装備を地上と村へ重複して残さない。通常戦闘全体の死亡ルールは維持する。
- 全守備兵を倒した後の「村の戦闘勝利を報告」で生存捕虜を解放し、装備を本人へ戻す。解放者はHP1/AP0・単独へ配置し、生存ユニットと重複しない空きマスを使用する。空きがない場合は解放処理全体を拒否して保持状態を維持する。
- 契約先ユニットが村領域へ来訪したときだけ捕虜/死体と装備を受領できる。装備は受取拠点の既存装備一覧へ、人物は操作不能の `factionState.villagePrisoners` へ保存する。本人の装備は外し、村の保持一覧から除く。受取後の捕虜利用/交換/消費は未実装。
- 救援は専用の「仮操作: 契約解除して救援」で解除を模擬し、友好度+10と村の生存捕虜の解放を確認する。既に他プレイヤーへ引き渡した捕虜は自動返還しない。解除交渉や救援の実際の達成条件へはまだ接続しない。
- 村の契約/事件/要求権/捕虜、受領した人物と装備は既存セーブへ保持する。ロードやプレイヤー切替で再付与しない。

専用回帰は `scripts/check-v39-village-incidents.mjs`。スマホ390/PC1100で、実受注・部分納品・討伐の実戦処理・友好度・魂移転・強襲全員判定・実戦敗北・保存・救出・来訪受領・装備重複防止・救援分岐を確認する。通常村の `check-v39-village-event-ui.mjs` も維持する。

`scripts/check-v39-village-event-ui.mjs` でPC/スマホの実受注・部分納品・保存復元・残り納品・報酬一回性、ID変更に依存しない種類ディスパッチ、未知条件/効果の拒否と期限失敗を確認する。既存の村の警備/建設・輸送・侵入試験も配信用ビルドの回帰へ含める。
