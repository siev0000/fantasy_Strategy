# 一般村イベント共通ルール

最終更新: 2026-10-14

## 現行接続

`イベント_一般村.json` の既存納品・周辺討伐依頼を、ID個別分岐から `v39-event-rules.js` の種類駆動処理へ移した。IDは保存・重複防止・クールダウンの識別子として使い、処理の種類は `生成設定.方式` / `目標.タイプ` / `完了効果[].タイプ` から判定する。原本と生成JSONの値は変更していない。

| 項目 | 対応 |
| --- | --- |
| 発生条件 | 一般村友好度、プレイヤー種族。未知条件は成立扱いしない |
| 生成方式 | 村不足資源、周辺脅威 |
| 目標 | 単一の納品、単一の討伐 |
| 対象 | JSONの走査範囲・タグ・好戦的条件・最小/最大対象数で確定 |
| 完了効果 | 一般村友好度変更、村産出資源受取 |
| 失敗効果 | 一般村友好度変更 |
| 再発生 | 再発生フラグとクールダウン |
| 期限 | 受注ターン＋期限ターン。期限で失敗し、進行中のまま放置しない |

- 受注時に解決済み必要量/対象IDと元定義のスナップショットを保存する。定義を更新しても既に受けた依頼の条件・報酬を勝手に差し替えない。
- 詳細を見るだけでは受注しない。既存の土地タブで依頼ボタンから受注する。
- `部分納品:true` の納品目標は、現在の選択拠点の在庫から残り必要量まで納品できる。村へ実際に渡した量と進捗を即時保存する。報酬・友好度は必要量すべての納品後だけ付与する。
- 「納品・報告」で進める。部分納品済み分を再び請求しない。完了・期限後の報酬再受領は拒否する。
- 共通効果処理は未知効果を拒否し、適用途中で失敗した場合は元の状態を返す。
- 数量計算「不足度と村規模」や謝礼の正式係数はまだ未確定。以前の共通バランス値を暫定アダプターとして維持し、JSONに勝手な数値を追加しない。

## 既存機能と残作業

仮の警備・建設支援依頼は既存の `config` 定義を維持する。今回の共通処理へ移ったJSONの納品・討伐とは区別する。

契約/定期支払/休息地解放、イベント生成敵、一般村領域内の防衛施設建設、複数目標の順次進行は未対応。`inspectV39EventDefinition` が未対応箇所を返し、不明な条件や効果を無条件化して実行しない。共通基盤を作ったことと、JSONにある全試作イベントの完成を混同しない。

## 検証

`scripts/check-v39-village-event-ui.mjs` でPC/スマホの実受注・部分納品・保存復元・残り納品・報酬一回性、ID変更に依存しない種類ディスパッチ、未知条件/効果の拒否と期限失敗を確認する。既存の村の警備/建設・輸送・侵入試験も配信用ビルドの回帰へ含める。
