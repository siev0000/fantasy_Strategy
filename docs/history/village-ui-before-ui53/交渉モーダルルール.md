# 交渉モーダルの現行ルール

- 現行UI 52: 報酬の1種類制限を撤廃。取引と同じバスケットへ金・既知物資・人口を複数追加でき、追加/分類変更で他の品目や数量を置き換えない。個別に数量編集・削除し、選択中の品目だけメーターを表示する。交渉は全品目の合計価値で一度判定し、AP20を1回消費。合意した全品目を受注時に固定し、完了時に一括移転する。一品でも不足すれば納品・報酬移転・完了をすべて取り消す。人口の最低残数は全種族の要求合計で判定し、品目の並べ替えで同ターン再交渉制限を回避できない。旧単独形式の合意・保存データは引き続き読める。UI50/51の「1種類」は廃止仕様。


- 現行UI 51: UI50の報酬専用インライン選択画面は廃止。現在の取引と同じ `tradePickerModalHtml` と `v39-trade-picker.js` で「＋→ヘッダー直下の全画面物資選択→決定」を表示する。分類タブ/検索/物資名/数量メーター/固定の決定位置/背景ロック/フォーカス循環/Escを共用。報酬画面本体も `v39-trade-baskets` の2列構成（達成条件／相手への要求）とし、取引用スタイルを共用する。人口候補と報酬1種類の制限だけを呼出元データとして渡し、通常取引の対象や契約処理は変えない。


- 現行UI 50: 報酬変更は依頼カードの「交渉」で一覧から専用表示へ切り替える。チェック操作では画面を切り替えない。「依頼一覧」でチェック・入力値を保持して戻る。物資選択・アイコン右上の数量入力・選択時のメーターは通常取引の `tradeResourcePicker` / `tradeBasketHtml` / `tradeAmountEditor` を共用する。金・既知物資と人口から1種類を選び、交渉/脅迫を選択して固定フッターで要求する。AP20・受注前のみ・合意期限5ターン・受注時固定・相手の在庫非公開は維持する。

## 表示

- 現行UI 49: 一覧に出す新規依頼は村計画と実際の進捗から生成するものだけ。イベント会話の選択肢由来の依頼候補を追加しない。会話・交渉テストも固定の依頼を埋め込まず、実際の不足/脅威を配置して通常の生成処理を使う。過去の会話式依頼は旧保存の完了互換に限る。

- 現行UI 48: すべての依頼は同じ一覧で左側のチェックを使って複数選択し、フッターからまとめて受注・報告する。チェック時に別画面や会話の選択肢へ移動しない。受注時の自動納品/別の納品チェックは廃止し、受注後のチェックから支援・報告する。友好度は文字へ戻し、達成条件を共通物資アイコン＋数量にする。下記UI 46/47の詳細切替・単一受注・即時納品チェックは履歴であり、この現行仕様で置き換える。

- UI 47: 依頼カード全体を選択対象にし、カード内に「この依頼を選ぶ」等の操作ボタンを置かない。Enter/Spaceでも選択できる。受注/報告は固定フッターで確定し、単一の受注/完了選択肢を持つ会話付き依頼も同じ場所へ集約する。複数の固有分岐は勝手に選ばない。物資依頼の「受注のみ」ボタンは「受注時に物資を渡す」チェックへ置き換え、オフなら受注だけ行う。これは一括受注のチェックボックスではなく、村ごとの受注枠は変更しない。
- 報酬は共通アイコンと数値だけを表示する。金・資源のglyph/colorは `resource-icon-glyphs.js` を共用し、人口/友好度も同じ定義元から取得する。名称・人口の種族等はtitle/aria-labelへ保持する。物資がなくても友好度報酬があればそのアイコンだけ表示し、「物資報酬なし」の重複枠は置かない。

- UI 46: クエストは生成元を問わず「依頼一覧」の共通カードで表示する。「村からの依頼」と「会話・依頼」の別リストを作らない。会話が必要な依頼を選択した場合だけ一覧から詳細へ切り替え、「依頼一覧へ」で共通一覧へ戻す。受注中は同じカードに進捗・期限・報酬を表示し、会話付きの依頼も詳細を再表示できる。内部の番号付きセルや生成方式はプレイヤー向けの分類名にしない。

- `negotiation_hub_fixed_layout.html` を基準とする。村の交渉は「会話 / クエスト / 取引 / 情報」の4タブだけで切り替える。同じ目的の上部ショートカットは重複するため置かない。参考HTMLの仮の相場・台詞・依頼は実データとして移植しない。
- フィールドに重ねる既存の専用モーダルを使用する。村と取引は同じ会話表示部品を使用する。
- 村会話モーダルは画面全体を使用する。外側/ダイアログのpaddingは0、外枠線と角丸はなし、幅720px・高さ92dvhの縮小制限は使わない。ヘッダーと上段の会話は固定し、下段の選択肢/本文だけスクロールする。会話カード/操作ボタン自身の余白は別に維持する。
- 相手は上段の右に人物・左に茶色の発言、自分は下段の左に人物・右に青色の発言。既存ユニット画像の上側を切り出し、新しい人物画像データは作らない。村の代表は村ごとに自動生成・保存したleader（村長/族長/リーダー）を使用する。守備兵と別枠の交渉専任NPCで、守備兵不在・補充で人物を変えない。画像は村の種族と既存クラスの画像を共用する。
- 相手のセリフは上、自分の返答は下。既存依頼/取引の結果を発言へ反映し、直近30件の履歴を折りたたんで表示する。
- 自軍の生存する地上キャラから交渉役を変更できる。村の会話では村領域内のキャラを候補にする。取引の交渉役と物資運搬の担当者は別であり、交渉役の変更で運搬担当/部隊を変えない。
- 画面を閉じるだけでは取消・受注・成立にしない。同一画面セッション内では会話位置と取引入力を保持する。新しいマップの生成でUI記憶を消す。会話文/未送信入力のセーブ保存は未対応。
- 元の資源ヘッダー、画面見出し、人物と現在の会話、4タブ、下端の閉じる/実行ボタンは固定。会話をスクロール本文の外に分離し、下段の選択肢/クエスト/取引/情報だけをスクロールする。タブ切替時は下段だけを先頭へ戻す。現在の会話は高さを制限し、長文の全文は下段の情報タブ内の会話履歴で確認する。高さ520px以下では会話領域と余白を縮め、下段の操作領域を確保する。PCは横幅を活用し、参考HTMLの430px上限や小さい文字サイズをそのまま使わない。背後のマップへの入力伝播を遮断する。
- 会話タブは用件を選んで下端ボタンで実行する。襲撃は追加確認する。通常依頼はクエストタブで内容選択→受注→納品・報告。番号付きイベントの依頼一覧/戻る/回答も同じタブ内で実行する。
- 情報タブに人口/守備/所属/実際の村計画、交渉役選択/スキル/会話履歴をまとめる。未実装の相場や安全な経路を事実として表示しない。
- 村の取引タブには既存の取引rendererを直接マウントする。提案/その村との取引一覧、提供/要求の2列、物資選択モーダル、配送・日程の折畳みを使用。物資一覧はアイコン+数量だけの固定高の独立スクロール。数量は常にアイコン右上1箇所の直接入力で表示し、選択中でも消さない。選んだ物資1種類だけ、一覧の下の固定位置にメーター/増減/削除を出し、名前・数量を再表示しない。未選択時・選択物資の削除後は操作欄を空にし、別の物資を勝手に選ばない。配送・日程には配送設定のみを置き、物資アイコン/数量/収入/維持費の重複行を出さない。初回予約在庫/期日までの収入/維持費が不足する見込みは物資アイコンの「!」で示し、押すと固定ステータス欄に理由を出す。予測は配送欄の開閉に依存せず、数量/日程/拠点/在庫変更で更新する。下端の実行は共通の取引処理を呼び、代理クリックしない。マップで待ち合わせ位置を選ぶ間だけ画面を退避し、選択/取消後に戻る。
- 他プレイヤーなどとの独立した取引画面は維持し、人物/会話/スキルは「会話・スキル」に折りたたむ。会話・資源・取引のルール計算や未送信入力は共用し、重複実装しない。
- 提供物資は自国の出発拠点に在庫または収入があるものだけを表示し、追加時も再判定する。右上は「選択数/保有数」。通常生産・特殊資源の周期収入・特産品の貸出可能数を判定に使う。要求物資は自国が知っている物資だけを表示し、相手の在庫・収入・保有特産品を候補判定に使わない。基本資源は最初から既知、特殊資源と特産品は自軍の所持・発見・成立済み交換履歴から記憶する。要求側は要求数量だけを表示し、相手の保有数・収入・不足警告は出さず、ゲージ上限も相手に依存させない。未承諾の提案や無関係な他国の取引からは物資を学習しない。資材名はカーソル/フォーカス/選択時に共通欄へ表示する。独立取引と村ハブで共用する。
- 物資の追加は両側の見出し横の＋。配送は自国/相手の使者か双方待ち合わせを選び、待ち合わせだけ申込側による共通場所の詳細指定を出す。通常は使者1部隊だけで相手拠点に赴いて受渡す。詳細は `取引・郵送・貿易ルール.md`。

## APと確定

- 最新合意: NPCへの交渉・威圧判定は暫定AP20。AP0案は撤回する。数値は `config/v39-negotiation.json`。
- 会話の閲覧、依頼の受注/報告、取引条件の編集、プレイヤー相手の提案/承諾はAP0。スキル使用はそのスキルのAP。村の休息AP30は別ルールのまま。
- 現行でAP20を接続している判定はNPC資源取引の承諾判定、村の備蓄追加交渉、NPC取引の再開交渉。既存の交流/属国化/守護者の条件付き譲渡をすべて確率交渉へ置き換えた意味ではない。
- 判定前に確認を出し、拒否でもAPを消費する。入力不備・AP不足・同条件の再試行は判定前に拒否し、追加消費しない。拒否した取引で予約物資を差し引かない。
- 同じ村への同一条件の交渉は、同ターンに再判定できない。提案IDや交渉役を変えても回避できない。次ターンまたは異なる条件で再判定する。
- 試行は `factionState.negotiationAttempts` に保持し、取引の交渉役は `contract.negotiatorId`。旧提案の交渉役は運搬担当から補完する。

## スキル

- 会話の選択肢に混ぜず、別の「スキル」欄に出す。詳細・AP・使用後AP・交渉AP不足を表示して「使用を確認」で確定する。
- 初回対応は習得済みAスキルの即時自己強化。対象が自身、交渉/威圧の補正、効果時間があり、既存の支援スキル判定を満たすものだけを出す。
- 発動待機/魔法の詠唱が必要なスキル、相手への魅了/精神干渉、会話から攻撃する分岐は未対応。未対応スキルを即時発動へ勝手に変換しない。
- 実行は既存戦闘エンジンを使用し、AP・同スキル1ターン1回・CT・持続効果を共有する。交渉値には未失効の交渉/威圧補正を加える。
- 正式原本へ交渉用Aスキルを新設したわけではない。候補がなければ0件と理由を表示する。検証用スキルは自動テスト内だけで用意する。
