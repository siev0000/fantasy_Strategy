# 一般村イベント共通ルール

最終更新: 2026-10-21

## 現行の依頼生成元（UI 49）

- 新しい依頼は、村計画と実際の物資不足・守備力を超える周辺脅威・建設に必要な資材から生成する。シートの役割は村計画/依頼ひな型の定義であり、イベント会話の選択肢を別の依頼候補として出さない。
- クエスト一覧からイベント会話JSON由来の候補追加を削除した。専用テストの固定quests/numberedEventsも廃止し、通常の村計画生成を共用する。
- 会話・報酬交渉テストでは実際に食料備蓄を不足させ、村付近へ守備力を超えるウルフを配置する。固定の「食料20」「ウルフ2」等の依頼を別経路で追加しない。物資と脅威が解消すれば、未受注の候補もなくなる。
- 村の実行中/待機中の計画のうち、ひな型に対応する実際の支援不足がある計画を参照する。同じ討伐ひな型からウルフ依頼を二重に作らない。
- 既に保存された古い会話式依頼の報告・支払いは互換処理として維持するが、新規受注の一覧には追加しない。生成JSONやスプレッドシート原本を直接削除・改変したものではない。
- 検証: scripts/check-v39-progress-quests.mjs。390/1100で会話・交渉テストを実際に起動し、村計画由来の物資/討伐のみ、討伐1件、問題解消時に候補0件、チェック一括受注/保存/報告/未達時の巻戻しを確認。

## 現行: 一括受注と共通一覧（UI 48）

- 全依頼の左側に受注・報告用チェックボックスを置く。自動生成/番号付き会話を区別せず、選択しても別画面へ移動しない。複数選択後、フッターの「まとめて受注（件数）」で確定する。
- 受注中の依頼にも同じチェックを置き、選択した依頼を「まとめて支援・報告」できる。受注だけでは物資を納品せず、即時納品用の別チェックは廃止。受注前・受注中の混合選択時は「受注・報告」と明示する。
- 村ごとに1件の旧制限を撤廃し、questLogByPlayerIdへ依頼別の目標・期限・進捗・報酬・元定義を保存する。旧questsByPlayerIdは互換用の参照として維持し、旧セーブの受注も取り込む。同じ依頼の重複受注は禁止。
- 受注/報告は選択分を一つのトランザクションとして扱い、途中で条件不足なら選択分全体を未変更にする。各依頼は元の条件・消費・報酬・固有回答を使い、判定を飛ばさない。
- 期限失敗・警備/建設進捗・別プレイヤーとの計画重複・廃村化は、最後に選択した依頼だけでなく全受注記録へ適用する。
- 友好度報酬は「友好度 +10」の文字表示。物資報酬は共通アイコン＋数値を維持し、達成条件を「達成条件: 🌾20」「達成条件: ⚔2体」のように表示する。
- UI 49: 専用テストで同じウルフ2体を指す番号付き討伐例を削除。食料補給・ウルフ討伐・木材補給の3件を使用し、処理元ごとの重複依頼を出さない。旧セーブの受注済み記録は維持するため、専用テストを再開始して新しい配置で確認する。
- 検証: scripts/check-v39-quest-batch.mjs。390/1100で3件同時受注、ウルフ依頼1件、画面切替なし、保存復元、個別の物資/討伐報告、期限・警備並行進捗、途中失敗の巻戻し、旧セーブ移行を確認する。

## 履歴: 選択と受注・報酬表示（UI 47、UI 48で置換）

- 依頼カードをクリック/タップ、またはEnter/Spaceで選択するだけでは受注しない。カード内の選択ボタンを廃止し、受注/納品/報告はフッターへ統一する。
- 会話付き依頼は詳細を開いた後、単一の受注/完了選択肢をフッターから実行する。元の選択肢の条件・消費・返答・報酬を共用する。複数の分岐がある場合は本文で選択し、自動選択しない。
- 受注時の即時納品は「受注時に物資を渡す」チェック（初期ON）で選ぶ。物資が不足していれば表示せず、受注後に支援する。旧「受注のみ（後で支援）」ボタンは置かない。複数依頼の同時受注は追加しない。
- 報酬は共通アイコン＋数量。資源名/人口の種族/友好度はtitle・aria-labelで確認できるようにする。金等のシンボル色も共通定義へ合わせる。報酬が友好度のみならそのアイコンだけを表示し、物資報酬なしの枠は出さない。

## 依頼一覧の統一（UI 46）

- 村の自動生成依頼と番号付き会話の依頼を同じ一覧・同じカードにまとめる。名前・目標・報酬・期限・選択ボタンを共通表示し、「会話・依頼」の追加一覧は村モーダルに表示しない。
- 会話付きの依頼を選ぶと一覧を隠して詳細へ切り替える。「依頼一覧へ」で戻り、受注中カードから詳細を再開できる。詳細から戻る操作で受注や進捗を消さない。
- 表示統一であり、受注上限・固有の選択肢/条件・部分納品・報酬計算・保存形式は変更しない。既存の受注/完了処理を再利用し、代理クリックや別の報酬処理を追加しない。
- 実装: `v39-village-hub.js` の共通カードと `v39-village-dialogue-ui.js` の共通候補取得/明示選択API。テスト用の表示名から「会話テスト」の実装都合を除く。

- 下記の過去の検証記録にある魂要求・悪魔専用依頼は旧仕様。このテストを開始し直すと新仕様になる。過去の受注状態を含むセーブや、他の旧依頼原本まで一括変換するものではない。

## 現行接続

### 村の計画と自動依頼（2026-10-20）

#### 手動で試す専用テスト

- 起動はローカルセッションと専用マップを直接生成し、別テスト経由のマップ再生成は行わない。接続済みキャンバス/アクティブシーン/入力の準備を待ってから支援者・村を描画し、カメラ変更時に描画を明示更新する。起動中の再押下は同じ処理を共有する。処理中/データ不足/起動失敗ではテスト操作を残し理由を表示する。

- タイトルの「テスト操作」→「専用」→「鉱床・道具・部隊支援」→「村の計画・支援テスト」。現在のゲームを置き換える確認が出るので、必要なら先に保存する。
- 墓地建設/食料不足/討伐支援/守備兵不在の4村、各村に担当支援者、十分な物資を持つ自軍拠点を配置する。開始時点からシート由来の実計画・依頼・訓練を提示する。テスト専用の依頼完了処理は作らない。
- 開始後は墓地の村の「交流」欄。受注ボタン→「納品・報告」で支援し、「1T経過」で着工/完成を確認する。他の村へはフィールド上の村を選ぶか、「テスト」→「専用」の4つの村選択ボタンを使う。村選択ボタンは対応支援者を選択してカメラと交流欄を切り替えるだけで、移動や納品・撃破を代行しない。
- 食料の村も通常の受注/納品を使う。討伐の村では先に受注し、南の実在ウルフを通常の移動・戦闘で倒して戻り「依頼完了」で報告する。守備兵の村は初期状態で補充訓練中。シートの訓練期間（現在3T）が経過すると通常軍1部隊が補充される。
- 配置/Lv/最低移動力は `config/v39-village-plan-test.json`。操作支援者4体はLv30・移動120以上。死体は通常の期限を持ち、専用マップの自然災害だけ抑止する。セーブにマップ識別と計画・村を含め、読込後も村選択を使える。
- `check-v39-village-plan-playable.mjs` はタイトルの実ボタンから起動し、390/1100で4計画の提示、実受注/納品、討伐対象固定、3T後の完成/補充、保存読込後の村選択を検証する。自動試験では討伐戦闘そのものの完走は代行していない。

#### データと実行ルール

- 原本は引き続き「イベント」1シート。10〜15行に村計画6件、16〜17行に依頼ひな型2件を置く。新しいシートは作らない。V:ACの「計画対象/優先度/判定基準/工程/支援依頼ID/対象範囲/数量上限/目標ターン」は見出し注記を参照。
- 有効な計画は周辺安全確保・守備隊補充・食料備蓄・墓地建設。教会は現行効果に不浄除去がないため試作、奪還は所有履歴が未接続のため試作とする。試作行を実行対象へ含めない。
- 専用変換器は「村計画.json」「村依頼ひな型.json」も生成する。通常の番号付き会話とは出力を分けるが、納品・討伐・友好度・セーブは既存処理を共用する。新規計画の進捗を原本へ書き戻さない。
- 村のターンごとに共通生産計算による実収入と維持費を在庫へ反映し、優先度順で主計画表示1件・待機表示2件を保存する。既存の訓練・建設中の工事は緊急計画へ切り替えても進む。建設場所を他勢力に取られた工事は進めない。
- 食料は目標ターン分の備蓄不足を検知するが、純収入で目標期間内に解決できる場合は支援を依頼しない。守備隊補充は既存の実訓練を参照し、訓練期間は守備隊計画の目標ターン（未設定時のみconfig）を使う。
- 墓地計画は領域内の実在する有機死体/死体資源を契機とする。施設の費用・条件・枠・建設上限・工期・通常キュー処理を共用し、条件不足を無視して建てない。資材不足の1種類を上限以内で依頼し、納品分を実在庫へ加える。完成施設を共通フィールドと墓地保護判定へ反映する。
- 周辺の生存・敵対的な敵から脅威を抽出する。守備側/敵側の簡易戦力比較で村が劣る場合のみ討伐支援を生成する。受注時に対象ID/数量を固定する。守護者や別ワールドの敵は対象外。
- 同じ計画の支援を別プレイヤーへ同時に受注させない。報酬は暫定友好度+10、期限15T・再受注5T。UI 48以降は村ごとに複数依頼を並行受注できる。受注後の対象消滅は既存討伐の対象ID判定を使い、撃破者別の貢献判定や未達依頼の自動取り下げは未対応。
- 旧固定の穀物50/木材50/ウルフ3体の3行は無効化。悪魔向け修繕物資の個別イベントと参考4行は維持し、受注済み旧依頼は保存内容から継続できる。通常一覧の旧補給/警備/建設支援は新規提示せず、計画由来の依頼を提示する。専用事件テストは従来どおり。
- 交流欄に現在計画・工程・残り工期を表示する。専用の計画一覧モーダル、種族別の信仰施設選択、村研究の自動進行、貢献度別報酬、長期バランスは後続。

検証: `check-v39-village-plans.mjs` は不足数量生成/実納品/友好度/二重報酬防止/通常費用と工期の建設/同T重複防止/途中保存/共通施設反映/実在討伐対象/自力対応可能な脅威の依頼抑止を確認する。

### 番号付き会話の接続範囲

- `v39-village-dialogue.js` が共通会話進行と既存の受注/納品/討伐/友好度/資源処理を接続する。別のクエスト在庫や友好度を作らない。
- 村領域内の地上の生存者がいる操作ターンに実行する。通常の会話・受注・報告はAP不要。交渉/威圧/スキルのAPは既存ルールのまま。
- 友好度/種族/資源保有/受注済み/討伐達成を条件として扱う。未知の条件・効果、特産品の貸出など在庫と異なる資源は成功扱いしない。
- 単一納品はシートの消費量と既存の納品消費を二重請求しない。番号付きは一括納品、従来の部分納品依頼は従来のまま維持する。
- 指定討伐は受注時の生存対象を固定する。受注前に倒された対象は使わない。暫定範囲は `V39_QUEST_BALANCE.villageNumberedHuntRange`。全ワールドの任意の討伐数カウンターとは区別する。
- 報酬は村の実在庫から支払う。魂は既存の `soulStock` を使い、人口から自動生成しない。報酬不足なら納品・完了・友好度も含めて元に戻す。
- 受注定義と会話定義のスナップショット、適用済み番号をプレイヤー別/村別/実行ID別に保存する。原本更新後も進行中の条件を変えず、戻る/保存/再開で再支払しない。再発生はクールダウン後に新しい実行IDを作る。
- 同じ既存モーダル内で一覧/選択肢を切り替える。回答は既存の上下会話へ出し、元の資源ヘッダーを取引と共用する。

専用テスト「村依頼・悪魔契約テスト」の **会話テスト: 木材納品 / ウルフ討伐 / 悪魔の修繕依頼** から確認できる。原本の参考例とは別の固定テストデータである。

`イベント_一般村.json` の既存納品・周辺討伐依頼を、ID個別分岐から `v39-event-rules.js` の種類駆動処理へ移した。IDは保存・重複防止・クールダウンの識別子として使い、処理の種類は `生成設定.方式` / `目標.タイプ` / `完了効果[].タイプ` から判定する。原本と生成JSONの値は変更していない。

| 項目 | 対応 |
| --- | --- |
| 発生条件 | 一般村友好度、プレイヤー種族。未知条件は成立扱いしない |
| 生成方式 | 村不足資源、周辺脅威 |
| 目標 | 単一の納品、単一の討伐 |
| 対象 | JSONの走査範囲・タグ・好戦的条件・最小/最大対象数で確定 |
| 完了効果 | 一般村友好度変更、村産出資源受取 |
| 失敗効果 | 一般村友好度変更 |
| 再発生 | 再発生フラグとクールダウン |
| 期限 | 受注ターン＋期限ターン。期限で失敗し、進行中のまま放置しない |

- 受注時に解決済み必要量/対象IDと元定義のスナップショットを保存する。定義を更新しても既に受けた依頼の条件・報酬を勝手に差し替えない。
- 詳細を見るだけでは受注しない。既存の土地タブで依頼ボタンから受注する。
- `部分納品:true` の納品目標は、現在の選択拠点の在庫から残り必要量まで納品できる。村へ実際に渡した量と進捗を即時保存する。報酬・友好度は必要量すべての納品後だけ付与する。
- 「納品・報告」で進める。部分納品済み分を再び請求しない。完了・期限後の報酬再受領は拒否する。
- 共通効果処理は未知効果を拒否し、適用途中で失敗した場合は元の状態を返す。
- 数量計算「不足度と村規模」や謝礼の正式係数はまだ未確定。以前の共通バランス値を暫定アダプターとして維持し、JSONに勝手な数値を追加しない。

## 既存機能と残作業

### 採用済みの編集書式（2026-10-14）

イベントの正式な編集原本は `@game_data` の「イベント」1シート、1行=1イベントとする。選択肢・回答・条件・消費・報酬・効果は各セル内で改行し、`1.` / `1-1.` / `1-2.` 等の同じ番号で対応付ける。子選択肢の親は番号から求め、効果等のない番号は省略できる。詳細と例の正本は [`イベントシステム設計.md`](./イベントシステム設計.md) 21節。

これは採用済みの入力ルールであり、シート作成・番号付きセル変換・会話分岐の実装完了を意味しない。既存のJSON納品/討伐と契約等の未対応範囲は引き続き下記の区別を維持する。

仮の警備・建設支援依頼は既存の `config` 定義を維持する。今回の共通処理へ移ったJSONの納品・討伐とは区別する。

## 報酬表示と変更要求（2026-10-21）

- 通常依頼と単一目標の番号付き依頼に、現在の物資報酬・友好度報酬を表示する。物資報酬が未設定なら「物資報酬なし」と明記し、原本にない金を自動追加しない。
- 依頼選択後/受注前に「報酬の変更を要求」を開き、金・既知の物資、または村の種族の人口と数量を指定する。数量は入力とメーターで変更。人口は全プレイヤーが要求でき、通常のpopulation/populationByRaceへ受け取る。隷属・捕虜の別分類や魂への自動変換は作らない。
- 村領域内の生存交渉役で交渉/脅迫を行う。AP20、同ターン同条件は再試行不可。脅迫は威圧技能と戦力差を使い友好度-5、通常は交渉技能を使う。成功率・報酬価値・人口価値・提示有効期間等はconfig/v39-quest-rewards.jsonの暫定値。脅迫失敗で自動戦闘へは移行しない。
- 相手の在庫量や成功率を表示しない。要求候補は自国の既知物資を使い、村にないから候補を消すことはしない。魂は新しい物資要求の候補から除外する。提示量が用意できない場合も変更拒否として返す。
