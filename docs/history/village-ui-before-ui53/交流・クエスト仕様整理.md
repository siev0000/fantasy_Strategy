# 交流・クエスト仕様整理

確認日: 2026-10-21

現行UI 49: 新規依頼は村計画と実際の不足/脅威からのみ生成する。イベント会話の選択肢から候補を追加する旧方式は廃止。以下の番号付き会話に関する記録は旧保存の報告・支払い互換の説明で、新しい受注方式ではない。

## この資料の位置付け

現行コードと既存ルールを照合した確認用資料。**現状と整理案を区別する。整理案は未実装・未承認であり、この資料の作成によるゲーム動作の変更はない。**

詳細な数式・データ編集方法は末尾の個別ルールを参照する。既存資料に日付付きの追記や「未実装」が混在している場合、本資料では通常実装・試験実装・今後の案を分けて読む。

## 1. 用語と担当範囲

| 項目 | 役割 | 現状 |
| --- | --- | --- |
| 交流タブ | フィールド上の接触対象と操作の入口 | 村の操作ボタンも残っており、モーダルと重複 |
| 会話 | 相手の話や状況を見る | 村モーダルの「会話」タブ |
| 交流という行動 | 食料を使って村の友好度を上げる | 成否抽選ではなく、支払いによる関係改善 |
| 交渉・脅迫 | 報酬や取引条件の承諾を求める | 対応場面では技能・友好度等を使って判定 |
| クエスト | 依頼を受注し、目標達成後に報酬を得る | UI 46で一覧・カード表示を統一。内部の生成方式は維持 |
| 取引 | 双方の提供・要求と受け渡し条件を決める | クエスト報酬とは別の契約・運搬処理 |
| 物流 | 継続する物資ルートと運搬者を管理する | 左の独立タブ。会話の入口ではない |

「会話」「クエスト」「取引」は同じ村モーダルから操作できるが、内部の契約・受注・報酬処理まで一つになっているわけではない。

## 2. 現在の画面

村の共通モーダルは **会話 / クエスト / 取引 / 情報** の4タブ。

| タブ | 現在ある内容 |
| --- | --- |
| 会話 | 村の様子、交流、部隊で休息、属国化、襲撃 |
| クエスト | 通常依頼の選択・受注・支援・報告、番号付き会話依頼、対象依頼の報酬変更要求 |
| 取引 | 自国の提供、相手への要求、物資選択、数量、配送・日程、契約の確認 |
| 情報 | 村人口・Lv・守備・所属・計画、村長、性格、交渉担当、使用可能な支援スキル、会話履歴 |

- 元の資源ヘッダーを上に残す。会話表示とタブは固定し、下側の内容だけスクロールする。
- 村長は村ごとに生成・保存する交渉用NPC。守備兵とは別枠で、現在は非戦闘員。
- 性格は初回にランダム設定し保存。一人称・二人称・台詞をシートから使う。性格によるAI・成功率の変化は未実装。
- 会話履歴は画面セッション内の保持であり、村長・性格・受注状態と同じ保存対象ではない。

**残る重複:** フィールド下部の交流欄にも、村の休息・交流・依頼・属国化・襲撃などがある。一方、放浪者の勧誘・守護者関連・廃村への再入植は、この欄に残る独自機能。

## 3. 行動の費用と判定

| 行動 | 現行の費用・条件 | 注意 |
| --- | --- | --- |
| 会話の閲覧・条件の編集 | 基本APなし | 選択肢に消費条件がある場合はその定義を適用 |
| 依頼の受注・納品・報告 | 操作自体の追加APなし | 納品物や選択肢固有の消費は必要 |
| 交流による関係改善 | 設定値分の食料 | 交渉技能による抽選ではない |
| 部隊で休息 | 参加者各AP30 | 全員が村領域内でAPを満たす。同部隊の同ターン重複不可 |
| 報酬変更の交渉・脅迫 | 交渉役AP20 | 同ターン・同対象・同条件の再試行不可 |
| NPCとの取引交渉 | AP20 | プレイヤー間の承認操作とは別扱い |
| 交渉支援スキル | 各スキルのAP・使用制限 | 対応する自己強化を使用。すべての戦闘スキルを使えるわけではない |
| 属国化 | 友好度60以上等 | 現在は条件達成型。報酬交渉と同じ成否抽選ではない |
| 襲撃 | 独立した敵対行動 | 脅迫を拒否されただけで自動実行しない |

友好度は-100～+100。クエストの友好度報酬は個別定義を優先する。「標準+10」は全旧データを一括上書きした意味ではない。

## 4. クエストの流れ

```text
依頼を見る
  → 必要なら報酬の変更を要求する
  → 受注する（目標と合意報酬を固定）
  → 納品・討伐等を進める
  → 支援・完了報告
  → 完了時に報酬を一度だけ受け取る
```

### 通常の村依頼

- 村の計画と実際の不足・脅威から候補を生成する。食料確保・守備補充・墓地等の計画が接続されている。計画案すべての完成を意味しない。
- UI 48以降は村ごと・プレイヤーごとに複数件を並行受注できる。全種類を同じチェックボックスで選び、まとめて受注・報告する。
- 討伐は受注時に対象IDを固定する。受注前の討伐を新しい依頼の実績にしない。
- 物資依頼は定義が許す場合に部分納品できる。報酬は全量完了後。
- 必要物資があれば「受注して支援」で同じターンに完了できる。「受注のみ」も可能。途中失敗ではまとめて元に戻す。
- 期限がある依頼は、期限ターン以上で完了不可。村のターン処理で失敗状態へ移し、定義された失敗効果を適用する。

### 旧番号付き会話の依頼（新規候補としては廃止）

- シートの `1`、`2`、`1-1` 等で選択肢・返答・条件・費用・報酬を対応させる。
- 受注と完了の選択肢は別。単純な物資依頼では、受注後の「物資を支援」から既存の完了選択肢を実行できる。
- 固有の返答・費用・条件を維持する。複数の報告分岐を勝手に選ばない。
- 未対応の条件や効果を無条件成立として扱わない。複合目標や任意の契約効果まで汎用実行できる状態ではない。

**UI 46で修正:** 通常依頼と番号付き依頼は共通の「依頼一覧」に同じカードで表示する。会話付きの依頼を選ぶと詳細に切り替わる。内部の進行・保存や受注枠まで一括で変更したものではない。

**UI 47で修正:** カード内の選択ボタンを廃止し、カード全体で選択・フッターで受注/報告する。報酬は共通アイコンと数値に統一。「受注のみ」の別ボタンは即時納品チェックに置換。会話付き依頼の単一受注/完了操作もフッターから行う。複数受注には変更しない。

**現行UI 48:** UI 46/47の別詳細画面・単一受注・即時納品チェックを廃止。左のチェックで全種類を複数選択し、まとめて受注する。受注中も一覧でチェックして報告する。全依頼の進捗・期限・報酬は個別に保存する。友好度は文字へ戻し、達成条件を共通アイコン＋数量で示す。

## 5. 報酬変更の現行仕様

| 項目 | 現在の扱い |
| --- | --- |
| 対象 | 通常依頼と、単一目標・完了選択肢1件の番号付き依頼 |
| 変更時期 | 受注前のみ。受注後は変更不可 |
| 要求内容 | 金・既知の物資、または村の種族の人口と数量 |
| 人口の資格 | 悪魔限定ではなく、どのプレイヤーも要求可能 |
| 人口の分類 | 通常人口として受け取る。隷属・捕虜等の新分類は設けていない |
| 判定 | 交渉または脅迫。脅迫は威圧等を参照し友好度-5 |
| 拒否 | 現在の報酬条件を維持。自動戦闘にはならない |
| 合意の有効期間 | 未受注の提示は5ターン。受注時に依頼へコピーして固定 |
| 受け取り | 完了時、村の実在庫・人口から選択中の自軍拠点へ移す |
| 不足 | 事前予約なし。完了時に払えなければ納品・完了・報酬を確定しない |
| 最低人口 | 報酬で村人口を0にしない |
| 元の報酬 | 変更時は旧物資報酬との二重支払いを防ぎ、友好度報酬は維持 |

原本に物資報酬がない依頼へ、金を自動追加してはいない。人口から魂への変換、通常取引での人口交換、武器や配下を報酬として選ぶ機能は今回の実装に含まれない。

専用村テストの「悪魔の要求」と魂要求ボタンは廃止し、両プレイヤーが通常依頼の報酬交渉で人口を要求する形へ変更（UI 44）。その他の旧依頼・過去セーブには魂要求権・魂在庫を使う経路が残る。新しい要求候補には魂を出さず、人口報酬に変更した場合は旧魂報酬を置き換える。**旧データの魂方式をすべて人口方式へ移行した状態ではない。**

## 6. 取引・事件・別系統の境界

| 系統 | 実装状況・区別 |
| --- | --- |
| 通常取引 | 提供・要求、使者、待ち合わせ、予約・収入確保、物理運搬。クエストの即時報酬移転とは別 |
| 特産品取引 | 在庫の消費ではなく保有効果の期間貸出。初期期間10ターン |
| 村の継続守護・生贄契約 | 仮契約を作るテストと事件処理はある。通常の交渉から契約締結・定期履行まで完成していない |
| 生贄・救援事件 | 専用テストで休息時の強襲、実戦、拘束・受渡し等を確認可能。通常イベント全般へ完成済みとはしない |
| 拒否後の戦闘・再交渉 | 採用した設計案はあるが、報酬変更の拒否から自動で接続されてはいない |
| 洞窟ドワーフ | 購入・製作・納品・討伐・階層依頼の別実装。村共通モーダルへの統合は未実施 |
| 守護者・覇権地 | 専用の依頼・友好・取得処理。一般村依頼とは別 |
| 放浪者・国家外交 | 勧誘や国同士の関係を扱う別の処理。村の会話と同一ではない |

| 管理先 | 内容 |

主な実装元: `v39-world-population.js`（入口）、`v39-village-hub.js`（共通画面）、`v39-neutral-village-rules.js`（通常依頼）、`v39-village-dialogue.js`（番号付き会話）、`v39-quest-rewards.js`（報酬変更）、`v39-village-plans.js`（村計画）。UIだけ追加して同じルールを複製しない。

## 8. 整理後の構成案（確認用・未実装）

1. **交流タブは接触の入口にする。** 相手・所属・友好度・受注状況と「話す」を表示。村の受注や休息ボタンをここにも重複して置かない。
2. **操作は共通モーダルの4タブへまとめる。** 会話で通常交流と敵対行動、クエストで受注と報酬、取引で物資交換、情報で村の状況を扱う。脅迫は独立タブにせず、対応する交渉の方式として選ぶ。
3. **依頼の見せ方を共通化する。** 自動生成・番号付きの区別をプレイヤーへ押し付けず、依頼名・目標・進捗・期限・報酬・受注状態を同じ様式で表示する。固有会話は残す。まず表示統一し、内部ルールの無理な一括置換はしない。
4. **村以外は段階的に接続する。** 放浪者・守護者・洞窟イベントの固有条件を維持し、必要なところから共通画面を使う。すべてを通常村の処理へ押し込まない。

### 次に決めること

| 優先 | 確認事項 | 整理案 |
| --- | --- | --- |
| 1 | 上記の画面分担でよいか | 入口は交流、操作はモーダルの4タブ |
| 2 | 通常依頼・番号付き依頼の受注枠 | UI 48で並行受注・共通チェック選択へ変更済み |
| 3 | 基本報酬と支払い保証 | 原本に標準報酬を明記する。完了時不足を許す現行方式を維持するか、受注時に村側で取り置くか決める |
| 4 | 旧魂報酬の移行 | 人口報酬へ寄せるか、旧専用テストだけに残すか決める。魂化は別スキル |
| 5 | 通常交流・属国化の交渉化 | 食料による関係改善・友好度条件を維持するか、AP20の交渉判定へ統一するか決める |

## 9. 仕様確認に使うテスト

「テスト操作」→「専用」→「村・交流テスト」から「会話・報酬交渉」を開始する（旧「村長・交渉総合テスト」）。会話・依頼・報酬変更・取引・村長・交渉役を確認する。開始すると現在のゲームを置き換えるため、必要なら事前保存。

同じ分類内の「村の計画・支援」で危機から依頼を作る流れ、「契約・強襲・救援」で仮契約・強襲・受渡しを確認する。性格の台詞プレビューを表示できても、その台詞に対応するゲーム行動がすべて実装済みという意味ではない。分類全体は[専用テスト構成](./専用テスト構成.md)を参照。

本資料作成時はコード・設定・既存資料の照合のみ。ゲーム動作の変更や、新たな実機操作検証は行っていない。
