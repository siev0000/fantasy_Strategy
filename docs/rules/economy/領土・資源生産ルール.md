# 領土・資源生産ルール

最終整理: 2026-10-03

この文書は、領土マスから得る資源収入、人口による稼働率、土地用途、施設による生産補正をまとめる個別ルールである。
現行v39では人口許容、雇用枠、拠点共通稼働率、土地用途倍率、施設補正を領土収入へ接続済みである。`data/source/export/json/地形.json`、`施設.json`、`都市基本データ.json` を正本として利用し、同じ内容をコード側へ固定値として重複定義しない。

---

## 1. 基本方針

### 都市特化の条件・補正（UI99 / 2026-10-24）

- UI99: 条件と必要規模を満たした都市特化だけを拠点→運用→都市専門化に表示する。選択済みの特化は条件を失っても現在の選択として残す。未解禁の候補は非表示。切替待機中は解禁済みの他候補を無効表示にし、残りターンを記載する。
- 未確認の変更可能候補がある拠点は、左の拠点一覧右上に黄色の `!`。選択拠点のヘッダーには `! 都市特化を変更可能` ボタンを表示し、押すと運用ページの都市専門化を開き、候補へスクロールする。自動で画面やモーダルは開かない。確認済みでも変更可能ならヘッダーボタン自体は残し、`!` だけを消す。
- 拠点ごとの `citySpecializationSeenIds` に確認済み候補IDを保存する。都市専門化が実際に表示されているときに、その時点で変更可能な候補だけを確認済みにする。非表示パネルの再描画・概況を開くだけ・待機中では確認扱いにしない。既読の候補は残し、新たな候補IDの解禁で再通知。既読履歴のない旧セーブは未確認として表示する。
- 新規候補の `!` は開いた候補内では確認の目印として残し、閉じる/別タブ/別拠点へ移動すると消す。他拠点・他プレイヤーの確認履歴は変更しない。待機中は一覧/ヘッダーへ変更通知を出さず、待機終了後に未確認の変更候補があれば通知する。非表示ワールドの条件判定はそのワールドの土地・地形を参照する。
- 確認: `scripts/check-v39-city-specialization-notices.mjs`（390/1100px）。一覧/ヘッダー/候補の通知、ワンクリック導線、確認と再表示、画面外再描画、新解禁、拠点分離、切替待機/終了、未解禁非表示、既読保存を検証する。

- UI98: 原本の `幸福度補正 / 治安補正 / 軍隊上限補正` を `幸福度 / 治安 / 軍隊` へ改名し、既存値を引き継いだ。旧名の別列やJSON専用項目は残さない。AA:AIへ `ヒーロー / イベント設定 / 道路発展数 / 環境安定度 / 穢れ / 効果範囲 / 常時発動スキル / 耐性 / 災害耐性` を追加。未指定の新規数値は0、文字列は空欄、効果範囲は所属領土を既定とする。既存の生産技能・EXP・運搬・召喚Lv補正は維持。
- `ヒーロー / 軍隊` は既存の保有上限へ加算。国の補正と共存し、英雄誕生枠・同時訓練枠は変えない。幸福度・治安は既存目標への加算。回復は最大HP百分率ポイント。浄化値は毎ターン `浄化−穢れ` を1回適用し、既存下限−20を維持する。
- `効果範囲` は空欄/`所属領土` なら当該拠点の自領全体、`中心0` は中心のみ、`周囲2` は中心からヘックス距離2以内の所属領土。同一ワールドに限定する。常時スキル・浄化・回復・都市耐性・災害耐性・現地の環境安定度に使用する。保有枠・生産・研究等の拠点全体補正は範囲で分割しない。
- `常時発動スキル` は `守護精神/索敵強化` のようにスキル一覧のP名を指定する。範囲内の自軍に一時的に適用し、範囲外・別ワールドでは解除。既に習得している同名スキルと重複せず、再評価しても累積しない。HP/地形/攻撃手段等の条件は既存パッシブ判定を共用する。自身/部隊全員を対象とする対応済みPが対象で、発動元個体が必要な他部隊員指定や未対応条件は設定注意を表示する。Aスキルの自動使用・攻撃の自動連射は行わない。
- `耐性` は `炎20/氷10`。共通属性名とユニット戦闘の固定減少＋割合軽減を共用し、都市規模Lvを防御側Lvとして領土攻撃へ適用する。耐性貫通も既存方式。住民/駐留ユニットにはこの列を直接付与しない。耐性100なら無効化可能、通常の領土被ダメージ軽減だけの場合は従来の最低1を維持する。
- `災害耐性` は `山火事=50/落雷嵐=-20`。災害シートの名前またはIDを指定し、被害へ `max(0,1−値/100)` を掛ける。正数で軽減、負数で弱点。既存の産出低下・治安被害、火山/溶岩の土地・施設・備蓄・収容人口被害へ接続。住民ユニットへの直接ダメージは既存の個体耐性を使い、この列では変更しない。火山/溶岩の炎被害には都市の炎耐性も適用する。
- `環境安定度` は0基準の環境安定度目標への加算（0〜100）。当該領土が自然災害の発生元に選ばれた際、気象等を計算した発生率へ `1−安定度/100` を掛ける。強制発生・魔法設置は抑制しない。毎ターンの拠点状態へ目標と有効値を保存する。
- `道路発展数` は毎ターン整備できる自領マス数。未整備マス→既存道路の順、中心に近い順で道路1→2→3へ進める。海/湖/火山/溶岩/壁や特殊資源等のあるマスは除外。地形を上書きせず `roadDevelopmentByTile` へ保持し、移動AP計算では道路地形の移動コストを使用する。高低差・壁・飛行・過積載制約は維持。ターン重複処理を防ぎ、保存復元に対応。道路0なら領土走査を省略する。土地の領土状態に道路段階、拠点に整備済みマス数を表示する。
- `イベント設定` は既存イベント会話のIDを `/` 区切り。`ID=25` は毎ターン25%で候補、IDのみは100%、0は候補にしない。拠点ID/ターン/イベントIDによる固定抽選で再読込の再抽選を防ぐ。既存の発生条件/クールダウン/実行方式は変えない。拠点には候補IDを保存・表示し、一般村の既存会話候補では指定IDの抽選結果を使用する。自都市専用の新イベント定義や自動実行アダプタを追加する機能ではない。
- 数値内訳は都市専門化の選択中/レアごとに表示。ユニット共通能力画面には都市常時スキル名、補正のある能力には都市加算の説明を表示し、共通スキル画面にも一時付与Pを表示する。不正な属性/災害名/イベントID/範囲/Aスキルは候補の設定注意として表示し、無条件効果には変換しない。
- 確認: `scripts/check-v39-city-area-effects.mjs`（390/1100px）。名称と数値、範囲・別ワールド、常時Pの条件/同名/累積/解除、実領土攻撃の属性耐性、災害耐性/弱点、浄化−穢れ、枠加算、道路整備と移動AP、自然災害抑制、実火山被害、既存村イベント候補への接続、実経済ターン、保存復元。

- UI97: 「都市」N:Zへ `農業 / 林業 / 漁業 / 工業 / 魔術 / 浄化 / 回復 / 研究EXP補正 / 訓練EXP補正 / 軍隊上限補正 / 運搬容量補正 / 交渉 / 召喚Lv補正` を追加。各ヘッダーの注記に単位と適用先を記載。通常14種とレア3種の数値を読み込み、空欄は0として共通計算する。値の変更はシートで行う。
- 農業・林業・漁業・工業は、拠点生産の有効技能へ加算する技能ポイント。直接の産出百分率ではなく既存の技能→生産計算を使う。通常都市の旧食料/資材倍率は交易都市を除いて0へ変更し、技能加算との二重補正を避けた。レアの既存倍率は維持。
- 魔術は所属拠点の研究担当者の魔法研究用技能へ加算。研究EXP補正は全研究の毎ターンEXPへの百分率。ユニット自身の永続技能や能力は書き換えない。
- 訓練EXP補正は当該施設の拠点で、基礎EXP＋教官加算の合計へ百分率適用する。教官本人の報酬は増やさない。軍隊はその拠点での軍隊保有上限への加算で、同時訓練枠は変更しない。
- 運搬容量補正は所属拠点の運搬者の積載容量への百分率。採取・洞窟輸送・物流・取引・過積載移動・取引UIで共用。交渉は所属拠点の交渉技能へ加算し、威圧には適用しない。
- 召喚Lv補正は施設の所属拠点、またはスキル召喚者の所属拠点から取得。施設/四属性完成/国の補正に加算する。候補条件は補正前Lv、生成Lvと費用は補正後Lvを使う。所属IDがない旧ユニットは選択拠点を使い、存在しない所属IDから他拠点へは補正を流さない。
- 浄化はその拠点の領土マスへ毎ターン1回加算する。回復はその領土上の自軍の自然回復率へ加算する最大HP百分率ポイント。施設/発見地形の回復と共存し、既存の移動・戦闘・飢餓・危険地帯の回復条件を維持する。
- 確認: `scripts/check-v39-city-specific-effects.mjs`。生産技能、魔法/全研究EXP、訓練、軍隊と英雄枠の分離、積載と取引速度、交渉と威圧の分離、施設/スキル召喚と費用、浄化の範囲/二重適用防止、実ターン回復、保存復元を検証。

- 原本は `@game_data` の「都市」シート。通常14種類とレア3種類の条件・数値を正式な運用列へ接続。`data/source/export/json/都市.json` は最新XLSXから同シートだけ生成する。都市名による倍率分岐、未知の特化/特性への一律ボーナスは廃止。
- G:M列は `必要拠点Lv / 食料産出補正 / 資材産出補正 / 幸福度 / 治安 / 領土被ダメージ軽減 / 切替待機T`。補正列の空欄は0。食料/資材/軽減は百分率、幸福度/治安は目標値への加算。最低規模は行ごとに参照し、未設定の旧データだけ設定値3（都市）へフォールバックする。数値一覧はシートを正本とし文書へ複製しない。
- 条件列は `/` または改行でAND。研究条件例 `魔法Lv:3以上` は拠点Lvと国の研究到達Lvの高い方を使用。未知の条件/不正数値は解禁しない。
- `人口:100以上` は当該拠点の人口、`農場数:3以上` はその拠点に属する領土に配置済みの農場のあるマス数。工事予定・他拠点・他国の施設は含めない。`周辺地形:海|湖` は中心+周囲1マスで候補のいずれかがあること。`ワールド:洞窟` は拠点の `cave:` ワールド、`住民系統:アンデッド` は最多人口の住民種族を既存アンデッド判定へ渡す。`都市特性:浮遊` は既に持つ特性を要求し、浮遊特性を自動付与しない。
- 通常特化は拠点につき1つ。初回は即時選択でき、選択時に条件を判定する。条件が後で変わっても特化は維持。現在選択中の特化の `切替待機T` が過ぎてから次へ切替可能。同じものの再選択は待機期限を延ばさない。旧セーブに選択ターンがない場合、遡って待機を課さない。
- レア特性の固定抽選は従来のIDハッシュ/20%設定を維持し、選ばれる最低規模と補正は行から参照。保存済みのレア特性は保持する。食料・資材倍率は通常特化とレアごとに乗算、幸福度/治安/軽減値は加算。未知の特性や遺産名だけでは追加補正を与えない。
- 幸福度は種族別目標へ、治安は治安目標へ直接加算。国補正・研究・施設と共存し、既存の追従速度と0〜100制限を維持。領土生産は既存の雇用率・技能・住民状態計算後に特化倍率を適用。
- 領土被ダメージ軽減はその拠点に所属する領土に限定し、他勢力と野生敵の領土攻撃を同じ関数で軽減する。軽減合計は0〜90%、被ダメージは四捨五入し最低1。ユニットへの攻撃・災害ダメージには適用しない。従来の `cityDefenseBonus` 保存だけで終わらせず、実際の領土攻撃へ接続する。
- 拠点→運用→都市専門化で、候補名/数値補正/条件/未達理由/切替待機を表示。選択ID・選択ターン・レア特性は従来のセーブ項目で保持する。
- 実装: `v39-city-specialization-rules.js`、`v39-civic-rules.js`、`v39-economy-rules.js`、`v39-faction-territory-assault.js`、`v39-enemy-raiding.js`、`v39-settlement-ui.js`。確認: `scripts/check-v39-city-specialization.mjs`（14種の解禁、拠点の分離、原本数値の変更反映、重複、目標値、領土襲撃、待機、保存、スマホ/PC表示）。
- 未実装: NPCが特化を自動選択する方針、遺産3種類の恒久効果、レア固有アクション、放浪/水上/空中都市の名称に対応する移動や浮遊機能。今回は数値補正だけを運用し、名称だけで追加機能があるとは扱わない。

### 国データの共通補正（UI95 / 2026-10-24）

- 実装済み: 国全体の補正を `player.factionState.countryBonuses` に保持し、未指定は0。信仰システムや専用選択画面は一旦作らず、後で方針・信仰・イベントからこの補正へ接続する。既存の体制12候補は削除・再編せず、値の自動付与もしない。
- `happiness`: 符号付き数値。自国の全拠点の種族別幸福度目標へ加算する。幸福度を即時に書き換えず、従来のターンごとの追従/0〜100制限を維持。既存の施設・研究・特産品補正と加算し、拠点の内訳には「国」と表示する。
- `heroLimit`: 0以上の整数。既存のヒーロー保有上限へ加算。軍隊上限、英雄誕生枠、人口・素材・訓練条件は変更しない。上限を減らしても既存ユニットは削除せず、以後の作成判定へ反映する。
- `summonLevel`: 0以上の整数。すべての新規召喚の生成Lv補正。
- `summonLevelByFamily`: 系統名をキーとする0以上の整数の辞書。系統は既存の `resolveV39SummonFamily` に従う（火精霊/水精霊/風精霊/土精霊/アンデッド/デヴィル/エンジェル）。全般＋該当系統の値を、既存施設ボーナスに加算する。例: 全般1、火精霊2なら火精霊+3、他は+1。
- 召喚候補や複数体選択の上限は補正前Lvで従来どおり判定。施設/スキル召喚の両方へ適用し、呼集や既に生成したユニットには適用しない。施設召喚の金費用・維持費は補正後の実Lvに従う。召喚詳細では施設補正と国補正を区別する。
- 国の実行時データであり、種族別の初期値を持つ「勢力」シートや、既存の `nationPolicy.modifiers` のコピーではない。原本・生成JSONに新たな値は入れていない。今後、シートから付与する場合は原本で項目と適用元を確定してから接続する。
- 正規化・参照は `frontend/src/lib/v39-country-bonuses.js` に集約。旧セーブは0、`player-state.js` の再構築/JSONセーブでも保持する。他国には影響せず、NPC勢力にも同じ計算を使用。
- 確認: `node scripts/check-v39-country-bonuses.mjs`。未設定/不正値・幸福度の正負・実経済ターン・ヒーロー上限と軍隊不変・施設/スキル共通の召喚系統・実プレビューLv/金費用・入力非破壊・保存復元を検証する。
- 見送り: 信仰専用画面、信仰12候補の効果量、英雄の生存/死亡判定、崇敬対象選択、変更条件と期間、国の方針選択UI。都市ごとの方針は別タスク。

### 拠点からの開拓（2026-10-03）

- 通常土地の取得は、ユニットの移動・調査から切り離して拠点の開拓で行う。調査は資源・遺跡・残留品などの発見と既存の危険度低下に使う任意行動。通常土地の領土化には調査・危険度0・ユニットの滞在を要求しない。
- 拠点タブの「開拓」で地図の黄色の候補を選び、担当人数・工期を確認して開始する。陸地はその拠点に所属する健全な自領に隣接した探索済みマスが対象。離れた土地は新拠点等を起点として広げる。
- 海・湖は完成した船着き場の周囲1マス、港の周囲2マスを対象とする。起点の施設はその拠点の自領に属し、破壊・略奪されていないこと。建設中施設は起点にしない。範囲は施設マス基準であり、海の領土を取得しただけで水域の開拓範囲を延長しない。
- 対象マスに生存モンスターや他勢力ユニットがいる間は開拓不可。死体は障害にしない。他勢力領土・一般村とその範囲・勝利対象土地は通常開拓では取得できず、従来の専用条件を維持する。
- 開拓中は担当人数を生産要員から外す。人口・種族構成・食料維持消費は変えず、備蓄資材の直接消費は追加しない。余剰人口で担当できるなら生産は減らない。
- 敵侵入、起点施設の喪失、人口不足などで条件を満たさなくなった場合は進捗を保持して停止。そのターンは担当者を生産へ戻し、条件を満たすと自動再開する。中止時も担当者を即時に戻し、計画を削除する。
- 暫定値: 1件10人・2ターン・1拠点同時1件。`V39_LAND_EXPANSION_BALANCE` に集約。担当人数・工期は計画開始時に保存する。
- 通常の経済ターンで1回進行し、最終工事ターンも生産要員を外す。完了後は対象を資源化の自領としてその拠点へ所属させる。新しい土地の生産・収容力の経済計算は次ターンから。画像には「開」と残りターン（停止中は停止）を表示する。
- 計画は各プレイヤーの各拠点の `landExpansionProjects` に保存し、セーブ/ロードする。NPC勢力も同じ候補・費用・進行条件を使う。

- 領土を所有しているだけで、その土地が常に最大産出を出すわけではない。
- 拠点人口を、その拠点の領土で働くための就業人口として扱う。
- 土地には「人口許容」と「雇用枠」を別々に持たせる。
- 人口が増えるほど雇用枠を埋められるため、領土全体の産出量が増える。
- 全雇用枠が埋まった後は、人口だけが増えても既存領土の産出量はそれ以上増えない。
- さらに産出を増やすには、領土拡張、土地用途の変更、または生産施設の建設が必要になる。
- フィールド上のユニットは拠点人口へ加算せず、就業人口としても数えない。ユニットの維持消費は人口成長・食料不足ルール側で別途計上する。

## 2. 土地用途と雇用枠

領土タイルは現在の土地用途ルールに従い、`資源化` と `居住化` を持つ。

| 土地用途 | 人口許容 | 雇用枠 | 産出倍率 |
|---|---:|---:|---:|
| 資源化 | +5 | 10人 | ×2.0 |
| 居住化 | +15 | 5人 | ×1.0 |

- 村・町・都市・大都市の中心となる拠点タイルは、従来どおり居住化扱いとする。
- 土地タブの「居住化解除」から、追加の居住化マスを2ターンで資源化へ戻せる。拠点本体の占有マスと発展工事で使用中のマスは解除不可。
- 居住化完了時に、そのマスの完成施設と建設待ちを撤去する。施設HP、拠点の施設一覧・効果、世界側の施設一覧も削除する。変更前に撤去対象と資材が戻らないことを確認ポップアップで知らせ、キャンセル時は変更しない。
- 居住地から施設への変更も確認後に建設を開始できる。拠点本体の占有マス、発展工事に使用するマス、土地用途変更中のマスには施設を建設できない。居住化解除時も確認を行う。
- 完成施設・建設中施設があるマスの土地用途は `施設.json` の `土地用途` を参照する。現在は `居住化` とし、人口許容+15、雇用枠5、基礎産出倍率1.0を使う。村画像は表示せず、施設画像・建設中表示を使う。
- 人口許容はその拠点が保持できる人口量に使用する。
- 雇用枠はその土地の資源産出を最大まで稼働させるために必要な就業人口量を表す。
- 資源化は人口を住まわせる能力が低い代わりに、雇用枠と資源産出が大きい。
- 居住化は人口許容が大きい代わりに、雇用枠と資源産出は小さい。

人口許容は土地用途だけでなく、拠点規模の収容力も加算する。

```text
拠点の人口許容
= 全領土マスの土地用途による人口許容
+ (拠点規模の1マス収容人数 × 実際の占有マス数)
```

- 拠点規模の `1マス収容人数` と `占有マス数` は `施設.json` の拠点規模行を正本とする。
- 町の2マス、都市の3マス、大都市の7マスは、表示だけでなく拠点規模の収容力にも使用する。
- 領土または拠点占有マスが損傷している場合、そのマス由来の人口許容は残HP割合に応じて低下する。
- 居住化では土地用途分が `+15`、資源化では `+5` となるため、資源化から居住化した場合は人口許容が1マスにつき10増える。
- 居住化したマスは、元の地形・高低差・森林や山の画像を維持したまま、暖色の敷地区画を土地用途レイヤーとして重ねて表示する。地形データそのものは変更しない。拠点本体の占有マス以外で居住化が完了したマスには、既存の村画像を表示する。
- 居住化・資源化の変更中は対象マスへ変更先の頭文字と残りターンを表示する。完成施設と建設中施設は `建築_アイコン一覧1.webp / 建築_アイコン一覧2.webp` を4列×3行で分割し、施設名に対応する画像を村画像と同程度の60pxで対象マスへ表示する。建設中は半透明画像と残りターンを表示し、画像対応がない施設だけ施設名の先頭1文字へフォールバックする。
- 拠点発展時は現在の占有マスを固定したうえで、必要な追加マスを地図上から手動選択する。候補は同じ拠点に属する自領の居住化マスで、既存占有マスと連結し、施設・建設・土地用途変更がないマスに限る。
- 水上マスも地形だけでは発展候補から除外しない。領有、居住化、連結、空きマスの条件を満たした場合は拠点占有マスとして選択できる。
- 選択マスに村・町など既存の下位拠点規模マスが含まれる場合、再利用した1マスにつき発展工期を1ターン短縮する。新規の居住化マスは短縮せず、短縮後の工期は最低1ターンとする。短縮値は `V39_SETTLEMENT_DEVELOPMENT_BALANCE` を調整箇所とする。

## 3. 就業人口の自動配分

土地ごとに住民を手動配置する操作は行わない。
拠点人口と、その拠点に所属する全領土の雇用枠から共通の稼働率を算出し、自動的に全生産マスへ反映する。

```text
総雇用枠
= 拠点に所属する各領土マスの雇用枠の合計

稼働率
= min(1, max(0, 拠点人口 - 進行可能な開拓担当人数) / 総雇用枠)
```

例:

```text
拠点人口 50人
総雇用枠 60人

稼働率 = 50 / 60
       = 約83.3%
```

この場合、対象拠点の生産マスは原則として同じ約83.3%の稼働率で計算する。
開拓担当者がいない場合、人口が60人へ到達すれば100%稼働となり、それ以上人口が増えても同じ領土構成のままでは生産量は増えない。

## 4. マス収入の基本式

領土マスの資源収入は次を基本式とする。

```text
マス実収入
= 地形の基礎産出
× 土地用途倍率
× 稼働率
× 施設補正
```

- 地形の基礎産出は `地形.json` の各資源列を参照する。
- 土地用途倍率は、資源化なら `2.0`、居住化なら `1.0`。
- 稼働率は拠点人口と総雇用枠から自動算出する。
- 施設補正は対象土地または拠点に有効な `施設.json` の効果を参照する。
- 現行実装に残る経済全体の暫定スケール値は、このルールの基礎設計とは分けて扱う。

例:

```text
地形基礎産出: 穀物10
土地用途: 資源化 ×2.0
雇用枠: 10人

就業0人相当   → 稼働率0%   → 穀物0
就業2人相当   → 稼働率20%  → 穀物4
就業5人相当   → 稼働率50%  → 穀物10
就業10人相当  → 稼働率100% → 穀物20
```

## 5. 施設による生産強化

土地は人口と土地用途だけでなく、施設を建てることでさらに産出効率を伸ばせる。
施設定義の正本は `data/source/export/json/施設.json` とする。

施設では少なくとも以下のデータを参照する。

- `施設名`
- `条件地形`
- `影響範囲`
- 必要な都市能力Lv
- 建設コスト
- `農業`
- `林業`
- `漁業`
- `工業`
- `生産力`
- `土地用途`（施設のあるマスの人口許容・雇用枠・基礎産出倍率）
- その他、施設ごとの効果列

### 5-1. 生産施設の例

現行 `施設.json` には、土地の資源生産を伸ばす施設として以下が定義されている。

| 施設 | 条件地形 | 影響範囲 | 主な生産補正 |
|---|---|---|---|
| 農場 | 平地 | 単体マス | 農業 +100 |
| 伐採場 | 森 | 単体マス | 林業 +100 |
| 採石場 | 丘 | 単体マス | 工業 +100 |
| 鉱山 | 山 | 単体マス | 工業 +100 |
| 港 | 海辺 | 単体マス | 漁業 +100 |

対応技能が100なら施設補正は2.0倍になる。施設マスは居住化の基礎産出1.0倍なので、対象資源は `1.0 × 2.0 = 2.0倍`、補正対象外の資源は1.0倍となる。他の条件が同じなら、対象資源は施設なし資源化マスの2.0倍と同量であり、そのさらに2倍ではない。
倍率用の重複列は追加せず、既存の `農業 / 林業 / 漁業 / 工業 / 生産力` を使う。編集原本はスプレッドシート `@game_data` の施設シートであり、JSONだけに列を追加しない。

- `条件地形` を満たす土地に建設する。
- `影響範囲=単体マス` の効果は、その施設が置かれたマスだけへ適用する。
- `影響範囲=全体` の施設効果は、定義された効果に応じて拠点全体へ適用する。
- 生産施設を建てても雇用枠を無視して最大産出になるわけではない。まず人口による稼働率を計算し、その上で施設補正を掛ける。
- 施設は1マスにつき1つまでとし、完成施設または建設中施設があるマスには別の施設を建設できない。
- 施設画像は対象マス中央へ村と同程度の60pxで表示する。
- 居住化の工事中は村画像を50%の半透明で予告表示し、中央より少し上に `🔨2T` の形式で残りターン数を表示する。文字は領土線・選択枠より上。居住化で撤去予定の完成施設・建設待ちの画像は工事中に重ねない。通常の施設建設にも同じ建築マーク付きターン表示を使う。

### 5-2. 施設補正の扱い

資源カテゴリに対応する施設効果は `都市基本データ.json` の対応技能と `施設.json` の効果値を参照する。
基本的な生産補正は次の考え方とする。

```text
施設補正
= 1 + (生産力 + 対象資源に対応する生産技能) / 100
```

例:

```text
農場
農業 +100

対象となる農業資源への施設補正 = ×2.0
```

複数の施設効果が有効な場合の加算・適用範囲は、`施設.json` の数値と `影響範囲` を正本として処理する。

## 6. 人口成長との循環

この生産ルールは `人口成長・食料不足ルール.md` と接続する。

```text
人口が増える
↓
雇用枠をより多く満たせる
↓
領土収入が増える
↓
人口・ユニット維持消費を差し引いた余剰が増える
↓
人口成長ゲージが貯まる
↓
さらに人口が増える
```

ただし総雇用枠が100%埋まると、人口だけでは生産量が増えなくなる。
その後は次のいずれかが必要になる。

- 領土を拡張して新しい雇用枠を得る。
- 居住化から資源化へ切り替えて生産能力を高める。
- 対象土地へ生産施設を建てて施設補正を得る。

このため、人口増加だけで無制限に資源収入が増える構造にはしない。

## 7. 領土修復

略奪・損傷などで通常産出が停止した領土は、修復対象として扱う。
同時に修復できる領土数は、拠点の鍛冶能力と拠点規模で決める。

```text
同時修復可能な領土数
= 鍛冶Lv + 拠点の規模Lv
```

- 拠点規模Lvは `施設.json` の `規模Lv` を正本とする。
- 現行値は、村1 / 町2 / 都市3 / 大都市4。
- 例: 鍛冶Lv2の町なら、同時に4マスまで修復できる。
- 修復コスト・修復ターン数・複数候補がある場合の優先順は、既存データ・ルールに定義がなければ別途決定する。

## 8. 実装前に残る確認事項

- 農業・林業・漁業・工業は生産項目であり、`種族.json.className` と対応する `クラス.json` の対応技能値を人口加重し、生産倍率表へ換算して求める。稼働率は人数補正、生産項目倍率は資源種別ごとの技能補正として別々にタイル収入へ掛ける。技能35を100%とし、定義された節点間を直線補間する。ユニットの能力値は未接続であり、現時点では拠点タブに表示する。

- 災害・占領・領土損傷時に稼働率または施設効果をどの段階で低下させるか。
- 修復コスト・修復ターン数・修復対象の優先順位。

これらは別途決定するまで、通常の人口・雇用枠・施設補正ルールを共通基準とする。

## 9. 領土外採取・船着き場（2026-10-02・周辺漁業は実装済み）

### 領土外での採取（実装済み / 暫定ルール・2026-10-02）

- キャラの「行動」一覧に「採取」を追加。現在地の森から木材系資源、洞窟から石材・金属・貴金属・宝石系資源を採取する。地形名と基礎産出は `地形.json`、資源分類は `都市基本データ.json` を参照する。非発見の隠し洞窟は参照しない。
- 暫定採取量は `地形の基礎産出 × 既存収入スケール(0.1)` の1ターン分。技能・人数・施設・拠点稼働率は掛けない。森の現行データなら木材10・黒木7・特木3。資源定義をコードへ重複保持しない。
- 暫定APは1回100（`v39-gameplay-balance.js` の `V39_GATHER_BALANCE.apCost`）。AP不足・死亡・待機・調査中・自動輸送中は不可。実行時に即座に採取・AP消費・行動済み記録を行う。満載で何も積めない場合はAPを消費しない。積める範囲だけ取得する場合は通常のAPを消費する。
- 獲得資源は既存の部隊共有 `cargo.resourcesByType` へ積載する。単独・輸送指定者は `cargoByUnitId` に個別保持する。既存のSIZによる運搬上限を利用する。拠点在庫へ直接加算せず、帰還時の既存搬入処理へ接続する。
- 暫定で自領・他勢力領土はどちらも対象外。領土収入と採取の二重取得を避ける。1マス1ターン1回まで（全プレイヤー共通）。採取済みターンは各プレイヤーの探索データへ保存し、全プレイヤー分を確認する。ロード後も同ターンには再取得できず、次ターンに採取可能になる。
- 資源枯渇・地形変化・技能/人数補正・食料採取・集積所との自動採取往復は未実装。恒久的な枯渇は現段階では設けない。

### 軍隊ユニットの輸送指定（実装済み）

- 拠点タブの「輸送」で、選択拠点の占有マス内にいる生存軍隊ユニットを輸送用に指定・解除できる。領土全体ではなく、拠点中心とその中心へ紐づく付属占有マスを対象とする。
- ヒーロー・ネームド・死亡ユニットは新規指定の対象外。輸送用に指定したユニットは通常の部隊移動から除外し、本人を選択した場合は単独で手動移動できる。
- 指定状態は個体の `transportAssignment` に拠点ID・指定ターン・`status=awaiting-route` を保存し、セーブ/ロードでも保持する。自動往復が開始済みという意味ではない。
- 拠点外や死亡後も元の拠点の輸送一覧へ残し、解除できる。解除時に積載物や部隊所属を変更せず、通常の部隊移動へ戻す。既存の部隊共有運搬品と単独の個体別運搬品は保持し、自動輸送用への分配はまだ行わない。
- 指定だけでは移動しない。搬入先・資源を選択して「往復開始」を押すと、下記の拠点間輸送を行う。

### 拠点間の自動往復（実装済み / 2026-10-02）

- 拠点タブの「輸送」で、指定軍隊ごとに同じプレイヤーの別拠点と運ぶ資源を選ぶ。瞬時の共有在庫ではなく、出発拠点から搬入先への実物輸送と空荷帰還を繰り返す。他プレイヤーへの交易・郵送ではない。
- 担当プレイヤーのターン終了時、残りAPで移動する。全員のターンが終わった場合だけAPが通常通り回復する。同じ個体の輸送処理は同じターンに1回まで。自動往復中の個体は未行動確認から除外し、手動で待機したターンは輸送しない。
- 出発拠点の占有マスで積み込み、搬入先の占有マスで荷下ろしする。運搬上限は既存の `resolveV39UnitCargoCapacity` を使う。積み込み分だけ元在庫を減らし、到着時だけ搬入先の在庫へ加える。食料を選んだ場合も搬出されるため、出発拠点の食料備蓄には注意する。
- 1ターンには片道の移動だけを進め、到着したら次ターンから帰還する。帰還後の再積み込みも次ターンに行う。積み下ろしの追加APは現段階では設けない。
- 移動AP・地形の通行条件・高度差・世界端の折返し・生存ユニットのマス占有は通常移動と同じ。通行不能・輸送先消失時は荷物を保持して待機し、次ターンに経路を再探索する。在庫切れなら出発拠点で待ち、補充後に再開する。
- 荷物は部隊の `cargoByUnitId` に個別保持する。既存の部隊共有 `cargo` を勝手に分配・転送しない。死亡時は個別荷物を死体の運搬品へ移す。状態・荷物・処理済みターンはセーブ/ロードでも保持する。
- 「往復停止」で自動移動を止める。拠点の占有マスにいる場合は荷下ろしし、拠点外なら積載物を保持する。積載中は搬入先変更・輸送指定解除を禁止し、停止後に手動で拠点へ戻して荷下ろししてから変更・解除する。
- 森・洞窟での手動採取は上記のとおり実装済み。集積所の建築・保管と採取地点を指定した自動往復は、引き続き未実装。

### 集積所の後続案（未実装）

- 調査済みの無所属1マスへ集積所を建て、一時保管から輸送ユニットが拠点へ運ぶ案。人口・周辺領土・自動収入を持たせない。
- 建築中の担当ユニット拘束、中断・再開、費用、工期、保管上限、集積所を輸送先にする接続は後続仕様として整理する。拠点間自動往復の実装だけでは、集積所を実装したことにはしない。

### 船着き場・港の定義

編集原本 `@game_data` の施設シートへ追加し、`施設.json` を再生成済み。採取資源・採取範囲は周辺漁業の収入計算へ接続済み。必要拠点段階と改築処理はまだ未接続。

| 施設 | 必要拠点段階 | 採取資源 | 採取範囲 | 建築時間 |
| --- | --- | --- | --- | --- |
| 船着き場 | 村以上（仮） | 魚 | 周囲1マス | 1ターン（仮） |
| 港 | 町以上 | 魚 | 周囲2マス | 既存の2ターン |

- 海・湖へ隣接する陸地に建設する。`条件地形=海辺` は既存の海・湖隣接判定を利用する。
- `必要拠点段階` は所属拠点の最低段階。町指定なら都市・大都市でも建設可能。空欄は段階制限なし。
- `採取範囲` は施設からの六角マス距離。対象は海・湖であり、陸地の魚産出を自動的に対象へ含める指定ではない。
- 港の `改築元=船着き場` は同じマスの完成施設からの改築を指定する。船着き場がなくても新規の港建設は可能とする。
- 改築ターンは `港の建築時間 - 船着き場の建築時間`。港の `改築短縮ターン` はシートの `=D31` で船着き場の建築時間を参照し、現行データでは2-1=1ターン。
- 船着き場の経済Lv1は仮設定。資材費は既存シートの消費量参照数式を維持し、現行値は木材50・石材50・鉄50。港の経済Lv2・資材費・漁業100は変更しない。
- 周辺漁業は毎ターンの拠点自動収入として実装。範囲内の無所属の海・湖をすべて候補とし、`地形.json` の魚産出 × 拠点稼働率 × 拠点人口の漁業倍率 × 施設補正 × 水域災害補正 × 施設HP割合 × 既存収入スケールで計算する。漁業用の雇用枠は追加せず、既存の拠点共通稼働率を用いる。
- 暫定の重複防止ルール: 領土化済み水域は施設による追加採取対象から除外し、自領なら従来の領土収入だけを得る。他勢力領土から採取しない。同勢力の複数施設・拠点の範囲が重なる水域は、最寄りの施設1つだけへ割り当てる。同距離は拠点ID・マスキー・施設名の順で固定する。
- 完成施設のみ採取し、建設中・破壊済み施設・略奪された設置マスは採取不可。拠点の収入と設置マスの土地収入表示へ接続する。得た魚は既存の人口維持・成長処理にも使われ、備蓄の差分が収入と同じ値になるとは限らない。
- 未確定: 改築時の資材費と工事中の旧施設稼働、改築差分が0以下の場合の扱い。
- 港同士の隣接+20%は提案段階。採用・対象・重複上限の回答前には確定値としてデータへ追加しない。

## 一般資源とヘッダー分類（2026-10-03）

- 一般資源は3分類: 食料（穀物・野菜・肉・魚）、資材（木材・石材・鉄）、通貨（金）。
- ヘッダーはこの3分類と特殊資源の計4項目。詳細・簡易どちらも同じ分類と在庫合計を使い、換算倍率は掛けない。
- 黒木・特木・銀鉄・青金鋼・赤黒鋼・宝石・死体・魂などは特殊資源側で個別の在庫を表示する。死体・魂は食料の表示合計から除外するが、既存の種族別消費・人口増加条件と代用不可ルールは変更しない。
- 銀は既存在庫・用途を保持して特殊資源側へ表示する。金への換算・廃止は未確定。
- 特殊資源内は「在庫」「特産品」を切り替える。特産品の発見情報と備蓄は別データとし、発見だけでは在庫が増えない。
- この変更は表示分類の整理。特殊素材の周期採取は「調査・特産品ルール.md」に従う。既存の装備材料条件・資源データ・セーブ在庫は削除しない。
- 分類定義は frontend/src/lib/v39-economy-rules.js の GENERAL_RESOURCE_GROUPS。一般資源以外の既存資源は自動的に特殊資源へ分類する。
### 特殊素材6種の産出・消費調整（2026-10-03）

- 対象: 黒木・特木・銀鉄・青金鋼・赤黒鋼・銀。
- @game_data「地形」の対象列にある既存の通常産出・地形補正を0へ変更。通常資源の木材・石材・鉄・金などは変更しない。
- @game_data「消費量」の対象6列は、変更前の計算済み値を100で割って四捨五入した整数へ一度だけ変換。100→1、200→2、50→1、10/20→0。320→3、640→6であり、1〜2への上限設定はしない。
- 変換は原本の数値調整であり、実行時・JSON出力時に再び100で割らない。空欄はそのまま保持する。
- 上位装備の対象セルにあった前行×2の数式は、丸め後の前行参照では元値の四捨五入結果を再現できないため、この調整では計算済み元値から固定値へ変更。元値と元数式はシートのセル注記へ保存した。通常素材の数式は維持する。
- 地形・消費量の2シートのみ最新XLSXから変換器で再生成し、警告・エラー0を確認。
- ランダムな特殊樹木・鉱脈の配置と採取は採用方針。6種の配置・周期採取・在庫追加処理を実装済み。発見済み自領1マスあたり基本5ターンで1個を所属拠点へ加算する。既存在庫は消さない。

### 宝石追加と採取バランス確認（2026-10-12）

- 宝石を加えた特殊素材7種を周期採取する。原本「地形」の宝石産出・道路補正は0、「特産品」は特殊資源／採取周期5／量1／鍛冶研究速度補正0.2、「消費量」の宝石は旧値÷100を四捨五入。既存在庫と洞窟内の手動採取1個は維持する。
- 原本の最新「地形」「消費量」「特産品」を再生成。原本で更新済みの装備用木材・鉄・特殊素材費用も反映する。
- 採取量は基本5ターンで1個を維持する。施設の旧単位の特殊素材費用は原本「施設」で旧値÷100を四捨五入し、JSONへ再生成する。町の黒木は1、都市は2、大都市は4。1地点・研究なし・在庫0の採取待ちはそれぞれ5・10・20ターン（発見・通常資材・建築時間は別）。
- 更新済み「消費量」を参照する施設の数式は既に新単位のため、再度100で割らない。城壁などの黒木・銀鉄は各5、大聖堂の黒木は10を維持。通常資材もその数式を最新の原本で再計算する。
- 大都市の特殊素材費用は、都市の丸め後の値を2倍にせず、変更前の大都市の値を独立して換算した固定値とする。元の値・数式は原本セルの注記へ保存。例: 都市の青金鋼25→0、大都市50→1。以後の費用調整も原本から行う。
- 建設・拠点発展では、黒木・銀鉄の手持ちを必要量まで優先消費し、不足分だけ黒木1→木材100、銀鉄1→鉄100で代替する（暫定倍率）。元の木材・鉄費用に追加し、合計が足りなければ開始不可。画面には実際の費用と代替内訳を表示する。他の特殊素材・装備製作には適用しない。調整は `V39_CONSTRUCTION_MATERIAL_BALANCE`、原本の基礎費用は変更しない。
- 洞窟の鉱床化後は宝石1個/ターンを現地在庫へ産出し、地上の1個/5ターンとは別設定。運搬は必要。洞窟を確保すると5倍の速度となるため、合わせて検討する。
- `node scripts/report-v39-special-resource-balance.mjs` で現行データから地点数・研究Lv別の採取待ちを再計算できる。発見・移動・研究解禁・運搬などは含めない理論比較であり、プレイ全体の所要ターンを保証しない。
