# 特殊村と軍隊の奉納契約

更新: 2026-10-22 / UI68。

UI69追記: 自勢力の完成した対応祭壇により、転生最低保証Lvを4/5/6へ強化する。下記Lv3は施設なしの基礎値。既に最低保証以上なら下げず、不足分だけ取得する。値は施設シートの `転生最低Lv` を参照し、軍隊の定期奉納人数や転生の一度払いを増幅しない。詳細は [召喚・呼集ルール](../units/召喚・呼集ルール.md)。

## 役割

### 魂APPの取得記録（UI200）

- 人口用資源「魂」の個数と、合成用の保管魂は従来どおり別管理。今回のAPPは資源数ではなく `factionState.soulAppTotals` の取得実績。正 `positive` と負の絶対値 `negative` を別々に加算し、相殺しない。
- 村の人口報酬が天使/悪魔への受取時に魂へ即時変換された場合、1人あたり、その村の受取勢力に対する友好度（0〜100）÷ `villageSoulAppDivisor`。天使は正、悪魔は負。初期の除数は2。友好度が0以下ならAPPは0。通常人口として受け取った場合は加算しない。
- 確保されたユニットの生贄受取で即時魂変換した場合と、`魂回収` による保管成功時は、変換前ユニットの現在APP ÷ `unitSoulAppDivisor`（初期5）。符号と小数を保持する。APPの成長計算も負値を保持し、それ以外の能力の下限制限は維持する。
- 生贄受取履歴/死体の回収済み印で再加算を防ぐ。保管魂には取得時の `soulApp` を保存し、ロードや再描画では再加算しない。装備は魂へ移さない。過去セーブの既存魂を遡って加算しない。
- 設定はゲーム開始設定/管理のゲーム設定の「魂APP」で変更。`config/player_config_options.json` の「ゲーム進行設定 → 魂APP」が初期値・範囲・項目名の正本。変更は以後の変換に適用する。取得済みAPPは保持し、設定画面で正負の合計を確認できる。マルチはホストのみ編集、サーバーとクライアントで範囲検査して共有する（サーバー変更反映には再起動が必要）。
- 魂の個数は従来の消費資源、正負の魂APPは減らさない累計実績とする。魂を人口増加・召喚等で消費してもAPP累計は減らない。上位種化もAPPの消費ではなく、天使は正の累計、悪魔は負の絶対値累計で条件を判定する方針で確定。
- `soulAppEvolutionRequirement` の初期値500は上位種化用の確定した調整値。**進化先・必要Lvは未確定で、上位種化そのものは未接続**。自拠点の奴隷人口は個別APP/村友好度の出自を持たないため、今回のAPP加算対象外。数量としての魂変換は維持する。
- 原本「クラス」CQ列 `必要正魂APP` / CR列 `必要負魂APP` を追加。アーチエンジェルは正500、ヘヴンエンジェルは正1000、アーチデヴィルは負500、ヘルザーデヴィルは負1000。アーク系は未変更。既存の `合計Lv` / `条件クラス` と併せて判定する設計。負側も絶対値で記入する。空欄はそのAPP条件なし。現時点ではシートの条件データ設定までで、取得処理には未接続。上位種化条件を接続する際にゲーム設定の必要APPとの優先関係も定める。既存の職業変更を種族進化として流用して主要種族を取り違えない。
- 実装先: `v39-soul-app.js`、`v39-soul-storage.js`、`v39-village-sacrifice.js`、`v39-quest-rewards.js`。`scripts/check-v39-soul-app.mjs` で除数変更・正負・人口報酬・生贄/死体の変換・再取得防止・勢力データのJSON保存復元をブラウザなしで検査。

- 勢力NPCはプレイヤーと同じ勝利競争を行う。一般村は生活・発展・防衛と依頼/取引を担う。
- 村として存在する天使/エンジェル、悪魔/デヴィル、吸血鬼/ヴァンパイアは強力な特殊村。勝利競争には参加せず、生贄を定期的に奉納する契約で軍隊を提供する。種族だけを理由に、同種族の競争勢力まで村へ変更しない。

## 軍隊加入と維持

- 村モーダルの「会話 → 生贄の奉納・軍隊加入」で供給元の自拠点・住民種族・契約軍隊数を選び、フッターで確定する。交渉役が地上の村中心から1マス以内にいる必要がある。廃村/敵対中の村とは締結できない。
- 生贄は指定拠点の生体住民（人口定義の増加条件が「食事」の種族）から差し引く。魂/死体の在庫、配下のユニット、捕虜を自動で選ばない。今回、供給元から村への物理輸送は行わず、周期到来時に人口を直接精算する。
- **定期奉納は加入軍隊の維持費。奉納のたびに新しい軍隊を生成しない。** 契約数は1〜3駒。新規契約/停止後の再開は今回分を支払い、増枠時は追加分のみ支払う。増枠や供給元変更で既存の支払期日を延ばさない。
- 追加APなし。初回加入/帰還後の再参加は村の隣接する配置可能な空きマスへAP0で配置する。全駒分の配置場所・人口が確保できないときは人口を消費しない。既存軍隊のHP/AP・装備は増枠や維持費支払いで回復・再支給しない。
- 契約後は既存のワールドターン処理で、生存中の契約軍隊数に応じて自動支払いする。死亡による欠員は自動補充しない。洞窟等を表示中も保存された地上の契約を処理する。同一ターンの二重処理を防ぎ、経過ターンを飛ばした場合は経過周期分を精算する。
- 人口不足/供給元の消失、村の廃村/敵対等で契約は停止し、契約軍隊は即時帰還する。死亡扱いにはせず、同じユニットID・装備・残HP・個人の荷物を契約側へ保管する。部隊所属・行動予約・教官指定を解除し、再開時には単独/AP0で戻る。共有荷物は残存部隊に残し、最後の軍隊が帰還する場合は契約側へ保管する。
- 停止後の自動再開はしない。村で人口と配置場所を確保して手動再開する。「契約を停止」で任意帰還も可能。契約数を減らす場合は一度停止して再設定する。契約軍隊は施設格納できない。
- 村が丸ごと配下になる契約ではない。帰還・維持履歴と待機軍隊は村の `offeringByPlayerId` に保存する。通常の一般村から生贄を受け取る `sacrificeContract` とは方向も目的も異なる。

## 転生の交渉（UI68）

- 村の会話から「転生を交渉」を選ぶ。対象は現在の交渉者本人で、選択中の別ユニットや勢力全体の種族を変更しない。軍隊/動物軍隊・召喚体・契約軍隊は対象外。村中心から1マス以内、地上の自分の操作ターン、生存・行動予約なしが必要。廃村/敵対中は不可。
- 天使村ならエンジェル、悪魔村ならデヴィル、吸血鬼村ならヴァンパイアを**種族Lv3**まで取得し、その種族を主要種族（ユニットのrace）へ切り替える。元の種族Lvは補助クラス側へ保持し、職業Lv/前提職/習得スキル/取得済みの第二職/装備を保持する。例: ゴブリンLv5＋ファイターLv5 → エンジェルLv3＋ゴブリンLv5＋ファイターLv5（総合Lv13）。人族の基礎種族ボーナスは実Lvではないため、元の人族Lvを新たに加算しない。
- 既存の対応種族Lvがある場合は不足分のみ取得。既にLv3以上ならそのLvを下げずに主要種族を切り替えるだけ。同じ主要種族を必要Lv以上持つ場合は再実行不可。別種族を往復して取得済みLvを増殖させない。取得によって総合Lv上限120を超える場合も不可。
- 指定自拠点の生体人口を生贄として一度だけ支払い、通常交渉のAP20を交渉者から消費する。**軍隊契約の定期維持費とは別**。生贄人数は暫定3人、設定変更可能。供給元には最低残人口を残す。条件不足時は人口・APとも消費しない。同一ターン/同条件制限と待機済みチェックは共通交渉処理を使用する。現在は条件を満たせば成立し、確率抽選は追加していない。
- 転生後は新種族の通常配分で将来のLvを成長させる。転生直後に総合Lvを半分ずつ再配分し直さない。途中のEXPはレベル内の進捗率を新種族の必要EXPへ換算して保持。HP/APは回復しない。上位職取得時は転生時の配分記録から新しい職業配分へ引き継ぐ。
- ユニットの主要種族画像を優先し、以前の合体外見で新種族の画像を隠さない。種族/成長開始配分/履歴は通常セーブ、魂の成長情報にも必要な配分を保持する。

## 調整値一覧

`config/v39-special-villages.json` が今回追加した契約サブシステムの暫定設定。既存のシート管理対象クラス/勢力/スキルJSONは編集しない。

| 設定 | 初期値 |
| --- | --- |
| offeringIntervalTurns | 5ターン |
| peoplePerArmy | 軍隊1駒につき1人 |
| maxArmiesPerOffering | 同一村・同一プレイヤーの契約上限3駒 |
| minimumRemainingPopulation | 供給元拠点に1人を残す |
| armyLevel | 新規軍隊Lv15 |
| militaryLevel | 軍隊編成プロフィールの参照Lv4 |
| reincarnation.enabled | true |
| reincarnation.raceLevel | 3（取得済みなら不足分のみ） |
| reincarnation.people | 転生時に生贄3人（暫定・一度だけ） |
| reincarnation.minimumRelation | null（友好度の追加条件なし。数値を入れると必要友好度） |

軍隊は通常の生成・種族成長・職業装備・軍隊プロフィールを使用する。新規の特殊村守備軍もこのLv/編成を下限として使用し、通常村は変更しない。既存守備兵のLv・HPを勝手に書き換えない。既存契約の維持費/周期は締結時の値を保持し、契約更新時に新設定を読む。
