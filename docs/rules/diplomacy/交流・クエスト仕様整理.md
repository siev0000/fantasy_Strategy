# 交流・クエストの現行仕様

更新: 2026-10-21 / UI53。現行の入口・操作・保存・未対応範囲の索引です。旧方式を復活させるための資料ではありません。

## UI245: 協定申込みの通知と未回答マーク

- 自分宛の有効な協定申込みを既存の通知ログへ表示する。申込元・種類・期間・回答期限を記載し、通知プレビューの選択またはログの「外交を開く」から該当勢力の外交画面へ移動する。
- 未回答中は「管理」「国家・外交」「外交」タブへ小さい！を表示。国家・外交を開くと未回答がある場合は外交タブを優先する。開いただけではマークを消さず、承諾/拒否/期限切れで除去する。
- 正本は diplomacyRelations の proposal。画面再描画で通知を重複せず、保存読込時は未回答を再確認する。通知ログは既存のセッション内ログを使い、他プレイヤーへ切替えた場合は宛先以外に内容/操作を公開しない。
- Nodeの実協定処理と通知/バッジ/遷移のモック検査は scripts/check-v39-diplomacy-notifications.mjs。実ブラウザは未確認。

## UI244: 交流入口の対象判定を修正

- 交流対象を一般村だけに限定せず、NPC/他プレイヤー勢力の領土も対象にする。resolveV39MapContact が選択マスと選択ユニットから対象を解決し、領土外周に隣接するユニットから開ける。所有マップと拠点の領土情報を使い、村の配列だけで判断しない。
- 選択マスの記録がない場合も選択ユニットから交流を表示する。ユニット選択/交流タブ切替時も再表示する。地上・生存・距離の制約は維持し、遠方勢力を選んだだけではボタンを有効にしない。
- 一般村は既存の会話・依頼モーダルを使用。勢力は「取引」「外交・協定」を表示し、既存の取引モーダルと国家・外交画面へ選択相手を渡す。勢力用の村クエスト等は新設しない。相手勢力の取引下書きは一般村/既定相手と混同しない。
- scripts/check-v39-village-border-contact.mjs で実際の画面表示関数と操作ハンドラをNode/DOMモック検証。表示対象とボタン、選択勢力への遷移を確認。実ブラウザは未確認。

## UI243: 領土の外からの交流

- 村との交流は、領土内または村のいずれかの領土マスから六角距離1以内にいる生存ユニットで行える。村中心からの距離ではなく領土の外周を基準にする。領土情報がない旧データは中心マスを基準とする。
- 会話役一覧、会話アクセス、依頼一括受注/報告、報酬交渉、取引の村候補、特殊村の転生/奉納契約、生贄受取、襲撃の接触判定は v39-village-contacts.js の isV39VillageContactUnit に統一。地上/生存/退出中でない条件は維持する。AP・友好度・契約の追加条件も変更しない。
- 隣接ユニットのマスを選択しても村の交流入口を表示する。村のマス自体を選択する従来の入口も残す。
- 村への通行許可は不要になったのではなく、交流に入域を要求しない。休息は引き続き部隊全員が村の領域内にいることを要する。
- scripts/check-v39-village-border-contact.mjs で内側/外周隣接/遠方、死亡/洞窟/退出中の除外、実会話判定と一括依頼のアクセスをNode検証。実画面未確認。

## 画面の分担

| 場所 | 役割 |
| --- | --- |
| フィールド下部の交流 | 接触済み村の一覧・位置への移動、選択した村の情報・受注中件数と「村で会話・依頼」の入口 |
| 村モーダル：会話 | 村の様子・交流・部隊で休息・属国化・襲撃 |
| 村モーダル：クエスト | 共通一覧のチェックで複数受注・支援報告、受注前の報酬交渉 |
| 村モーダル：取引 | 提供・要求、物資選択、配送・日程、契約一覧 |
| 村モーダル：情報 | 村長・性格・計画・人口・守備・交渉役・支援スキル・会話履歴 |

村の休息・交流・受注・報告・属国化・襲撃・別取引ボタンを交流欄へ重複表示しません。受注件数は全受注記録から数え、最後に受けた1件だけを表示しません。
UI67: 天使/悪魔/ヴァンパイアの特殊村では会話に「生贄の奉納・軍隊加入」を追加。自拠点人口の定期奉納による軍隊維持は [特殊村・奉納契約ルール](特殊村・奉納契約ルール.md) を参照。一般村から生贄を受け取る事件契約や、人口報酬の魂化とは別処理です。
UI68: 特殊村の「転生を交渉」で交渉者本人が対応種族Lv3を取得して主要種族を変更します。自拠点人口の生贄3人（暫定）とAP20を一度だけ支払い、軍隊の定期維持契約とは分離します。元の成長・装備・習得スキルは保持します。
村モーダルを開くと接触履歴 `contactedByPlayerIds` を村へ保存します。単に地図で発見・選択しただけでは登録しません。旧セーブは友好度・依頼・イベント完了・属国化・襲撃の記録から接触を判定します。一覧は現在のプレイヤーの村名・座標・友好度・受注中件数のみで、相手の現在在庫や人口は表示しません。選択は位置へ移動してマスを選ぶだけで、交渉モーダルを自動で開きません。洞窟等では地上へ自動切替せず案内します。
放浪者の勧誘、守護者の依頼/取得、廃村への再入植は別の実行条件を持つため交流欄に維持します。洞窟NPCの別画面を今回の変更で削除・統合していません。

## 依頼の生成と操作

1. 村計画と実際の不足・脅威から依頼ひな型を解決します。シートのイベント会話の選択肢や固定テスト依頼を新規候補へ追加しません。
2. 「クエスト」の全依頼に左チェックを置き、フッターでまとめて受注します。チェックだけでは別画面へ移動せず、納品もしません。
3. 受注後に必要な物資支援・討伐等を進め、チェックしてまとめて支援・報告します。
4. 選択分の途中で条件が不足すれば、その操作全体を元に戻します。物資依頼の部分納品は元定義が許す場合だけ行います。
5. 目標・対象ID・期限・報酬は依頼別に保持します。村ごと1件制限はありません。同じ依頼の重複受注はできません。

新規依頼に番号付き会話の受注画面は使いません。受注済み旧セーブだけは元定義と適用済み効果を保ち、完了互換を維持します。旧データを通常一覧へ再追加する理由にはしません。

## 報酬の交渉

### 自動生成依頼の標準報酬（UI214）

- UI215: 自動依頼の友好度も条件の重さで増加する。表示・受注時確定・達成時加算は `getV39QuestRelationReward` を共用する。納品20個を基準、警備3Tを基準とし、それ未満でも元の友好度報酬を減らさない。討伐/建設は件数、複合は各条件の重みの合計。定期納品は1回分の納品重み×回数なので、12個納品が+10なら12個×3回は+30。最終工程で一度だけ加算し、途中納品では加算しない。
- 基準値と1依頼の上限（初期100）は同設定の `relationScaling`。新規自動依頼は受注時に `relationReward` を保存する。UI214の受注済み自動依頼で未保存なら現条件から計算し、旧イベント会話等の明示報酬は変更しない。友好度自体の-100〜100制限は従来どおり。

- 計画から生成する新しい依頼には、友好度に加え、村の余剰在庫から金と物資を組み合わせる。設定は `config/v39-quest-rewards.json` の `automatic`。対象資源/目的別予算/在庫配分率/保護備蓄を調整可能。
- 暫定値: 維持食料10T分、基本建築資材各30、金10、次の未払い建設費、既存の未取り置き報酬を保護。依頼で要求中/村の計画で不足中の資源は報酬へ出さない。魂・死体・人口・希少素材は自動報酬の対象外。
- 余剰の25%以内、予算5〜60、金を予算の半分目安＋最大2種類の余剰物資。討伐/警備/建設支援は目的に応じ、継続納品は総納品数で予算を計算する。払える在庫がなければ物資を捏造せず、友好度と「余剰物資なし」を表示する。
- 一覧での提示は現在在庫に応じて変わり、受注時に確定。標準自動報酬は受注時に村の使用可能在庫から取り分け `rewardEscrow` へ保存するため、他の建設や受注と二重に使わない。複数受注は既存の順次・全体ロールバックを維持する。
- 報酬は依頼の全工程完了時に一度だけプレイヤーの選択拠点へ加算し、村からの二重減算はしない。部分納品/定期納品の途中では支払わない。期限切れは取り分け分を村へ戻す。既に受注済みの旧依頼の報酬は遡って変えない。手動で交渉した報酬は従来の受注時確定・完了時実在庫払いを維持する。
- `scripts/check-v39-automatic-quest-rewards.mjs` で実ひな型の一覧/受注、保護在庫、取り分け/支払い/返却の保存則、資産捏造なし、保存復元、完了/期限切れの一度限り処理をNode検証。画面確認はユーザー側。

- 受注前の「交渉」で表示を切り替え、「依頼一覧」でチェック・入力を保持して戻ります。
- 取引と同じ2列バスケット、同じ全画面物資選択モーダルを使用します。「＋→分類/検索/複数選択→決定」で追加し、右上の数量を直接編集。選択した品目だけメーターを出します。
- 金・既知物資・村の種族の人口を複数要求できます。悪魔限定ではありません。人口は通常人口として選択拠点へ移します。魂へ自動変換しません。
- 判定は合計価値・交渉/威圧技能・友好度等。AP20を1回消費し、威圧は友好度-5。同じターンに同じ条件で再試行できず、並べ替えで回避できません。
- 未受注の合意は5ターン有効。受注時に全品目を固定し、完了時だけ村の実在庫・人口から支払います。一品でも不足すれば納品・完了・報酬移転を確定しません。
- 元の物資報酬は置換し、友好度報酬は維持。友好度は文字で表示します。UI214から標準自動依頼の物資報酬は上記の余剰在庫規則で生成します。
- 相手の資源在庫は表示しません。人口は要求対象の種族を表示し、保有人数は表示しません。

## 費用と確定

| 操作 | 現行の費用・判定 |
| --- | --- |
| 会話閲覧・条件編集・受注・支援報告 | 操作自体の追加APなし。必要物資は別途消費 |
| 交流 | 設定された食料。交渉抽選へ変更しない |
| 部隊で休息 | 参加者各AP30。全員が村領域内にいてAPを満たす必要あり |
| 報酬交渉、NPC取引の承諾/再開/備蓄確保 | AP20。同条件制限・入力不備・AP不足を共通判定 |
| 交渉支援スキル | スキル自身のAP・CT・同ターン使用制限 |
| 属国化 | 友好度60以上等の既存条件。報酬交渉と同じ抽選ではない |
| 襲撃 | 明示選択・確認が必要。報酬拒否から自動戦闘にしない |

村長は守備兵と独立して生成・保存し、性格・一人称・二人称・台詞を共用します。性格によるAI変更は未対応です。会話履歴・未送信UI入力は画面セッション内の保持であり、永続保存とは区別します。

## 別系統と未対応

- 通常取引は契約・予約・運搬を伴います。クエスト報酬の完了時移転とは別処理です。
- 特産品取引は保有効果の期間貸出（初期10ターン）。報酬交渉の対象には追加していません。
- 配下・武器・薬の取引、通常取引の人口交換、遠隔オンライン承認は未対応です。UI62では天使/悪魔が村の人口報酬を受け取ると暫定で人口用魂へ即時変換します（config/v39-soul-conversion.json）。村の実人口を減らし、受取側人口との二重加算はしません。対象外種族/変換OFFは従来の人口移転です。
- 村の守護/生贄契約・強襲・捕虜/装備受渡しは専用事件テストの範囲を持ちます。通常交渉から契約締結・定期履行まで完成した扱いにしません。
- 自動報酬の長期バランス調整と、旧魂報酬の全面移行は残作業です。UI214で標準自動報酬の生成・受注時取り置きを追加済み。交渉で変更した報酬の取り置きは未対応です。
