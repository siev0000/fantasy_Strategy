# NPC勢力の開始と行動

更新: 2026-10-27 / UI141（村支援・成長はUI123）。

## 期限付き協定（2026-10-27 / UI141）

勢力間の既存 `diplomacyRelations` を拡張。操作は「管理 → 国家・外交 → 外交」。不可侵・通行協定のほか既存交易協定/同盟も同じ申し込み・承諾・期間指定を使う。

- 期間は締結時に指定。`V39_DIPLOMACY_BALANCE` の `treatyDurationTurns`（初期10T）、`treatyMaximumTurns`（100T）、`treatyProposalLifetimeTurns`（回答期限3T）を参照。申し込みだけでは発効しない。相手プレイヤーは自分の操作時に承諾/拒否し、NPCは次の外交処理で友好度＋提案者の信用が必要友好度を満たすか判定する。国家AIが人間へ申し込む場合も勝手に締結しない。
- 不可侵と同盟の有効中は、魔族同士の宣戦不要例外より協定を優先して攻撃・宣戦を禁止。通行協定だけでは不可侵にならない。
- 通行/同盟は相互に領内移動と相手駒の通り抜けを許可するが、停止時の重複は禁止。平時の他勢力領への新規進入には通行/同盟が必要。戦時の侵攻・魔族同士の既存敵対例外は維持。村の領土判定は今回変更しない。通行は所有権・採取権・建築権・施設召喚権を付与しない。
- プレイヤー移動範囲と自動経路/AIの共通移動コストで領内進入を判定。成立済み取引の担当使者は、相手領との契約に限り通行可能とし、既存の往復配送を止めない。
- 更新も双方同意。残存期間の末尾へ指定期間を加算し、更新で友好度を繰り返し稼がない。自然失効は終了、`treatyExpiryNoticeTurns` 前に一度だけ予告する。
- 一方的な破棄は `treatyCancellationLoss` 分の友好度と `treatyCancellationTrustLoss` 分の破棄者の信用を失う（いずれも暫定10）。信用は勢力ペアの `trustByPlayer` に保持し、NPCの承諾判断に使う。
- 通行/同盟の終了・破棄時に、既に相手領内にいる地上ユニットIDだけを記録。`treatyExitGraceTurns`（3T）の間は退出のための移動を許可する。一度領外へ出た駒の再侵入や別駒の新規進入は許可しない。期限終了だけで自動宣戦/攻撃/強制移動はしない。猶予後も領内に残る場合は通常の進入制約に戻る。
- 協定、回答待ち、更新期限、信用、退出猶予は既存外交状態として通常セーブに保存。終了/予告/ NPC回答は当事者の行動ログへ通知。
- 国家AIは発見済み勢力へ不可侵→通行→交易、友好度が十分なら同盟を申し込む。拒否/破棄後の再提案は `treatyAiRetryTurns`（5T）待ち。人間の申し込みを自動操作する機能ではない。

実装: `lib/v39-diplomacy-rules.js`、`v39/world/v39-nation-diplomacy-ui.js`、`lib/v39-movement-occupancy-rules.js`、共通移動コスト/自動経路。検証: `scripts/check-v39-treaties.mjs`（390/1100px、申し込み/承諾/拒否/回答期限、NPC回答、更新、魔族の不可侵、通行・占有、終了/通知/猶予、破棄、保存復元）。

未実装: 情報/現在視界の共有、共同防衛、施設利用協定、金品を添えた協定交渉、村との通行協定。オンラインの継続外交通信は既存の未接続範囲を維持し、今回オンライン対応済みとはしない。

## 村支援・取引・成長（UI123）

勝利を目指すNPC勢力へ接続。一般村自身の対外売買AI、人間の自動操作ではない。既存の食料・建設・軍備優先を維持する。

- `v39-npc-commerce.js`: 発見・接触済み、非敵対で設定以上の友好度を持つ独立村へ、自拠点の食料備蓄・建設・徴兵・装備費用を残した余剰を提供する。知っている資源種類に限定し、通常特産品の利用権、魂・死体の自動取引は含めない。不足物資があれば数量1対1で交換を提案する。村が要求中の物資や維持備蓄を買い上げない。資源別の価格評価は未対応。
- 交換する不足がなければ、村の進捗から生成された物資依頼を参照して郵送支援する。**依頼の自動受注・完了・報酬取得ではなく、届いた在庫が村の計画に使われる支援**。村の在庫や自国在庫を遠隔で即時増加させない。
- 提案・承諾・備蓄追加確保は共通取引APIの `aiTurn` 文脈から実行。NPCの解決フェーズだけ許可し、操作プレイヤーIDやフェーズを偽装しない。村の通常交渉確率とAP20、追加確保交渉、1/3予約、積載、往復、同時交換・帰還入庫、死亡/期限切れ中断を共用する。拒否時も交渉APは消費。中断は自動再開しない。条約の定額金収入を物資取引の代用にしない。
- `v39-npc-growth.js`: 同じ装備の次品質へ更新。個体は在庫品を優先し、なければ通常の製作・装備変更、モブ軍隊は固定装備のレア度一新を使う。付与済み装備の自動置換や任意の武器種変更は行わない。鍛冶研究・実素材・旧装備の返却を共用し、安全時に通常移動で帰還して更新する。
- 上位職は既存の取得可能候補を1件選ぶ。単一前提職・必要スキル・施設・超過Lv1以上を免除しない。前提職13→10＋上位職3、総合Lv/EXP維持、施設徴兵の成長停止も従来どおり。完成施設への帰還で条件を満たす場合は移動する。複合職の新規取得方式や必要施設の専用建設計画は追加しない。
- 建設・装備等の不足から特殊資源を選び、`特産品` の地形・高度・気候・発見研究条件を参照。必要研究は既存前提グラフから選び、着手済み研究は強制切替しない。把握済み地形の未調査適地へ移動し、既存の100AP・途中進捗・範囲・翌ターン完了で調査する。未発見資源の実配置座標は計画に使わない。経路待ち候補は一定期間避ける。
- 発見済み資源の周期産出量を開拓評価へ追加。食料優先中でない場合、設定距離内の非隣接の発見地へ隣接開拓をつなぐ候補も扱う。人口・所有・地形・費用の条件を維持し、発見だけで在庫を増やさない。他勢力所有地の奪取、新規中継拠点、地上以外の取得は今回の範囲外。
- 使者・調査員は通常探索/調達/魂・死体探索との競合を避ける。取引で搬入予定の不足分は重複調達を抑え、領有・周期産出待ちを普通の採取と区別する。`aiState.growthPlan` とクールタイムを保存。診断「研究・成長」は完了Lv/項目・進行項目・担当・EXP・装備不足・資源段階を読み取り専用で表示。長期記録にも研究状態・成長計画・契約段階を保持する。

調整: `config/v39-npc-faction-ai.json` の `commerce`（有効化/間隔/同時数/数量/猶予/最低友好度）、`growth`（有効化/装備間隔/調査候補数/経路再試行間隔）、`resourceExpansion.rareResourceApproachRange`。全勢力が自給・勝利できるバランス保証や、通常特産品利用権の自動取引は未対応。

検証: `scripts/check-v39-npc-growth-commerce.mjs`。ブラウザ内実モジュールで物資交換の予約→移動→交換→帰還入庫、支援契約・拒否・非公開村、製作費/クールタイム、上位職移行、人間のターン制約、発見研究→100AP調査→発見→開拓評価→周期産出を確認。初期在庫・研究完了・乱数はテスト条件であり実ゲームの無料支給・確率固定ではない。

## 新拠点の近接入植設定（設定済み・処理未接続）

- `V39_DIPLOMACY_BALANCE.settlementProximity`（`frontend/src/lib/v39-gameplay-balance.js`）へ設定を追加した。新拠点設立・発見への適用とNPC候補地評価は未実装であり、設定の `enabled:true` だけで現在の友好度を減らすことはない。
- 暫定の `distanceBands` は拠点中心同士のヘックス距離3マス以内で友好度低下20、4〜6マスで10、範囲外は低下なし。小さい距離帯から最初に該当した1件を使い、複数帯を重ねて引かない。今後の調整は設定を正本にする。
- `applyOnDiscovery:true`、`applyToInitialPlacement:false`、`oncePerSettlementPerObserver:true`。他勢力が新拠点を認識した時点で、対象拠点と認識側勢力の組につき一度だけ適用する方針。最初から認識できれば設立時、未発見なら発見時に処理する。毎ターンの再減点や、近くの相手拠点数による重複減点は行わない。
- 住民の不満度ではなく勢力間の外交友好度を扱い、プレイヤー/NPC共通とする。友好度の上下限・通常の時間経過・条約判定は既存の外交処理へ接続する。NPCは認識している近隣勢力だけを立地の外交リスクに使い、他者の未発見拠点を裏読みしない。
- 新拠点設立の人口移転・資材・建設期間・具体的なNPC建設判断は未接続。今回その費用を勝手に追加したり、初期配置・既存拠点へ遡及ペナルティを与えたりはしない。

UI120: NPC診断の「資材」では、各拠点の在庫を `現在値 (+増減)` / `現在値 (-増減)` で表示する。通常ヘッダーと同じ `buildV39ResourceSnapshot` と `lastEconomyDelta.food/material` の記録を使い、別の予測収支計算を追加しない。括弧内は直近の経済更新の実増減であり、人口/兵の維持・代用消費や人口成長などを反映した在庫差分。経済更新外の建築・製作・輸送等の単発増減をすべて含む通算差分や、満額消費できた場合の需要予測ではない。ゼロは `+0`、記録前/資源項目未記録は `未集計` とし、正負を色だけで表現しない。閲覧によってAIや経済を進めない。

## 食料の確保を優先する判断（UI115）

- 勝利を目指すNPC勢力は、拠点別の実際の通常食料産出と、住民・所属兵・訓練予約兵の維持需要を比較する。通常食料の代用消費は人口維持と同じ処理を用い、魂・死体は代用品にしない。飢餓による消費半減を持続可能な収支と見なさない。
- 毎ターンの収支赤字と備蓄不足を分ける。初期備蓄が十分でも収支改善は行うが、それだけを理由に無期限の物資搬入任務を作らない。備蓄の基準は `resourceTeams.stockReserveTurns`。
- 食料優先中は、共通の建設完了・生産処理で実際に食料が増える施設を優先する。建築条件・費用は免除しない。食料施設の不足資材も調達目標へ加え、食料備蓄、食料施設用資材の順に資源任務へ優先度を付ける。建設候補がなければ開拓・調達を待つ。
- UI117: 食料施設の前提施設も、施設データの `前提施設` を再帰的にたどって整備対象へ含める。直接増産しない墓地を除外して農場も解禁できなくなる循環を修正した。既存の前提充足判定・費用・土地・研究条件は維持し、循環参照で無限再帰しない。建設可能な増産施設の経路へ到達した後は、その費用を確保して別の前提整備へ散財しない。前提施設の不足資材も食料施設用の調達目標として扱う。
- UI119: 資源任務は候補を評価してから同時任務数上限へ絞り、積荷の帰還、既知の取得先（余剰拠点/残留品/採取地）、供給元探索、搬入待ちの順に割り当てる。同じ段階では食料備蓄等の既存の優先度を維持する。取得元のない食料探索だけで上限を埋め、取得可能な建築資材を除外する停止を防ぐ。未発見地点は使わず、実在庫・積載・通常移動・AP・到着時取得を共用する。取得元が既知でも経路やAPの都合で実行できない場合は待機理由を残す。
- 食料施設/その前提の資材不足がある間は `foodPriority.constructionReserveUnits`（初期1）と通常の `resourceTeams.reserveUnits` の小さい方を調達時の守備残数にする。2駒しかいない場合も通常軍1駒を調達へ出せるが、君主・ヒーロー・召喚体等の除外条件は変えない。普通の任務と一般村は従来の守備残数を維持する。
- 食料施設用の不足資材が実際に増産される既知の隣接地は、食料の素の増産地より先に開拓候補とする。これにより食料施設の費用を払えないまま食料産出地だけを増やし続ける状態を抑える。建設費・開拓人口・所有/地形・探索条件は免除しない。非隣接の中継拠点化や自動売買は別工程。
- 土地の開拓は食料の実増産を優先し、次に食料施設用資材を扱う。従来の探索済み・隣接地・所有・人口条件を維持する。自拠点間の余剰輸送も従来の積載・備蓄保護を使う。狩猟・漁獲の新規行動や自動外交取引は今回追加していない。
- 新規軍備増強は抑制するが、現在兵と訓練予約の合計が `foodPriority.minimumDefenseUnits` 未満なら最低限の補充を許可する。この数は勢力全体のユニット駒数で、君主も含む。開始済みの訓練・建築、積荷の帰還、戦闘・自衛は中止しない。
- 複数拠点では不足の大きい拠点を計画対象にする。所属拠点未設定の旧ユニットは切替前の所属を保持し、移動や維持費の転嫁は行わない。通常食料が安定して備蓄も満たせば通常の増強へ戻る。
- 設定は `config/v39-npc-faction-ai.json` の `foodPriority`（有効化、最低守備数、建設予測候補数）。実装は `v39-npc-food-priority.js`、既存の開発計画・開拓・資源部隊処理。一般村には新しい徴兵抑制を適用せず、人間プレイヤーを自動操作しない。
- NPC診断の「資材」「行動目標」に、拠点別の通常食料産出・維持、代用後の収支不足・備蓄不足と優先状態を表示する。診断表示だけではAIを実行せず、保存済み計画を参照する。

UI110: 魔族の初期拠点へ地形で抽選した人族の奴隷住民10〜15人を追加。既存の混住生産・維持消費へ接続する。魂/死体不足時は既存の勢力AIから人数を消費して変換できるが、暫定で最低5人を残し1T1人まで。在庫が足りている場合は使わない。住民身分と初期支給・換算・保存の正本は[人口成長・食料不足ルール](../economy/人口成長・食料不足ルール.md)を参照。NPCだけの無料資源生成や新たな人口供給ループではない。

## 自勢力内の拠点間調達（UI108）

- 地上の勝利NPCが複数の自拠点を持つ場合、資源任務は他の自拠点の余剰物資を採取地より先に候補にする。同じワールドの配置済み拠点だけを対象にし、他勢力・一般村の在庫を勝手に取得しない。一般村は現状1拠点のため、村同士の売買に流用しない。
- `config/v39-npc-faction-ai.json` の `internalSupply.enabled` で新規調達を切替、`foodReserveTurns` で供給元の最低食料備蓄期間を設定する。食料は資源任務の備蓄期間より少なくしない。各拠点の次の建設費用（代替材解決後）、現在の徴兵予定費用、食料備蓄、設定された魂/死体の人口需要を残し、それを超える実在庫だけを運ぶ。未選択拠点の建設不足も拠点別に計画へ含める。
- 供給元の予定保護量は `aiState.supplyBudgetBySettlement`。到着前には在庫を減らさず、現地で `loadV39SettlementResource` が現在の在庫・保護量・不足量・積載余力を再確認する。受渡し分だけ元在庫を減らし、実際の部隊/個人の荷物へ加える。積み込みに追加APは設けず、移動AP・地形・災害・生存・集合条件は通常処理を使う。
- 同じ不足拠点へ運搬中の実荷物を数え、重複して積みすぎない。部隊共有荷物は一度だけ数える。不足分を全て搬入中なら他の担当は待つ。輸送中の荷物がある軍隊を新しく部隊へ組み替えて配送先を消さない。
- 荷物には個別の `cargoDeliveryTargetByUnitId` または部隊共有の `cargoDeliveryTargetSettlementId` を保持する。共通荷下ろしは指定先以外の拠点では行わず、供給元へ即座に戻したり、途中の拠点へ落としたりしない。指定先で在庫へ加え、空荷になったら指定を消す。採取/残留品回収の資源任務にも持帰り先を保持する。
- 既存自動輸送、物流画面の通常ルート、NPC調達の拠点積み込み量の計算を同じ `loadV39SettlementResource` に統一。別の積載上限・物資増殖用の処理を作らない。外交取引の成立・対価・友好度判定は追加していない。
- 勢力データ正規化で資源任務・部隊目標数・備蓄基準が失われる問題を修正。通常セーブへ保存し、旧データで実行用情報がない場合は残っている診断用計画から復元する。配送先も保存し、ロード後に同じ荷物を届ける。完全に失われた過去情報は復元しない。
- NPC診断の資源分担と直近コマンドに供給元・不足拠点・取得量/現在の対象を表示する。他勢力の非公開物流を通常画面へ公開する変更ではない。
- 検証: `scripts/check-v39-npc-internal-supply.mjs`。備蓄/建設費保護、遠隔/他勢力/別ワールド/プレイヤーの除外、個人/部隊積載、小数端数、実在庫/荷物の保存則、即時返却防止、二重積込/搬入中量、実配送と保存後の再開・旧診断復元、実AI接続、390/1100px。通常の物流/洞窟輸送・旧自動輸送・資源軍隊・開拓も回帰確認する。
- 未実装: 他勢力プレイヤーとの自動売買・調達交渉、新規中継拠点化、洞窟等をまたぐNPC調達。一般村への交換/郵送支援と、発見済み特殊資源へ向かう限定的な隣接開拓はUI123で接続（冒頭を参照）。

## 不足資源に合う隣接地の開拓（UI107）

- 勢力NPCと一般村で `v39-npc-resource-expansion.js` を共用する。不足量を拠点/資源ごとに最大値で整理し、既存の `getV39LandExpansionCandidates` が許可した探索済み候補だけを評価する。プレイヤーの開拓を自動実行しない。
- 候補を取得した後の通常経済収入を予測し、現在との差分へ不足量の重みを掛けて比較する。村の住民技能・人口稼働率・土地用途・地形・既存施設・危険地帯の産出補正を使い、全不足資源を合わせた増産評価が正になる候補を選ぶ。森/鉱石の名称を別のAI用産出表へ固定しない。
- 評価設定は `config/v39-npc-faction-ai.json` の `resourceExpansion`（`enabled`、`deficitWeightCap`、`candidateLimit`）。候補上限内で比較する。通常工期・担当人数・同時上限は既存 `V39_LAND_EXPANSION_BALANCE` を使う。OFFでも開始済みの計画は通常処理で進む。勢力NPCは不足がない場合/OFF時には従来の通常開拓を続ける。
- 所有済み土地、一般村の領域、覇権地、未探索地、敵がいるマスは取得しない。海/湖は通常どおり船着き場/港の範囲が必要。同じ土地に他村の開拓予約がある場合も競合する。工期中に敵や他勢力が入れば通常の停止判定を使い、除かれれば続ける。
- 一般村の資源作業処理で開始済み計画を一度だけ進め、完成したマスの領有者・所属拠点・資源用途・村の領域一覧を更新する。完成前には通常収入を加算しない。完成後は次の村経済処理から実在庫へ加算する。開拓担当人数を村の就業人口から予約し、停止中は通常生産へ戻す。
- 勢力は既存の経済ターン処理で工期を進める。村専用の勝利勢力や新しい開拓キューは作らない。進捗は通常セーブへ保存し、NPC診断/村→情報に「資源地の開拓」の対象・残りT・停止理由を表示する。
- `scripts/check-v39-resource-expansion.mjs` で木材不足時の森優先、人の除外、探索/所有/覇権地/水域/人口/予約競合、非産出資源、OFF、重複開始、就業人口予約、村の中断/再開/完成/実収入、保存、実NPC起動経路、390/1100px表示を検証する。
- 未実装: 非隣接地への開拓経路計画、遠隔の中継拠点、自動購入・対外調達交渉。隣接候補で資源を増やせない場合は条件待ちとなり、既存の探索・採取・村の支援依頼を維持する。

## 資源任務の分担（UI106）

- 勢力NPCと一般村に共通の資源任務処理を追加。一般村は勝利勢力へ登録せず、村の守備軍・在庫・独立した作業状態を共通APIへ渡して結果を戻す。一般村の接続は[一般村ルール](一般村イベント共通ルール.md)。プレイヤーを自動操作しない。
- 建設・徴兵・食料備蓄・魂/死体需要の不足を拠点/資源別に整理する。同じ在庫への複数用途は最大不足量で扱い、支出予約の合計とはしない。不足量を `resourcesPerArmy` で割って切上げ、資源ごと・全体の上限まで軍隊任務を要求する。
- 調整値は `config/v39-npc-faction-ai.json` の `resourceTeams`。初期値は100不足につき1任務、同じ資源は2任務まで、勢力6任務/村3任務まで。2駒は任務に新規割当せず、統治者・ネームド・召喚体・他の自動任務・調査中・別マップを候補から外す。全資源へ軍隊を割当後、余剰があれば2駒の部隊へ既存編成APIでまとめる。集合条件・通常AP・積載・地形・災害を共用する。
- 既存の通常軍隊/精鋭軍隊を先に割り当て、足りなければ通常の徴兵費用・人口・上限・訓練を満たして補充する。勢力の基本6駒目標を必要任務数に応じて拡張し `maxUnits` を超えない。基本目標を超える補充は軍隊のみ。無料即時支給・未解禁職の生成はしない。将来の不足を解消するための徴兵費用も不足していれば、既存兵の探索・依頼/経済処理で解決を待つ。
- 供給元未発見は移動探索。隠れた資源を発見する「調査」は自動開始しない。見た土地の採取可能な森・発見済み洞窟、発見済み残留品を対象にし、既存採取/回収で実荷物へ入れる。採取は担当資源だけ、AP・運搬上限・領土外・マスごとの同ターン制限を維持。普通の森で石や食料を生成しない。
- 荷物があれば指定拠点へ戻り、共通の `v39-cargo-deposit.js` で搬入する。部隊の搬入口に生存隊員が入り、全員が同ワールドの占有マス内または中心周囲1マスにいる場合に部隊荷物を下ろせる。全員の同一マス重複は要求しない。別マップや離れた隊員がいる部隊の遠隔搬入は不可。
- 戦略探索は資源担当を別目標へ動かさず、通常の覇権地/対外行動は未割当兵で継続する。資源需要が解消しても荷物を持つ任務は帰還まで維持する。任務・対象・担当・待機/集合/訓練状況を保存し、NPC診断に「資源確保の分担」を表示。同ターンの再実行は既存AI判定で止める。
- 残る制約: 採取に対応しない資源は探索待ちとなり、既存の領土収入・建設・村の支援依頼等で解決する。一般的な資源の自動購入/他拠点からの調達交渉、資源目的の村の遠隔開拓、新しい魂契約方針は本工程に含めない。既存の魂/死体要求パターンは継続する。
- `scripts/check-v39-resource-teams.mjs`: 不足数/重複排除・予約上限・軍隊/部隊・統治者/プレイヤー除外・未発見供給元・実採取/帰還/搬入・村の有償訓練/完成・村の勝利勢力混入防止・保存・診断390/1100pxを検証。既存の採取、部隊編成、支援、村計画も回帰確認する。

## 種族適性・都市特化（UI104）

- 対象は勝利を目指す `isPlayer=false` のNPC勢力。一般村は別の発展AIを維持し、プレイヤーの選択を自動変更しない。
- 種族シートの推奨クラスを徴兵する種族から加点する。同職の生存駒数による減点で偏りを緩和。既存の軍隊優先、解禁/資材/枠/訓練条件を共用し、推奨職が作れなければ他の候補を選べる。空欄は適性加点なし。
- 都市特化は配置済み・現在ワールドの各拠点について、住民種族の人口比で推奨都市を加点する。住民構成データがない旧拠点のみ勢力種族を使う。都市の効果値は都市JSON、評価係数は `config/v39-npc-faction-ai.json` の `citySpecialization` から取得。
- 食料不足、当該拠点の次の建設資材不足、全国の戦力増強、視界と索敵を満たす敵対者、進行中の研究を評価する。魔術向け加点は魔法研究中のみ。未発見の敵の位置は参照しない。
- 既存の都市規模・施設・研究・地形等の解禁条件と切替待機を共用する。現在の特化がある場合は `minimumSwitchGain` 以上改善するときだけ変更し、同点は現状維持。適性は取得制限・解禁免除・能力値そのものの追加ではない。
- `v39-npc-city-specialization.js` が評価と共通選択APIへの適用、`v39-npc-development-plan.js` が徴兵評価を担当。診断→NPC勢力に各拠点の現在/候補・待機・住民適性・状況理由を表示し、通常セーブへ保持する。
- `scripts/check-v39-npc-affinity.mjs` で人口比、条件、待機、食料優先、資材不足の拠点分離、未発見敵、軍隊徴兵、実AI選択、同ターン再実行抑止、保存と390/1100px診断表示を確認する。一般村の施設適性はUI105で[一般村ルール](一般村イベント共通ルール.md)へ接続。プレイヤー推奨表示は後続。

## 開始設定

- ゲーム開始設定の「ゲーム進行」にNPC勢力数（0〜8）を設ける。新規設定の初期値は2。一般村数、操作勢力数、参加者数とは別。
- `gameSettings.npcFactionCount` として設定・セーブに保持する。古い設定や、数を渡さない内部テストの開始は0とする。
- 通常の開始種族とクラス候補からNPC統治者を生成する。初期編成はヒーロー枠の統治者1体＋軍隊ユニット2体。単独の一般兵2人や、2つの部隊枠という意味ではなく、1駒に複数人が編成された通常軍隊を2駒支給する。
- 通常の `getV39UnitCreationOptions` / `inspectV39UnitCreation` から、開始時の軍事Lv・施設によって解禁されたクラス/army種別を読む。統治者と同じ基礎職を優先し、候補がなければ作成可能な基礎職へ。共通の軍隊初期Lv、装備、combatProfileの人数/HP倍率/攻撃回数、ユニット生成を使用し、通常の初期配置で別々のマスへ置く。未解禁の上位/精鋭軍隊へは変えない。
- 数は `config/v39-npc-faction-ai.json` の `initialArmies`（初期2）。配置前の開始時支給なので、資源/人口の徴兵支払いや訓練キューは発生させない。通常の徴兵制約を緩和したわけではない。既存セーブへ追加支給・既存兵の置換は行わない。テストの「勢力追加」は既存編成の複製用途を維持する。
- 人の初期配置後、NPCの拠点を自動配置する。配置不能なら拡大/勢力数削減の案内を出す。人の担当勢力や操作順へNPCを加えない。
- ローカルと通信ホストの開始状態生成は同じNPC生成を使う。通信ではホストの生成済み状態を配布する。

## 行動方針

### 役割の分離（2026-10-21 / UI67）

- 勢力NPCはプレイヤーに相当する競争相手。探索・領土拡張・戦力増強・覇権地の確保を進め、勝利を目指す。
- 一般村NPCは地域の生活・発展・防衛と、依頼/取引/交流を担う。勢力NPCと同じ勝利競争AIを適用しない。建設や資源計算などの基礎処理は共用してよいが、役割・目標・報酬を同一にしない。
- 村として配置された天使・悪魔・ヴァンパイア等は、通常の村とは異なる強力な特殊勢力として扱う。ただし勝利は目指さない。一定ターンごとの生贄の奉納により、仲間への加入や対応する種族への変異が可能になる立ち位置。
- 加入対象は軍隊ユニット。基本は1駒を配下に迎え、生贄の量を増やすと2駒、3駒と契約数を増やせる。軍隊内の人数を増やす意味ではなく、村全体が配下になる意味でもない。定期奉納は加入済みの軍隊を維持する費用で、奉納ごとに軍隊を追加生成しない。
- 役割は種族だけで決めない。同じ種族が競争勢力として生成された場合まで、勝利を目指さない村へ変更する意味ではない。村/勢力の分類と種族の性質を分離する。
- UI67では軍隊加入・定期奉納を実装。自拠点の生体住民を指定して人口から差し引く。UI68では交渉者本人の転生（対応種族Lv3・主要種族切替）を追加。詳細と暫定調整値は [特殊村・奉納契約ルール](特殊村・奉納契約ルール.md)。捕虜/配下を個別指定する奉納、NPC勢力が自動でこの加入契約や転生を行う方針は未実装。既存の人口用魂への即時変換や一般村への生贄要求とは別契約。

- 人の操作終了後の既存AIフェーズで行動する。一般村とは別の国・拠点・部隊を持つ。
- 未発見の覇権地は目標に使わない。発見した未確保の覇権地を優先し、既存の奥地入場・攻略・退出・取得処理を使う。
- 取得した地点は確保期間中または妨害中に防衛目標とする。同じ勝利判定が人とNPCを評価する。
- 攻撃可能な敵がいるときは探索でAPを使い切らず、戦闘へ回す。対象がなければ移動して視界を広げる。隠れた資源の調査を探索前の定型処理としては実行しない。地上/奥地の座標や退出待機を混同しない。
- 訓練を建設より先に判定する。生存ユニット+訓練待ちの基本目標数は6で、UI106では資源任務数に応じて拡張する。`config/v39-npc-faction-ai.json` から変更可能。
- 建設候補は施設シートの前提施設・基礎優先度を使用し、防衛・探索に加点する。食料不足時は食料施設とその前提となる墓地の優先度を上げる。通常の研究・地形・費用・枠・工期を満たす必要がある。
- 同施設を際限なく増設せず、拠点の建設キューがある間は次の建設を開始しない。村と共通の前提判定は `v39-facility-development-rules.js`。

## 実行元と確認

UI66では行動目標に加え、建設・戦力増強・不足資材を表示する。`v39-npc-development-plan.js` の共通判定を実際の建設/徴兵と診断用計画に使用する。実行後の状態から次の候補を保存し、UIは `aiState.developmentPlan` を読むだけ。旧セーブ等で計画がない場合は次のAI行動で判断する。

- 建設: 選択拠点の建設中施設/残りT、または実行可能な次候補。実行可能候補がない場合は、資材以外の障害が少ない候補を優先順位順に表示し、条件待ちであることを明示する。建設中の次候補は完成後に判断。資材は代替素材を解決した実費用で比較する。
- 戦力: 生存＋訓練中と `unitTarget`（初期6）を比較。通常軍隊を優先する既存候補順と作成条件を共用し、種族/職業/軍隊か個体か/完成Lv、人口・軍事Lv・上限等の不足条件を表示する。1軍隊は人数に関係なく1駒。訓練予約で目標に達していれば「訓練完了待ち」とする。
- 求める資材: 建設/戦力増強/食料備蓄/魂・死体による人口増加の用途別に在庫/必要量と不足を表示。同じ資源を用途別に示し、同時支出を予約した合計ではない。表示は直近AI判断時点。UI106で上記の資源任務へ接続したが、自動取引は未実装。

検証: `scripts/check-v39-npc-development-plan.mjs`（資材不足→補充→実建設/訓練、建設中、戦力目標達成、保存読込、390/1100の診断、表示によるAI無変更）。

テストON時は「テスト操作 → 診断 → NPC勢力診断」のヘッダー内リストで1勢力ずつ選択する（UI111）。現在プレイヤーの視界では絞らない。下の表示ヘッダーで「資材」「人口」「施設・建設」「行動目標」を切り替え、選択内容だけを描画する。

UI112: 勢力リストは見出しの右横で折り返さず、残り幅へ縮める。項目は一覧順の `N1 / 種族` の短縮表示とし、元の勢力名はoptionのtitleへ保持する。320/390px・18px文字設定でも見出しと同じ行になることを検証する。

UI113: 診断内の見出し/勢力リスト/内容タブ/本文/カード/在庫行の余白は縦2px・横3pxを基準にする。`v39-npc-diagnostics.css` の共通変数 `--v39-diagnostic-padding-y` / `--v39-diagnostic-padding-x` を参照し、今後の診断用操作もこの基準に合わせる。ボタンとリストの固定最小高さ34pxは診断内で解除し、文字サイズは縮めない。

- 資材: 拠点ごとの現在の全在庫と「不足資材（AI判断時の在庫／必要）」を分ける。不足一覧はAIの保存済み判断であり、現在の全在庫一覧や予約量の合計ではない。
- 人口: 拠点別総人口・種族構成・奴隷住民内訳・保存済み成長/不足・人口許容/就業枠/稼働率を表示する。
- 施設・建設: 拠点ごとの完成施設/工事と、次の建設目標・条件待ち理由・都市特化・資源地開拓を表示する。
- 行動目標: 現在の目標/対象名/座標/必要資源、直近コマンド、資源任務、戦力増強計画、所属ユニットの軍隊人数・Lv・ワールド・座標・HP/APを表示する。目標未決定は未設定と示す。

診断を開いたり表示を変えてもAIを動かさず、目標・生産・不足を再計算しない。描画と切替の処理は `v39/dev/v39-npc-diagnostics.js` に集約し、既存テスト操作のイベント委譲/更新処理から呼ぶ。追加の購読やタイマーは作らない。

勢力と表示内容の選択は状態更新・テストタブ切替でも維持し、対象勢力が消えたときは残る最初の勢力へ戻る。勢力選択は標準select、表示タブは左右/Home/Endキーにも対応する。「前回処理ターン」は通常表示から除外。`aiState.lastProcessedTurn` は同ターンにAIが二重行動しないための内部判定として維持する。敵AI診断は野良と村守備軍向けのまま。NPCなしの場合は選択リストを無効にして未登録の案内を表示する。`scripts/check-v39-npc-diagnostic-layout.mjs` で390/1100pxの切替・在庫と判断値の区別・キーボード・選択維持・勢力削除・0件・ゲーム状態非変更を検証する。

開始画面は `v39-field-settings-final.js`、生成は `v39-game-state-bridge.js`、自動配置は `v39-initial-placement.js`、行動は `v39-faction-ai.js`。同じ処理を別の画面やタイマーへ追加しない。

`scripts/check-v39-npc-start.mjs` は390/1100で入力から生成、NPC2勢力の配置、人のみの担当/ターン、保存読込、設定再表示、実ラウンドのAI、発見済み覇権地の目標、NPC0を確認する。既存のlocal-session、faction-ai-objective、faction-ai-explorationも使用する。

## 魂・死体を求める方針

- `config/v39-npc-faction-ai.json` の `resourcePatterns` が行動パターン。`standard` は追加行動なし、`soul-hunter` は増加条件「魂」、`corpse-hunter` は「死体」に対応する。種族名ではなく既存の人口用クラス定義を読むため、悪魔/デヴィル、吸血鬼/ヴァンパイアの別名も共通解決する。同じ増加条件の他種族にも自動適用される。
- `racePatternIds` で種族別にパターンIDを指定できる。例: `{"エンジェル":"standard"}`。勢力単位の `factionState.aiState.behaviorPatternId` があればそれを優先する。`standard` を指定すると強制停止。設定対象は新規生成だけでなく既存NPCにも適用される。
- 不足判定は配置済みの各拠点の住民種族と実在庫。基準は `minimumStock`（初期1）と、次の人口増加に不足するゲージを既存の資源価値へ換算した量の大きい方。別拠点の在庫を合算せず、同拠点・同資源の需要は重複計上しない。
- `actions` の配列順に `recover`（発見済み残留品）、`demand`（既知村への生贄要求）、`raid`（既知勢力への襲撃）を評価する。順序変更/項目削除が可能。確保期間中の覇権地防衛を最優先し、具体的な資源目標があるときは新たな覇権地攻略より優先。供給元未発見の探索だけを理由に覇権地攻略を止めない。
- 残留品は人と共用の `recoverV39GroundLootState` で実際に消費し、所属部隊の荷物へ移す。拠点へ帰る通常AP移動を行い、既存 `depositV39PlayerCargo` で納庫する。遠隔取得や在庫の自動生成は行わない。
- 村は現在の視界か接触記録で認識したものだけ。廃村・属国・敵対村・他勢力の契約済み村を除外。地上の生存ユニットが村の中心から1マス以内に到着したとき、共通交渉AP20と威圧技能/周辺攻撃力/守備軍攻撃力で成否を判定する。`sacrificeDemand` が仮の確率・技能係数・戦力係数・友好度低下幅。成功は既存 `sacrificeContract`、失敗も試行時点と `demandCooldownTurns`（初期5）を保存する。AP不足/同条件同ターン/待機済みは拒否する。
- 契約しただけで村人を消したり魂・死体を在庫へ加算したりしない。既存の休息強襲/救援分岐（契約先との友好度しきい値）へ接続する。村が実際に保持している捕虜・死体を受け取る処理はUI62で通常プレイ/NPCへ共通化した。保管庫の合成専用魂は人口用の魂在庫とは別で、勝手に消費しない。定期的に村人を供給する仕組みは未実装。
- 襲撃は既知勢力のみ。`allowWar` が有効なら既存 `declareV39War` を使って宣戦し、既存戦闘/反撃/死亡処理へ渡す。同盟/不可侵の有効期間中は選ばない。戦争成立だけで魂や死体は生成しない。戦後の残留品が発見されれば通常回収へつながる。野良の無差別狩猟や村への拒否即襲撃は今回追加しない。
- 調査は隠れた資源等を発見する独立行動。コマンド/APIと既存のAP/進捗/完了処理は維持するが、UI64以降は通常NPCの探索にも自動で付けない。NPCが経済目的で調査を開始する別方針は今回追加していない。開始済みの調査を消したりAPを払い戻したりはしない。
- 目標/試行結果/宣戦/回収は既存NPC診断のコマンドに表示。契約・試行期限・行動履歴・荷物は通常セーブに保存する。

`scripts/check-v39-npc-resource-policy.mjs` はViteの5173（`V39_POLICY_TEST_URL`で変更可能）で、既存データによる魂/死体判定、通常方針への切替、未発見情報の除外、要求の成功/拒否/AP/再試行、条約除外/実宣戦、残留品の実回収、実AIイベント・保存読込・通常納庫、390/1100の診断表示を確認する。通常方針の既存目的/探索テストは明示的にstandardを指定して比較する。

戦力の精密評価、拠点昇格の計画、長期の供給量/勝率調整は今後の対応。今回の確認は複数NPC間の長期勝率や完全攻略のバランスを保証するものではない。

## 暫定の魂への即時変換

- `config/v39-soul-conversion.json` の `enabled`（初期true）で切替。`receiverClassNames`（エンジェル/デヴィル）を人口用種族定義の名前と比較し、天使/悪魔の表記にも対応。受取勢力の種族で判断し、配下に天使が1体いるだけでは対象にならない。`soulsPerPerson` は初期1。OFF後も既に変換済みの魂や受取履歴は巻き戻さない。
- 契約先の実際の `heldUnits` を、地上の中心から1マス以内で受け取る。プレイヤーは村の会話タブの「生贄を受け取る」→フッターで実行。NPCは保有契約に未受取対象があれば同じ `receiveV39VillageSacrifice` を使う。元の対象を村から除き、適格な1体につき人口用魂1へ変換、受取ユニット/部隊の荷物へ入れる。装備も荷物へ分離し、既存の通常移動・拠点納庫を使う。受取自体の追加APはない。
- 対象のID/所有者/受取村/ターン/魂数を `sacrificeReceiptHistory` に保存。村内の重複IDと受取済み対象の再受取を防ぐ。自分の拘束ユニットは受取対象にしない。アンデッド/召喚体/魂回収済み対象からは魂を生成せず、変換OFFや対象外勢力と同様に `villagePrisoners` へ装備なしで保持する。履歴・荷物・保持対象は通常セーブに保存する。
- 村の人口報酬も同じ種族/比率/切替を使用し、天使・悪魔へは魂を受取拠点へ加算する。村側の実人口を減らし、受取側の人口は同時加算しない。通常勢力とアンデッド種族の人口報酬は従来の人口移転。報酬欄は変換後の魂アイコン/個数で表示し、元の人口報酬をツールチップで説明する。
- 野戦で敵を倒しただけの自動変換、保管庫の魂の消費、全村人の自動供給、定期輸送は追加していない。変換能力をスキル条件へ変更するのは後続。

検証: `scripts/check-v39-soul-conversion.mjs`。5173で条件・ON/OFF・種族別名・元装備・二重受取・通常人口報酬を確認し、3000の配信ビルドで会話からの受取、保存読込、実AI受取→荷物→帰還時納庫を確認する。390/1100の画面は `output/web-game/soul-conversion`。

## 移動探索と資源調査の分離

- UI63: 魂/死体が不足し、既知の回収先・村・襲撃先がない `resource-search` は、その場の調査を開始しない。APを使って未踏の視界へ向かう。調査済みマスかどうかと、既に見渡したマスかどうかは区別する。既に開始済みの調査を勝手に消したりAPを払い戻したりはしない。
- 既存の `visibility.exploredTileKeys` と現在の実視界を使い、踏査済みで到達可能な土地から未踏境界までの経路を探す。近い未踏領域へ向かうため、調査未実施の隣マスを無条件で往復する処理にはしない。村の位置や未発見資源を目標には使わない。
- 部隊の移動AP・地形・高度・占有・災害通過ダメージを既存処理で検証。`scouting.maxStepsPerTurn`（初期6）以内でAPが続く限り移動し、各歩で視界/既知勢力を更新。村等の具体的な供給候補を認識したら探索を止めて既存の接近/要求/回収目標へ切り替える。到着済みかつAPが残れば同じAIターンに要求できる。戦闘可能時は戦闘を優先する。
- 経路の探索ノード数は `scouting.searchNodeLimit`（初期512）で制限。同一部隊の重複探索を避ける。踏査履歴は通常セーブへ保持し、配下の人数分に別履歴を増設しない。旧 `resourceScouting` 設定も読込互換として残す。
- UI64: 通常 `explore` と供給元 `resource-search` が同じ `scoutNpcMap` を使う。移動の候補選択から `surveyedTileKeys` の依存も除外し、「調査済みだから探索しない」という混同をなくす。通常探索でも目的や覇権地が認識されたら移動を止めて目的を切り替える。
- `scripts/check-v39-faction-ai-exploration.mjs` は通常探索で調査を開始しないこと、複数歩/次ターン継続/AP消費、全マス調査済みでも経路が同じこと、独立した調査コマンドの実行を確認する。`scripts/check-v39-npc-move-scout.mjs` は配信3000で供給元探しの調査なしの複数歩/AP消費、移動中の村発見→要求切替、視界外の村を使わないこと、次ターンと保存後の踏査履歴、390/1100の診断を確認する。
