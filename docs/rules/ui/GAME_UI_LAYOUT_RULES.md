# ゲーム操作UIの構成

## UI248: 料理Ⅱの自動携帯食

- 携帯食料の「保存食を作る」操作は表示せず、料理Ⅱ完了後の補給/自動補給に統合する。説明欄は未解禁なら必要研究名、解禁後は自動加工の比率を示す。手持ちの表示は確定前の加工予定へ勝手に置換しない。
- 経済研究の料理Ⅰ→Ⅱを研究一覧へ追加。詳しい加工/在庫/部隊共有条件は人口成長・食料不足ルールUI248節。

## UI247: 初期ヒーローと軍隊の設定

- ゲーム開始時の設定を、種族→1/2ヒーローのクラス→主人公/拠点名→2/2初期軍隊のクラス選択→マップ設定/配置の順にする。軍隊クラス選択から名前設定へ戻せる。
- クラス選択は既存 ClassSelectModal の基礎職限定モードを再利用する。別の作成画面や軍隊数値定義は新設しない。未選択で途中のプロフィールを確定しない。
- 旧プロフィール呼出しで軍隊クラスがない場合はヒーローと同じ基礎職、または候補先頭を使う。初期2駒の生成・配置・通信の仕様は CHARACTER_STATUS_RULES.md のUI247節を参照。

## UI246: 詠唱の吹き出しと発動待機の魔法陣

- 詠唱中は話し声を示す三点入りの吹き出しをユニット右上に表示する。従来の砂時計と円形台座は使わない。
- 詠唱完了/発動可能状態はユニット中央に魔法陣を表示し、画像の背後へ配置する。直径はユニット枠直径、不透明度80%。従来の右上の稲妻は廃止。準備済みという意味であり、習得済みの即時魔法全般に常時付ける表示ではない。
- フィールドとユニット一覧は v39-cast-symbol.js の共通図形（吹き出し/二重円と星形）を使用。一覧では従来の状態アイコン位置を維持する。詠唱時間/AP/移動で解除等の処理は変更しない。
- scripts/check-v39-cast-presentation.mjs で共通SVGとPhaserの描画、背景への配置をNodeモック検証。実ブラウザは未確認。

## UI245: 外交の通知導線

- 協定申込みを通知ログと一時プレビューへ表示し、選択で相手の外交画面へ移動。「管理」「国家・外交」と外交タブへ未回答の！を表示する。返答/期限切れでマークを消し、再描画や操作担当切替で通知を重複しない。
- 既存通知欄に宛先限定の外交アクションを追加し、別の通知画面は新設しない。詳細は交流・クエスト仕様整理のUI245節。

## UI244: 隣接交流の画面接続

- 交流タブは相手領土または隣接ユニットから対象を表示。村には会話・依頼、NPC/他勢力には取引と外交・協定を出す。マス未選択でも選択ユニットで判定し、ユニット選択/タブ切替で更新する。
- UI243では一般村の距離条件のみが接続され、勢力が対象から漏れていた。今回、実表示関数/操作ハンドラのNodeモック検証を追加。詳細は交流・クエスト仕様整理UI244節。

## UI242: 工期表示を左上へ・初期調査の再初期化修正

- 工期バッジをマス中央から左へタイル幅22%、上へ32%移動。中央の建物画像を空ける。大きさはUI241のまま。値は map-entity-size-rules.js の construction で管理する。
- 初期調査は資源/特産品の生成後にも適用する。従来の生成処理で調査記録が初期化されていた問題を修正。通常の研究・近接発見条件は維持する。
- 実際の生成ハンドラ/描画関数をNodeモックで検査。既存セーブ補修は経済ルールUI242節を参照。実画面は未確認。

## UI241: 工期バッジと高度境界

- 建設の残Tバッジは map-entity-size-rules.js の turnFontTiles を0.30から0.18へ縮小。建物画像を覆う面積を減らす。
- 高度境界は実際の辺から高地側へ3ワールドpxずらし、暗い下地線と明るい細線の二重描画にする。領土線と同一箇所を奪い合わず、高い側も読み取れる。高度差1と2以上の線幅差は維持。既存の高度レイヤー/霧/画像の前後関係を変えない。
- Node描画モックで高地側へのずれ/縁取り/バッジ値を検査。実画面はユーザー確認。

## UI240: 初期調査・予約表示・建設説明

- 建設画面の説明は工期の直下に必要素材（必要数/在庫/不足）を表示する。維持費とは区別し、素材欄は重複させない。
- 自分の建設・発展・壁の予約を現在ワールドの地図に不透明度40%で表示する。同じ土地の複数建物予約は先頭のみ。選択中の同じプレビューは二重表示せず、着手・取消後は予約表示を除去する。実際の施設や資材は予約表示によって変更しない。
- 領土拡張予約は同じマスの再選択で解除、選び直すと末尾へ追加する。後続予約は自動削除せず従来どおり着手条件を再判定する。
- Nodeの実操作イベントと描画モックで解除/再追加、予約の対象範囲、半透明値、取消時の描画除去を検査。実画面は未確認。

## UI239: 拠点フェーズの手順誘導・拡張ワンタップ

- 拠点フェーズ開始時は拠点タブ内の領土拡張を開き、候補選択を開始する。初期の「概況を開いて領土拡張を探す」手順は不要。左の拠点を切り替えた場合も、拡張画面では現在の拠点の候補を表示する。
- フェーズ方式の領土拡張は、候補マスを押すだけで拡張順の末尾へ追加する。マスごとの「計画に追加」ボタンは不要。同じマスを再度押すとその予約を解除する（UI240）。取消は一覧からも可能。実際の領土取得・費用・人数の条件は従来どおり完了/着手時に判定する。現行方式の直接開拓は旧手順を維持する。
- 共通ガイドは「1/3 領土拡張 → 次へ：建設」「2/3 建設 → 次へ：ユニット追加」「3/3 ユニット追加 → 予約の確認へ」。前へも用意し、追加不要の工程は次へ進める。建設は既存の建設画面、ユニット追加は既存のユニット一覧の作成・訓練画面を使用し、機能や在庫を複製しない。
- 建設画面・ユニット作成画面のヘッダーにも同じガイドを表示する。ユニット追加の後は拠点画面へ戻して最終確認を開く。確認では全拠点の拡張/建設予約と訓練中・予約件数を示し、承認した場合だけ拠点フェーズを終える。取消では時間を進めず見直せる。
- ガイドの現在工程は画面用の状態であり、自動着手の予約正本 `operationPlans` や訓練正本 `unitTrainingQueue` と別にデータを二重保持しない。新しい拠点フェーズ/操作担当では領土拡張から案内する。ユニットの費用・訓練条件は既存処理のまま。
- Nodeでワンタップ追加順/連鎖候補/重複禁止、ガイドの前後操作・既存画面への接続、最終確認の訓練数を検査。実画面は未確認。

## UI238: 拠点フェーズの入口・終了確認と個別の順序

- 拠点フェーズに入ると、共通計画一覧ではなく「拠点→概況」を開く。拠点画面には現在「拠点フェーズ中」であることと「拠点フェーズを終了」を固定領域に表示する。共通の「計画n」入口は撤去し、「領土拡張」と「建設・建設順」から各操作を行う。
- 領土拡張では拡張予定だけの「拡張順」を表示し、候補選択中は予約順の数値を地図にも表示する。追加後も候補選択を継続する。建設画面では建設予定だけの「建設順」を表示し、追加後も施設・土地を続けて選べる。「拠点へ」で拠点の建設順へ戻る。
- 拡張順の並べ替えは建設順を動かさず、建設順の並べ替えは拡張順を動かさない。保存と自動着手の正本は同じ `operationPlans` を使い、別のキューを二重保持しない。既存の資材不足時の後続先行は維持する。
- フェーズ終了を押すとゲーム配色の確認ダイアログを表示し、全拠点の領土拡張/建設の予約件数・予約なしの注意・次の拠点フェーズまで編集できないことを示す。「戻って見直す」は終了せず、「確認して終了」でのみ次へ進む。右上のターン操作からも同じ確認を通る。予約追加だけではフェーズを終了しない。
- 確認後は「拠点フェーズ終了。戦闘・探索を開始します」と通知して部隊画面へ移る。複数人の場合は当該勢力の終了を通知し、次の勢力の拠点画面へ進む。ダイアログ表示中に操作担当/ターン/フェーズが変わった場合は古い確認で終了しない。
- 拠点画面の固定部分は可変行数に対応し、本文だけスクロールする。Nodeで終了のキャンセル/承認・自動遷移・種類別並べ替え・確認内容を検査。実画面は未確認。
## UI237: 右上のフェーズ数値と切替テロップ

- 既存の右上ターンボタンの大きさは維持し、上段にT番号、横線を挟んで下段に数値のみ表示する。領土運営は金色の0、戦闘探索は水色の1〜設定戦闘ターン数。分母やフェーズ名は小さなボタン内へ入れない。
- 詳細なフェーズ名/回数はtitleとaria-labelに保持する。現行方式では下段を非表示にし、従来のT番号表示だけを残す。
- UI236のフィールド上端の常設案内は廃止。ヘッダー直下にフェーズ移行時だけ「領土運営/戦闘・探索フェーズへ移行しました」のテロップを3秒表示する。初回表示時も案内し、同じフェーズ内のターン経過・画面更新・操作担当変更では繰り返さない。動きを減らす設定ではアニメーションのみ停止し、表示時間は維持する。
- 表示用データの共通処理は `frontend/src/v39/ui/v39-turn-phase-display.js`。Nodeで数値/色の状態/通知再生条件/終了タイマー/現行方式への復帰を検査。実画面は未確認。

## UI236: フェーズ進行と計画画面

- フェーズ方式ではフィールド上端に領土運営/戦闘探索の周期進捗を表示。ターン終了の操作は領土運営中「計画を確定」へ切り替わる。確定操作だけでは1T経過しない。
- 拠点ヘッダーに「計画 n」を追加。開拓・建設で予約した項目を一つの一覧にし、順序上下・開始予定T・取消・保留理由・着手履歴を表示する。計画画面にも確定ボタンを置く。戦闘探索中は編集不可の参照表示とする。
- 建設画面と開拓確認はフェーズ方式で「計画に追加」と表示する。資材不足でも予約可能で、実着手時に既存ルールを再判定する。配置済み施設を直接増やす仮表示はしない。
- 画面はユーザー確認担当。Node検査・ビルドのみで画面確認済みとは扱わない。

## UI232: 基本タブの行動別表示

- 基本タブは行動選択一覧と、選んだ行動の専用操作表示を同じタブ内で切り替える。別モーダル/別タブは増やさない。移動・待機・回復待機・調査・採取・魂回収・携帯食料/補給を対象とし、条件付きの洞窟行動や部隊行動も同じナビゲーションを利用する。
- 上端の固定ヘッダーは一覧時「行動を選択」、選択時は行動名となる。行動名のヘッダーを押すと一覧へ戻る。専用表示では他の行動を隠し、操作欄を基本タブ内に広く表示。ヘッダーと移動確認をスクロール領域から分離する。
- フィールドの移動先/魂回収対象/集合先などは従来通り上画面で指定する。戻る時に移動/攻撃プレビューや魂回収/集合先選択を解除するが、実行済み待機や補給等を取り消すことはしない。行動の実行後も専用表示を維持する。
- 既存のDOMとイベント、AP/在庫/行動判定は再利用し、専用操作画面を複製しない。基本タブ内の再描画や条件付き行動の入れ替えは同じキーで追従し、選択行動が非表示/削除なら一覧へ戻る。スキルタブの展開仕様は変更しない。
- 共通処理: `frontend/src/v39/unit/v39-basic-action-navigation.js`。`scripts/check-v39-basic-action-navigation.mjs` と携帯食料の回帰テストで確認。実ブラウザ確認はユーザー側。

### フィールドユニット画像のSIZ補正（UI192）

- `map-entity-size-rules.js` の `MAP_ENTITY_SIZE_RULES.unit.sizScalePoints` を共通設定とし、SIZ85＝従来の50%、170＝75%、500＝100%で線形補間する。500以上は100%を上限、極小値は10%を下限とする。SIZ未設定・不正値は旧表示の100%を維持する。
- 自軍・他勢力・一般村・モンスターの画像と画像未設定時の代替表示へ適用する。選択枠・クリック範囲・占有範囲・能力値・一覧の肖像サイズは変えない。SIZの更新を描画更新条件に含める。
- エフェクト設定の人型プレビューは同じ計算の `previewSiz`（170）を使用する。設定による攻撃エフェクト倍率とは独立。
- `node scripts/check-v39-unit-siz-scale.mjs` で補間・上下限・未設定値とフィールド画像描画関数の適用倍率を検証する。画面確認はユーザー担当。
### マップ画質・描画元の解像度（UI194）

- 管理 → 表示設定 →「マップ画質」に軽量・標準・高画質を用意する。指定なしは標準。`mapQuality` を端末のlocalStorageへ保存し、リセットで標準に戻す。
- 原因: `v39-static-graphics-cache.js` が地形・高低差線・Fogなどを固定0.5倍のRenderTextureへ焼き込み、元のワールド寸法へ引き伸ばしていた。特にカメラ拡大時に画像化された斜線・海岸の段差が目立つ。UI193の後処理フィルタでは、この描画元の情報欠損を解消できなかったため撤去した。
- 軽量は従来の半解像度キャッシュ、標準は等倍キャッシュ、高画質はGraphicsを画像化せず直接描画する。高画質は拡大時も線の形状を保持するが、静的な描画命令を毎フレーム処理するため負荷が増える。標準のキャッシュ用画素数は軽量の約4倍。既存の1枚900万画素・GPUテクスチャ寸法の上限は維持し、超過時やCanvas環境では直接描画へフォールバックする。
- 数値は `lib/v39-map-quality.js`、共通キャッシュは `v39/map/v39-static-graphics-cache.js`。地形・高低差・Fog・気象オーバーレイを画質変更時に更新し、旧キャッシュを除去する。地上・地下の非表示レイヤーも次に表示するとき更新する。カメラ倍率・クリック座標・ゲーム状態・ユニットなどの画像素材は変更しない。
- `node scripts/check-v39-map-quality.mjs` は実キャッシュ関数の半解像度/等倍のサイズ、直接描画時に画像化/命令消去をしないこと、旧キャッシュ除去、画素数/GPUサイズ/Canvasフォールバック、更新キー・保存配線を検査する。GPUの実画面と負荷測定はユーザー担当で、未確認。
### 土地変更時の建築画面保持（UI197）

- 建築中の画面で別のマスを選択しても閉じず、対象座標と候補/条件/素材を更新する。他勢力・未所属のマスでは画面を維持し、建築できない理由を表示して着工ボタンとプレビューを無効にする。自領に戻すと再評価する。拠点発展ボタンも他領では実行不可。
- 壁の「囲むマス」は同じ拠点内では範囲へ追加/解除し、別の自拠点を選んだ場合はその拠点の計画へ切り替える。他領・未所属は囲む範囲へ混ぜない。戻る/別タブ/ターン変更など既存の終了条件は維持する。
- 沼地・湿地は地形画像を使用し、旧来の文字/図形マークを重ねない。薬草・峡谷などのマークは変更しない。
- 土地詳細の「特産資源」に発見済み資源の名前を表示する。テスト時は未発見名とその旨も表示し、通常プレイでは未発見資源の有無/名称を漏らさない。現行定義にない名前は「現行データ未定義」、名前欠落は「名称なし」と表示する。古い資源データの自動削除・別資源への置換は行わない。円形資源マーカーにも共通資源アイコンの色を適用する。
