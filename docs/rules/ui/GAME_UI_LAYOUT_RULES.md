# ゲーム操作UIの構成

更新: 2026-10-16。機能の有無だけではなく、判断と操作のしやすさを検証する。

## 共通契約

- 2026-10-26 UI127: 基本行動に「回復まで待機」を追加。目標HP率/待機中の表示と開始・解除を同じカードへまとめる。目標率は管理のゲーム設定で変更しセーブ保存。詳細は CHARACTER_STATUS_RULES.md の「回復まで待機」。回復待機中も共通カード/フィールドの待機色を使用する。

- 2026-10-26 UI124: 今ターンに明示的に待機した生存ユニットは、フィールド画像/代替アイコンと共通カード画像だけを明度72%で暗くする。HP/AP・Lv・選択枠・所有者色は維持し、AP切れや通常行動済みだけでは暗くしない。次ターンは通常色へ戻す。判定と明度は `v39-unit-action-rules.js` を共用し、描画キャッシュにも待機ターン/現在ターンを含める。

- 2026-10-23 UI92/93/94: エフェクト基本タブに「表示位置・伸長」を追加。通常/発射元→対象（横/縦）を選択可能。伸長時も角度・位置X/Y補正は有効。向き設定だけを自動追従のため無効化し値は保持。属性タブでは伸長項目を非表示。同一ブラウザのカテゴリ保存値はゲーム戦闘へ即時反映する。詳細は戦闘エフェクトルールの「発射元から対象への伸長」を参照。

- 2026-10-23 UI90: エフェクト設定の上段へ距離/範囲/円半径をまとめて追加。距離1〜8、単体/着弾円/直線、円半径0〜4を変更し、遠いマスを直接選択できる。対象範囲を色分けし、距離とマス数を表示。UI91では倍率を固定（初期50%）し、手動倍率/全体表示でのみ縮尺を変更する。再生/コマ送り/静止画/実マップ確認で同じ選択を参照し、スキルやゲーム本体の攻撃判定は変えない。確認: scripts/check-v39-effect-preview-range.mjs。

- 2026-10-23 UI89: 施設召喚の詳細に召喚数/編成をまとめて配置。候補のLvで許される1〜最大数を選び、個別/軍隊1駒を切り替えるとプレビュー/費用/必要素材/維持素材を更新する。候補を変えて選択数が対象外になった場合は1体へ戻す。個別配置は必要マスを順に選択/再選択で解除し、全マス選択後のみ確定。戻るで数と編成を保持、キャンセルでは費用を使わない。下限の1体を選べることを維持。確認: scripts/check-v39-summon-batches.mjs。

- 2026-10-23 UI88: 未選択で折り畳んだ共通ユニットカードでも画像上のLvを表示する。画像未対応の種族アイコン側もLvを維持。選択/未選択でカード高さ、名前2行の予約領域、右下HP/APの3px細線位置は変更しない。部隊・ユニット一覧・召喚などの共通CSSで適用。確認は scripts/check-v39-compact-unit-cards.mjs。

- 2026-10-23 UI85: 建築候補は前提施設が所属拠点で完成するまで非表示。工事中は解禁に数えない。通常施設の改築先は改築元が完成しているマスだけで表示する。住居の規模は現在と次段階だけを対象とし、次段階も前提施設未完成なら隠す。解禁済みでも研究/素材/施設枠などが不足する候補はグレー表示のまま選択可能で、不足理由を確認できる。前提判定は既存 hasV39FacilityPrerequisites を共用する。建築APIの実行条件やデータ数値は変更しない。確認は scripts/check-v39-construction-categories.mjs。

- 2026-10-23 UI84: 建築ヘッダーで「すべて／住居／鍛冶／魔法／信仰／軍事／経済」を切り替える。住居は施設シートの「1マス収容人数」>0、研究系は対応する必要Lv>0で分類し、複数所属を許可する。分類は v39-construction-categories.js を共用し、新しいデータ列は不要。住居の村/町/都市/大都市は詳細と収容人数を表示し、次段階だけ既存の拠点発展へ進める。候補なしでは詳細/プレビューを解除。教会などに収容人数が未設定なら住居へ表示しない。確認は scripts/check-v39-construction-categories.mjs。

- 2026-10-23 UI83: 土地選択→建築で下画面の土地タブだけを建築表示へ切替。左に地形に合う施設の画像/名前の縦一覧、右に効果/工期/必要素材と所持数/研究/所属拠点/施設枠/維持費を表示する。条件不足も選択して理由を確認可能。維持費は既存施設の課金処理がないため「なし（現行仕様）」であり、新たな維持費を導入しない。ヘッダー左の戻るで選択マスを維持して土地へ復帰、下端は建築開始のみ。上画面には既存の施設画像/代替マーカーを透過45%で重ね、確定前に資材/配置を変更しない。別土地選択・別タブ・ターン/勢力/ワールド変更・ロード等では表示とプレビューを解除。拠点発展モーダルは規模拡張だけにし、施設管理タブは維持。実行は既存 startV39Construction/inspectV39Construction を共用し、対象土地の所属拠点から費用と枠を参照する。確認は scripts/check-v39-land-construction.mjs。

- 2026-10-23 UI82: 共通カードの名前は選択/未選択とも実幅に合わせて全文を2行以内へ縮小する。省略記号と3行化を廃止。短名は通常サイズ、欄の高さとゲージ位置は維持。共通カードが name-fit モジュールを読み込み、ResizeObserverと追加/更新された名前だけの測定で全画面へ適用する。詳細は UI_TYPOGRAPHY_RULES.md。

- 2026-10-23 UI81: 未選択カードのHP/AP細線は画像の下ではなく右側の最下部へ固定する。名前は最大2行分を確保し、1行/2行でゲージ位置とカード高さを変えない。画像の高さは名前2行＋ゲージ用余白を下限として共通CSSで算出し、画像未対応時の種族アイコンも同じ寸法へ揃える。選択時は従来表示。compact-unit-cardsで画像右側/下端固定/名前との非重複/名前長による位置不変/画像基準の高さを検証。

- 2026-10-23 UI80: 多数のカードを表示すると一覧内で行が圧縮され、ゲージが次行へはみ出す不具合を修正。共通 v39-unit-card.css でカード高さ/内部行を内容サイズに固定し、flex縮小も禁止する。未選択の下限は min-content。描画入口は v39-unit-card.js のまま維持し、画面ごとの補修CSSは追加しない。多数表示・390x600の低い表示領域・内部要素の包含・隣接行非重複・末尾へスクロール選択を回帰テストに追加。

- 2026-10-23 UI79: 共通ユニットカードは未選択時に画像/名前/HP・APの細線（3px）のみへ折り畳み、選択時は従来の座標/Lv/数値付きゲージを表示する。名前は縮小せず2行を維持。部隊・ユニット一覧・召喚/呼集・合成・格納など共通描画の利用箇所へ同じ既定値を適用する。複数選択は選択済みカードを展開。特殊画面で必要なら collapseUnselected:false で解除できる。確認は scripts/check-v39-compact-unit-cards.mjs。

- 2026-10-23 UI78: 施設召喚・スキル召喚・呼集の候補カードもユニット一覧と同じportrait指定を使う。画像解決・シート切り出し・Lvバッジ・経験値枠は v39-unit-card.js を共用し、画像がない候補だけ旧アイコンへ戻す。召喚条件/選択/グレー表示は変更しない。確認は scripts/check-v39-summon-portraits.mjs。

- 2026-10-23 UI77: 拠点ヘッダーに施設タブを追加。完成施設を1件1行で縦に並べ、選択行の直下にHP・召喚/格納操作・改築状況を表示。長い効果説明は折り畳む。選択は拠点ごとに維持し、施設選択時は共通マップフォーカスを使う。土地タブは選択マスの自軍施設だけ同じ操作描画を使う。他勢力・空マス・リセット時は操作を表示しない。建設中一覧と墓地の保護残数を維持。実装は v39-facility-panel.js / v39-settlement-ui.js / v39-land-detail.js。確認は scripts/check-v39-facility-panel.mjs（320/390/1100）。

- 2026-10-21: 村の交渉は `negotiation_hub_fixed_layout.html` を基準に会話/クエスト/取引/情報の4タブへ整理。相手は上右、自分は下左、発言は反対側。元の資源ヘッダーと下端の閉じる/文脈別実行を固定し、4タブは本文の上端へ追従。交渉役・スキル・履歴は情報へ。村の取引は同じハブ内へ既存rendererをマウントし、新しい全面モーダルを重ねない。独立した国家間取引画面は維持する。参考HTMLの仮会話/相場や小さすぎる文字サイズは移植しない。

- 2026-10-18: 拠点はユニット画面と同じ左右分割。左は拠点名・段階・人口の縦一覧、右は選択拠点の名前と概況/生産/施設/運用。左右は独立スクロールし、右ヘッダーとタブは固定。拠点切替で右タブを維持する。発展は概況、施設は専用タブの縦一覧、取引/物流は運用へ配置し、横拠点タブと常設操作列は廃止。入口は拠点の描画元で生成し、既存の発展/取引モーダル・物流画面へ接続する。

- 2026-10-18: 左の「物流」は交流と別タブ。任務一覧/詳細/設定モーダルを所有し、基本行動へ運搬の担当者/搬送先パネルを混在させない。入口警備は土地、物資ルートは物流、取引契約の変更は既存取引画面へ分担する。物流が開いている間だけ現在の計算済み経路と停止/待機をフィールドに表示する。詳細は `物流・運搬ルートルール.md`。

- 2026-10-17: フィールドの部隊詳細は「能力 / 基本 / スキル」の3タブ。基本は移動/待機/調査/採取/会話/休息/洞窟出入り・階層移動/道具使用・補充・製造/鉱床運用。スキルは武器・身体武器攻撃/習得スキル/魔法/パッシブ/召喚・呼集・合体。攻撃手段はスキルへ統一する。操作ロジック/AP/対象選択条件を複製せず、既存のイベント委譲の共通親 `detailTechniqueList` を使い、基本の描画先 `detailBasicList` と技能の描画先 `detailTechniqueRows` を分ける。内部タブキーはstatus/basic/action（actionはスキル）で、移動確認と現地操作への自動遷移だけbasicを選択する。ユニットを切り替えても表示タブは維持する。

- 2026-10-17: 自キャラステータスの表示名を「ユニット一覧」に統一。部隊タブは固定ヘッダーの件数付き部隊セレクト/新規部隊/編制変更から操作し、左側に選んだ部隊のメンバーだけを表示する。部隊一覧を縦に全展開しない。単独も選択でき、空の部隊は空表示。部隊選択と詳細タブは他タブから戻っても維持する。

- 2026-10-17: 自キャラの「キャラクター」一覧は活動中の生存者・施設格納生体・霊廟の保管遺体を同じ共通カードで表示する。一覧内の選択欄で「すべて / 活動中 / 施設内 / 霊廟」を件数付きで絞り込み、既存4タブは増やさない。保管先施設名/座標（地上以外は洞窟）をカードと詳細へ表示。保管中も能力/スキル/装備/成長を閲覧可能とし、編成/装備変更/道具設定/上位職取得は表示しない。死亡者一覧の霊廟表示も維持する。状態配列へ表示用データを再登録せず、閲覧用の合成一覧を作る。

- 共通ステータスはPC/スマホとも2列固定。「攻撃 / 防御」「魔力 / 精神」「命中 / 速度」「SIZ / APP」「移動 / 飛行」を表示する。飛行は技能値を参照するが技能欄では重複表示しない。フィールド・ユニット一覧・合成の共通描画へ適用する。

- 一覧で対象を選び、詳細で状態・効果・費用・条件を確認して実行する。内部IDや実装説明を主要情報にしない。
- 選択中は枠と背景と文字で示す。操作できない場合は理由を確認できるようにする。
- ヘッダーとタブは固定し、一覧と詳細だけをスクロールする。入れ子の全面モーダルを増やさない。
- 文字は共通のPC15px/スマホ12pxと表示倍率を使う。全文を縮小して押し込まない。
- 元の資源ヘッダー、旧研究一覧、既存のゲーム条件・費用・保存データを維持する。
- 既存の描画元を変更する。別のDOM監視や代理クリックで完成画面を上書きしない。

## 検証

- フィールド下部「部隊」の部隊員/単独カードもユニット一覧と同じ画像・切り出し・Lv右下・経験値枠を使う。画像なしの場合だけ従来アイコンへ戻す。HP/AP・座標・自動操作表示・選択操作は維持し、別の画像対応表やカードCSSを増やさない。`scripts/check-v39-squad-portraits.mjs`で320/390/1100pxの画像一致/読み込み、画像クリック、タブ保持と部隊切替を検証する。

ユニットの表示対象だけを切り替えた場合は、開いている詳細タブを維持する。自キャラ画面の「能力/スキル/装備/成長」はキャラクター一覧・部隊一覧・部隊員の切替で能力へ戻さない。フィールドの「能力/基本/スキル」もカード選択・マップ上の選択で維持する。ユニット固有のスキル展開や装備操作メッセージは新しい対象向けにリセットする。

部隊編制の候補は初期状態で「単独＋編集中の部隊」、新規作成時は単独のみを表示。「他の部隊も表示」で移籍候補も選べる。各候補に所属を独立表示し、自動任務などの選択不可理由で所属を隠さない。他部隊から選択済みの候補は表示を戻しても残し、保存前に元所属→移籍先を表示する。チェックを外した現部隊員は単独へ戻る。表示切替・取消では所属やAP・座標を変更しない。

編成の地理条件と、所属を維持した単独行動/散開/集合は [部隊編成・散開・集合ルール.md](../units/部隊編成・散開・集合ルール.md) を参照。部隊操作は自キャラとフィールド詳細で共通表示し、長押しだけの機能にしない。

320/390/1100pxで、実データを使い選択→詳細→実行/戻るを確認する。スクリーンショットで密度と主従を確認する。自動テスト通過のみを「使いやすい」の根拠にしない。未修正・要再検証はUI_FIX_QUEUEへ残す。
