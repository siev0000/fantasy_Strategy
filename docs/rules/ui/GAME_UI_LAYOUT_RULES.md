# ゲーム操作UIの構成

## 選択モーダルの表示ルール

- 候補一覧で名前・アイコン・Lvなどを比較できるようにする。詳細には選択により変わる操作や性能を表示し、候補一覧と同じ情報の繰り返しを避ける。
- 選択中の候補と現在のタブだけ、明るい枠と左端の印で強調する。未選択の候補は文字とアイコンを読める配色にし、枠と背景を控えめにする。複数選択では選択済みの候補すべてに印を付ける。レア度や利用可否の表示と、キーボード操作のフォーカス表示は選択状態と区別する。共通スタイルは `v39-selection-state.css` を使う。
- 「？」は共通ナビとする。画面全体の案内はヘッダー、個別項目の案内は項目名や操作ボタンの横に置く。「？」を押すと対象の近くに案内を重ねて表示し、元の画面や項目の開閉状態、表示の位置は維持する。同じボタン、外側のタップ、Escで閉じる。
- 案内は「次にどこを押すか」「いつ処理されるか」を短く伝える。施設の役割・上限・再使用条件など、操作判断に必要な詳細もここで確認できる。現在の不足や実行できない理由は操作ボタンのそばに表示する。
- 各画面は `v39-screen-help.js` の共通描画に案内の見出しと内容を渡す。開閉と表示位置は共通処理で管理する。固定の案内文は `v39-screen-help-copy.js` にまとめ、ゲームの状態やシートから取得する数値・説明を差し込む。「保持道具」では道具の選び方、個数の単位、在庫からの支給時期と補充時の上限を「？」で案内する。
- 資材は共通の `resource-icon-glyphs.js` のアイコンと必要数で示す。同じ資材は支払い時点ごとに合算し、アイコンを押すと資材名を確認できる。不足している資材は操作ボタンのそばに所持数と必要数を表示する。
- 資源と道具の画像は「都市基本データ」「特産品」「道具」の `画像ファイル`・`画像番号` から読む。`inventory.webp`・`arcanum.webp` は横10×縦5で左上が1番。薬草のように両方の表示で使うアイコンは該当行に一度だけ指定し、名称で共有する。指定が重なる場合は道具の指定を使う。取引・特産品一覧・道具の操作一覧・生成や召喚の費用欄で画像を使い、指定が空欄なら従来の表示を使う。上部の資源バーでは、食料は「穀物」、資材は「木材」、金は「金」の割り当てを使い、未設定時は従来の文字アイコンを表示する。アイコン設定で割り当てた画像は、枠を保ったまま画像部分を1.5倍で描画する。
- 施設召喚とゴーレム工房は同じ「項目一覧画面1」を使用する。呼び出し元は候補・操作項目・費用・戻り先などをデータとして渡す。画面側が左に候補カード、右に「能力」「スキル」と操作欄を表示する。ゴーレムのサイズは右で選ぶ。
- 付与がある場合は右下の「付与へ進む」から共通の付与画面を開く。戻る・確定の操作は設定された行き先に従う。ゴーレム工房は付与と予約の再確認にこの画面を使用する。
- 施設召喚は「召喚時」と「維持」、ゴーレム工房は「作成時」と工期を表示する。
- 項目一覧画面1では候補カードの画像を長押しすると、その画像を拡大する。画像集の場合は該当する1枠を表示する。外側のタップまたはEscで閉じ、一覧の選択とスクロール位置に戻る。
- ゴーレム工房では候補を全種表示し、作成可・別の工房で作成可・条件未達を一覧に出す。「作成可能のみ」は、選択中のサイズでどこかの自軍工房が条件を満たす候補に絞る。右の操作欄ではサイズと工房を選ぶ。工房の作成者、補正後の工期、追加スキル枠を比較できる。追加スキルの増加数は未習得の候補がある付与元の数とする。

- 項目一覧画面2は初期クラス選択とクラス・種族獲得で共用する。呼び出し元から候補・取得条件・能力やスキル・戻る操作を受け取る。上位職の未達候補は理由を確認でき、確定はできない。
- 項目一覧画面3はモンスター合体で使う。レシピ候補、素材枠、候補素材、合体結果のプレビュー、操作ボタンを受け取って表示する。合体条件と確定処理は合体側が判断する。
- タイトルのモーダル一覧から、確認用データを使って装備付与とゴーレム付与を直接開ける。

## 共通モーダルに渡すデータと表示先

各呼び出し元が候補・初期選択・条件・操作を用意する。共通画面は受け取ったデータを配置し、選択や確定を呼び出し元に返す。スキル取得、施設の使用可否、在庫消費、合体の確定は呼び出し元が処理する。

### 項目一覧画面1

諜報もこの画面を使う。派遣・防諜・報告を `tabs`、各一覧を `rows`、選択中の詳細・入力を `detail`、指示・戻る操作を `actions` で渡す。派遣と防諜では人物カード、報告ではターンと任務名を表示する。「戻る」の行き先は勢力情報。 勢力の「概要」では拠点タブの描画を共用し、諜報で記録した項目を閲覧表示する。

`renderV39ItemListScreen1(options)` に見出しと表示用データを渡す。施設召喚・呼集は対象ユニットと施設の選択肢、ゴーレム工房はレシピ・サイズ・工房の選択肢、装備生成は装備候補と選択中の品質での性能を渡す。

| 渡す項目 | 表示先・使い方 |
| --- | --- |
| `title`, `titleId`, `help`, `closeAttribute` | ヘッダーの画面名、見出しID、？の説明、閉じるボタンの識別属性 |
| `tabs[{id,label}]`, `activeTab` | ヘッダーの種別タブと現在のタブ |
| `rows[{id,unit,label,meta,icon,metrics,unavailable,badge}]`, `detail.selectedId` | 左の候補一覧。ユニットカードまたは名前・アイコン・性能を表示し、選択中の候補を強調する。可否の印と文言は `badge` から取る |
| `listNotes`, `listControls`, `listActions` | 左の候補一覧の上に出る説明・選択欄・操作ボタン |
| `detail.unit`, `detail.activeDetailTab`, `detail.notes`, `detail.equipment` | 右の能力・スキル・装備の詳細。補足は能力欄、装備データがあるときは装備タブに出る |
| `detail.kind:"item"`, `heading`, `icon`, `facts`, `sections` | 右の装備などの詳細。見出し・画像、項目名と値、追加説明の順 |
| `detail.controls[{id,label,options,value,attribute}]` | 右の詳細の上に出る選択欄。工房やサイズの選択など |
| `detail.kind:"review"`, `heading`, `lines` | 右の予約再確認の見出しと内容 |
| `footerNotes`, `costs[{label,amounts,summary,stock}]`, `status`, `actions`, `enhancement` | 右下の補足・費用・状態・操作。素材はアイコンと数量で表示し、`stock` があると所持数／必要数を出す。`enhancement` があると「付与へ進む」を追加する |

画面1と共通の付与画面では、ボタンに `id`（操作）、`label`（表示名）、必要に応じて `value`（選んだID）、`destination`（遷移先）、`disabled`（操作不可）、`attribute`（既存操作の識別属性）を渡す。操作時は `readV39ItemListAction` が操作・値・遷移先を返す。候補や詳細タブの識別属性は `detail.candidateAttribute`、`detail.cardAttribute`、`detail.detailTabAttribute` で指定できる。

### 項目一覧画面2

初期クラス選択は種族・前回選んだクラス・基礎クラス限定の有無を `ClassSelectModal` に渡す。ゲーム内の取得画面は `openV39AcquisitionPicker({kind,race,choices,unmet,subtitle,onConfirm})` から開く。`choices` は取得可能な名前の配列で、先頭を初期選択に使う。`unmet` は未達クラスの `{name,reasons}` 配列。種族獲得時は `kind:"race"` と種族キーを `choices` に渡す。各画面の呼び出し元が図鑑・クラスデータを引き、下記の表示用データを `V39ItemListScreen2` に渡す。

| 渡す項目 | 表示先・使い方 |
| --- | --- |
| `show`, `title`, `subtitle` | 表示の開閉、ヘッダーの画面名、進捗や取得に関する補足 |
| `preview{style,src,label,fallback}` | 上段のプレビュー。シート画像の表示指定を `style`、個別画像を `src` で受け取る。省略時は上段を表示しない |
| `categories`, `category`, `categoryLabel` | 分類タブ、現在の分類、読み上げ用ラベル |
| `listLabel`, `rows[{id,label,icon,unavailable}]`, `selectedId`, `emptyText` | 左の候補一覧。名前・アイコン・「未達」と選択状態を表示する。候補も分類も空なら空欄メッセージを出す |
| `selected{label,type,description,requirement,reasons,unavailable}` | 右上の候補名、種別・説明・取得条件・不足理由。`unavailable` が真なら決定ボタンを無効にする |
| `detail{statusRows,skillRows,resistanceRows,equipmentRows,equipmentMode,equipmentTitle,skillNames,statusSource}`, `activeDetailTab`, `skillTitle` | 右の能力・技能・耐性・装備・スキル。現在のタブとスキル欄の見出しも指定する |
| `backLabel`, `confirmLabel`, `categoryAttribute`, `rowAttribute`, `confirmAttribute` | 右下の戻る・決定と、分類・候補・決定の識別属性 |

画面2は `category`・`select`・`detail-tab` で選択値を返し、`back`・`confirm`・`close` を呼び出し元が処理する。取得画面で決定した場合は、呼び出し元が `choices` に含まれることを確認して `onConfirm` に名前を渡す。

### 項目一覧画面3

モンスター合体は `openV39FusionModal(actorId, mode)` で開始する。最初に発動者IDと方式（`skill` または `facility`）を受け取り、合体側が候補レシピや素材の状態を判定して `renderV39ItemListScreen3(options)` に渡す。

| 渡す項目 | 表示先・使い方 |
| --- | --- |
| `title`, `titleId`, `caption`, `closeAction` | ヘッダーの画面名、見出しID、方式／APの表示、閉じる／戻る操作。レシピ選択では方式の表示を省く |
| `recipes[{id,label,preview,notes}]`, `recipeAttribute`, `emptyText` | レシピ選択のカード。画像・合体先の名前・必要素材や可否を表示する |
| `preview`, `controls` | 素材選択画面の上段に出る合体結果プレビューと、その下のレシピ・方式・スキル選択欄 |
| `slots[{id,label,selected}]`, `slotAttribute` | 素材枠の切り替えタブ。必要条件や選択済みの印は呼び出し元が `label` に入れる |
| `candidateHeading`, `candidateScope`, `candidates[{id,content,reason}]`, `candidateAttribute`, `emptyText` | 左の素材一覧の見出し、探す範囲、素材カード、使用できない理由、空欄メッセージ |
| `detail` | 右の「選択素材／合成後」と能力・スキル・装備・成長の詳細 |
| `status`, `actions[{attribute,label,disabled}]` | 下部の状態／不足理由と、素材を選ぶ・確認・確定などの操作ボタン |

`preview`、`controls`、`detail`、カードの `content` は、呼び出し元の既存レンダラーが作る表示断片を渡す。画面3はボタンに識別属性を出力し、呼び出し元が素材選択・確定・戻る処理を受け持つ。

### 共通の付与画面

装備は、選択済みまたは生成直後の装備の在庫キーと戻り先を受け取って開始する。ゴーレムは、選択済みのレシピ・サイズ・工房を引き継ぎ、頭を初期選択にする。装備は `renderV39EnhancementScreen(options)` を直接、ゴーレムは画面1の `detail.kind:"enhancement"` から同じ描画処理を呼ぶ。

| 渡す項目 | 表示先・使い方 |
| --- | --- |
| `groups` | ゴーレムの左列の部位・改造。装備では省略する |
| `choices[{id,value,label,focused,selected,disabled,description}]`, `emptyText` | 装備では左列、ゴーレムでは右上の候補一覧。`focused` は詳細を表示中の候補、`selected` は付与案に選択済みの候補 |
| `target{heading,icon,lines}`, `choice{label,lines,amounts,action}` | 装備では右列、ゴーレムでは右下の詳細。対象・在庫や上限、候補の効果、必要素材、選択・解除の操作を表示する |
| `summary`, `costs`, `status` | 詳細の下に出る選択済みの付与、作成全体の費用・工期、結果や不足理由。ゴーレムの `footerNotes` はここで `summary` として使う |
| `actions` | 最下段の戻る・付与実行・予約確定 |

### タイトルのモーダル一覧

一覧の登録に `id`、`group`、`name`、`from`、`fixture`、`selector`、`open` を渡す。`group` は一覧の区分、`name` はボタンの名称、`from` はその下に出る通常の入口。選択された `id` を使って確認用画面を開き、`fixture` で確認用データを準備して `open` を実行する。`selector` は確認画面を開けたか判定するために使う。

| 確認項目 | 最初に準備・選択するもの |
| --- | --- |
| 装備付与 | 武具作成テストの在庫からアンコモンの剣を選び、「この装備に付与」を押す |
| ゴーレム付与 | ゴーレム作成テストの工房を開き、作成可能な候補で「付与へ進む」を開く |


## 固定マップ作成

- 「プレイ形式を選択」から「固定マップ作成」を開く。下部左サイドの「マップ」で新規作成、勢力の追加・切り替え、JSON保存・読み込み、ゲーム開始、地形・資源配置を操作する。
- 「マップ」で選んだ地形はマスを切り替えても保持し、新規マップの初期地形にも使う。範囲選択では始点と終点を押し、「範囲に反映」で地形をまとめて変更する。高度は単マス編集で変える。ランダム生成した地形と高度も下地に使える。
- 「拠点」は通常の拠点一覧を使う。「拠点を追加」「一般村を追加」は既存の初期配置画面を開く。「領土拡張」から地図で選んだマスをその場で領土に加えられる。
- 「土地 → 建築・設備 → 建築」で通常の施設一覧を開き、地図上の自領から設置先を選ぶ。固定マップ編集中は資材・研究・前提施設・建築数・工期を適用せず即時に配置する。施設・壁はJSONに記録する。
- 「部隊」から「作成・訓練」を開き、種族・職業・Lvを指定して配置先を選ぶ。編集時は人口・資材・研究・訓練の制限なく配置する。開始にはプレイヤー操作の勢力が1つ以上必要で、各勢力に初期拠点と君主ユニットを配置する。
- 「JSON保存」で下書きを含めてファイルに書き出す。「JSONを開く」で再編集できる。「このマップで開始」またはタイトルの「固定マップで開始」から始めると、配置済みの状態でターン1に入る。開始時の不備はメッセージに表示する。

## アイコン設定（開始前の確認用）

- 表示用のアイコンは種別と対象名で設定する。建築費、産出、収支、依頼、地図の特産品も各資源の割り当てを参照する。画面用アイコンには基本行動、管理メニュー、研究カテゴリ、技の分類、地形マーカーを登録する。新しいアイコンを追加するときは設定対象と描画側を一緒に追加する。
- 上部の資源バーから開く内訳では、穀物・野菜・肉・魚など、各資源の名前で「資源・資材」の割り当てを参照する。

- 「プレイ形式を選択」の「設定」→「アイコン設定」から開き、閉じるとプレイ形式の選択に戻る。ゲーム開始前のマップ画面と「ゲーム開始設定」からも開ける。
- 付与カラー設定は「プレイ形式を選択」の「設定」→「付与カラー設定」、または装備モーダル右上から開く。付与系統ごとに武器アイコンの本体色と輪郭色を個別に設定できる。系統がない場合は付与能力名を使う。複数の付与がある場合は、本体・輪郭それぞれで最初に色が設定された付与を使う。設定はローカル開発サーバーの `config/v39-enchantment-colors.json` に保存する。旧データは色が設定された最も低い段階の値を本体色として読み込む。
- ヘッダーで装備・資源や資材・道具・画面用アイコンを切り替える。左の一覧で対象を選び、右の一覧でアイコンを選ぶ。「資源・資材」は都市基本データと特産品を表示し、同じ名称は都市基本データの行にまとめる。右の候補は武具、楽器・音楽、道具・資材、地形、個別画像、文字アイコンに分ける。新しいアイコン用画像は `assets/images/アイコン/` 直下に置く。単体画像は自動で候補になり、分割シートは同じファイル名で分割数と分類を `config/v39-icon-sheets.json` に登録する。既存シートの参照を維持し、地形はマップの地形定義と同じ画像番号を使用する。ユニット用画像は従来の `assets/images/units/` に置く。アイコン候補の上に分類とシートの選択欄を横一列に置く。シート選択欄は、選んだ分類に複数の画像シートがある場合に表示する。シートと候補の番号範囲は `config/v39-icon-sheets.json` で管理し、空きマスやクレジット欄は候補に含めない。番号は画像シートの左上を1として行順に数える。 `weapons.webp` の旧指定1〜50番には50を足す。
- 画面用アイコンには人口・友好度・索敵・攻撃・防御・建設・住宅・設定・一覧・携帯食料・補給・手持ち物資の割り当てを保存できる。人口は報酬や取引、友好度は外交や報酬、索敵は調査、攻撃・防御はスキルに使う。基本タブの「携帯食料・補給」と「手持ち物資」は、割り当てが空欄ならそれぞれ 🍞 と 🎒 を表示する。
- 「割り当て」で選択中の候補を設定し、「外す」で指定を空欄にする。⚙から保存、JSON読み込み、JSON出力ができる。
- 同じローカルサーバーに接続しているPC・スマホでは、⚙の「共有JSONに保存」で `config/local/v39-icon-settings.json` を更新する。装備・資源／資材・道具・画面用アイコンのうち、ゲームデータに対する変更だけを保持し、ページ再読み込みで反映する。別の端末が先に保存していた場合は再読み込み前の設定からの上書きを止める。共有JSONに接続できない環境では、同じブラウザー内に保存できる。
- 公開版と保存設定のない端末では、配信ビルドに組み込んだ `config/v39-icon-settings.json` の確定済み割り当てを使用する。ローカル共有JSONやブラウザーに保存した設定がある場合は、保存設定を優先する。
- JSONには種別、対象名（装備名・データ分類・名前）、画像ファイル、画像番号を記録する。文字を割り当てた場合は文字アイコン、色を変更した場合は `アイコン色`（`#RRGGBB`）も記録する。色は選択中の対象に適用する。「元の色に戻す」で指定を解除する。旧装備専用JSONも読み込める。

## 装備モーダル

- 装備アイコンは装備シートの「画像ファイル」「画像番号」を使う。`weapons.webp` は横10×縦10、`armory.webp` は横10×縦5で、左上を1番として行順に数える。画像の指定が空欄なら装備種別の従来アイコンを表示する。
- 装備を行で表示するときは左に装備アイコンと名前、右に部位とレア度の略号を置く。略号は文字で表示し、レア度による色は行全体の枠に使う。「消費量」の品質定義を参照する。召喚の装備タブと部隊画面は同じ装備行を使う。武器アイコンの背後には枠と同じ品質色の淡い光を表示する。

- 装備モーダルはPC・スマホとも全画面で表示する。ヘッダーと「一覧・キャラ装備・生成」のタブ、一覧・生成・付与の主操作欄は固定する。一覧タブは上段の装備タイルと下段の選択中の装備詳細に分け、各段を個別にスクロールする。タイルはアイコン・ランク・個数を表示する。装備の性能欄は項目名と値を1行に並べる。
- 生成は上段に生成予定の装備のアイコン・性能・レア度を表示し、下段で装備、レア度、個数を指定する。「装備を選ぶ」は項目一覧画面1を開く。左にアイコン・名前と、選択中のレア度での威・守・攻撃APを表示する。数値が0の項目は省く。右に選択候補の詳細を表示し、「決定」で選択を生成画面に反映する。「戻る」は元の選択を維持する。
- 一覧の「この装備に付与」は装備名の横に固定し、選択中の在庫装備を付与画面へ引き継ぐ。在庫への付与は1個ずつ行う。生成では「装備を選ぶ」の横の「付与」から共通の付与画面を開き、「付与を反映」で選択を生成画面へ戻す。「戻る」では編集中の選択を取り消す。「生成を予約」で全個数に同じ付与を適用する仕事を予約し、素材を確保する。付与後の性能・合計素材・必要ポイント・完成予定を事前表示する。ヘッダーの製作ポイントを押すと、選択拠点の製作・魔術・信仰の残り／上限を作業一覧の上に表示する。
- 装備とゴーレム作成は共通の付与画面を使う。装備付与は左に候補、右に対象と詳細を置く。ゴーレム付与は左に部位・改造を置き、右を上段の付与候補と下段の詳細に分ける。スマホでは装備・ゴーレム作成のどちらから開いた付与画面も全画面で表示する。効果・必要素材は詳細に表示し、戻る・確定は下部に固定する。ゴーレムは部位・追加スキルごとに対象を切り替え、選択内容と付与Lv上限を確認して作成予約へ進む。各画面の条件判定と確定処理は呼び出し元が行う。
- 装備付与では品質・付与枠の上限や重複で付与できない候補を表示しない。必要な研究Lvが現在より1高い候補までは表示する。選べる段階がない候補は左でグレー表示する。候補を選ぶと右に研究Lv・素材・ターン内の付与回数などの不足理由を赤字で表示し、「追加」「Lv変更」は条件を満たす段階で押せる。
- 装備付与の右下には、追加済みの付与とゲージで選択中の段階を合わせた必要素材・消費ポイントを表示する。同じ付与の段階変更時は変更後の予定額を表示する。生成経由では生成に必要な素材と製作ポイントも含める。
- 装備生成が完成すると、次のターン開始時に所属勢力の通知欄へ予約1件につき1行を表示する。通知には拠点名・付与後の装備名・完成個数を載せる。
- 必要素材を表示し、拠点・鍛冶Lv・素材の条件を満たさない場合は生成を無効にして理由を表示する。付与候補の条件と費用も選択中の拠点のデータを参照する。

- ユニット一覧で自軍の生存ユニットを長押しすると「キャラ装備」を開く。左にユニットのアイコンとステータス、右に現在の装備を並べ、右の部位を選ぶと装備変更へ進む。部隊の能力タブでは「装備」の見出しや「装備なし」の長押しで「キャラ装備」を開く。キャラクター詳細や部隊の装備欄で装備済みの行を長押しすると、該当部位の変更画面へ進む。
- 装備変更は上段に候補、下段に変更前（左）と変更後（右）の比較を表示する。候補カードは左の縦中央にアイコンを置き、右に付与後の装備名・強化Lv・ランク・在庫を表示する。初期表示の「装備差分」は威力・ガード・APなど装備自体の性能を比較する。「スキル・能力への影響」では実際の装備変更と同じ計算で求めた能力差を表示する。どちらも上がる数値は緑、下がる数値は赤で示す。「決定」で反映し、「戻る」で呼び出し元へ戻る。

## UI238: 拠点フェーズの入口・終了確認と個別の順序

- 拠点フェーズに入ると、共通計画一覧ではなく「拠点→概況」を開く。拠点画面には現在「拠点フェーズ中」であることと「拠点フェーズを終了」を固定領域に表示する。共通の「計画n」入口は撤去し、「領土拡張」と「建設・建設順」から各操作を行う。

- 建設順のカードは左のつまみをドラッグして並べ替え、右上の「×」で予約を取り消す。つまみにフォーカスして上下キーでも並べ替えられる。建築画面では施設詳細の「必要素材」横の「？」から、拠点ごとの開始予定ターン別の素材の合計必要量・現在庫・不足量を確認できる。拠点から開く計画一覧では一覧の下に表示する。表示は現在庫との比較で、素材は着手時に消費する。
- フェーズ終了を押すとゲーム配色の確認ダイアログを表示し、全拠点の領土拡張/建設の予約件数・予約なしの注意・次の拠点フェーズまで編集できないことを示す。「戻って見直す」は終了せず、「確認して終了」でのみ次へ進む。右上のターン操作からも同じ確認を通る。予約追加だけではフェーズを終了しない。
- 確認後は「拠点フェーズ終了。戦闘・探索を開始します」と通知して部隊画面へ移る。複数人の場合は当該勢力の終了を通知し、次の勢力の拠点画面へ進む。ダイアログ表示中に操作担当/ターン/フェーズが変わった場合は古い確認で終了しない。
- 拠点画面の固定部分は可変行数に対応し、本文だけスクロールする。Nodeで終了のキャンセル/承認・自動遷移・種類別並べ替え・確認内容を検査。実画面は未確認。
## UI237: 右上のフェーズ数値と切替テロップ

## 検証

- フィールド下部「部隊」の部隊員/単独カードもユニット一覧と同じ画像・切り出し・Lv右下・経験値枠を使う。画像なしの場合だけ従来アイコンへ戻す。HP/AP・座標・自動操作表示・選択操作は維持し、別の画像対応表やカードCSSを増やさない。`scripts/check-v39-squad-portraits.mjs`で320/390/1100pxの画像一致/読み込み、画像クリック、タブ保持と部隊切替を検証する。

ユニットの表示対象だけを切り替えた場合は、開いている詳細タブを維持する。自キャラ画面の「能力/スキル/装備/成長」はキャラクター一覧・部隊一覧・部隊員の切替で能力へ戻さない。フィールドの「能力/基本/スキル」もカード選択・マップ上の選択で維持する。ユニット固有のスキル展開や装備操作メッセージは新しい対象向けにリセットする。

部隊編制の候補は初期状態で「単独＋編集中の部隊」、新規作成時は単独のみを表示。「他の部隊も表示」で移籍候補も選べる。各候補に所属を独立表示し、自動任務などの選択不可理由で所属を隠さない。他部隊から選択済みの候補は表示を戻しても残し、保存前に元所属→移籍先を表示する。チェックを外した現部隊員は単独へ戻る。表示切替・取消では所属やAP・座標を変更しない。

編成の地理条件と、所属を維持した単独行動/散開/集合は [部隊編成・散開・集合ルール.md](../units/部隊編成・散開・集合ルール.md) を参照。部隊操作は自キャラとフィールド詳細で共通表示し、長押しだけの機能にしない。

320/390/1100pxで、実データを使い選択→詳細→実行/戻るを確認する。スクリーンショットで密度と主従を確認する。自動テスト通過のみを「使いやすい」の根拠にしない。未修正・要再検証はUI_FIX_QUEUEへ残す。

### フィールドユニット画像のSIZ補正（UI192）

- `map-entity-size-rules.js` の `MAP_ENTITY_SIZE_RULES.unit.sizScalePoints` で、SIZ85＝50%、170＝75%、500＝100%を線形補間する。500〜1049は100%。大型ユニットは `largeSizScalePoints` で、SIZ1050＝150%、1500＝175%を線形補間し、1500以降は175%。極小値の下限は10%、SIZ未設定・不正値は100%とする。
- 自軍・他勢力・一般村・モンスターの画像と画像未設定時の代替表示へ適用する。大型ユニットは3つの占有マスの重心に画像を表示し、選択は各占有マスで受け付ける。SIZの更新を描画更新条件に含める。
- フィールドのキャラ画像を所属枠・領土線・選択枠より前に描画する。所属枠と選択枠の線の不透明度は `V39_MAP_FRAME_ALPHA` で調整する。
- エフェクト設定の人型プレビューは同じ計算の `previewSiz`（170）を使用する。設定による攻撃エフェクト倍率とは独立。
- `node scripts/check-v39-unit-siz-scale.mjs` で補間・上下限・未設定値とフィールド画像描画関数の適用倍率を検証する。画面確認はユーザー担当。
### マップ画質・描画元の解像度（UI194）

- 管理 → 表示設定 →「マップ画質」に軽量・標準・高画質を用意する。指定なしは標準。`mapQuality` を端末のlocalStorageへ保存し、リセットで標準に戻す。
- 原因: `v39-static-graphics-cache.js` が地形・高低差線・Fogなどを固定0.5倍のRenderTextureへ焼き込み、元のワールド寸法へ引き伸ばしていた。特にカメラ拡大時に画像化された斜線・海岸の段差が目立つ。UI193の後処理フィルタでは、この描画元の情報欠損を解消できなかったため撤去した。
- 軽量は従来の半解像度キャッシュ、標準は等倍キャッシュ、高画質はGraphicsを画像化せず直接描画する。高画質は拡大時も線の形状を保持するが、静的な描画命令を毎フレーム処理するため負荷が増える。標準のキャッシュ用画素数は軽量の約4倍。既存の1枚900万画素・GPUテクスチャ寸法の上限は維持し、超過時やCanvas環境では直接描画へフォールバックする。
- 数値は `lib/v39-map-quality.js`、共通キャッシュは `v39/map/v39-static-graphics-cache.js`。地形・高低差・Fog・気象オーバーレイを画質変更時に更新し、旧キャッシュを除去する。地上・地下の非表示レイヤーも次に表示するとき更新する。カメラ倍率・クリック座標・ゲーム状態・ユニットなどの画像素材は変更しない。
- `node scripts/check-v39-map-quality.mjs` は実キャッシュ関数の半解像度/等倍のサイズ、直接描画時に画像化/命令消去をしないこと、旧キャッシュ除去、画素数/GPUサイズ/Canvasフォールバック、更新キー・保存配線を検査する。GPUの実画面と負荷測定はユーザー担当で、未確認。
### 土地変更時の建築画面保持（UI197）

- 建築中の画面で別のマスを選択しても閉じず、対象座標と候補/条件/素材を更新する。他勢力・未所属のマスでは画面を維持し、建築できない理由を表示して着工ボタンとプレビューを無効にする。自領に戻すと再評価する。拠点発展ボタンも他領では実行不可。
- 壁の「囲むマス」は同じ拠点内では範囲へ追加/解除し、別の自拠点を選んだ場合はその拠点の計画へ切り替える。他領・未所属は囲む範囲へ混ぜない。戻る/別タブ/ターン変更など既存の終了条件は維持する。
- 沼地・湿地は地形画像を使用し、旧来の文字/図形マークを重ねない。薬草・峡谷などのマークは変更しない。
- 土地詳細の「特産資源」に発見済み資源の名前を表示する。テスト時は未発見名とその旨も表示し、通常プレイでは未発見資源の有無/名称を漏らさない。現行定義にない名前は「現行データ未定義」、名前欠落は「名称なし」と表示する。古い資源データの自動削除・別資源への置換は行わない。円形資源マーカーにも共通資源アイコンの色を適用する。
