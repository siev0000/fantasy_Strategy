## 儀式施設と召喚表の接続（2026-10-23）

UI76表示: 施設召喚は召喚元の施設名・拠点名、スキル召喚は召喚者名を右側の共通ユニットヘッダーに表示する。新規個体のsummonへfacilityName/settlementNameまたはcasterNameを保存し、元施設/召喚者がなくなっても参照できる。古いセーブはslotKey/casterIdから現存データを検索し、不明な場合だけ汎用表示へ戻す。旧自動接尾辞は表示時に除外し、新規個体名には付けない。ユニットID・召喚枠・効果時間・クールタイムは変更しない。

### 現行: 施設召喚とスキル召喚（UI74）

UI89: 施設召喚は同種1組を維持する。召喚画面の「召喚数」で1〜召喚可能最大数、「編成」で個別/軍隊1駒を選ぶ。設定はconfig/v39-facility-summon-costs.jsonのmaximumBatchCount（初期4）とbatchLevelRatios（1体=1、2体=.75、3体=.6、4体=.5）。体数ごとの上限は施設の最大Lv×割合を切り捨て、補正前の召喚表Lvと比較する。例: 上限25なら1/2/3/4体の対象上限は25/18/15/12。施設ボーナスは各個体へ付与し、軍隊化してもLvは合算しない。軍隊は既存の召喚軍隊の人数/HP/攻撃回数処理を共用する。

召喚時の金/必要資材と5T維持費は体数分。個別は体数分の異なる空きマスを選び、軍隊は1マスを選ぶ。必要マスが不足・重複・範囲外なら全体を拒否し部分生成/部分請求しない。段階Iの個別複数召喚だけ配置範囲を周囲1へ広げ、1体/軍隊の段階別0/1/2範囲は維持する。選択済みマスは再選択で解除でき、全マス指定後だけ確定可能。戻るで体数/編成を保持する。

枠にはunitIds（旧unitIdも先頭生存個体として維持）を保存。別種類の混在・生存中の追加召喚/補充は禁止。一部消滅では残りの組を維持し、最後の消滅から既存25T待機。改築/保存/別ワールド移動でも同じ組を引き継ぐ。通常スキル召喚は従来の効果文字列の数/軍隊指定を維持し、この施設用の任意体数枠で上書きしない。確認: scripts/check-v39-summon-batches.mjs（閾値境界/1〜4体/個別・軍隊/費用/維持/部分損失/保存/別world/スマホ選択）。

UI87: 召喚表の任意列「必要資材」「維持素材」を消費へ接続。記法は `宝石1 / 魂2`（`宝石_1` も可）。必要資材は生成1体ごとに召喚時、維持素材は生成1体ごとに設定の維持間隔（初期5T）で支払う。施設/スキル召喚で同じ在庫支払い処理を使い、空欄は追加消費なし。施設のLv×2金は別途必要で、金を素材にも書いた場合は合計する。スキル召喚には施設用の金費用を課さない。支払元は施設の所属拠点、スキルは召喚者の所属拠点（不明なら選択拠点）。素材は都市基本データの在庫資源名で判定し、食料/魂/死体はfoodStockByType、それ以外はmaterialStockByTypeを使う。未知素材・不正数値は無料扱いせず拒否する。土地保有扱いの特産品は対象外。地面の死体/霊廟の個体遺体を直接消費する追加機能ではない。

支払いは金と素材を一括検査し、不足時には金/素材/AP/HPの一部だけを消費しない。維持素材は生成時の定義を召喚体へ保存し、以後の支払期日とともに保存/ロードする。通常データ行の費用列は今回は空欄。召喚・呼集テストの開始時のみ検証拠点へ金1000/宝石10とフレイムエレメンタルの必要資材=宝石1/維持素材=宝石1を設定する。テスト設定はconfig/v39-call-test.jsonと拠点のsummonMaterialTestCostsで閉じ、共有召喚表を変更しない。確認: scripts/check-v39-facility-summon-costs.mjs（宝石の召喚/維持/不足/保存、魂の特殊資源在庫、スキルの人数分消費、別テストへ非継承）。

操作確認は召喚・呼集テスト→儀式I→フレイムエレメンタルを選択→配置。宝石10→9、5ターン経過後9→8になる。配信用ビルドでの画面操作と実ターン経過はscripts/check-v39-summon-material-gameplay.mjsで確認する。

UI86: 施設召喚は召喚時に補正込みの実Lv×2金を召喚元拠点の在庫から支払い、以後5ターンごとに同じ式で維持費を支払う。設定は `config/v39-facility-summon-costs.json` の `goldPerLevel`（初期2）と `upkeepIntervalTurns`（初期5）。Lvが変化した場合、維持費は支払い時の実Lvで再計算する。この金費用はスキル召喚には適用しない。金不足の候補は非表示にせずグレー表示し、配置確定時も再検査する。キャンセル/配置失敗では引き落とさない。

維持期日は召喚体の `summon.nextUpkeepTurn` に保存する。同一ターンの重複処理では請求せず、旧セーブの期日未設定個体は読み込み後の最初の処理から5ターン猶予を与える。維持費不足・支払元拠点消失時は暫定的に召喚解除し、既存の25T再召喚待ちへ移る。召喚装備/死体は残さず、実物の荷物だけ既存消滅処理で地面へ残す。支払い/解除は活動ログへ表示する。実装は `v39-facility-summon-costs.js` / `v39-facility-summoning.js` / `v39-summon-rules.js`。確認は `scripts/check-v39-facility-summon-costs.mjs`。

UI75: 候補一覧には対象条件を満たすものだけ表示する。系統外・召喚表の基礎Lvが施設/スキル上限を超えるもの・未解禁の表Lv25超・クラス構成など設定不正のものは非表示。補正後の生成Lvでは足切りしない。枠使用中・再使用待ち・施設占有・修復/改築中・空きマスなし・AP/HP不足・スキルCTなど一時的な実行不能は候補を残してグレーアウトする。選択すると理由を確認できる。施設切替などで選択中の候補が対象外になった場合は、表示中の先頭候補へ選択を戻す。

| 項目 | 施設召喚 | スキル召喚 |
| --- | --- | --- |
| 操作入口 | 拠点→施設→施設選択→施設召喚（または土地→施設召喚） | ユニット→スキル→召喚 |
| 必要条件 | 自軍の完成施設、段階別の範囲内に空きマス。術者不要 | 元スキルの習得・AP/HP・CT・配置先 |
| 対象Lv | その施設の上限I10/II20暫定/III25 | スキル効果の指定Lv。施設の上限では下げない |
| 維持枠 | 同じ拠点の同じ施設系統で同種1組（体数はLv条件で決定） | 施設の維持枠とは別 |
| 効果時間 | なし。施設から離れても活動可能 | 元スキルの効果時間を使用 |
| 再使用 | 組の全員消滅から25T。生存中の追加召喚・補充は不可 | 元スキルのCTを候補間で共有 |

施設召喚は施設・召喚候補を選択後、「召喚先を選ぶ」でフィールドへ戻る。色付きマスを選び「ここに召喚」で実行する。I/汎用儀式場は施設マスのみ、IIは施設マス＋周囲1マス、IIIは施設マス＋周囲2マス。段階は原本の「改築元」を辿った段数から判定する。味方・中立を含む生存ユニットと重なるマスには出現不可。敵（他勢力ユニット・野生敵・敵対村守備兵）が施設マスにいる間は周囲も含め召喚不可。死体・別ワールドのユニットは占有に数えない。地形と壁を共通の進入/壁判定で検査し、壁を越えて範囲の外側へ出現させない。実行時に再検査し、位置未指定/範囲外/占有に変化した場合は枠を消費せず拒否。戻る・中止・Esc・ターン/操作勢力/ワールド変更・ロード時は選択を解除する。スキル召喚は従来の術者隣接配置を変更しない。

施設の `施設召喚枠ID` が同じI/II/IIIは、同じマスの改築で上位へ置換する。枠は増やさず、活動中のユニットと撃破後の待ち時間を引き継ぐ。建築中や改築中は新規召喚不可。改築しても既存召喚体のLvを書き換えない。別系統・別拠点は別枠。

`施設召喚再使用T` の初期値は25。撃破ターンTならT+24は残1T、T+25に再使用可能。待ち時間は `facilitySummonsBySlot`、個体側は `summon.kind:facility` として保持し、保存/ロード・洞窟切替・上位改築でリセットしない。待ち時間が終わっても自動生成せず、再度候補を選んで実行する。施設召喚はスキルAP/CTを消費しない。

施設外での活動可は維持する。施設召喚体も共通の召喚体処理を使い、消滅時に初期装備・再利用できる死体を生成しない。後から積んだ実物の荷物は従来どおり地面へ残す。

原本は `@game_data` の「施設」「召喚モンスターリスト」。通常変換器で両シートを再生成する。召喚対象や段階別の効果値をコードへ重複定義しない。

- 施設の `召喚系統 / 召喚上限Lv / 召喚生成Lv補正 / 召喚補正前提施設 / 魂変換対象 / 魂変換倍率 / 転生最低Lv / 施設召喚枠ID / 施設召喚再使用T / 召喚完成Lv補正` を使用する。
- 自勢力の拠点の完成済み `buildings` だけを参照する。建築中・他勢力の施設・重複建築では効果を増やさない。同系統の上限・補正・倍率はそれぞれ最大値。
- 施設召喚はI=10（ユーザー指定）、II=20（暫定）、III=25。汎用儀式場は10。上限はその施設の値を使い、別施設の上限で引き上げない。通常の表上Lv25超の特殊解禁は別工程。
- スキル召喚は対応するランクI/II/IIIで生成Lv+1/+2/+3。施設召喚本体にはこのランク補正を加えない。汎用儀式場のランク補正は0。
- 四属性完成は火/水/風/土を同段階以上で揃える。Iは召喚表Lv10以下へ+1、IIはLv20以下へ+3、IIIはLv25以下へ+5。補正前の召喚表Lvで判定し、上位へ改築しても下位完成条件を満たす。水にはフロスト系も含む。両召喚に適用し、完成段階間・単独施設のランク補正とは重ねず大きい値を使う。四属性II完成時、表Lv8/15/20は完成+3、表Lv25は完成補正なし（スキル召喚の単独ランク補正は別判定）。表Lv25をIII完成でLv30生成できるが、表Lv30の候補はこれだけでは解禁しない。原本の `召喚補正前提施設 / 召喚完成対象上限Lv / 召喚完成Lv補正` で管理する。
- 天使/悪魔祭壇の魂倍率1.10/1.25/1.50、転生最低Lv4/5/6は原本の暫定値を参照する。
- 魂倍率は既存の人口用魂への即時変換へ適用。小数を保持し、合成用の保管魂には作用しない。転生は最低保証Lvまで不足分だけ取得する。

### 系統から候補を選ぶ召喚

```text
効果:召喚_アンデッド_Lv35_数1
効果:召喚_エレメンタル_Lv35_数1
効果:召喚_セレスチャル_Lv35_数1
効果:召喚_デヴィル_Lv35_数1
```

対象名が召喚表の `分類` と一致する場合、同分類で表の `総Lv` が指定Lv以下の候補を既存モーダルへ出す。スキル召喚はスキルの指定LvとAP等、施設召喚は選択施設の上限・維持枠・25T待機を実行直前に検査する。未解禁候補は理由付きで実行不可とする。既存のクラス名を直接指定する召喚も維持する。

表の `クラス構成`（空白区切りの `クラス名_Lv`）の合計と `総Lv` は一致が必要。生成時に配分を `summonGrowth` として保持し、追加Lvは基礎種族へ与える。装備列を参照し、複数武器候補は生成時にコモン1個を抽選する。候補は元スキルのAP・HP・効果時間・CTを共用し、候補を替えてCTを回避できない。

特殊祭壇によるLv25超の解禁は未実装。表の「プリンシパリティ」「パワード」の構成には現行クラス原本にない `アークエンジェル` があり、今回クラスを自動作成・置換せず実行不可にする。個人のカスタム召喚体編集・召喚支援パッシブは引き続き別工程。

実装先: `frontend/src/lib/v39-ritual-facilities.js`、`v39-facility-summoning.js`、`v39-summon-rules.js`、`v39-soul-conversion.js`、`v39-special-villages.js`。検証: `npm run check:ritual-facilities`、`npm run check:facility-summoning`。

## 現行実装: 召喚

習得済みの複数の召喚スキルを、部隊の行動欄では **召喚** 1項目へまとめる。押すと専用モーダルを開き、左の候補から対象を選ぶ。能力・スキルの表示は自キャラ詳細と同じ共通描画関数を使う。候補選択では消費せず、右下の「召喚する」で確定する。

これは複数の元スキルを表示上まとめる機能であり、1スキルの文字列から候補種族をランダム生成する機能ではない。AP・HP消費、CT、効果時間は選んだ元スキルの値を使う。同じ元スキルは1ターン1回、CTがあればそれも守る。別候補の元スキルは別々に使用できる。

### モーダルの更新

- 同じ候補のカード、詳細領域、タブ、実行ボタンを保持して更新する。通常の状態通知では閉じず、AP・HP・CTと候補の可否を最新にする。一覧スクロールと同じ対象/タブの詳細スクロール・開閉を保持し、別対象/タブを選ぶと詳細は先頭へ戻す。
- 呼集の選択対象が死亡/任務等で使用不可になった場合は、理由を表示して実行不可にする。選択解除は可能。候補自体が消えた場合は選択数から除く。別の呼集スキルを選ぶ場合は選択をリセットする。
- 操作プレイヤー/ワールド/ターン/フェーズの変更、召喚者の死亡、別ユニット選択、ロード/再生成では閉じてロックを解除する。実行直前の可否検査は従来どおり行う。

### 効果の書式

```text
効果:召喚_スケルトン_Lv5_軍隊4_数2
効果:召喚_ゾンビ_Lv5_軍隊3_数2
効果:召喚_グール_Lv9_数1
```

- `召喚_対象名_LvN`: 対象はクラスJSONの名前と完全一致。Lvは生成ユニットの総合Lv。
- `軍隊N`: 1軍隊ユニットの編成人数。省略すると個人ユニット。
- `数N`: 生成ユニット数。省略時は1。軍隊人数とは別。
- Lv・人数・数は正整数。同じ指定の重複や未知のトークンは不正として拒否する。
- `効果時間`: 必須。正のターン数、または `5t` のような既存ターン表記。
- 基礎能力を持たない上位種は、単一の `条件クラス` を遡った基礎種族＋指定クラスとして能力を計算する。グールはゾンビの基礎能力を継承する。召喚は通常のクラス取得条件の検証とは別。

### 仕様確定・未実装: 召喚強化パッシブの対象指定

召喚スキルの生成指定と、召喚後のユニットを強化するパッシブは分離する。召喚強化パッシブは `行動:P` とし、既存のパッシブ共通記法に合わせて `効果`・`対象`・`条件`・数値項目を分けて記載する。

#### 自身が召喚した全ユニットを強化

```text
行動:P
効果:召喚支援
対象:自身の召喚
攻撃+10 防御+10
```

- `対象:自身の召喚` は、そのパッシブ所持者が召喚処理で生成した召喚ユニットを対象とする。
- `条件:召喚クラス_...` を付けない場合は、自身が召喚した対象すべてへ適用する。
- 呼集で移動させた既存ユニットや、死体からのアンデッド化など召喚処理以外で存在するユニットは `自身の召喚` に含めない。

#### 特定の召喚対象だけを強化

```text
行動:P
効果:召喚支援
対象:自身の召喚
条件:召喚クラス_スケルトン
攻撃+10 防御+10
```

- `条件:召喚クラス_対象名` は、召喚されたユニットの対象クラス名で絞り込む。
- 対象名は召喚効果と同様にクラスJSONの名前と完全一致させる。例: `召喚クラス_スケルトン` / `召喚クラス_ゾンビ` / `召喚クラス_グール`。
- 同名パッシブの重複や異なるパッシブ同士の加算は、既存のパッシブ共通適用ルールに従う。
- この節は記載ルールの確定のみで、2026-10-15時点では召喚ユニットへの実効果接続は未実装。

### 仕様確定・未実装: カスタム召喚体・モンスター合成・派生

召喚時に毎回、種族・追加クラス・Lv構成を組み立てる方式にはしない。召喚に使用する構成は **カスタム召喚体として事前に用意・登録**し、召喚時は登録済みの召喚体から選択する方式を基本とする。

- カスタム召喚体は、基礎となる種族/クラスと追加クラスの構成を事前に保持する。
- 追加クラスLvは総合Lvへ含める。例として、スケルトンLv5＋ファイターLv5は総合Lv10として扱う。
- 召喚時の戦闘中操作でクラス構成を都度作成せず、登録済み構成を呼び出す。
- カスタム召喚体の保存形式、登録上限、編集UI、召喚可能総Lvの判定は未実装であり、実装時に別途定義する。

#### `@game_data` の「モンスター合成」シート

モンスターの組み合わせと1体からの派生は、同じシート内で **別表**として管理する。複数体合成と1体派生は処理が異なるため、1種類のレシピへ無理に統合しない。

**合成レシピ**

| 素材 | 合成結果 | ボーナスクラス | 獲得スキル | 状態 | 備考 |
| --- | --- | --- | --- | --- | --- |
| `ホース_1,デヴィル_1` | バイコーン | エボリューションホーン |  | 確定 | ユーザー指定 |

- `素材`: 合成に使用するモンスターを1セルへまとめて記載する。各素材は `モンスター名_必要数`、複数素材はカンマ区切りとする。
- 必要数は正整数。必要数が1でも `_1` を省略しない。
- 素材数は2種類に限定しない。3体以上や同種複数を要求するレシピも同じ1セル方式で記載する。例: `スネーク_3,ドレイク_1`。
- 必要数は、合成結果の体構成や多頭など「実際に複数個体を素材として要求する理由」がある場合だけ増やす。大型化・巨大化・単純な上位化のために同種個体数を増やさない。巨大化は既存のクラス側で表現する。
- `合成結果`: 合成後のモンスター名。
- `ボーナスクラス`: 合成成功時、合成結果が追加で獲得するクラス。空欄なら追加クラスなし。
- `獲得スキル`: 合成成功時、合成結果が追加で獲得するスキル。空欄なら追加スキルなし。
- `状態`: `確定` / `候補` / `未定` を使用する。仮レシピや素材構成が未確定のものは `候補` または `未定` として正式レシピと区別する。
- `備考`: 仮レシピ、参照元、未登録素材などの補足を記載する。
- ボーナスクラスと獲得スキルは、合成結果名そのものとは分離して保持する。合成結果ごとの追加能力をコードへ固定定義しない。
- JSON化するときは、編集原本の `素材` セルを変換器側でモンスター名と必要数へ分解し、ゲーム実行コード側でセル文字列を再解析しない。具体的な出力JSON構造は変換器実装時にこのルールを満たす形で固定する。
- `ボーナスクラス` と `獲得スキル` は、正式変換時には `クラス` / `CS` 原本に存在する名前との参照検証を行う。
- 2026-10-16時点では `エボリューションホーン` は「クラス」原本へ未追加であり、バイコーンのレシピ側のみ先行して確定している。

**派生レシピ**

| 元種 | 派生クラス | 派生結果 |
| --- | --- | --- |
| ウルフ | フロストアニマル | 氷ウルフ |

- 派生は複数体を素材にする合成ではなく、`元種` へ `派生クラス` を追加して `派生結果` として扱う1体変化。
- `派生クラス` は可能な限り「クラス」原本の名前と完全一致させる。対応クラス名がまだ存在しない派生は、派生結果だけを確定扱いにしてクラス欄を空欄のまま残し、変換時に未解決参照として扱う。
- 初期の派生対象は、2026-10-16のユーザー指示により画像生成時にNotionへ整理していた対応を `@game_data` へ転記する。ただしゲームデータとしての編集原本は転記後の `@game_data` とし、Notionを実行時参照元や二重の正本にはしない。
- `出現敵` の「種族＋サブクラス」から拾った候補が、同じ元種・派生クラスでNotion転記済みの確定派生と異なる結果になる場合は、勝手に上書きせず `候補` として競合を残す。

「モンスター合成」シートのJSON変換、合成/派生処理、ボーナスクラス・獲得スキルの付与、カスタム召喚体への接続は **仕様確定済み・未実装**。現時点では生成済みJSONやゲーム実行コードへは接続しない。

### 配置・所属・消滅

- 操作中の生存ユニットが、自分と同じワールドの隣接する空きマスへ生成する。召喚者が部隊所属なら同じ部隊へ追加する。単独なら召喚者を移動先頭にした部隊を作る。
- 召喚ユニットは通常の部隊員5体上限とは別枠。編成画面にも通常人数と召喚人数を分けて表示する。部隊移動・支援・期限時の所属削除は共通処理を使う。
- 必要数の地形進入可能なマスをすべて確保してから一括生成する。生存ユニット・洞窟NPC・壁が塞ぐマスには生成しない。配置不足、AP不足、待機済み、CT中などは理由を表示し、消費しない。
- モーダル中は背後のフィールド入力をロックする。閉じる・Escape・ワールド/ターン等の変更でロックを解除する。
- 効果時間の期限、またはHP0で消滅。死体や生成装備は残さない。消滅後の部隊所属・選択・行動待機データも取り除く。
- 採取・運搬などで後から得た実物の荷物は元のマスに残す。生成装備を実在庫へ移せないよう装備交換を禁止する。
- 生成メタデータを保存・復元する。各ワールドの既存経過処理で期限を判定する。

### 調整値・テスト

`v39-gameplay-balance.js` の `V39_SUMMON_BALANCE` にLvの入力上限と軍隊HP倍率を置く。現行倍率は追加1人ごとHP+50%の暫定値。

シート対象外の `テストクラス.json` / `テストスキル.json` / `テストゲーム状態.json` に上記3種類を接続。ユーザー更新に合わせ、召喚はテストサモナーへ移した。各AP30・効果時間5t（試験値）。呼集はSkill6に追加し、初期のオーガのテストサモナーを総合Lv12にする。通常ゲームへ自動追加しない。正式スキルへの追加は原本 `@game_data` を編集して再生成する。

技能取得は総合Lvではなく職業Lvで判定する。人族なら総合Lv11でSkill11、亜人/魔族は総合Lv11で職業Lv5。Skill6には総合Lv12が必要。Skill11以降の取得は既存の可変処理で可能であり、データ参照検証もSkill10固定から可変列へ変更した。

`scripts/check-v39-summon-ui.mjs` でPC/スマホのクリック操作、候補プレビュー、確認/取消、AP・人数・数・配置・保存・期限を検証する。

## 現行実装: 呼集

```text
効果:呼集_動物_数2
```

無から新規生成する召喚とは異なり、同ワールド・自分の領土にいる生存する自軍の対象から、モーダルで最大2ユニットを選び隣へ呼ぶ。既存ID・HP・AP・装備を保持する。既存ユニットを効果時間で消してはいけない。対象条件、軍隊と数の扱いを召喚と混同しない。

- 行動欄の「呼集」から召喚と同じ共通詳細付きモーダルを開く。対象条件ごとの元スキルを選び、1～指定数まで選択して確定する。
- 自領土外・別ワールド・死亡・自動任務中・発動待機中は選択不可。確認時に再検証し、配置不足等なら移動も消費もしない。全員の地形適性を満たす配置を一括で探索する。
- 呼んだ対象は呼集者の部隊へ移籍する。呼集者が単独なら、呼集者を移動先頭とした部隊を作る。元の所属と移動先頭を整理し、HP・AP・装備・IDは保持する。新しい召喚期限は付けない。実行者だけスキルのAP/HP消費とCTを適用する。
- 呼集対象は既存ユニットなので通常の部隊員5体上限に数える（召喚ユニットだけ別枠）。定員不足・共有運搬品の荷下ろしが必要な場合は、移動/加入/消費を一括拒否する。個人持ちの運搬品は既存の編成ルールで新部隊へ移し、複製しない。すでに同じ部隊の対象は重複登録しない。
- テストタブの「鉱床・道具・部隊支援」内に「召喚・呼集テスト」を追加。テストサモナー、領土内のウルフ/ホース、領土外の比較用ウルフを配置する。現在のゲームを置き換えるため確認を表示する。
- `scripts/check-v39-call-ui.mjs` で実際のテストボタン、複数選択、選択不可対象、保存、Lv別取得を確認する。

正式な召喚シートによる候補抽出・所属選択は保留。習得済みスキルから選ぶ現行方式を維持する（2026-10-14ユーザー確認）。

- 無から召喚するスケルトンに、コモンの剣・槍・棍棒から各生成ユニットへランダム1個を付ける。候補/品質の設定は `config/v39-summon-equipment.json`、性能は生成済み「装備」「消費量」を参照する。明示的なクラス武器1がある場合はそちらを優先する。
