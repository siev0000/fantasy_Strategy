# スキル効果の対応状況

## 共通の強制移動（UI170）

- スキル・災害の移動/怯み耐性/距離/障害物/衝突被害は `v39-forced-movement.js` に一本化する。`v39-disaster-knockback.js` は災害データの変換のみ、`v39-skill-forced-movement.js` はスキルと命中記録の変換のみを担当する。判定式・衝突処理を各入口へ複製しない。
- 効果の記載は `効果:吹き飛ばし` / `効果:押し出し`（発生源から離れる）、`効果:引き寄せ` / `効果:吸引` / `効果:引力`（発生源へ）、`効果:ランダム吹き飛ばし`。方向明示の `吹き飛ばし_外向き` / `_内向き` / `_ランダム` も使える。別名対応と既定値は `config/v39-forced-movement.json`。
- スキルの判定威力は数値 `ノックバック`、既存の数値 `体幹` の順に使用し、通常の判定/追加威力とパッシブ補正で成長させる。どちらもない明示的な強制移動効果は攻撃威力を使用する。数値ノックバックがある既存「打ち倒し」等も対象だが、転倒等の別効果まで実装済みとは扱わない。
- 命中した実ユニットIDだけを、直接攻撃のHP処理後に1回移動する。ミス・死亡・別ワールド・発生源本人は対象外。HP被害0でも命中していれば怯み判定を行う。範囲の対象別倍率を判定威力にも適用。AP/CTは元のスキル処理のみで、移動による追加APを取らない。
- 外向きは発生源から離れる。中心に重なるときだけ六方向からランダム選択。内向きは発生源までで止まり、通り越さない。すでに内向きの発生源上なら動かない。ランダムは六方向から1つ選び、途中で向きを変えたり、塞がれた方向を引き直したりしない。
- 初期の怯み耐性・50ごと1マス・最大3マスは共通configを参照し、災害の既存シート上の個別設定は明示的な上書きとする。衝突時は双方へ軽減済み判定値を打撃威力として適用。詳細は[災害ルール](../world/災害ルール.md)の竜巻節。移動による詠唱解除は既存の共通状態更新へ委ねる。
- プレイヤー/勝利NPC勢力・敵・一般村守備兵・反撃の実戦入口へ接続。衝突被害は通常の戦闘ログ/HP表示へ渡す。Node検証は `scripts/check-v39-forced-movement.mjs`（3つの実戦入口と反撃を実行、共通物理/方向/衝突/命中/詠唱）と `scripts/check-v39-tornado-knockback.mjs`。実ブラウザ画面は未確認。

UI143: 共通戦闘の魔法はスキル選択で先払い詠唱し、完了後に位置を指定して発動する。待機/ターン経過は保持、移動/別行動で解除、別魔法で置換。魂回収・蘇生・地形変換・防御魔法も共通戦闘入口のものは同じ。転移・召喚/呼集の専用画面は維持。操作・保存・例外の正本は[戦闘ダメージ・耐性ルール](戦闘ダメージ・耐性ルール.md)の詠唱節を参照。

| 記載 | 動作 |
|---|---|
| `効果:転移 射程:100` | 地形制限なし。射程内の自拠点または登録地点へ転移 |
| `効果:転移_森 射程:100` | 出発マス・目標地点・実際の到着マスがすべて森の場合だけ転移 |
| `効果:転移 射程:100 待機:1T 効果時間:3T` | 準備1T後に出発地点と登録先を結ぶ双方向の門を3T残す |

- `射程` は既存のスキル射程計算を共用。100は地上10マス・地下20マスが基準で、既存の射程補正も適用する。距離は経路長でなく六角距離（ラップ対応）。壁越しの視線は要求せず、到着マス自体の壁・通行条件と占有を確認する。
- CS151行「木々渡り」はAP60・`効果:転移_森 射程:100`。CS777行は「転移の扉」から「次元の扉」へ改名し、AP100・`攻撃手段:魔法 効果:転移 射程:100`。クラス「デヴィル」のSkill10は既存のCS参照式により改名される。Lv10アクティブは今回のユーザー指定による例外で、他のクラススキル配置は再設計しない。
- 操作可能なスキル一覧では転移系を「転移」1項目へまとめる。押すと同じ欄を専用表示へ切り替え、戻るで通常スキルへ復帰する。転移先を選んだ後、各スキルの射程・AP・不可理由を比較して選ぶ。読み取り専用の能力一覧は元のスキル名を保持する。
- 現在地はAPなしで使用者ごとに1地点を記憶し、全転移スキルで共用。名前指定・上書き・解除が可能。自分の配置済み拠点は登録不要で候補へ追加する。射程外・別マップの記憶も消さず、スキルを選択不可にして理由を表示する。
- 通常の対象は使用者のみ、または所属部隊の生存者全員。部隊全員が同一マップ・使用者の周囲1マスに集合していることが必要。登録地点の周囲1マスまでの通行可能な空きマスへ重複なしで割当て、全員を配置できなければ全体を拒否する。到着マスも射程・地形制限の対象。
- 発動操作で既存のAP/HP費用・CTを適用し、使用者と任意同行者は当該ターン待機。`待機` 列で準備ターンを指定し、未指定は既定1T、明示0は即時発動。ターン待機の場合は指定の全体ターン開始前、回復より先に発動する。使用者の被ダメージ、死亡、移動、対象/編成/登録先変更、到着先の占有等で失敗・中断し、費用は返還しない。ログに成功/失敗を記録する。準備と登録地点は通常セーブへ保存する。
- `効果時間` が正のターン数なら、発動時は使用者を移動させず門を設置する。開通時点から期間を数え、期限ターンに消滅。完成後は作成者が移動・死亡しても維持される。味方・他勢力・敵のいずれもスキル不要で利用できるが、NPCが自動で利用先を判断する処理は未接続。
- 門のマスに立つと「基本」に「転移門に入る」が出る。使用者のみ/所属部隊全員を選択し、利用者1駒ごとにAP20（仮、`config/v39-teleport.json.gateUseAp`）を消費する。往復なら往復分を消費。AP不足・待機/準備中・集合不足・出口付近の空き不足は全体を拒否し、APを取らない。利用時に射程を再計算せず、固定された対の出口へ移動する。地形制限と通行条件は維持する。
- `対象:相手` の技は自身/部隊用と区別し、専用の相手選択を表示する。相手と転移先の両方が使用者の射程内で、敵対・発見済み・同一マップ・生存が必要。相手を事前に待機させない。発動時にも対象・射程・発見・到着場所を再確認し、対象だけを移す。軍隊1駒は1対象。相手への強制転移と持続する門の併用は未対応として拒否する。
- 強制転移ではスキルの `魔法` が正の数値であることを要求する。発動時に共通 `v39-status-resistance.js` で一度だけ抽選し、抵抗成功なら移動なし・術者の費用は返還なし。成功率と抽選結果はログへ記録。計算式・仮の係数は[戦闘ダメージ・耐性ルール](戦闘ダメージ・耐性ルール.md)の状態抵抗節を参照する。
- `config/v39-teleport.json` が登録数1・準備1ターン・到着/集合半径1の初期設定。実装は `lib/v39-teleport-rules.js`、表示は `unit/v39-teleport-ui.js`。ダメージによる中断印は状態bridge、発動は共通ターンの回復前処理へ接続。攻撃候補から転移を除外し、通常のダメージ攻撃として誤使用させない。NPCが自ら登録・転移先を選ぶ方針は未接続。

## 2026-10-13 確定: 部隊支援・部隊条件パッシブの記載

以下の書式を共通部隊パッシブへ接続済み。CS変換器は既存の対象/条件/効果と数値記法で解釈できる。正式クラス/CS原本登録は未完了で、同名正式行がない場合のみconfig/v39-expedition-defaults.jsonの試作クラス・スキルを使用する。

- `行動:P` とし、`効果`は処理の種類、`対象`は補正を受ける相手、`条件`は発動条件、数値項目は補正量に分ける。クラス名で効果を直接決めず、習得したスキルから処理する。
- `効果:部隊支援` は同じ部隊のメンバーへ能力補正を与える処理。
- `対象:他部隊員` は本人を除く部隊員、`対象:部隊全員` は本人を含む部隊員、`対象:自身` はスキル所持者。
- `条件:部隊クラス_名前` は指定クラスを持つ部隊員がいる条件。`条件:部隊種族_名前` は指定種族を持つ部隊員がいる条件。条件の存在確認には本人も含める。
- `条件:部隊統治者` は `isSovereign` が真の部隊員がいる条件。「王」を架空のクラス名として検索しない。
- 対象・条件とも、同じ所属部隊・同じワールドの生存者だけを参照する。死亡・離脱・世界変更で条件が外れれば解除する。
- 同じスキルの複数所持者からの支援は重複させない。異なるスキルの補正は加算する。再描画・ロード・再計算による恒久加算をしない。
- 未対応の条件・対象を無条件の自身強化へ置き換えない。通常の無条件パッシブと部隊補正で同じ数値を二重適用しない。

| 用途 | 詳細欄の記載例（`行動=P`） |
|---|---|
| コマンダーの部隊支援 | `効果:部隊支援 対象:他部隊員 攻撃+5 防御+5 命中+5` |
| 本人を含む部隊支援 | `効果:部隊支援 対象:部隊全員 防御+5` |
| 特定クラス同伴時の自身強化 | `対象:自身 条件:部隊クラス_ナイト 攻撃+10` |
| 特定種族同伴時の自身強化 | `対象:自身 条件:部隊種族_エルフ 魔力+10` |
| 王の騎士の自身強化 | `対象:自身 条件:部隊統治者 攻撃+10 防御+10 精神+10` |

例の数値は現行の仮補正または書式説明用で、全スキルの正式バランス確定を意味しない。複数条件のAND/OR書式や、同名スキルに異なる補正値がある場合の選択規則は別途確定する。同名スキルは正式テーブルのユニーク行を使う。CS原本の編集・スキル一覧再生成は `SPREADSHEET_DATA_WORKFLOW.md` に従う。

### パッシブの共通適用ルール（2026-10-11）

- `行動=P` の習得済みスキルを対象に、能力・技能・耐性・身体武器値・行動数値の同じ分類処理で加減算する。同名スキルは重複加算しない。
- `条件 / 条件系統 / 攻撃手段` がない能力・技能・耐性・身体武器値は、種族/クラスからの再生成時に常時加算する。身体武器値は既存の値÷10のLv換算に従う。
- 条件付き数値は共通条件判定を通す。現在の対応条件は地形名、技名、攻撃手段、系統/属性、HP割合、既存のガード時（反撃）判定。複数条件があれば全条件を満たす必要がある。
- 無条件の行動補正（威力/回復/ガード/AP等）は行動計算時に加算する。射程は既存の武器・スキル補正との合算経路を使用する。
- `威力 / 全威力` の補正は元の威力へ加算し、補正値だけで元威力を上書きしない。元の技に全威力がある場合も属性の加算分を失わない。
- 常時能力へ適用したスキル名を保持し、戦闘計算時に同じ能力補正を再加算しない。元データからの再生成で値を確定するため、画面更新で補正が蓄積しない。
