### 発動スキルの対象候補（共通）

候補の正本は config/v39-skill-triggers.json の targets。発動付きスキルは次の値から選ぶ。通常のAスキルの対象記法を制限する変更ではない。

| 対象 | 意味 |
| --- | --- |
| 自身 | 発動スキルの所持者本人 |
| 発動元 | そのイベントで本人と関わった相手。被出血付与なら付与者、出血付与なら出血を与えた相手 |
| 攻撃者 | 原因となった攻撃を行ったユニット。攻撃由来のイベントだけで使用可能 |

空欄・未登録の対象は実行しない。候補が不足する場合は、この一覧・config・対象解決処理・テストを一緒に追加してから使用する。未登録値を発動元へ読み替えない。対象が必要なイベントにその相手の情報がない場合も実行しない。

### 流血の刃の記載例（合意済み部分）

```text
行動:P
発動:被出血付与
条件:原因_攻撃
効果:反撃_出血値_切断
判定:HP
対象:攻撃者
```

- 自分が攻撃を受けて出血値が実際に増えた場合に、その原因の攻撃者へ反応する。既に出血中というだけでは発火せず、毎ターンの出血ダメージでも発火しない。
- 流血の刃は `効果:反撃_出血値_切断` / `判定:HP`。今回追加された出血値を切断の基礎威力へ変換し、通常と同じ判定・追加威力・防御・耐性の計算へ渡す。HPは既存の能力値 `status.HP` を参照し、残HPを直接参照しない。AP0・射程は検証用の暫定値。反応から反応は発生させず、無限連鎖を防ぐ。
- 共通記法は `反撃_参照値_属性`。参照値は `出血値`（出血付与/被出血付与の今回追加量）、`被ダメージ`（被ダメージイベントの実HP被害）、`今回回復量`（回復付与/被回復の実回復量）。属性は通常の攻撃属性列から選ぶ。例: `発動:被ダメージ / 効果:反撃_被ダメージ_打撃 / 判定:攻撃`。未知の参照値・属性・不一致の発動では実行しない。スキル名による分岐はない。
- 固定威力の反撃は従来どおり `効果:反撃` と通常の属性威力列を使用できる。`追加威力` は通常の能力値補正として使用する。
- Aスキルで一定期間この反撃を付与する方式は記法検討中・未実装。今回の対応は発動付きPの共通記法。
- シートでは候補をプルダウン選択できる形にする案。実際の入力規則と選択肢の管理場所は未実装。

### 本編への接続

- 怯ませ/被怯み・拘束/被拘束は語彙登録のみで、成立判定からのイベント接続は未実装。既存の吹き飛ばしを無条件に怯み成立と見なさない。
- 発動条件付きPは常時の能力・攻撃補正へ加算しない。未知の発動名・未対応条件・未対応効果は無条件化しない。現時点の反応効果は反撃/回復、条件は空欄・原因_攻撃/回復/ターン・出血中、対象は共通候補の自身/発動元/攻撃者に対応する。
- 反応は所持者が生存し、APと射程・同じワールドの条件を満たす場合だけ実行。反撃のダメージは通常の共通計算を使用し、参照できる追加値は今回付与量/今回ダメージ/今回回復量/現在出血値。参照倍率と安全上限はconfigで変更する。

### 出血
- `出血`の数値を持つ攻撃が命中すると、通常の判定/追加威力による状態威力を出血値として加算する。付与時に通常攻撃と同じ防御軽減（魔力判定なら精神）・出血耐性・耐性貫通を適用し、軽減後の値だけを蓄積する。HPダメージの乱数・クリティカル・全体ダメージ倍率は付与値へ掛けない。反撃の参照量も実際の追加量。
- 出血ダメージは毎ターン、減少前の出血値÷10を切り捨てた値。その後に付与時の初期値÷10を減らし、10ターンで0にする。追加で付与されたら現在値＋追加量を新しい初期値として10ターンに更新する。同じターンの重複処理を防ぐ値も保存する。
- スキルで実際に回復したHPと同じ量だけ出血値を下げ、0で解除。過剰回復分は含めない。この回復換算率は暫定1でconfigから変更可能。消耗品・拠点休息など戦闘外の回復との接続は残作業。
- 毎ターンの出血被害は出血付与イベントを発生させない。流血の刃は既に出血中というだけの攻撃、Miss、毎ターンの出血被害では発動しない。

- スキルの判定威力は数値 `ノックバック`、既存の数値 `体幹` の順に使用し、通常の判定/追加威力とパッシブ補正で成長させる。どちらもない明示的な強制移動効果は攻撃威力を使用する。数値ノックバックがある既存「打ち倒し」等も対象だが、転倒等の別効果まで実装済みとは扱わない。

|---|---|
| `効果:転移 射程:100` | 地形制限なし。射程内の自拠点または登録地点へ転移 |
| `効果:転移_森 射程:100` | 出発マス・目標地点・実際の到着マスがすべて森の場合だけ転移 |
| `効果:転移 射程:100 待機:1T 効果時間:3T` | 準備1T後に出発地点と登録先を結ぶ双方向の門を3T残す |

## 2026-10-13 確定: 部隊支援・部隊条件パッシブの記載

## 能力ダメージ・呪い・状態効果の確定ルール（2026-11-04）

- 対象は全ステータス・技能。例: 効果:速度ダメージ。呪い:50 がある場合は速度への呪いとして扱う。
- 通常ダメージ・状態付与はステータスで減衰する。能力ダメージ/呪いも付与時に防御（魔力判定は精神）と対応耐性で軽減する。
- 能力ダメージと呪いは別々に保存し、同じ対象能力への付与は加算。元の能力値は書き換えない。低下後は最低0、APPのみ負値を許可する。
- 通常回復/自然回復の回復威力分だけ、各能力ダメージをそれぞれ減らす。HP満タンでも有効。呪いは通常回復で治らず、呪い回復の威力分だけ各呪い値を減らす。
- 毒・燃焼・出血は効果ターンまで持続。出血は既定の初期値基準の減衰を維持する。
- 睡眠・沈黙・拘束・凍結は軽減後の状態威力を成功率/持続ターンに加算する設計。換算係数は未確定で後日バランス調整する。未実装扱いを維持する。
- 即死・強制転移・アンデッド化の抵抗は精神。吸血は実際に追加した出血値と同量を即時回復する。
- 解除は対象効果の威力を上回れば解除。ただし呪い回復は前述の数値減少方式。
- 持続する防御/能力強化は同じ補正の最大値を反映し、各期限を保持する。1ターン強化・変身・パッシブは別枠で重複可能。
- 接続状況は実装/検証後に本節へ追記する。未接続の効果を実装済みとみなさない。

### 吸血・ドレイン・毒の追加方針（2026-11-05）
- 効果:ドレイン は実際に減らした相手HPの100%、効果:ドレイン_10 は10%を回復。過剰ダメージ・ガード等が吸収した量は含めず、複数対象の実HP被害を合計した後に割合を掛け、HP単位へ切り捨てる。死亡者は蘇生しない。
- 効果:速度ダメージ + 毒:50 は毒による速度低下。通常能力ダメージ/呪いとは別のabilityPoisonへ蓄積し、防御/毒耐性で軽減。通常回復では戻らず、毒回復の回復威力分だけ各毒低下値を減らす方式で接続。
- 吸血は攻撃で実際に追加した出血値と同量をその場で回復。毒/燃焼の継続HP被害は、付与時に防御/耐性で軽減した値を毎ターンそのまま与える（÷10ではない）。拘束は語彙/威力項目のみで、行動制限は未接続。

- 能力指定なしの 毒:30 は継続毒。燃焼:30 または 効果:燃焼 + 炎:30 は継続燃焼。効果時間で指定した回数だけ次ターンから被害を与える。毒値は攻撃時の直接HP威力には足さない。通常の炎属性ダメージは維持し、燃焼値は別に付与する。
- 再付与は各投与分の威力/持続を個別保持し、各ターンの被害は加算。毎ターンの被害へ防御を二重適用しない。効果時間未指定時はconfig/v39-skill-triggers.jsonのperiodic.defaultDurationTurns（検証用暫定3T）を使用する。毒回復は毒による能力低下と継続毒の各付与値を回復威力分ずつ減らす。
- 検証用に吸血/ドレイン10%/毒の速度低下/持続毒/燃焼/毒回復を追加。実装済み項目について以前の未接続一覧を更新する。

### 拘束・組み付きの共通仕様（2026-11-05・後続の確定仕様を優先）

### 1. 用語と対象

- **怯み**: 相手のAPを減らす攻撃効果。**怯み耐性**はAPダメージの元になる怯み威力へ適用する。
- **スタン相当**: 怯みで対象APが0に達し、そのAPでは行動できなくなった結果を指す。別のスタンゲージ、数ターンの強制行動不能、自然回復以外の専用AP回復は追加しない。次のターンには従来のAP回復を通常どおり適用する。通常の行動でAPを使い切っただけの場合を怯み成立として扱わない。
- **体幹**: 吹き飛ばし・押し出し・引き寄せと**転倒**の威力。旧数値 `ノックバック` は体幹へ統一する予定。怯みAPダメージと強制移動・転倒は独立して判定する。
- 強制移動で使っている現行 `怯み耐性` は怯みAPダメージ側へ切り分ける。強制移動の新たな専用耐性は未確定のため、この仕様だけを根拠に追加しない。
- スキルデータに既存の `怯み` と `スタン` が混在するため、記載名・取り込みの互換方針は原本更新前に整理する。名前だけでどちらかの効果を自動推測しない。

### 2. 怯み（APダメージ）の確定計算

命中した各Hitについて、**そのHitのHPダメージを適用した後の対象の現在HP**で計算する。多段攻撃は1スキル1回にまとめず、各Hitで独立して怯みAPダメージを与える。怯み威力の成長には、既存の判定・追加威力・パッシブ補正との整合確認を要する。

```text
有効怯み耐性 = max(0, 対象の怯み耐性 - 攻撃側の耐性貫通)
Lv固定軽減 = 有効怯み耐性 × 対象Lv / 10
軽減後怯み威力 = max(0, 怯み威力 - Lv固定軽減)
耐性割合倍率 = 1 - min(100, 有効怯み耐性) / 100
乱数 R = 0.70 ～ 1.00
APダメージ計算値 = 軽減後怯み威力 × 耐性割合倍率 × R
                 / (1 + (対象の防御 + 対象の現在HP) / 100)
最終APダメージ = round(APダメージ計算値)  // 全補正後・各Hitにつき1回のみ四捨五入
適用後AP = max(0, 適用前AP - 最終APダメージ)
```

- 固定軽減＋割合軽減＋耐性貫通は [戦闘ダメージ・耐性ルール](戦闘ダメージ・耐性ルール.md) と共通。**APから耐性値を直接引くのではなく、怯み威力に先に適用する**。
- HPダメージ用の乱数0.4〜0.5や最終HPダメージ倍率は転用しない。怯みの乱数は70〜100%。
- **将来の全ダメージ端数統一**: 中間の固定軽減・耐性割合・防御計算・乱数には四捨五入を挟まず、命中した各Hitの最終APダメージだけを `round` で整数化する。HPなど他の最終ダメージも同じ原則で統一予定（[戦闘ダメージ・耐性ルール](戦闘ダメージ・耐性ルール.md)参照）。転倒の成功判定値はダメージではないため丸めない。
- 怯みによってAPが0になった場合のみスタン相当として扱い、次ターンの通常AP回復を妨げない。死亡Hitの適用は実装前の未確定事項。
- **反応イベント `怯ませ` / `被怯み` の暫定発動条件（決定済み・未実装）**: 1Hitで対象の**実際のAP減少量が15以上**なら、そのHitの攻撃側・被弾側に対応するイベントを発火する。減少量は最終APダメージの四捨五入・現在AP上限の適用後、`適用前AP - 適用後AP` で判定する。例：30APの計算結果でも残AP10なら実減少10なので発火しない。連撃は各Hitを独立判定し、複数Hitの減少量を合算して15に達しただけでは発火しない。APが0かどうかはスタン相当の呼称の判定であり、このイベントの閾値とは別。閾値15は暫定バランス値として後で調整可能とする。


### 3. 体幹による転倒判定の確定計算

```text
転倒判定値 = 160 × (体幹威力 / 35)
           × (1 + 攻撃側の判定能力 / 100)
           × R / (1 + (対象の防御 + 対象の軽業) / 100)
乱数 R = 0.30 ～ 1.00
成功条件 = 転倒判定値 >= 100
```

- 転倒閾値 **100**、基準係数 **160**、体幹威力は通常の**比例成長**。転倒専用の追加成功率抽選はしない。
- 比較用の想定基礎威力はLv1〜10で35、Lv11〜20で55。攻撃側判定能力100・対象防御100・軽業100では、命中後の成功率がそれぞれ約8.9%・57.6%。これはバランス調整の基準例であり、レベル帯だけでスキルの体幹値を自動上書きする指定ではない。
- 転倒は `効果:転倒` など、**転倒を指定する技**に適用する。単なる体幹数値・強化付与だけでは転倒させない。既存 `効果:打ち倒し` の対応も移行時に調査する。
- 転倒判定の攻撃側倍率と共通スキル威力成長を二重計算しない。技能 `軽業` の実際の現在値の取得・未所持時の扱いは実装時に確認する。

### 4. 転倒中の確定効果

| 項目 | 効果 |
| --- | --- |
| 起き上がり | **20AP** を消費すると即時復帰、残APで通常行動可能 |
| 移動・攻撃・アクティブスキル | 起き上がるまで不可 |
| 回避 | **-25%** |
| ガード | **0**（ガード軽減を無効化し、防御能力は0にしない） |
| 防御 | 通常どおり |
| パッシブスキル | 有効 |
| 自然解除 | なし。起き上がるまで継続 |

**転倒中の強制移動（決定済み・未実装）**: 転倒中でも吹き飛ばし・押し出し・引き寄せを受ける。自発的な通常移動だけを禁止し、強制移動は妨げない。移動後・衝突後も転倒は解除されず、距離と衝突は既存の共通規則に従う。転倒と強制移動はそれぞれ独立に成立判定する。

盾・障壁への影響、同一Hitの細かな処理順、AP不足時の起き上がり操作/敵AIは**未確定**。

### 5. 後続実装の注意点

- 現行の強制移動距離/障害物/衝突ダメージ/災害（竜巻など）は実装済みの経路を維持しつつ、旧 `怯み耐性` への依存を解消する。体幹による転倒判定だけを理由に吹き飛ばし距離を変更しない。
- `@game_data` がデータ編集原本。スキル・災害の移行が必要な場合は [スプレッドシート更新手順](../../SPREADSHEET_DATA_WORKFLOW.md) に従い、`data/source/export/json` の生成物を直接編集しない。
- プレイヤー・敵・一般村守備兵・反撃・範囲・多段・死亡・セーブ/ロード・UI/ログ/反応発動を共通の戦闘経路で検証する。
- **この節への追記のみでは機能実装・ゲーム内検証は完了していない。** 実装が完了した個々の項目だけを「実装済み」に更新する。
