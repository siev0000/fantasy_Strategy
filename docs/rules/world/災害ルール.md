# 災害の現行ルール

更新: 2026-10-28

## 降雪・吹雪の表示（UI184）

- UI186: 雪/吹雪の `outlineWidth` を0.7から1.1へ太くする。他の降水描画値とゲーム効果は変更しない。

- UI185: 見やすさ調整として雪/吹雪の粒を1.5倍（半径3/2.7）へ拡大し、青灰色 `#8196A6` の細い縁取りを追加。粒数・速度・揺れ・角度は維持。縁取りの太さ/濃さも同じ描画設定で変更できる。六角内への収まり判定は縁取り幅も含める。

- 既存の雨描画を共用し、気象「雪」はゆっくり降る白い粒、「吹雪」は多めの粒を45度方向へ速く流す。色・粒数・大きさ・速度・揺れ・角度は `config/v39-atmosphere-display.json` の `rain.snowByWeather` / `rain.types.snow,blizzard` に保持。新規画像や独立した降雪エンジンは追加しない。
- 気象とは別の `snowfallMap=true`（テスト操作の降雪ONや既存セーブ）も同じ粒表示へ接続し、従来の静止した雪結晶文字を廃止する。気象の吹雪を優先し、台風などの局地気象上書きは維持。積雪マップだけでは粒を出さない。降雪と積雪、寒波の青い霧は別扱いで、地形の高さの色を変更しない。
- 視界内だけを描画し、地下・覇権地奥地は除外。雨と同じ粒数上限/更新間隔/カメラ間引き/片付けを使う。雪や吹雪の索敵・移動・HP被害ルールは今回変更しない。Nodeで地域気象/局地上書き/手動降雪/保存/粒の動き/実描画を検証。実画面はユーザー担当。

## 津波の施設HP被害（UI183、UI184で検証完了）

- 原本「災害」津波の詳細設定 `facilityDamageMultiplier=1` により、津波の既存威力200を完成施設へも適用する。0/未設定では施設被害なし。プレイヤー/NPC勢力の全拠点・一般村の、現在ワールドかつ実際の被害マスにある完成施設が対象。工事中だけの施設や別ワールドの施設は対象にしない。
- 領土攻撃と共通の拠点防御・属性耐性計算と、都市の災害耐性/弱点を適用する。複数の対象災害が重なる場合は軽減後の最大被害1回。通常の災害tick記録で同T二重処理を防ぎ、施設HPと拠点一覧の両方へ反映する。
- 施設HPの減算は火山/溶岩と `damageV39FacilityHealth` を共用。既存最大HP（未設定なら100）を使い、HP0は撤去せず「損壊」で機能停止。効果は残HP率へ連動し、既存の物資消費を伴う修理で復旧する。火山/溶岩の倍率や備蓄損失は変更しない。
- 施設被害も既存の災害ログへまとめ、詳細は「農場：100ダメージ」の形式。見出しの被害数は施設を「施設○件」と数え、ユニットと混ざる場合も区別する。自軍/観測/ワールド制限は維持し、未観測の他勢力施設を漏らさない。
- 原本更新/読み戻し/災害のみ再生成、Nodeで実ターン・同T・保存・世界別・重複・損壊・通常修理・一般村・耐性・ログを検証。ユニットへの既存の津波被害と描画は変更しない。実画面はユーザー担当。

## 地震・火山噴火・疫病の画像表示（UI182）

- 視界/発生前/期限切れの非表示を維持し、火口が見えない場合に噴火画像を周囲の見えるマスへ移さない。発生条件・被害・溶岩などのゲーム処理は変更しない。UI180/181時点の「地震・噴火・疫病は未変更」は本節の実装で更新する。
- Node実描画で画像枠/70%不透明度/サイズ/火口1枚/視界/期限/旧バッジ0を検証。実画面はユーザー担当。

## 台風の風向追従・津波の範囲画像（UI177）

- 地域の気象に六角近傍インデックスの `windDirection` を保持する。天候が切り替わるときだけ前の風向から最大1段階（60度）変化し、同じ天候の期間中は維持。気候ID・地域・ターンによる決定的な抽選で、保存後も再現する。変化量は `config/v39-weather.json` の `wind.maximumChangeSteps` で調整する。旧セーブで風向が未設定でも同じ種から補い、次の気象更新で保存する。気象照会にも風向を返す。
- 原本の台風詳細に `followWind=true / windTurnSteps=1` を追加。発生時はその地域の風向を初期方向とし、その後は移動前の現在地の風向へ毎T最大60度ずつ旋回してから1マス進む。六角近傍配列の添字順ではなく実際の時計回り順で旋回する。風向を取得できない場合は従来の方向を維持し、同Tの再処理では旋回しない。既存イベントの保存済み設定は上書きせず、新規発生から適用する。発達/衰弱/索敵/移動阻害は維持。
- 津波は既存「自然災害_アイコン一覧」の対応枠を使い、1イベントにつき大きな1枚を実中心に配置する。実半径で拡大し、視界内かつ影響範囲内の六角マスだけへマスクする。見える端へ中心を移さず、範囲外や未観測マスには表示しない。マスごとの小さいアイコンは出さない。倍率ではなく半径に追従し、移動/視界/期限変更で更新する。描画設定は `config/v39-atmosphere-display.json` の `fieldArtwork.disasters`。台風と六角範囲マスクを共用し、再描画/シーン終了で破棄する。
- 津波の発生条件・移動・威力200・被害範囲は変更しない。UI177時点で残件だった施設HPへの専用被害はUI183/184で接続済み。Nodeの動的災害/津波描画/台風描画/落雷描画で検証し、実画面はユーザー担当。

## 台風の威力による移動・飛行低下（UI176）

- 原本の台風 `災害詳細設定.movementImpediment` に `power=100 / reductionPerPower=0.005 / edgeMultiplier=0.5 / flightMultiplier=2 / maximumReduction=0.9` を暫定設定。HP被害用の威力は0のままとし、直接ダメージ・死亡・盾/障壁/ガード消費は起こさない。
- 中心で威力100%、外縁で50%、中間は六角距離で線形に減衰する。半径0は中心の強さ。局所威力を戦闘と共通の `resolveV39DefenseReducedPower`（威力÷(1+防御/100)）で軽減し、換算係数を掛けて移動低下率とする。防御には現在地の地形・パッシブ・部隊/都市支援を反映する。HP攻撃の命中/乱数/最終ダメージ倍率は使わず、経路探索や表示のたびに結果が変わらない。
- 飛行値があるユニットの移動と飛行能力への低下率は地上の2倍（上限90%）。飛行値の低下は高度差を無視できる量・地形進入条件へも反映。低下した移動値から既存の基礎APを求め、高度・地形・早業・積載・地下倍率を従来どおり適用する。固定の移動コスト加算や恒久ステータス変更ではない。
- 1歩の出発/到着マスのうち強い影響を採用し、範囲への侵入/脱出も同じ計算。複数台風は加算せず最大低下率を使用する。移動/発達/衰弱後の中心と実範囲を毎T投影し、期限後は解除。保存済みイベントは詳細を維持し、新規発生から新設定を使う。
- プレイヤー・NPC・物流・部隊追従の共通 `resolveV39UnitMovementStepCost` へ接続。ユニット詳細の移動/飛行も現在地の有効値を表示。Nodeで防御/距離/飛行/高度/AP/重複/期限/非変更を検証し、画面はユーザー担当。

## 台風の衰弱（UI175）

- 災害詳細 `radiusDecayPerTurn=1` を追加。発生ターンは指定サイズを維持し、次ターン以降の移動後の中心マスで判定する。気候温度が `minimumClimateTemperature=20` 以上の海では `radiusGrowthPerTurn=1` ずつ発達（最大半径4）。陸地・湖・20未満の海では半径1ずつ縮小する。海の気候温度が不明ならサイズ維持。いずれも直接HP被害は追加しない。
- 半径0は中心1マス。さらに衰弱して0未満になるターンで終了し、豪雨・索敵/視界・射撃補正・渦画像の範囲も解除する。通常の5T期限やマップ端での終了は維持する。
- 暖かい海へ戻った場合は現在半径から再発達する。経過年齢から最大サイズへ戻さない。同Tの再処理は変化なし。イベントの現在半径/詳細/処理Tを既存保存経路に保持する。新設定は新規発生イベントから適用し、設定のない旧イベントは従来の発達を維持する。
- テストの自動拡大OFFは拡大だけ停止し、陸地/冷海での衰弱は有効。発達量/衰弱量/温度/最大半径は既存シートの詳細設定から調整可能。風向連動は今回含めない。
- Nodeで実ターン処理・保存往復・内陸/冷海/湖・再発達・期限/効果解除を検証。実画面確認はユーザー担当。

## 台風の霧相当ペナルティ（UI174）

- 原本「災害」台風の詳細設定 `fogPenalty=true` により、範囲内→外・外→内・範囲横断の索敵/視界を通常の霧と同じ共通処理で軽減する。通過マスごとの索敵50・視界1は `V39_FOG_BALANCE` を共用し、台風側へ数値を複製しない。同じマスに霧や複数の台風が重なっても霧相当分は1回だけ数える。
- 豪雨による既存の索敵補正と射撃命中×0.75は維持する。直接HP被害を追加せず、霧画像の追加・地面色の変更もしない。移動/発達した実範囲と期限終了へ追従し、新しく発生する台風へ適用する（既存イベントの保存済み詳細は上書きしない）。
- Nodeの動的災害検証で内外/横断/重複/保存後移動/期限切れを確認。実画面はユーザー担当。

## 災害被害の画面ログ（UI171 / UI172 / UI173）

- 災害の行動履歴だけでなく、右側の既存「戦闘」チャンネルへ自然災害/危険地帯/地形被害/災害通過のHP被害を表示する。専用の新チャンネルや攻撃扱いの `combat-log` イベントは追加せず、環境被害イベントから直接共通ログ表示へ渡す。
- 表の項目は災害の種類ごとにまとめ、見出しに発生源名、本文に「被害○体 / 合計○ダメージ」だけを表示する。UI173から開いた詳細も「ユニット名：44ダメージ」のみとし、同じユニットへの被害を合算する。HP前後・属性内訳・衝突威力は保存用の行動履歴に残し、画面の詳細には繰り返さない。竜巻の直接被害と吹き飛ばし衝突は異なる原因として分ける。
- 同じ担当プレイヤー・ワールド・ターン・原因の追加被害は既存項目へ加算し、対象体数はユニットIDで重複を除く。次ターンは別項目にする。履歴と折りたたみ中のプレビューを同じ内容へ更新し、新規マップ/ロードで集約キャッシュを破棄する。保存用の行動履歴には個別の被害情報を残す。
- `resolveV39DisasterDamage` が発生源名/IDを保持し、最大被害を選んだ結果や複合ダメージにも引き継ぐ。行動履歴も同じ `v39-environment-damage-log.js` の整形を使う。移動時被害のunitId/targetId差を吸収し、落石や災害通過を一律「溶岩」と呼ばない。
- 被害時の可視スナップショット、自軍所有、索敵/視界、ワールド/担当プレイヤーを守り、死亡後に対象が消えても観測済み被害は残す。裏側ワールドや未観測敵の被害は右側へ公開しない。0件の処理や単なる再描画ではログを追加しない。既存のHP表示/被害処理・反撃・戦闘状態の判定は変えない。
- Node検証: `scripts/check-v39-environment-damage-log.mjs` で実ログイベント/チャンネル、保存行動履歴、内訳/衝突回数、可視性/ワールド/プレイヤー境界を確認。画面確認はユーザー担当。

## 竜巻の複合被害・吹き飛ばし（UI168）

- 災害シートの竜巻49行を正本とし、詳細設定 `damageComponents` に打撃/切断の配分、`knockback` に耐性名・1マス当たりの判定値・最大距離を保持する。現在の合計威力140は打撃70/切断70へ等分する。それぞれ既存の防御・属性耐性で計算し、障壁/盾/ガードの残量を引き継いで合算する。合計威力を各属性へ丸ごと二重付与しない。他の重複災害との最大被害優先は維持する。
- 吹き飛ばしはHP被害とは別判定。既存の怯み耐性と共通耐性式を使い、`max(0, 威力 − 対象Lv/10 × 有効怯み耐性) × (1 − 耐性率)` を判定値とする。精神による軽減はなく、吹き飛ばし判定自体でHPを減らさない（UI169の衝突時は別途打撃被害）。現在は判定値50ごとに1マス（端数切上げ）、最大3マス。0なら移動しない。数値は暫定で原本から調整できる。
- 生存中のプレイヤー/NPC勢力/敵/一般村守備兵を対象に、そのターンに被害判定した竜巻の範囲から外向きへ押し出す。UI170から中心上では六方向からランダムに1つ選ぶ（従来の進行方向固定を変更）。APを消費せず部隊所属を維持。通常の状態更新による移動検出で詠唱の解除も既存処理へ委ねる。
- 経路は共通の六角直線を使い、壁・瓦礫・通行不能地形・他ユニット・マップ端の手前で止まる。勢力を問わず重複着地せず、同じ処理内で着地点を予約する。飛び越え、連鎖押し出しは行わない。複数の竜巻は最も強い判定1回とし、同一ターンの再処理/ロードで二重に押し出さない。
- UI169: 他ユニットに衝突した場合は、吹き飛ばされた側・衝突相手の双方へ、怯み耐性で軽減済みの吹き飛ばし判定値をそのまま打撃威力として適用する。移動できる空きマスが0でも隣接ユニットへ衝突する。移動距離による威力減衰は追加しない。各側の防御/打撃耐性/障壁/盾/ガードは共通ダメージ計算で個別に適用し、相手の怯み耐性で衝突威力を再軽減しない。壁等との衝突被害は追加しない。
- 衝突で死亡した場合も、相手への同時衝突被害は適用して通常の死亡情報を保持する。その衝突では先へ進まない。すでに移動処理を終えた味方/NPC/村守備兵が後から衝突された場合も最終HPへ反映する。災害のダメージ表示/ログへ双方の被害を渡し、ロードや同一ターンの再処理で再発させない。
- UI170で物理処理を `v39-forced-movement.js` へ移し、スキルも同じ処理を使う。災害側の `v39-disaster-knockback.js` は入力変換だけにする。`knockback.direction` は任意の `away` / `toward` / `random`（省略は外向き）を変換器で検証する。原本の既存数値は変更しない。効果記載とスキル入口は[スキル効果対応状況](../units/スキル効果対応状況.md)の共通強制移動節を参照。移動距離/着地点は災害ログへ記録。Node検証は `scripts/check-v39-tornado-knockback.mjs` と `scripts/check-v39-forced-movement.mjs`。画面の確認はユーザー担当。

### 落雷の視認性修正（UI166）

- UI165の上下2本の横線を廃止し、マス・時間ごとに向きと位置が変わる短い枝分かれ電光へ変更。予兆は淡い青、着弾は白い芯と黄色の外光で区別する。地面の色やアイコンは追加しない。
- 着弾は上空2マス相当から対象へ伸びる太い稲妻と分岐を表示。最初の550msを明瞭に保ち、以後減衰して計1350msで消す。表示値は既存 `lightning` 設定の `strikeHeightTiles` / `strikeWidthMultiplier` / `strikeHoldMilliseconds` / `strikeMilliseconds`。

## 攻撃による地形破壊・落石・瓦礫（UI150、UI153でシート管理へ移行）

- 通常攻撃を含む実際の攻撃解決時に適用する。支援/回復/表示プレビューだけでは地形を壊さない。値の原本は `@game_data`「災害」42〜46行の丘陵崩壊・山岳崩壊・洞窟落盤・落石・瓦礫。`災害.json` から `lib/v39-terrain-disaster-rules.js` が共通設定を解決し、`lib/v39-terrain-destruction.js` が判定、`v39/world/v39-terrain-destruction.js` が戦闘/ターン/UIへ接続する。`config/v39-terrain-destruction.json` は表示エフェクトだけを保持し、地形被害の数値は重複定義しない。
- AM:AUは「地形災害処理 / 攻撃発生属性 / 威力軽減 / 地形耐久 / 地形被害倍率 / 高度低下 / 撤去AP / 変化後地形 / 発生猶予ターン」。UI160でAOを旧「攻撃発生威力」から「威力軽減」へ改称した。各ヘッダーに単位・適用対象の注記を付けた。「対象地形」は地形破壊行では完全一致・スラッシュ区切り。「落石」は既存のダメージ属性/威力列も使う。発生方法=攻撃、基本発生率=0として自然抽選・一般災害の強制発生から除外する。地形破壊テストから実際に攻撃して確認する。
- 対象ごとの属性・閾値・倍率・高度低下を適用する。有効=FALSEで当該定義を停止し、未定義/不正値を旧configで復活させない。変換器は必要数値・処理名・対象重複を検証する。予告済みの落石は威力・属性・猶予期限・瓦礫耐久を保存して継続し、新規発生は再生成済みのシート値を使う。旧保存の予告で追加項目がない場合だけ現行の落石属性/瓦礫耐久を使う。
- 能力/パッシブ補正後・ユニット防御前の物理/打撃成分を計算する。同一行の物理と打撃は最大値を使い二重加算しない。通常武器とスキルの追加武器分は既存の武器参照を使い、武器単体攻撃に再加算しない。炎だけ等は対象外。ユニットの最終ダメージ倍率には連動しない。
- 実際に到達した範囲の倍率を掛けた威力から「威力軽減」を引き、正なら倍率を掛けて地形耐久を減らす。初期の軽減値は地上200、洞窟岩壁50、瓦礫0、倍率1。Lv10戦士の威力83/140では地上地形を壊さない。多段Hit数や軍隊人数を重ねて地形を同じ攻撃で反復破壊しない。壁/結界で受け止めたマスには同時に地形ダメージを通さない。
- 初期耐久は丘陵500、山岳/岩場1000、洞窟岩壁200。対象と耐久はシートで調整可能。0になると地上では高度を初期1段階下げ、同じマスを再度下げない。洞窟岩壁は通路に変え、隣接床に高度を合わせる。地形名そのものを別の資源地形へ変換する処理ではない。
- 崩壊マス（地下では隣接通路を優先）の1マスに落石を予告し、次ターンの世界別処理で一度だけ落とす。敵/AIの解決中に発生した予告にはさらに1Tを加え、直後の同じ終了処理で即落下せず、次のプレイヤー行動期間を残す。落石は打撃威力80を共通ダメージ式へ渡す。配置済みの人間/敵/村守備隊を対象とし、通常耐性/防御/最終倍率に従う。即時の埋没死や強制移動はしない。ダメージ表示は災害の遅延フィードバックを共用する。
- 落石後は耐久100の瓦礫で新たな進入と射線を止める。瓦礫内のユニットは離脱できる。基本の「瓦礫撤去」は隣接または同マスでAP20と攻撃値分の耐久を消費。複数ユニットで進捗を共有する。物理/打撃攻撃でも耐久を削り、0で開通する。瓦礫を隣へ飛ばして再封鎖する連鎖は行わない。
- マップ外周、入口/出口/階段、重要イベント、覇権地、配置施設/拠点の地点は保護する。発生直前にも再判定する。追加の保護座標はマップの `protectedTileKeys`。隣接から低威力の通常攻撃/撤去で開通できるため、瓦礫を通れない場合にも撤去手段は残す。
- マップの `terrainDamage.cells / pendingByTile / rubbleByTile` と既存のgrid/heightLevelMapへ記録し、世界切替・背景処理・セーブ/ロードで保持する。通常の移動/部隊/敵AI/輸送の共通通行費用と射線を更新する。自動輸送は迂回/停止し、除去後に経路を再評価する。NPCが撤去を自律的に計画する処理は後続。
- フィールドは亀裂/警告/瓦礫の図形、土地の詳細は耐久/落石予定T、隣接するユニットの基本欄は撤去ボタンを表示する。追加画像は不要。テスト操作 → 専用 → 地形破壊テスト。通常の棍棒で丘陵を複数ターン攻撃し、落石→撤去→保存を確認できる。自動検証は `scripts/check-v39-terrain-destruction.mjs`（通常攻撃、専用効果不要、閾値、累積/上限、予告、実洞窟/保存、被害、撤去/AP、共通自動経路、エフェクト倍率）。

## 雨・砂嵐のフィールド表現（UI155/UI156）

- 砂嵐は既存の霧テクスチャを茶色へ着色して災害のマス範囲へ描く。追加画像は不要。`config/v39-atmosphere-display.json` の `sandstorm` から色/深度を参照し、霧の共通濃さ設定で調整できる。砂嵐単独はユニットより下の深度11.8、既存霧等との重なりは従来のグラデーション合成/深度を維持する。範囲のアイコン表示でなくマス全体を覆う。
- 雨は画像を使わず `v39-rain-layer.js` の共通Graphicsに雨筋を描く。UI156では地面の色を変更せず、濃い青・不透明度0.9・線幅2.1を基本とし、本数を通常雨3/豪雨・雷雨5/台風6に減らした。ズームを引いた場合も線幅が画面上で小さくなりすぎないよう補正する。元の地域気象と台風の範囲が更新されると表示も追従する。雪/吹雪・地下/覇権地内部には雨を出さない。
- 雨の強さは `config/v39-weather.json` の `rainStrengths / rainStrengthByWeather / rainStrengthByDisaster` が正本。弱い雨=縦から0度・索敵-20、豪雨/雷雨=25度・索敵-40、台風の局地降雨=45度・索敵-60。`lib/v39-rain-rules.js` を表示と索敵で共用し、角度と補正の強さを別々の固定分岐にしない。数値は後から変更できる暫定値。
- 索敵は霧と同じ射線を使い、外→中・中→外・雨域を挟む場合に適用する。ただし雨のマス数で乗算せず、経路上の最大の雨補正を1回だけ引く。既存の霧/砂嵐による補正とは加算。今回、雨による地形視界範囲/射程/AP/ダメージへの補正は追加しない。
- 索敵用の `map.rainConditions` は地域ごとの強さと局地上書きの派生キャッシュであり、編集原本ではない。通常ターン・手動天候変更・世界/保存の初期化で再投影し、台風が過ぎた後は通常の天候補正へ戻る。雨の表示対象は実際の気象データから同じルールで選ぶ。
- 雨の対象範囲は気象があるマスとし、通常プレイでは従来の大気表示用LOS内に制限する。テストは全域を候補にできるが、実描画はカメラ内のみ。雨筋の始点/終点は六角形の内部に制限し、ユニットより下の深度11.9を使う。気温を示すテスト用の色分け表示とは独立する。
- 雨の密度/長さ/速度/色/不透明度/線幅/縮小時の最低線幅/深度/更新間隔/最大本数は表示configの `rain`。初期は90ms間隔・最大900本で、画面外は描画せず、毎回の背景テクスチャ生成やマップ全体の再構築はしない。角度は気象configの強さから読む。対象なし・世界切替・シーン終了で描画/更新リスナーを解除する。
- 確認はテスト操作 → 環境 → 「新災害5種を確認」。砂嵐の地点で茶色の霧、台風の地点で雨を比較する。既存の気象変更で雨/豪雨/雷雨/晴れも比較できる。`scripts/check-v39-rain-sand-display.mjs` は描画用データ・六角範囲・密度上限・動き・カメラ絞込・更新間引き・破棄をNodeで検証。ブラウザの画面確認は未実施。
- 台風の渦画像はUI160でユーザー素材を受領・接続した。詳細は上記の台風節、素材状態は[画像準備リスト](../../references/画像素材準備リスト.md)を参照。

## 常設の危険地帯・適応と防衛（2026-10-20、配置・効果・保存を実装）

一時的な災害とは別に、常に危険がある場所を設ける。6種類を原本の「地形」「災害」36〜41行へ登録し、両JSONを再生成した。配置・被害・表示・保存は実装済み。AIの国家規模の居住地選定や安全な迂回路の生成保証など、以下で残件とした部分は未実装。

### 現在の調整値と実行経路

| 種類 | 現行の暫定効果 |
| --- | --- |
| 酸の沼 | 侵入/滞在時に威力20。酸専用属性は未追加、既存の毒属性・毒耐性で計算する |
| 毒沼 | 滞在で毒威力10・3Tを付与。離れても期限まで継続、再滞在で更新 |

- 数値は最終ダメージでなく共通戦闘計算前の威力。種族/クラス/装備の既存耐性・防御・盾/障壁を使用する。毒耐性100なら環境毒を付与しない。接触型の酸/毒沼は飛行値が正なら回避できるが、ガス・霧・極寒は飛行だけでは回避しない。
- 地形BW「危険地帯設定」のJSONが災害ID・対象地形/隣接地形・地下対応・高度・地域サイズ・配置率・半径の正本。災害AK「常設危険地帯」、AL「危険地帯効果」のJSONが接触型/毒/移動/回復/不浄/風抑制期間の正本。既存の属性・威力列も共用し、ヘッダーに注記した。
- 通常生成では対象地域12×12、最初の候補地域に1箇所を確保し、追加地域は暫定18%。対象地形がなければ配置しない。半径1を既定として対象地形内の不規則な連結範囲を作り、基本地形や施設・洞窟入口は置き換えない。地上の瘴気は廃墟/遺跡/洞窟地点、洞窟内は酸と奥地の瘴気を生成する。洞窟入口の近傍を避ける。
- 常霧/瘴気の発生源は `map.hazardZones` として永続保持し、通常災害の全体1件/Tの抽選・期限切れの対象にしない。既存保存に発生源がない場合、ロードだけで新規配置はしない。生成し直したマップから適用する。
- 風系統・炸裂0.5以上の攻撃範囲に入った常霧/瘴気のマスは3T抑制し、その後自動復帰。元の地形・発生源は残す。通常霧/死の霧の除去とは別の抑制期限を保存する。
- ターン被害・環境毒・浄化低下は同じTに重複適用しない。地上/洞窟・別ワールドを分離し、被害ログ/数値ポップアップは既存経路で表示。色は既存の霧画像合成、マーカーは中心のみ、土地の環境効果は常設として表示する。
- 土地タブの「環境効果」は上部の全幅欄へ表示する。一時霧等の⌛残り、常設地帯の「（常設）」、風で抑制中の「抑制⌛残り」を区別する。未索敵は「未確認」。データが末尾のスクロール外へ押し出されない配置にし、マス未選択へ戻った場合は古い表示を残さない。
- 初期拠点の候補中心と隣接マスに危険地帯がある候補を除外。敵の通常追跡/逃走は耐性を考慮して被害の低い進路を優先し、大きな被害が見込まれる1歩を避ける。国家の居住地選定、物流等の全自動経路の危険評価、資源配置による誘導と安全な迂回路保証は残件。
- テスト→環境→「危険地帯6種を確認」。6地点へ通常/耐性100の観察者を配置。地点選択と「発生地点へ」、1T経過、土地の環境表示で確認する。`check-v39-hazard-zones.mjs` は6種・地上/洞窟生成・通過/滞在・毒・耐性・飛行・移動負担・回復阻害・風の抑制/復帰・6Tの実進行・保存を検証する。

| 名称 | 配置先 | 主な影響 |

- 元の地形とは別の環境レイヤーで保持し、「沼＋酸」「洞窟＋酸」のように組み合わせる。既存の一時災害を無期限化するだけの扱いにはしない。

### 種族・クラス・装備による適応

- 被害には既存の属性・耐性計算を共用する。酸は暫定で毒属性/毒耐性を使用し、酸専用属性・専用耐性の追加は将来検討とする。
- 高耐性は被害の軽減であり、自動的に完全無効とはしない。既存計算で安全に過ごせるか判定する。
- 被害への耐性と居住適性は別。耐えられるだけで幸福度・生産力への恩恵を付けず、得意/苦手地形は既存の居住適性と整合させる。危険地帯そのものへの居住適性を追加するかは未確定。
- 侵入側にも耐性装備・保護魔法・飛行等の対策を残す。飛行で酸の水面など接触型の危険を回避できる案とするが、霧・ガスなど空間型の影響は飛行だけでは回避しない。回避条件は危険地帯ごとのデータで管理する想定。
- AIは通常追跡/逃走の進路へ予想被害と耐性を反映する。国家規模の居住地選定等への対応は残件。
- 危険地帯は除去するだけでなく、適応した勢力が残して領土防衛に使える設計とする。

### 通常霧と常霧の区別

- 現行の通常霧は既に災害の「全体1件/ターン」抽選とは別で、8×8地域ごとに5ターン周期・暫定5%・5ターン持続・最大3地域の処理がある。今回、これらの数値は変更しない。
- 今後の案では、多湿・降雨後などの地域条件を通常霧の発生しやすさへ反映する。常霧地帯はマップ生成時に一部の谷・湿地等へ配置し、通常霧より安定して霧がある場所として区別する。
- 常霧も風で一時的に晴らせるが、発生源が残れば再発生する。再発生待ち3Tは調整可能な暫定値。通常霧と同じ索敵効果を共用し、死の霧へ自動変化させない。
- 死の霧は既存の死体・不浄ルールを維持し、通常霧・常霧とは発生条件を分ける。
- 発生率・配置数/密度・範囲・威力・再発生待ち・回避条件は上記原本列へ集約。色の合成順・表示色は既存 `config/v39-atmosphere-display.json` へ追加。バランスの最終確定は残件。

## 発生・終了の通知

- 通常の地上ターン処理で自然発生を抽選する。テストモードONは発生条件ではなく、抽選確率も変更しない。
- 共通災害の発生時に「災害名 発生中」、期限が切れた処理時に「災害名が終了」を、活動ログと右側の通知欄へ各1回出す。継続中の毎ターン通知や、同じターンの再処理による重複は出さない。被害・落雷地点の既存ログは別に維持する。
- 通常モードでは操作プレイヤーの現在の索敵範囲と災害の影響マスが1つでも重なる場合のみ通知する。中心が視界外でも範囲の端が見えれば対象。未表示ワールドの処理では画面側の索敵を使わない。
- テストモードONでは視界外・未表示ワールドも操作プレイヤーへ通知する。他プレイヤーの活動ログへ一律配信しない。右側の通知は発生時の観測・プレイヤー・ワールドを保持し、通常モードに戻したとき視界外だったテスト通知を非表示にする。後から探索しても過去の未観測通知を追加しない。
- 期限切れの災害は既存のactiveDisastersから削除するため、保存・読込後にも終了通知を繰り返さない。火山噴火は従来の専用地形システムで、この共通災害の通知とは別経路。
- `check-v39-disaster-notifications.mjs` で通常視界/範囲端/視界外/テスト全体/未表示ワールド、重複抑止、保存と右側表示を検証する。`check-v39-disaster-natural.mjs` は通常ターンの自然抽選による開始・終了ログも検証する。

## 山火事の通過と滞在（2026-10-19）

- HP割合を廃止し、通過は1マスにつき炎威力20、発生時と毎ターンの滞在時は3倍の炎威力60。20/60は最終ダメージではなく計算前の威力であり、滞在の3倍も計算前に掛ける。`computeAttackDamage` とガード共通処理を使い、防御・Lvによる耐性減算・炎耐性・共通ダメージ倍率・乱数・盾/障壁で軽減する。攻撃者の能力補正や装備加算なし、環境被害なので命中判定は必中。通過被害と滞在被害は別に適用する。直接被害を持つ他災害も下表の威力方式へ移行。
- プレイヤーの実移動経路・各部隊員の隊列経路を判定。敵AIは1歩ごとの実行とWorker内シミュレーションで共通処理。通常輸送・物流部隊・取引輸送・集合・教官・鉱床担当の通常の経路移動にも接続する。
- 同じ座標の隊列フレームが続いても二重被害にしない。別のマスへ進めば、そのマスにも火がある場合は再度被害を受ける。複数災害の重複は同じ1歩では最も大きい算出ダメージを採用。
- HP0になれば死亡したマスで停止し、通常の死亡処理へ渡す。通常移動の演出も死体を終点へ滑らせない。移動確定時の予約APは消費し、途中死亡時のAP返却は行わない。
- 期限切れ/別ワールドの災害で移動被害を受けない。旧イベントに新列がない場合は災害IDから現在の定義を補完する。
- 恒久的な火炎地への塗替え、飛行等による山火事専用の免疫、テレポートや特殊な入口交代等の経路を持たない位置変更は今回の対象外。

## 属性・威力と落雷（2026-10-19）

### 火事・山火事の見直し方針（採用方針、着火・延焼は未接続）

- 火事を共通処理とし、森林での火事を山火事として扱う。現在の実装は既存「山火事」の発生/継続被害のみ。以下の攻撃着火や延焼はまだテストできない。
- 通常の炎攻撃は、そのマスに届く防御軽減前の炎威力50以上で着火率3%。範囲の広さによる追加補正はなく、対象の各可燃マスで1行動につき1回だけ抽選。多段で抽選回数を増やさない。
- 効果:燃焼付きは炎威力50未満でも着火抽選し、可燃地10%/森林20%を暫定値とする。ユニットの燃焼と土地への着火は別処理にする。「燃焼があれば確実に着火」とはしない。
- 延焼は隣接可燃マスごとに毎ターン1回。森林10%/その他の可燃地3%を暫定値とする。複数火元からの重複抽選はしない。同じターンに新しく燃えたマスから連鎖延焼させない。水面/裸の岩は燃えず、施設の可燃判定は別途定義が必要。
- 各マスに燃焼期限を持たせ、再着火で無限延長しない。火事の持続値・燃え尽きたマスの再着火制限・施設への被害は未決定。
- 強風/暴風は延焼率×2、雨は×0.5、豪雨は延焼停止を暫定採用。風だけで着火させない。風向は今回扱わない。
- 雷雨は一律禁止しない。落雷地点では着火抽選し、降雨の強さで着火/延焼を抑える。豪雨でも落雷地点の着火は禁止しない。落雷の着火率と豪雨時の着火補正は未決定。
- 現行の天候は「雷雨」1種類で降雨強度や独立した風を持たない。雷雨と豪雨の区別/風補正を実装する際に降雨強度・風の状態を接続する。既存の自然災害条件「強風」の代替判定を、この新しい延焼補正の実装済み扱いにしない。

### 現在の属性ダメージ

直接ダメージを持つ8種もHP割合から威力方式へ移行した。以下の値は調整可能な暫定値。移動時被害と滞在3倍は山火事のみで、他8種はターン処理時に適用する。

| 災害 | 属性 | 威力 | 被害地点 |
| --- | --- | --- | --- |
| 洪水 | 打撃（水流） | 20 | 全域 |
| 地震 / 土砂崩れ | 打撃 | 80 | 全域 |
| 落雷嵐 | 雷 | 自然140〜250 / 魔法由来200 | 範囲3マスにつき1発＋端数確率 |
| 聖光暴発 | 光 | 40 | 全域 |
| 魂嵐 | 精神 | 30 | 全域 |
| 瘴気 | 毒 | 20 | 全域 |
| 流星落下 | 打撃 | 100 | 全域 |

- 洪水は現行に水耐性がないため、水流による打撃として打撃耐性を使う。魂嵐は精神/精神耐性で軽減するHP被害。精神状態異常の蓄積ではない。火山/溶岩は専用処理のまま。
- 災害AE/AF/AG列は「被害範囲方式」「ランダム被害マス数」「ランダム被害基準マス数」。全域/ランダムを指定する。AGが正数なら面積比例、0/空欄ならAFの固定数を使用する。0件を未設定にしない。
- 落雷は発生時と継続中の毎ターン、範囲内の重複なしのマスを抽選。発数は N÷3 の整数部分＋小数部分の確率で1発追加。7マスなら2発＋1/3、8マスなら2発＋2/3、9マスなら必ず3発。1〜2マスの場合は0発もあり、最低1発への切り上げはしない。マップ端では実際に存在する重複なしの範囲マス数Nを使う。ユニット位置とは無関係で、空きマスにも落ちる。直撃後の追加回避抽選はなく、雷耐性・防御・ガード/盾/障壁を通常計算する。威力は最終ダメージとは異なる。
- 発数の端数抽選と落雷先の抽選は同じ乱数系列で毎ターン行う。抽選は災害イベントIDとターンで固定し、当たったマスをdamageTileKeys/damageTickTurnへ保存。同じターンの強制再処理・ロードで再抽選/再ダメージしない。影響範囲tileKeysは収入/アイコン用として維持する。
- 落雷地点に黄枠・白い稲妻を表示し点滅する。通常は索敵外へ表示しない。テスト索敵外は他の災害と同じ半透明。現在見える落雷と被害は通知ログでも確認できる。
- テスト→専用→「災害テスト」に落雷も統合。中心(12,10)と隣接6マスに観察者を配置。テスト限定で5ターン継続し、「1T経過」で毎ターン観察する。通常の継続時間はシートの値（現在1ターン）を使う。落雷専用の起動ボタン/起動処理は設けない。
- check-v39-lightning.mjsで24種の基盤と別に、抽選の分散/空きマス/耐性/精神軽減/移動では当たらない/重複防止/保存/期限・実UIを検証する。

## 地域気候・天候と発生条件（2026-10-19）

### 自然発生の確認モード

- 「テスト→専用→災害テスト」の環境欄に「自然発生用に初期化」「固定配置に戻す」を設置。切替時は現在のゲームを置き換える確認を出す。
- 自然発生モードでは初期災害を置かず、森林/平地・山岳・河川・雪原と4地域の天候を用意する。最初の天候は5ターン、乾燥/降水の条件蓄積を用意するが、その後は通常の天候推移。調整値は `config/v39-disaster-test.json` の `natural`。原本の発生率は変更せず、強制発生も使わない。
- 「1T経過」または「10T経過」で通常の世界処理を進める。10Tは既存の一括進行処理を共用し停止可能。敵・魔獣暴走用の個体は自然発生モードには置かない。火山噴火は従来どおり専用処理で、この共通抽選とは別。
- テストモードでは `worldEnvironment.disasterDiagnostics` に直近1ターンの抽選結果だけを保存。条件未達/対象地形なし/同一マス待機/抽選不成立/発生上限/自然対象外/自然発生、候補数・実効確率・抽選値・中心座標を区別する。強制発生は直近の自然抽選記録を上書きしない。
- 条件判定と乱数は本番の生成関数と同一。診断用に別抽選したり、当たりやすくしたりしない。現在の災害選択に対応する結果、全件一覧、直近4件の自然発生履歴を環境欄へ表示する。診断は通常モードでは新規記録せず、保存/読込は保持する。
- `check-v39-disaster-natural.mjs` で強制配置なし、原本発生率の維持、通常ターンでの条件付き自然発生、診断/保存、10T進行、固定配置への復帰を確認する。将来ターンの共有抽選を副作用なしで予測し、その直前の天候・ターンを設定して通常のターン終了処理と照合する試験も含む。連続プレイ全履歴の検証とは区別する。

### 気候と天候

- 気候プロファイルv3で旧セーブを読込時に再計算し、旧プロファイル由来の天候は現在ターンから再初期化する。火山環境の初期化は同じマップ用に初期化済みのweatherを保持し、新規マップへ古い災害を持ち越さない。過去の災害/地形は変更しない。
- 海/湖の負高度は水深なので、気温計算では0として扱い、深い海ほど大気温度が高くなる計算をしない。陸上の高度補正は維持する。

- 新規地上マップは全世界/一地域・周辺諸島/単一島を選択し、climateProfileを保存。12×12地域の高度と緯度で気温が下がる。全世界は中央から上下の極地へ、一地域・単一島は選択した気候帯・基準気温・湿潤度から小さな緯度差を付ける。新方式は気候から雪原・砂漠・森林量を決め、植生から気候へ再帰させない。詳細・設定値は[マップ範囲・気候生成ルール](マップ範囲・気候生成ルール.md)。
- 範囲未設定の旧マップは従来どおり地形の森林/砂漠等を湿潤度へ反映し、雪原/雪山/氷原を含む地域は基準気温上限-3℃にする。新方式にはこの雪地形由来の上限を適用しない。いずれも雪/吹雪の現在気温は0℃以下（snowfallMaximum）。旧セーブ更新で地形は塗り替えない。
- 地盤/季節/風向・風速は未実装。最初は気温/湿潤度と天候に限定する。
- 天候は晴れ/雨/豪雨/雷雨/雪/吹雪。寒冷な地域では晴れ/雪/吹雪、それ以外では晴れ/雨/豪雨/雷雨から湿潤度で重み付けして選択し、3〜5ターン持続する。
- worldEnvironment.weatherに地域の天候/気温/湿度/乾燥度/晴天連続ターン/降水連続ターン/持続期限/処理済みターンを保存。同じターンの繰り返し処理では蓄積を増やさない。天候と持続の抽選は気候ID・地域・ターンで固定し保存後も再現する。
- 洞窟では気候も天候も適用しない。洞窟を表示していても通常ターン処理で地上の天候が進み、地上へ戻ると保持される。旧セーブには読込時または初回の世界処理時に補完し、過去の全ターンを遡って災害は発生させない。
- 原本災害AH:AJは発生方法/発生条件/必要継続ターン。自然は条件なし抽選、条件付きは以下の条件を満たすマスから中心を選んで抽選する。イベント/条件イベント/専用処理は共通自然抽選の対象外。魔法の表示は分類であり、今回各スキルへ新たに接続した意味ではない。

| 種類 | 自然発生の条件 |
| --- | --- |
| 山火事 | 乾燥度55以上・晴天2ターン以上、既存の森林条件も必要 |
| 干ばつ | 乾燥度55以上・晴天3ターン以上、既存対象地形内 |
| 洪水 / 土砂崩れ | 現在豪雨か雷雨、降水2ターン以上、湿度65以上、既存対象地形内 |
| 落雷嵐 | 雷雨の地域のみ |
| 暴風 | 豪雨/雷雨/吹雪の地域のみ |
| 大寒波 | 雪/吹雪、気温5℃以下、降水2ターン以上 |
| 熱波 | 気温28℃以上・晴天2ターン以上 |
| 地震 / 流星 | 天候による追加条件なし |
| 闇侵食 / 魂嵐 / 瘴気 | 浄化-5以下または死の霧。天候では判定しない |

- 発生率 = clamp(基本発生率 × 地形相性 × 気候補正 × 天候/蓄積補正, 0, 1)。乾燥/高温は乾いた気候と乾燥度で、豪雨/雷雨は湿った気候と湿度で補正。条件外は抽選しない。従来どおり各種類1回/地上ターン・全体上限1件で、地域数ぶん発生回数を増やさない。シート順による優先も現状は維持。
- 反乱/飢饉/疫病/資源枯渇/信仰崩壊/経済恐慌は条件イベントへ分類し、天候・無条件の共通自然抽選から除外。これらを条件蓄積から災害イベントとして起動する専用処理は今回未接続。既存の食料不足による人口変化や既存反乱機能自体は変更しない。
- 聖光暴発/重力異常/時間歪曲/空間歪曲/魔獣暴走はイベント扱いにして共通自然抽選から除外。火山は従来の専用処理。
- テスト強制発生/直接発生APIは天候条件と自然発生率を無視し、指定位置がなくても既存対象地形から選ぶ。無効設定や範囲外座標の検査は維持する。
- config/v39-weather.jsonが地域サイズ・持続・気温/湿潤計算・天候重み・蓄積量・条件閾値の調整箇所。天候そのものによる直接の収穫補正、移動制限、霧や積雪は未追加で、今回は災害発生への接続のみ。
- 土地画面に天候/気温/乾燥度を表示（現在索敵内またはテストのみ）。テスト→環境→フィールドで、選択した地域の気候/天候/蓄積を確認し天候を変更できる。変更時は地域の気候を変えず、別地域には影響させない。
- 災害テストの開始時は「環境」を開く。固定24×24マップの4地域に、晴れ(4,4)/雷雨(16,4)/豪雨(4,16)/吹雪(16,16)を配置し、比較ボタンで選択・カメラ移動できる。ボタンは初期設定名ではなく現在の天候/気温/乾燥度を表示する。1T経過で蓄積・残り持続を更新し、通常の天候再抽選も行う。地形を用意した後に気候を再計算する。気温は固定気候＋天候補正のままで、テストの吹雪は固定気候を変えず、現在気温だけ降雪上限0℃を適用する。
- 気象条件の○/×は山火事/洪水/落雷嵐の現在の天候条件を実処理で評価した表示。○でも地形/自然発生率を満たす必要があり、強制配置済みの災害が気象と無関係に存在することとは区別する。降雨/降雪の画面エフェクトや風/着火/延焼は未接続。
- 「フィールド気象」がONなら、テストモードの地上フィールドへ気温別の色・六角境界・大きな数値（例23℃）を表示する。別カテゴリ/下部タブへ移動してもONを維持し、気象欄を開かなくても見渡して確認できる。数値は縮尺に合わせて調整し、初期配置の暗転より上に表示する。選択地域を強調し、狭い端地域にも数値を置く。OFF・洞窟・テストモードOFFで消去する。天候データには影響しない。これは気象の検査用表示であり、雨や雪の常時アニメーションではない。
- check-v39-weather.mjsで気候差、100×100、天候持続と一括/逐次の一致、条件判定、実自然発生、社会イベント除外、テスト操作/保存、洞窟を表示中の地上天候進行を検証する。

## 継続被害のタイミングと表示（2026-10-19）

## 画像表示

### 霧と重なる環境災害（2026-10-19）

- 通常の霧・死の霧・瘴気・熱波・大寒波は `pipo-fog018.webp` を共用する。単独は単色、2種類は2色、3種類以上は多色の横グラデーション。並びはconfigの順番で固定し、発生順に依存しない。同じ種類の複数発生は色を増やさない。大寒波は青い霧だけとし、氷画像は表示しない（UI159）。
- `config/v39-atmosphere-display.json` が色・順番・画像内の最低不透明度・描画解像度/分割サイズの調整元。死の霧だけは既存の死霊属性色を参照する。既定の不透明度は `V39_FOG_BALANCE.displayAlpha`（0.75）。地形テストの種類別スライダー/数値で0〜100%へ変更可能で、表示設定として端末に保存し通常プレイでも共用する。0%は非表示で、索敵・ダメージなどの効果は変更しない。重なった数では濃くせず、表示する種類の最大不透明度を使う。
- 地形テストには霧・死の霧・瘴気・霧＋瘴気の比較4区画と、常設危険地帯6種の環境レイヤーを配置する。「この濃さを全種へ」と初期値へ戻す操作も用意する。
- 各マスの色を一枚に合成して六角形へ切り抜き、半解像度・最大1024pxの分割画像へ焼く。同じ状態の再描画は省略し、解除時は不要な画像を解放する。マスごとのSpriteや複数の霧画像は重ねない。
- 瘴気/熱波/大寒波のアイコンは発生中心だけに小さく表示する。他災害の既存マーカーは維持。土地の「環境効果」で名前と残り⌛数値を確認できる。環境画像は通常プレイでは霧の視界ペナルティ適用前の通常視界範囲（洞窟の壁遮蔽は維持）、テストモードは全域へ表示する（UI129）。敵の発見や土地の探索済み判定は広げない。洞窟へ地上の災害色を持ち込まないが、洞窟内の霧・常設危険地帯は表示する。
- これは表示の統合であり、発生条件・被害・索敵ペナルティ・風による霧除去・持続は変更しない。熱波等を霧データへ書き込まず、それらへ霧の索敵ペナルティを追加しない。
- `scripts/check-v39-atmosphere.mjs` で単色/2色/多色、順番/濃さ一定、中心マーカー、土地表示、保存/期限/索敵、洞窟分離、100×100とキャッシュ再利用を検証する。

`自然災害_アイコン一覧.webp` は、1山火事 / 2洪水 / 3干ばつ / 4暴風 / 5地震 / 6落雷嵐 / 7大寒波 / 8熱波 / 9火山噴火 / 10土砂崩れ / 11瘴気 / 12疫病。

- `disaster-icon-artwork.js` が原本の番号を解決し、`v39-disaster-icons.js` が既存マップ上へ表示する。画像をユニット数・被災マス数ごとに別読み込みせず、1テクスチャを共用する。
- 通常は現在の索敵範囲にある災害マーカーだけ表示。テストモードでは索敵外も不透明度0.6で表示する。重複は個数を示す。
- 火山の発生/溶岩表示は専用システムを維持。共通災害側で火山イベントを二重発生させない。
- 保存済みの旧イベントに画像指定がなければ、災害IDから現在の画像定義を参照する。未対応画像や読み込み失敗は文字へ戻す。

## テスト

テスト → 専用 → **災害テスト**。現在のゲームを置き換えるため確認を出す。

- 現行の既定起動は霧・重なり比較も含む。従来の重複なし11種類だけを試す場合は、環境欄の「固定配置に戻す」を使用する。APIでは`startV39DisasterTest({atmosphere:false})`で同じ状態を作る。`natural:true`は比較配置を含まない。

- 山火事(4,4)、洪水(10,5)、干ばつ(8,10)、落雷(12,10)に加え、暴風(18,3)、地震(22,8)、大寒波(18,20)、熱波(4,20)、土砂崩れ(20,13)、瘴気(4,14)、流星落下(11,20)の計11種類を同時配置。影響範囲は互いに重ならない。落雷エリアの7観察者と既存3地点は維持し、追加7地点に各1観察者を置く。村と自拠点も既存検証データを共用。魔獣暴走の生成元としてウルフ(16,14)を1体置く（自然発生モードでは置かない）。
- 地点/下地/追加種類は `config/v39-disaster-test.json` の `events`、落雷は `lightning` で管理。追加災害の威力/範囲/継続は通常の災害データを使用し、1T継続の災害は開始時被害の後、次ターンに解除する。落雷の5T継続のみ既存の検証用指定。
- 環境欄の固定配置一覧で残りターン（⌛数値）/終了状態と座標を確認し「発生地点へ」でカメラ移動する。対象は通常の選択マスとしても反映し、天候情報を同じ地点へ切り替える。
- 同じ環境欄の「霧・重なり比較を開始」で比較用に再初期化できる。通常霧(8,16)、死の霧(14,16)、霧＋熱波(4,20)、死の霧＋大寒波(18,20)、霧＋瘴気＋熱波＋大寒波(4,14)を配置。「霧の比較地点」を選び「比較地点へ」で移動する。単独霧2地点にも観察者を置く。比較時だけ霧と対象災害の持続を5Tに揃え、通常11種・自然発生モードの継続設定は変えない。気象の色分けは比較開始時にOFF。配置/半径/持続はconfig/v39-disaster-test.jsonのatmosphereへ集中する。セーブ/ロードで維持し、固定配置/自然発生への初期化で解除する。起動時には現在のゲームを置き換える確認を出す。
- `scripts/check-v39-atmosphere-fixture.mjs` は比較用ボタン、5地点の選択/カメラ/効果内訳、保存、実1T、再起動時の人数重複防止、自然/固定モードへの復帰を390/1100pxで検証する。
- テスト → 環境のフィールド欄で、マスと災害種別を選び「選択マスで強制発生」。火山は既存の噴火ボタンを使用。

- 通常ターンを進め、HP/産出、持続と解除を確認。必要なら途中で保存/ロードする。
- `node scripts/check-v39-disasters.mjs` は320/390/1100pxで入口・数値0/FALSE・発生率0/1・被害/産出・別ワールド隔離・保存/期限・画像/索敵を確認する。

## 未対応の専用効果

説明文だけで以下を実装済みと扱わない。

- 山火事の恒久的な地形変化。
- 暴風の飛行コスト・射撃命中、大寒波/重力/空間の移動・飛行制限、時間歪曲のAP、空間歪曲の射程。
- 地震の断崖化/土砂崩れ/洞窟崩落、土砂崩れの封鎖、積雪拡大。
- 闇侵食等の精神・士気弱体、疫病専用の人口減少、反乱軍の発生、資源枯渇による壁HP変化など。

これらは専用数値列と移動/戦闘/地形更新の接続を別途行う。現在は上記の共通被害・産出・治安・追加個体で試験できる段階。
