# 洞窟マップ・生成テスト

最終更新: 2026-10-08

## 実装済み

- 開始画面の「洞窟生成テスト」から、独立したVue画面で地下マップを生成する。通常ゲームの勢力・敵・地上マップ・ターンは変更しない。
- 10種類の接続構成。ランダム選択または形状指定、シード指定、出入口2〜4か所を選べる。探索ゲームではランダム指定の場合、階層ごとにこの一覧から選ぶ。2026-10-08から部屋の位置・半径・楕円/不規則輪郭・向きと長い通路の曲がりをシードで変化させる。同じ形状指定でもシードが異なれば床配置が変わる。
- 探索ゲームの初期シードは空欄。空欄で探索開始すると新しいシードを自動生成し、マップと敵を抽選する。再現テストはシードを手入力する。ランダム/形状指定の設定は実際に抽選された形状IDとは別に保持し、次階層でもランダムなら再抽選する。生成済み階層の再訪とロードでは保存済みマップを使い、再抽選しない。
- 一本道・分岐型・大空洞型・環状型に加え、蛇行型（折り返しの長い経路）、十字路型（中央から四方向）、双大空洞型（2つの広間と連絡路）、連続小部屋型（9部屋を巡る）、網状回廊型（環状路と交差する近道）、螺旋型（外周から中央へ進む）を用意する。
- テンプレートは `data/manual/洞窟テンプレート.json`。現在はシート管理対象外の形状データであり、シート管理の地形・出現敵JSONへ独自列を追加しない。
- マップは六角形の隣接関係で通路を接続する。壁は通行不可。地上座標を地下座標へそのまま写すのではなく、各出入口の `surfaceEntrance` に地上の入口ID・座標を対応付けられる。
- 出現敵.jsonの有効な洞窟候補を抽選し、クラス.json等を使用する既存の能力計算で敵を生成する。未設定・不正な制作途中の候補は既存出現定義の検証に従って除外する。
- テストでは通路クリックで操作位置を移動し、通路上の敵を避けた経路を表示する。敵クリックで名前・Lv・HP・攻撃・防御・好戦性を確認できる。敵はこのテスト画面では行動しない。
- 生成は同じシード・形状・出入口数・原本データなら再現する。マップと敵の状態はテスト画面内だけで保持し、閉じると破棄する。
- 生成確認の「ランダム生成」は毎回新しいシードでマップと敵を生成する。形状指定時もその形状のまま床配置・敵配置を再抽選する。「同じシードで生成」は入力シードを維持して再現する。画面を開いた直後も新しいシードを使う。

## 調整用の暫定値

`V39_CAVE_BALANCE`（v39-gameplay-balance.js）を使用する。

- `tilesPerMonster = 12`: 安全地帯を除いた通行可能マス12ごとに1体（端数切り上げ）。
- `entranceSafeDistance = 2`: 出入口から通路距離2マス以内に敵を配置しない。
- `drakeWeight = 3`: 洞窟のドレイク候補は他種の3倍の抽選重み。
- `maxTestLevel = 15`: 洞窟テストで自動配置する通常敵の最大Lv。

形状JSONは部屋数・接続構成・通路幅・入口の接続先を指定する原本。通常生成の寸法は `V39_CAVE_BALANCE.mapWidth / mapHeight`（暫定25×28）を使い、地上HEXの横62px/行間56pxで正方形寄りにする。位置の揺れ・半径倍率・輪郭の変動・曲がり率も同設定で調整する。部屋中心と全接続口を床でつなぎ、外周の岩壁を維持する。検証用の固定座標形状だけは `生成方式:固定` を指定可能。生成済みセーブの床・出入口は再生成せず保持する。

### 通路幅と部屋の接続口

`data/manual/洞窟テンプレート.json` に通路ごとの指定を保持する。既存10形状もこの形式へ移行済み。

- `部屋`: `[中心X, 中心Y, 横半径, 縦半径]` の配列。部屋番号は配列の0始まりの位置。
- `部屋接続口`: 各部屋に対応する辞書。`接続口1: [X,Y]` のように部屋の縁に接続位置を定義する。
- `通路`: `幅`（1・2・3）と`経路`を持つ。始点・終点は `{部屋:0, 接続口:"接続口1"}` で参照する。折れ曲がる中継点は従来通り `[X,Y]` を指定できる。
- `入口接続`・`入口通路幅`: 各`出入口`をどの部屋のどの接続口へ何マス幅で結ぶかを指定する。生成時に最寄りの部屋中心へ自動接続する方式は廃止。
- 1幅は中心線のみ、2幅は進行方向の片側へ1マス、3幅は両側へ1マス拡張する。六角形の隣接マスを使用し、外周の岩壁は掘らない。曲がり角・交差点・部屋との合流部は床の和集合となり、局所的には指定幅より広くなることがある。
- 全形状を一律に太くせず、蛇行・螺旋は1幅中心、広間や十字路は2～3幅、他は細い通路と太い通路を混在させる。

例：部屋0の接続口1から、部屋1の接続口1へ幅2でつなぐ。

```json
{"幅":2,"経路":[{"部屋":0,"接続口":"接続口1"},{"部屋":1,"接続口":"接続口1"}]}
```

この指定は形状データであり、シート管理の地形JSONへ追加する項目ではない。原本の部屋を変更するときは接続口も更新する。通常生成では部屋と接続口を一緒に変換し、ランダムな輪郭でも接続口へ通路を確保する。

## 現行の洞窟探索（通常ゲームの所在マップ切替）

- 地上・地下共通で、移動範囲と経路の計画は未発見の敵・他勢力・村守備軍を占有障害として使わない（テストモードの半透明表示も通常の発見とは区別）。実移動では占有マスへ重ならず、接触した1歩の手前の停止可能位置へ戻す。味方・同盟は通過できるが停止不可。APは実際に進んだ経路分のみ消費し、隣接で接触して動かなければ消費しない。
- 接触した相手は、同じターン・同じマップ・接触時の座標にいる間、操作プレイヤーの視界内で発見扱いにする。`visibility.contactReveals` をプレイヤーごとに保存し、他プレイヤーへ共有しない。攻撃後の隠密低下とは別で、相手の隠密値は変更しない。

- 移動・攻撃の位置選択は、そのプレイヤー・所在マップ・操作ターン内だけ有効。敵ターン開始、プレイヤー交代、マップ切替、ロードで解除し、移動の保存用コマンドも元プレイヤー側で解除する。別マップに残したキャラは現在の画面から移動・攻撃・待機・調査・採取できない。AIや描画処理中の入力ロックは待機・攻撃・調査・採取にも適用する。
- 行動の「待機」でそのターンを終えたキャラは、APが残っていても実位置を変える隊列交換はできない。移動用の「その場待機」とは別扱い。地下の残移動AP・移動力表示は、実際に動く同じマップのメンバーだけで計算する。
- 洞窟テスト1階には会話専用ドワーフを配置。既存の下部行動欄から武器購入/製作・装備・5件の依頼を利用できる。詳細と仮値、保存範囲は `洞窟イベントテスト.md`。通常ゲームの洞窟へのNPC追加と正式な共通イベントへの接続は別作業。
- 下部は既存の操作UIそのものを使う。洞窟用カード・行動・装備UI・時計・簡易戦闘はマウントしない。フィールドも既存Phaserへ地下データをロードする。
- 既存ユニットがいる場合は選択中の部隊が入る。ユニットがいない開始画面のテストでは最初に種族系統を `人族 / 亜人 / 魔族` から選び、作成人数を人族3人・亜人2人・魔族1人とする。各メンバーの具体種族は選択した系統内から選び、名前・クラスを設定する。初期Lvは「洞窟へ来れるようになった時点」の想定に合わせて通常ユニット初期Lvから別途調整する。現行の人族Lv7・亜人Lv10・魔族Lv12は調整の基準値であり、洞窟開始Lvの確定値ではない。作成後は通常のplayers/factionState/units/squadsへ登録する。
- worldIdとlocationsByWorldで所在・マップごとの座標を保持する。HP/AP/装備/経験値/スキルは既存ユニットのデータであり、出入りで別ユニットへのコピーや巻き戻しをしない。
- activeWorldId/explorationWorldsにマップ・敵・地点・視界などマップ固有のデータを保持する。マップ切替では通常の新規生成イベントを発火せず、領土・敵の初期化処理を回さない。
- 地下でも通常の攻撃/回復/技能/AP/敵ターン処理を使用する。移動APも通常の移動力に基づく式。岩壁は通常移動の通行判定で不可とする。
- 地下ではプレイヤー・敵ともに視界を `1 + floor(索敵 / 37.5) + 2` マスとする。地上は従来の `1 + floor(索敵 / 75)`。地下の有効索敵は距離3まで元値を保持し、距離4以降は1マスにつき25減衰（下限0）。地上は距離2以降50減衰。地下の減衰率は `visionScoutStep / 75` に連動し、範囲追加も `visionBonusTiles` に連動する。索敵・隠密の元データは変更せず、範囲外・壁越しは引き続き非表示。表示/敵AIで同じ計算を使う。正の射程値は通常のマス換算後に2倍（射程20: 地上2マス/地下4マス）。射程0・未記載は隣接1マスのまま。調整は `V39_CAVE_BALANCE.visionBonusTiles / visionScoutStep / attackRangeMultiplier`、生成JSONは書き換えない。
- 地下移動の先頭は部隊の `movementLeaderId` に保存し、操作・選択キャラと分離する。未設定の旧セーブは登録順の最初の生存者を使い、死亡・別世界の先頭は同じ世界の最初の生存者へフォールバックする。後衛選択や階層往来では先頭・選択を勝手に変更しない。隊列は `formationType`（縦列／前2人）と `formationSlots`（ユニットID・行・列）を保存し、先頭の進行方向に対する相対位置へ各メンバーが並行移動する。六角形の前2人は斜め横の2枠。狭路や曲がり角では一時的に縦列へ縮め、広い場所で元の設定へ戻す。離れたメンバーは通行可能な経路で合流し、1歩ごとの移動は隣接マスまたはその場に限る。展開時に後衛が追いつく追加移動もAPとスライド演出へ計上する。死亡者は移動しない。新しい地下マップへの初回配置は入口で通行可能な縦列へ配置し、移動時に展開する。再訪時は保存済みの座標を保持する。地上も同じ相対隊列・追従方式を使う（2026-10-13変更）。
- 移動用の「その場待機」はユニットの `movementHold` を保存し、明示解除まで継続する。APを消費せず、通常のターン待機とも別状態。待機者は部隊移動から外れ、攻撃・魔法を使っても解除されない。先頭が待機中なら部隊移動を禁止し、解除または別キャラへの先頭変更が必要。階層移動・地上往来にも同行せず元の世界・座標へ残る。旧セーブは縦列・その場待機なしとして読む。
- 隊列入れ替え直後の1マス通路では、部隊員の隣接移動先を同時に割り当て、味方同士の位置入れ替えを許可する。前2人が収まらない場所は縦列へ縮退し、保存した隊列設定は維持する。各員は1歩またはその場に限り、停止位置は重複しない。地上・地下とも別部隊の自軍／有効な同盟のユニットは経路上で通過可能だが、そのユニットのいるマスを部隊の停止位置にしない。待機者や同盟者を勝手に動かさず、通過した距離のAPは移動部隊だけが消費する。敵・中立・期限切れ同盟・鍛冶師は通過不可。
- 先頭の明示変更ではその場待機者の座標を固定し、動けるメンバーの位置だけ交換する。待機した元先頭を残して移動する操作は維持する。前へ／後ろへで待機者自身の位置を交換したい場合は解除が必要。
- 洞窟の通常敵は出現敵シートの `出現形態 / 集団数_Min / 集団数_Max` を参照し、単独・小集団・群れを近接配置する。同じ遭遇には `groupId / spawnForm / encounterGroupSize` を保存する。空欄は単独1体。暫定でビートルは群れ5～8体、クモ・ムカデ・マインドフレイヤーは小集団2～3体。数値はシート原本で調整する。入口安全距離・壁・重複配置を避け、中心から半径2マス（`encounterGroupRadius`）以内の接続床へ配置する。床不足時は配置できる人数まで減らす。総数目安は従来の床12マスにつき1体を維持し、最後の集団は途中で切らず完了するため目安を超える場合がある。集団連携AI・群れ攻撃の演出統合は未実装。
- 入口上では行動欄に出入りを表示。下り口では次階層へ進める。周期ボス・群生地・鉱床は既存テンプレート生成を引き継ぎ、地点はPhaser上に表示して通常行動欄から採取/休息する。採取物は部隊の既存運搬品へ入る。
- 発見済みの鉱石・宝石は周囲1マス（六角形の隣接6マス）から対象をクリックして指定する。行動の「採取」で対象名・座標・残量・APを確認し、詳細の「使用」で採取する。地点/カード選択だけでは実行しない。選択キャラのAP30で1個を部隊運搬品へ追加し、埋蔵量を1減らす。隣接外・未発見・AP不足・待機済み・枯渇時は無効。キャラ/マップ切替時は対象を解除する。休息は群生地の上で行う。残量のある現地の群生地だけ行動欄へ表示し、地点/カードの選択で詳細を確認してから使用で回復する。採取は残量のある発見済み隣接鉱床がない場合は非表示とし、AP不足などの実行条件不足なら薄く表示する。APと地点の残量と獲得品を同時に確定し、採取結果は活動ログにも記録する。
- 戦闘EXPは地上と同じ次Lv必要EXP基準（`CHARACTER_STATUS_RULES.md` 3.4）。同じ階層の生存部隊員がそれぞれ同額を受け取り、人数で分割しない。
- 地上・洞窟の戦闘ログは右側ログのヘッダーで「通知→戦闘→チャット」と切り替えて閲覧できる。活動ログにも保存する。戦闘の新着、チャットを閉じている間の新着はフィールド上側へポップアップする。表示4秒・最大3件は `V39_LOG_PREVIEW_BALANCE` で調整可能。ポップアップを押すと該当ログ欄を開く。非表示マップの戦闘は活動ログへ保存するがポップアップしない。
- 地上の洞窟を固定走査順でグループ化して地下1階を共有する。中心入口から6マス以内・最大4入口は暫定値（`surfaceEntranceLinkDistance / maxSurfaceEntrances`）。別の入口から出ると対応する地上の洞窟へ戻る。地上出口と下り階段は分離し、地下2階以降の上り口は直前の階層へ接続する。移動するのは操作プレイヤーの選択部隊の生存者だけ。配置時は通行・敵・他部隊との重複を避け、空き不足では切替を中止する。
- 壁は視界と射程を遮る。近い壁そのものは見えるが壁越しの敵は見えず、敵味方とも壁越しに攻撃できない。直線・扇形・炸裂も壁を越えない。地下の端は反対側へラップしない。
- 隊列変更は地下のユニットカードを長押し・右クリックし、「移動先頭にする／縦列／前2人／その場待機（解除）／前へ／後ろへ」を選ぶ。キーボードはShift+F10でも開ける。常設の↑/↓は表示しない。「前へ／後ろへ」はリスト順だけでなく、交換する2人の実座標を同じターンに交換する。「移動先頭にする」も既存の隊列位置へ順番に入り直す。通行可能な経路をスライド表示し、完了後に座標と登録順を同時確定する。交換で実際に移動したキャラは、経路の各マスを通常移動と同じ地形・移動力・高低差の計算でAP消費する。動かないキャラのAPは減らさない。誰かのAPが足りなければ交換全体を行わない。選択キャラ・HP・装備・ターンを保持し、残りAPがあれば同ターンに移動できる。前2人への追加展開分が不足しても通常の1歩は進める。交換中は他の操作をロックする。同じ階層の生存者だけが対象で、動かすメンバーにその場待機者がいる場合は先に解除する。敵・壁等で経路がないときは座標も順番も変更せず通知する。縦列／前2人の幅指定自体は次の移動から反映し、狭路では一列に縮める。待機中はカードの座標欄に⏸を表示。スクロール時は長押しを取り消し、先頭の前移動・末尾の後移動は無効にする。
- 訪問済みマップの敵AI・待機技・死亡処理は各マップで進む。地上の地形/勢力AIと経済・建設・研究・外交は共通ターン内で一度だけ進む。地下へ入ったユニットも資源消費の対象。非表示マップはPhaserをロードし直さず、移動・攻撃演出を再生しない。所属の違うマップにいるユニットは同じ座標でも攻撃・索敵・占有・死体回収の対象にしない。地下の自然災害抽選は行わない。
- マップ別に敵の待機/CT、視界、調査履歴、採取残量、カメラを保存。セーブ時に表示中マップも同期し、ロード時は全階層の待機技を現行スキルJSONから復元する。2階層+地上の保存復元、別入口退出、上り階段、非表示階層AI、地上建設1ターン進行、所在別ダメージ判定を実画面テストで検証済み（`scripts/check-v39-cave-worlds.mjs`）。

## 旧独立探索テストの検証記録（現行画面では不使用）

以下は旧CaveAdventureの専用画面/簡易戦闘の記録であり、現行ゲームの仕様ではない。

開始画面の「洞窟生成テスト」→「探索ゲーム」から開始する。

### 表示と操作の共通化（2026-10-04）

- 生成確認と3人の作成は設定モーダル。探索開始後はモーダルを外し、通常ゲームの `.topbar / .playfield / .footer` へ表示する。
- 上下比率・PC/スマホの文字サイズ・左タブ・キャラカード・詳細・行動カードのCSSを通常画面と共用する。洞窟用に別のレスポンシブ配置を作らない。
- 地図のドラッグ、ホイール、2指ピンチ、＋−でカメラを操作する。ドラッグ終了は移動クリックとして扱わない。拡縮の上限は共通表示設定を参照する。
- 部隊タブは左に3人とHP/AP・並び替え、右に「ステータス技能／行動」。装備変更はステータス側から開く。キャラ画像も地上と同じ画像解決処理を利用する。
- 行動選択中は通路距離による射程を黄色、カーソル対象を赤で表示する。同じ行動の再押下または移動で解除する。回復は仲間カードの対象ボタン、またはフィールドの仲間を指定する。

### 2026-10-11 奥地マップの鉱床化（暫定実装）

- ボスを生成すると`map.caveBossIds`を保存する。ボスとそのマップの生存敵をすべて倒すと、部隊の行動欄から「鉱床化」が可能。自軍の同じ洞窟にいる生存キャラで、プレイヤーターン中・待機していないことが必要。暫定AP30。選択しただけで自動的に鉱床化はしない。
- ボス撃破後は行動欄の上部に「鉱床化する / あとで」を表示する。残敵がいる場合は理由を示し、鉱床化は残敵制圧後。「あとで」を選ぶとそのプレイヤー・そのボス世代の案内を閉じるだけで、通常の鉱床化ボタンは残る。見送り判断は保存し、ロード/タブ切替で繰り返し案内しない。再巣化したボスを撃破した場合は新しい世代として案内する。
- 現在は最終階層が未確定で、奥地が継続生成される。したがって鉱床化対象は**攻略したボスのいる奥地マップ1枚**であり、未攻略の奥地や上層まで一括所有しない。テスト探索でも同じ処理を使い、次の奥地へ進める。洞窟全体の攻略終了判定は後続仕様。
- 所有者は鉱床化した操作プレイヤー。`map.caveMine`に所有者・攻略ターン・処理済みターン・産出周期進捗・産出物・現地在庫を保存し、ワールド切替とセーブ/ロードでも保持する。
- 暫定産出は、そのマップに鉱石地点があれば鉱石1、宝石地点があれば宝石1を1ターンごとに現地在庫へ加算。地点数倍にはせず、鉱床化したターンは産出しない。元の有限採取地点が枯渇していても継続採掘できる。旧セーブでボスIDが保存されずボスも既に除去済みの場合は、攻略を推測して鉱床化しない。
- 共通ターン解決で各ワールドの死亡/アンデッド化判定後に採掘する。表示していない奥地も採掘し、同じターンの再処理では重複加算しない。暫定で生存敵がいる間は停止、所有権と在庫は保持し、敵がいなくなった次の解決から再開する。
- 自軍の同じ奥地の入口にいるキャラで「鉱床回収」を押すと全在庫を既存の部隊運搬品へ移す。暫定AP0。別プレイヤーや入口以外からは回収不可。拠点へ瞬間転送せず、既存の部隊物資運搬を利用する。回収できない場合は在庫を減らさない。

### 2026-10-11 未鉱床化の奥地の再巣化

- ボスを倒した奥地を鉱床化せず、プレイヤーが不在のまま5進捗ターン経過すると、別のモンスター集団が巣を作り新ボスが生まれる。プレイヤーが滞在するターンは加算せず進捗-1、下限0。複数人でも減算は1回。5ターンと減算値は既存`V39_CAVE_NEST_BALANCE`を共用する。
- 判定範囲は暫定で奥地マップ1枚。同じマップの生存プレイヤーユニット（待機/その場待機を含む）がいれば訪問中。別階層の滞在者や死亡者は数えない。残敵がいる間も進捗加算を停止する。攻略ターンには加算しない。非表示階層も共通ターンで進み、同ターン重複/ロードによる二重生成を防ぐ。
- `出現敵.json`の洞窟候補から種族・クラス・画像を選び、前のボスと別種族を優先する。別種候補がない場合だけ同種も可能。能力は既存JSON由来の敵生成を使い、通常個体Lvは候補最大Lv＋既存の階層補正、ボスLvは既存ボス補正と上限を適用する。
- **流入・食料確保は仮の抽象処理**。外の個体を実際に移動/減算する処理はまだない。流入計画を保存し、既定で同種族2体と、クラスの消費可能資源1種類20を持ち込む前提とする。食料必要量1未満なら成立不可。食料を消費しない種族は免除。この計画の個体は進捗中は盤面へ出さず、成立時に通常2体＋ボス1体を同時生成する。後から正式な流入や食料獲得へ置換する。
- 巣は既存`enemyNests / enemySquads`へ登録し、個体の`nestId / worldId`を紐づける。初期巣人口5はフィールド個体数と別の仮設定。入口安全距離、NPC、生存者、壁を避けた接続床へ集団を配置する。空き床や有効なクラスが不足して生成失敗した場合は、生成済み扱いにせず後続ターンへ持ち越す。
- 再巣化時はボスIDを新世代のものへ交換する。新ボス/残敵が生存中は鉱床化不可で、再攻略後はまた鉱床化を選択できる。鉱床化済みの奥地は今回の自動再巣化対象から外す（鉱床への侵入と警備は別の後続機能）。通常プレイで未視認の非表示世界の成立を通知しない。
- 追加の調整項目: `recolonizeUnclaimed / preferDifferentRace / arrivalFoodAmount / minimumArrivalFood / initialNestPopulation`。生成JSONは変更しない。

- 洞窟を巣にする場合、プレイヤーが来なかったターンに進捗を加算する。侵入中は加算せず、その滞在ターン数分だけ進捗を戻す。リセットではなく減算、下限0。複数プレイヤー・複数ユニットが同じターンにいても人数分は減算しない。
- 鉱床化した洞窟にも生物は侵入できる。警備兵は入口に配置する所有プレイヤーの軍隊ユニットで、専用NPCの自動生成はしない。警備されている入口は警備兵の突破が必要。`allowEntryIntoPlayerMine / guardPlacement / guardUnitSource / autoCreateGuards`で方針を保存するが、各設定をゲームへ反映する処理は後続実装。
- 進捗は`v39-cave-nest-rules.js`の共通関数で計算する。保存用データは`progressTurns / lastProcessedTurn / ready`。同じターンの再評価は無変更。未処理ターンのプレイヤー所在を推測して遡及加減算しない。
- 正式値が未確定: 食料が十分かの必要量、プレイヤー侵入を判定する洞窟全体/階層の境界、条件不足時の進捗、鉱床の採掘停止条件。未鉱床化奥地は上記の仮条件を使い、条件不足時は暫定で進捗保持。警備ユニットの能力・作成費用は既存の軍隊生成ルールを使用し、別の警備兵Lvや人数を新設しない。

### 共通ターン処理の状態取得・描画（2026-10-04）
- 表示中の世界を処理するだけの段階では、地図全体の保存・復元を行わない。別世界のユニットが混在するときは対象世界へ投影し、更新時に他世界のユニットを保持する。
- 非表示世界は従来どおり背景コンテキストで進行し、退出・セーブ時は必要なマップを保存する。通常の状態取得は独立コピーを返す仕様を維持する。
- 保存済みの別世界マップが不要な内部処理では `getV39GameState({ includeWorlds:false })` を使う。この結果を全状態として復元せず、必要な項目だけ更新する。
- ターン途中のコンテキスト内更新は通知せず、ターン末にまとめてUIへ反映する。ターン番号の取得、非表示敵の演出判定、ログ追加で地図全体のコピー・不要なUI更新を繰り返さない。

## 2026-10-13 部屋エリアと死の霧

生成時に部屋を起点として床/通路の所属を距離順に割り当て、caveAreaByTile/caveAreasを保存する。死の霧は発生した部屋所属エリアのみを覆い、接続通路全体/階層全体へ自動拡張しない。旧データの部屋情報がない場合のみ接続床を補完単位とする。複層Zは見送り。共通処理はv39-cave-areas.js。
