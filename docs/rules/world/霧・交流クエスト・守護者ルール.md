# 霧・交流クエスト・守護者ルール

更新: 2026-10-13。以下の機能は現行v39へ接続済み。明示した確定値以外の数値は、調整可能な試作値。

2026-10-20追記: 通常プレイの守護者/配下は覇権地の固定奥地へ配置する。地上の交流と依頼は保存された奥地の生存守護者を参照し、友好譲渡も維持する。攻略/退出/取得/NPCの往復は `覇権地奥地テスト.md`、村の防衛と再入植は `一般村防衛・廃村ルール.md` を参照。一般村の新規依頼は村計画と実際の不足/脅威から生成し、イベントシートの村計画・依頼ひな型を原本とする。旧固定4行/番号付き会話からの新規依頼提示は廃止。守護者依頼等の残る暫定定義は正式化完了扱いにしない。

## 1. 霧

- 2026-10-20: 常霧の谷/瘴気地帯を常設危険地帯として生成・保存・表示へ接続。発生源は残し、風の範囲内だけ3T抑制後に自動復帰。通常霧の既存周期/確率/持続や死の霧の発生条件は変更しない。常霧から死の霧へ自動変化しない。通常霧の地域気象補正は未接続。詳細は `災害ルール.md`「常設の危険地帯・適応と防衛」。

- 通常の霧と死の霧の両方に適用する。
- 観測者・対象・両者を結ぶ六角マスの経路にある霧を数え、外から中、中から外、霧越しの索敵に同じペナルティを適用する。
- 暫定では霧1マスにつき索敵値-50、視界半径-1。隣接1マスの視界は維持するが、隠密との判定は索敵減少後の値を使う。
- プレイヤーの発見・敵AI・勢力AIの索敵は共通ルールを参照する。縄張りの範囲自体は縮めない。
- `効果`に`霧`がある技は攻撃範囲へ一時的な霧を配置する。`氷霧`で発生を確認。名称だけから霧を推測しない。
- 持続は`効果時間`をターンとして読み、未指定時だけ暫定3ターン。再配置時は長い期限を残す。`mapData.fogMap`へ期限を保存する。
- 地形変換で作られた死の霧には、既存の地形変換の持続ルールを使う。
- 表示画像は通常霧/死の霧とも`assets/images/background/pipo-fog018.webp`を共用する。瘴気/熱波/大寒波との重なりは一枚のグラデーションへ合成し、重複数で濃さを増やさない。不透明度は表示設定を参照する。通常プレイの環境画像は霧のペナルティを適用する前の通常視界範囲まで表示し、洞窟の壁を越えない（UI129）。テストモードでは全体表示。画像の表示だけでは土地を探索済みにせず、敵の発見・攻撃・災害通知は従来のペナルティ適用後の範囲を使う。未探索の暗幕より上へ霧画像だけを重ね、地形・敵・施設の詳細は明かさない。色/順番は`config/v39-atmosphere-display.json`、詳細は災害ルール「霧と重なる環境災害」。旧`deathImage`は互換設定として残るが現行描画では使わない。
- 死の霧はエフェクト属性設定の`死霊`の色を参照する。単色設定ならTint、グラデーション設定なら先頭色を霧全体の着色に使う。属性設定変更時も再描画し、色コードを別途固定しない。
- 画像・透明度・索敵減少・視界減少の調整先は`frontend/src/lib/v39-gameplay-balance.js`の`V39_FOG_BALANCE`。
- 自然の通常霧は全勢力のターン終了後、5の倍数ターンに発生判定し、5ターン持続する（例: T5発生、T10消滅）。同じターンの再評価・ロードで再抽選しない。地下では自然発生しない。
- 発生量の暫定設定は8×8マスごとの地域で5%、同時最大3地域、半径1～2マスの不規則形。森林・湿地・沼地・湖・川のマスを中心候補にする。発生確率・対象地形・広さ・上限は未確定で、共通設定から調整できる。
- `系統`に`風`があり、`炸裂`が0.5以上の攻撃は実際の攻撃範囲内の通常霧・死の霧を吹き飛ばす。炸裂端数による範囲も対象。風属性値だけ・名称だけでは判定しない。敵味方共通。消した霧は次の自然発生判定まで自動補充しない。
- 死の霧の地形変換は特殊レイヤーから霧だけを取り除き、基本地形を保持する。通常霧の自然発生周期はスキル霧の`効果時間`を変更しない。

### 浄化値と死の霧・アンデッド

- マスの浄化0を中立とし、死体の残るマスは毎ターン-1（数が増えても同じ）。死の霧と死体が両方あるマスだけ追加-1とし、霧だけでは低下しない（UI122）。回収・蘇生・期限切れ・アンデッド化などで死体がなくなれば追加低下も止める。
- 浄化-5以下のマスで毎ターン排他的イベント判定。暫定は死の霧8%、アンデッド8%、何もなし84%。成立した同じマスは5T再判定しない。旧死体数×確率/5T抽選は廃止。
- 地上は発生地点+周囲1の7マス、洞窟は生成時の部屋所属エリアだけ。通路は近い部屋に割当て、階層全体へ広げない。複層Z座標は採用しない。
- 霧配置時には中心・周辺/同エリアの浄化を低下させない（UI122）。暫定持続5T、風で除去可能。死体が消えても既存霧を即座に消さない。発生だけで死体を消費しない。既に下がった浄化値は今回自動回復させず、不浄イベントの閾値・抽選や死体のアンデッド化確率も変更しない。
- 発生したばかりの霧から同じターンにアンデッドを重ねて生成しない。次Tから既存の死体変化を判定する。
- 浄化-5以下の死の霧内で、死体1体ごとに毎ターン、発生源100%・その他50%でゾンビ/スケルトンへ変化。発生源はLv+3。生成成功時だけ元ユニット/死体100を消費し、荷物を残す。空きがない・生成失敗なら保持。通常の霧内死体変化は有限の死体/配置先で抑制し、自然発生最大2体/5Tを別途適用しない。
- 死体のない不浄イベントによる自然発生は既存候補重み（ゾンビ50/スケルトン30/ゴースト20）を使用。同ワールドで最大2体/T、同マス5T。死体のあるイベントは死体変化処理を共有して自然発生上限を適用し、同じ死体から二重生成しない。
- 霧外の死体1%、空の死の霧2%という旧独立抽選は廃止。災害による既存発生は別処理。調整はV39_UNDEAD_SPAWN_BALANCE/V39_FOG_BALANCE。
- アンデッドAIの味方種族除外、死の刃の現在値-5、未実装の召喚所属/上位化はアンデッド・不浄ルールを参照。
- 肉食/雑食の生物の安全時の死体資源消費は維持する。埋葬行動は未実装案。霧・浄化・エリア・抽選済みターン・自然発生履歴は保存対象。

## 2. 一般村の依頼（UI53）

- 交流欄は村情報・全受注件数と「村で会話・依頼」の入口だけ。村の休息・受注・報告等は共通モーダルで行う。
- 新規依頼は村計画の実際の不足/脅威から生成。旧固定穀物50/木材50、番号付き会話、悪魔専用の別候補は出さない。
- 一覧の左チェックで複数選択し、固定フッターで一括受注・支援報告する。受注時に自動納品しない。村ごと1件制限は撤廃。
- 受注別に目標ID/必要量/期限/進捗/報酬を保存。納品は選択拠点の在庫を消費し村在庫へ加算、部分納品は定義に従う。討伐は受注後の指定対象に限る。
- 初期ひな型の報酬は友好度+10。受注前の交渉で金・既知物資・人口を複数要求でき、合意を固定して完了時に一括移転する。不足時は納品・完了・報酬全体を巻き戻す。
- 旧セーブの会話式依頼は完了互換だけ維持。詳細の正本は[一般村イベント共通ルール](../diplomacy/一般村イベント共通ルール.md)と[交渉モーダルルール](../ui/交渉モーダルルール.md)。

### UI103: 警備・建設・複合支援・定期納品の正式ひな型

- 原本は「イベント」21〜24行、イベント種別=依頼ひな型。新しい固定依頼や会話分岐ではなく、既存の村計画・不足・守備隊の状態から必要な候補だけ生成する。受注と報告は共通チェック一覧と固定フッターを使う。
- `計画対象=警備` / `目標=警備_3`: 守備不足・訓練中・脅威のある村で、対象範囲内に生存する自軍ユニットが3T連続して滞在。受注ターンは数えず、離れたターンは0へ戻す。
- `建設支援` / `建設_1`: 実計画の未完成施設を受注時に固定し、その村での完成を確認する。既存施設や自軍の別拠点への建設では新規依頼を達成しない。旧セーブの近隣自拠点建設依頼だけは従来の判定を維持する。
- `複合支援` / `警備_3/建設_1`: 両目標を保存し、両方の達成後に一度だけ報酬を付与する。片方だけで報告不可。任意の効果を無制限に組み合わせる汎用実行ではなく、今回対応した2種類のAND目標。
- `継続支援`: 食料不足の計画から資源と1回の量を固定。数量上限20、周期5T、猶予3T、目標ターン3（納品回数）の初期値。各納品日に村で支援報告し、選択中拠点の在庫を消費して村へ渡す。早すぎる報告・同周期の再報告・在庫不足は無消費で拒否。猶予を超えた後の報告は消費せず次回日を現在T＋周期へ更新する。過去分の一括徴収はしない。
- 定期契約の友好度・交渉済み報酬は最終回だけ。中間納品では報酬を付与しない。資源消費後に最終報酬が支払えなければ全体を元の状態へ戻す。周期・進捗・対象・報酬は保存後も維持する。
- 報酬+10、期限20T（単発支援）、クールダウン5Tを原本で調整可能。契約は各納品日を使い、単発の期限列は空欄。旧configの新規警備/建設候補を除去し、旧保存の完了処理だけ残す。
- これは有限回の手動定期納品契約。輸送部隊による自動履行は既存の取引・物流を使う別機能。威圧から締結する生贄・守護契約、任意の複合語彙、支援量の貢献度判定は未追加。
- 実装: `v39-village-support-goals.js` / `v39-village-plans.js` / `v39-neutral-village-rules.js`。確認: `check-v39-event-support.mjs` と「村の計画・支援」テスト。

## 3. 守護者の依頼・譲渡

- UI102（2026-10-24）: 原本は `@game_data` の「イベント」18〜20行。分類=守護者、種別=依頼を専用変換器で検証し、`イベント会話.json` へ生成する。仮configへのフォールバックはしない。新規は次の難しい3試練へ置換した。
- 希少資源の奉納（`GUARDIAN_TRIAL_RESOURCES`）: `黒木_10/特木_10/青金鋼_10/赤黒鋼_10/宝石_10`。5種類すべてを選択中の自拠点在庫から一括消費する。消費列の1-1にも同じ全項目を指定。不足が1種類でもあれば全資源・報酬・完了状態を変更しない。これらは在庫資源であり、特産品の期間貸出ではない。
- 周辺の村の発展（`GUARDIAN_TRIAL_DEVELOPMENT`）: `村発展_施設3_数2`、対象範囲16。範囲内の生存・未廃村・完成施設3種類未満の村から近い2村を受注時に固定する。村/町等の住居規模を除いた完成施設の種類数が3以上、かつ受注時より増加した状態で報告する。建設中・同名施設の重複は数えない。必要村数が不足する場合は受注を拒否し、必要条件を表示する。村自体の既存の自動建設/支援依頼を利用する。プレイヤーの支援量による貢献判定は未追加。
- 力の証明（`GUARDIAN_TRIAL_POWER`）: `試練召喚_守護者配下_Lv30_数1`、対象範囲3。奥地の配下（strongMinion）の種族・職業・装備を参照し、既存の共通能力計算でLv30の敵1体を地上の空き・侵入可能マスへ生成。配下不在なら守護者の基礎種族を使い、固有神獣自体を複製しない。空き不足時は受注も生成も行わない。再受注・保存復元で増殖させない。通常戦闘の死亡処理で討伐実績を保存してから消滅させる。単なるIDの消失では達成にしない。召喚体は死体/装備/携帯物を残さない。
- 資源数・施設数・村数・範囲・召喚Lv/体数・友好度報酬はシートで調整可能な初期値。各報酬は友好度+35、上限100。守護者ごとの固有試練構成・外交条件・特産品期間提供は未接続。
- 1=受注、1-1=報告、1-2=保留、2=辞退の番号を既存の守護者操作へ対応させる。番号付き会話画面や一般村の旧固定依頼を復活させる変更ではない。未対応の期限/再発生/追加条件/資源報酬/契約は変換時に拒否する。
- 受注時に数量・範囲・対象ID・友好度報酬・回答を固定して保存する。原本変更で進行中の条件を差し替えない。旧保存の必要数/進捗/完了IDは維持し、報酬未保存の旧受注だけ互換値を使う。
- 勝利対象土地を調査して発見し、生存する自軍ユニットが中心から3マス以内にいるとき、土地タブから交渉できる。
- 受注は1件ずつ、各試練1回。3試練すべてを報告すると「守護者を引き継ぐ」を選べる。友好度70だけでは取得不可。進捗・完了・召喚体の対象と討伐実績はプレイヤー/覇権地別に保存する。
- 旧木材/見張り/周辺討伐の受注済み保存は元の条件と報酬で完了可能だが、新規提示しない。旧IDの完了は新3試練の達成に数えない。旧見張りの連続ターン/中断判定も互換として維持。
- 受注中・交渉継続中は守護者AIがそのプレイヤーを攻撃対象から外す。ただし守護者を攻撃して交戦状態に入った場合は反撃し、交渉を拒否する。他プレイヤーとの戦闘は妨げない。
- 譲渡時は対象土地の占有マス全体を選択中拠点の領土へ登録し、守護者・配下・巣を撤去する。他プレイヤー所有マスを含む場合は譲渡を拒否する。
- 平和的な交代では撃破経験値・戦利品を付与しない。譲渡済み守護者は再生成しない。
- 戦闘で守護者を倒し、通常の領土取得処理で確保する既存の経路も維持する。

## 4. 勝利判定

### 2026-10-20 確保期間と妨害（実装済み）

- プレイヤー・NPCは共通の支配判定を使う。勝利対象土地の占有マスすべてを所有していることが必要。
- 土地取得時の確保進捗は0。以降のターン終了側の探索ステージで、影響範囲内に生存する敵対ユニットがいなければ+1、いれば-1。下限0、上限5。敵の人数にかかわらず1ターンの変化量は1で、5に達すると勝利する。取得しただけ・守護者譲渡直後に即勝利はしない。
- 現行の必要地点数は1、必要確保進捗は5（ユーザー確定）。地点数/期間は`V39_VICTORY_CONDITION_BALANCE`で調整する。別の儀式を今回の必須条件へ追加しない。
- 敵対勢力のユニットは共通外交の攻撃可否で判定。一般敵は好戦的個体/巣の個体/守護者/当該プレイヤーへの報復・村事件戦闘などが対象。自軍・通常の中立ユニット・死体・別ワールド・施設内保管中は数えない。索敵できるかではなく物理的な侵入で判定する。
- 占有範囲の端への侵入も妨害になる。判定時までに敵を倒す・範囲外へ追い出した場合は妨害なし。同じターンの再判定では加減算しない。ターンを飛ばして読み込んでも、未処理の過去ターン分をまとめて加算しない。
- 土地の一部でも所有を失うと、その土地の進捗を解除する。再取得時は0から。取得/喪失は領土更新時に観測し、取得ターンを余分に加算しない。
- 進捗・最終処理ターンをプレイヤー/土地ごとに保存する。旧未勝利セーブは新カウンタ0から開始し、過去の所有期間で即勝利させない。確定済みの旧勝利は維持する。勝利時は結果を保存し、通知して通常のターン進行を停止し、再判定で通知を繰り返さない。
- 交流画面の守護地詳細に確保進捗と妨害中を表示。プレイヤー/NPCは同じ処理を使う。洞窟の即時鉱床化・再巣化ルール自体は変更していない。
- 検証: `check-v39-victory-security.mjs` と `check-v39-victory-conditions.mjs`。

## 5. データ原本と未対応

- 正式な村イベントはスプレッドシートから生成されたJSONを読む。生成JSONだけの項目追加はしない。
- 守護者3試練と警備/建設/警備＋建設/定期納品のひな型は原本管理。動物分類は`config/v39-event-defaults.json`で仮管理。任意の契約や未対応語彙をシートへ書いただけで実行可能にはならない。
- `check-v39-guardian-sheet.mjs` は `check-v39-guardian-trials.mjs` を呼び、390/1100幅で新3試練、5資源の原子的納品、村の通常ターン建設、召喚体の実戦討伐と消滅、保存再開、旧依頼互換、3件報告後の平和取得を検証する。テスト操作→専用→守護者3試練テストから手動確認できる。
- 全イベント種別の汎用実行、依頼放棄、最終儀式、守護者納品の分割は未対応。一般村の部分納品・今回の有限定期契約とは区別する。既存の洞窟ドワーフ依頼も別経路。

## 勝利土地ごとの守護者候補（2026-10-20）

UI103より設定元は「勝利対象土地」シートG:N。`勝利対象土地.json` へ生成し、土地ごとに1候補を選ぶ。旧configと固定Lv設定は除去した。

- G「守護者候補」はname/race/className/uniqueと任意lowerForm/trialIdsのJSON配列。候補固有trialIdsがあればM列の土地共通試練より優先し、生成時に覇権地へ保存する。H「配下候補」はrace/classNameのJSON配列。I〜Lは守護者Lv/配下数/配下Lv差/配下Lv幅、M「試練ID」は有効な守護者イベント3件のID配列、Nは守護範囲。
- クラス未登録・無効/不明試練ID・重複試練・負数/型不正は変換エラー。固有クラス自体は新設せず、既存テンプレート参照を保持する。
- 現状は4土地とも共通3試練を指定。土地別の試練ID差し替えをゲームが読むよう接続済みだが、守護者個体ごとの固有問答・専用戦術を実装済みにはしない。受注済みの試練と生成済みの守護者は上書きしない。

- 朱雀はフェニックスの上位として扱う。同じ候補一覧へフェニックスを重複登録しない。火口の第三候補（溶岩竜等）は未確定なので追加しない。
- 固有クラスは現時点では未登録。候補設定の既存race/classNameを能力テンプレートに使用し、固有クラスの同名データが登録されたらそちらを優先する。クラーケンの能力テンプレートは暫定の水精霊＋幻獣で、正式な触手等の能力を実装済みとは扱わない。生成JSONやクラスを勝手に新設しない。
- ボスLv40と既存の巣・部隊・依頼・占領処理を共用する。名前/専用画像は選んだ候補を使用。取り巻きは下記の土地別種族・属性候補を使い、ボスと同じ神獣を複製しない。
- 候補選択時には同ワールドの生存敵・各勢力の配下を確認し、同名候補の重複を避ける。既存の守護巣があれば再生成しない。候補を使い切った場合は通常敵を代用せず生成を見送る。
- マップseedと土地ID/座標によって選び、生成されたユニットと巣を保存する。既に守護者が生成済みのセーブは置き換えない。通常敵の出現全般・召喚・合成の世界唯一制限はこの候補選択とは別であり、今回変更していない。
- `check:guardian-candidates`: 4土地/100seedで全11候補、重複除外、取り巻き非複製、画像、保存/読込、二重生成防止を確認する。

### 通常出現からの神獣除外（2026-10-20）

- 白虎Lv25の原因は「タイガー＋エンジェル→白虎」が合成候補にあり、通常強敵のレシピ条件を満たしていたこと。守護者候補の配置だけでは通常強敵から除外されていなかった。
- 通常強敵進化は合成レシピ限定に加え、ボーナスクラスに神獣を含む結果、および守護者候補設定で神獣テンプレートを使う固有名を除外する。通常出現定義も該当固有名/種族/サブクラスと神獣クラスを除外。守護者の専用生成はこの通常出現フィルターを通さず引き続き生成する。
- 合成操作自体はこの自然出現制限では禁止しない。既存セーブ中の生成済み白虎も自動削除しない。再生成した通常敵から適用する。
- 守護者固有依頼は会話案を大枠採用した未実装計画。白虎:凶獣討伐、スフィンクス:問答、応龍:水源の敵排除、麒麟:村支援、白沢:調査、九尾狐:特産品の期間提供、朱雀:アンデッド討伐、サラマンダー:鉱石納品、玄武:防衛、青龍:河川/沿岸討伐、クラーケン:食料納品/海域討伐。現状は既存の共通依頼を使用する。

### 土地別の配下（2026-10-20）

- 「勝利対象土地」の配下候補列で種族＋クラスを指定。出現敵に登録済みで、検証済みの単独定義だけ使用する。軍隊枠は混ぜず、登録のない属性組合せを付与して補わない。候補なしなら配下なし。
- 太陽: ソルアニマルのホーク/タイガー、黄昏: ムーンアニマルのウルフ/トレント、火口: 炎精霊/フレイムアニマルのボア・フォックス、海: シーアニマルのスネーク・クロコダイル/水精霊。現在未登録の太陽ホーク・トレントは生成されず、残りの登録済み候補を使う。
- 初期値はシートの配下数2、守護者Lv40、配下Lv差20/幅5でLv15〜20。配置床が不足した場合は置ける数まで。味方を含む生存ユニットのいるマスへ重ねない。
- 土地とseedで候補順を選び、同じ候補を必要なら複数配置する。生成済みの巣を維持するため、戦闘中に失った配下を毎ターン補充しない。神域の固定配置は生息地・気温による自然出現とは別のイベント配置で、通常の生息地条件を無理に満たす属性付与は行わない。
