# 画像素材の準備リスト

確認日: 2026-10-18

現在の実ファイル・画像対応表・ブラウザ上の画像解決処理を照合した一覧。
ゲームデータや画像の割当は変更していない。
「専用画像へ解決できない」と「実画像が存在しない」は区別する。シート内に既存画像がある場合は、新規制作せずファイル名と番号を設定する。

追補: 最初の確認は出現敵と動物中心で、合成結果の妖怪等と、非出現種族の確認が漏れていた。以下の6〜9節を追加。原本の「クラス」A1:E1223と「モンスター合成」A1:W98も読み取り確認した。シートの候補は、クラスとして正式実装済みという意味ではない。

## 1. 優先: 施設8種

施設データに存在するが、`facility-icon-artwork.js` の専用画像対応がないもの。
既存の建築シート2枚に登録済みの24施設は制作不要。

| 用意する画像 | 見分けるための要素 |
| --- | --- |
| 船着き場 | 小さな木製桟橋。大型の港とは区別 |
| 温泉 | 岩の浴槽・湯気。公衆浴場とは区別 |
| 調薬所 | 小屋・薬瓶・薬草 |

| 魔獣研究所 | 魔獣の飼育・合成を扱う施設 |
| 魂の保管庫 | 魂を封じた容器・魔法装置 |

単体画像なら256×256pxを制作上の目安とする（新しい必須規格ではない）。
現在の施設ローダーは4列×3行の建築シート形式。まとめる場合は `建築_アイコン一覧3.webp` とし、各枠の対象を併記する。8画像なので残り4枠は空欄でよい。
単体画像で受け取る場合は、接続時にローダー対応が必要。

シートで渡す場合は4列×3行、左上から右へ1〜12番とし、対象一覧を添える。

## 5. 受け渡し先

- 建物: `assets/images/アイコン/`
- ユニット集合画像: `assets/images/units/1ファイルまとめ/`
- 単体画像: 対象名を明記して渡す。既存の探索対象は `assets/images/illust/` などだが、配置形式と用途に合わせて接続時に決める。
- シートはファイル名に加え「番号 → 対象」の一覧を添える。画像内に番号や名前を焼き込まない。
- 追加しただけでは対応表・データ更新が必要な場合がある。自動で全対象へ接続されるとは限らない。

## 8. クラスに存在するが出現敵中心の確認から漏れたもの

以下は同名の専用ユニットファイルを確認できない対象。集合画像の枠を照合してから不足分を制作する。
共通画像や同種族の通常画像での仮表示と、専用画像が揃っていることは区別する。

| 系統 | 専用画像の確認/準備対象 |
| --- | --- |
| スライム | 毒スライム、ラヴァスライム、水晶スライム、氷スライム、ショゴスタイプ |
| ゴーレム | ウッドゴーレム、クレイゴーレム、ストーンゴーレム、アイアンゴーレム、フレッシュゴーレム、ボーンゴーレム、クリスタルゴーレム、アイスゴーレム、マグマゴーレム、サンドゴーレム、ミスリルゴーレム、アダマンティンゴーレム、マッドゴーレム |
| 上位アンデッド | レヴナント、ドゥームゾンビ、バンシー、ギャザード・グラッジ、蒼炎のデュラハン |

通常スライムには既存の単体画像がある。スライムをLvで小/中/大/特大へ切り替える専用シートは別途必要。
上位アンデッドには既存のアンデッド集合画像があるため、まず枠の中身を確認する。名前に対応する単体ファイルがないだけで、新規制作を必須とはしない。
デュラハン、ガスト、グール、ワイト、リッチ、ゴースト等は既存単体画像/シート対応があるため、この不足対象には含めない。

## 9. 追加動物の派生と人型職業

- 追加動物は通常6種だけで完成ではない。合成シートの派生欄に、ライオン（炎/太陽/地）、オウル（風/月/天使）、ディア（風/太陽/氷）、タートル（水/地/氷）、炎フォックスもある。これらの専用画像は未確認なので、通常画像の後に用意する候補。
- ライノセラス、エレファント、キャメル、クラブ、スクイード、スラッグ、ラビット等も合成シートの派生欄には存在する。ただし現在のクラス登録とは別。名称や採用状態を確認してから制作し、既存の昆虫・甲殻シート等との重複も避ける。
- 人型の上位職は、現在の方針どおり前提となる基本職画像を流用可能。上位職すべてに専用立ち絵を要求しない。
- 基本職でも、バード等は既存の12枠職業対応に専用枠がない。専用の職業姿を用意するなら別途対応が必要であり、上位職画像の不足と混同しない。
- 「幻獣」「神獣」「凶獣」「妖獣」などの補正クラス名ごとに汎用立ち絵1枚を作るのではなく、実際の合成結果の姿を用意する。
