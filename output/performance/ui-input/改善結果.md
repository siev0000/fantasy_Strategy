# タブ・スクロール中の負荷改善

2026-10-04。100×100・固定seed・390×844px・Chromium CPU 4倍低速相当で操作を計測。実スマホGPUを測った数値ではない。

## 原因と修正
- 拠点タブを開くたび、既に状態変更時に作成済みの表示を再計算し、DOMを交換していた。タブ切替だけの重複更新を削除。状態変更・拠点選択・建設更新は従来どおり反映する。
- 静止中も地図全体のContainer/Graphicsを毎フレームGPUへ送っていた。入力と時計処理は継続し、変更がないフレームはPhaserの更新専用stepを使う。地図変更・カメラ操作・Tween・攻撃エフェクト中は通常描画する。
- 通知されない表示変更も拾うため、静止中も1秒間隔で描画。調整箇所は `frontend/src/lib/phaser-map-panel-config.js` の `MAP_IDLE_RENDER_CONFIG`。

## 結果
同条件の拠点タブの同期処理: **197.4ms → 3.8ms**（各1回）。資料は `before100.json` / `after100.json`。追加スクロール計測は `after100-scroll.json`。

回帰テストで静止500msの描画0回・入力/時計更新31回、移動Tweenとエフェクトの連続描画、カメラ変更・ホイール拡大、長い下部一覧の実ホイールスクロールを確認。

洞窟往来・保存復元・背景世界AI・移動・AP・戦闘演出の既存テスト、フロントビルドも成功。ブラウザー例外なし。UIレイアウト・ゲームデータは変更していない。

入力の全ラグが解消したことを保証するものではない。大規模な状態更新直後と多数エフェクト中には従来の描画負荷が残る。継続する場合は端末・地図サイズ・操作箇所を指定して再計測する。
